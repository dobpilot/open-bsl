## 2026-08-07 — vm-call-by-name (implement)

**Задача:** узкий публичный API в `bsl-vm` для вызова процедуры/функции
модуля по имени из рантайма, поверх машинерии изолированного исполнения
`Выполнить`/`Вычислить`.

**Изменённые файлы:** только `crates/bsl-vm/src/lib.rs`.

- Новая `pub fn call_module_function(program, stack, name, args) ->
  Result<(BslValue, Vec<BslValue>), RtError>` рядом с `run_dynamic_snippet`.
  Вход обёрнут в `DynamicDepthGuard::enter()`; имя ищется регистронезависимо
  (`to_uppercase`) по `program.function_names`, попадание `i` даёт чанк
  `chunks[i + 1]`. Стек кадра — `[арг0..аргN-1]` + `push_own_registers`, за
  регистрами копия модульного блока, `Program` поднимается с тем же
  содержимым и `module_base` за регистрами, исполнение через `drive`.
  После возврата модульный блок переносится обратно в `stack` вызывающего,
  а слоты параметров `0..n_params` отдаются вторым элементом пары.
- Неизвестное имя и несовпадение арности — `RtError::DynamicError` с русским
  текстом (перехватываемо `Попытка`), новых вариантов `RtError` не заводил.
  Рассогласованная `Program` (имя есть, чанка нет) и короткий `stack` дают
  `RtError::InvalidBytecode` через `at`/`reg_load`. Голых `unwrap()`/`expect()`
  вне тестов не добавлено.
- Шесть юнит-тестов из ACCEPTANCE в том же `mod tests`, плюс два хелпера
  (`compile_src`, `module_state` — прогоняет верхний уровень через `drive`
  и отдаёт его финальный стек, то есть настоящее состояние модуля).

**Замечания по семантике (не платформенные, замера не требуют):**

- Аргументы передаются по значению: у рантайма нет слота вызывающего,
  который можно было бы алиасить (в отличие от `Instr::Call`, где
  `param_aliases` указывает в кадр вызывающего). Поэтому запись в параметр
  без `Знач` наблюдаема только через возвращаемые финальные значения слотов
  — это и есть будущий канал для `Отказ` на этапе json-callbacks.
- Арность обязана совпадать РОВНО. Проверено по коду: `bsl-sema` добивает
  список аргументов до `n_params` маркером `RExpr::Skipped`
  (`resolver.rs:869`), кодоген превращает его в `LoadSkipped`, а значение по
  умолчанию вычисляет пролог самой функции (`compile_param_defaults`). То
  есть вызывающий этот API может передать `BslValue::Skipped` и получить
  дефолт — отдельного механизма не нужно, но и «передать меньше аргументов»
  нельзя.
- `Program` клонируется целиком на каждый вызов (иначе не поменять
  `module_base`, а `drive` берёт `&Program`) — ровно то же делает
  `run_dynamic_snippet`. На этапе json-callbacks, где вызов идёт на каждый
  элемент документа, это может оказаться заметной стоимостью; сейчас не
  измерено и в задачу не входило.
- Маркеров `НЕ ИЗМЕРЕНО` не добавлял: API внутренний, платформой напрямую
  не наблюдаем, наблюдаемое поведение появится на следующем этапе.
  Реестр `open_questions.rs` не трогал.

**Неизвестное:** поведение при вызове функции модуля, содержащей
`Выполнить`/`Вычислить`, отдельным тестом не покрыто (в ACCEPTANCE такого
пункта нет). По коду путь корректен — `aliased` в `run_dynamic_snippet`
считается как `scope_id == 0 && module_base == 0`, а здесь `scope_id =
func_id >= 1`, так что фрагмент пойдёт неалиасной веткой, — но это
рассуждение, а не прогон.
