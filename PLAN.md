# PLAN

## TASK_ID: vm-call-by-name

## DIFFICULTY: hard

## TASK: Узкий публичный API в bsl-vm для вызова процедуры/функции модуля по имени из рантайма, поверх существующей машинерии изолированного исполнения `Выполнить`/`Вычислить`.

## CRATE(S): bsl-vm — только `crates/bsl-vm/src/lib.rs` (новая публичная функция рядом с `run_dynamic_snippet`; юнит-тесты в уже существующем `mod tests` того же файла).

## APPROACH:

- Добавить публичную функцию вида
  `pub fn call_module_function(program: &Program, stack: &mut [BslValue], name: &str, args: Vec<BslValue>) -> Result<(BslValue, Vec<BslValue>), RtError>`:
  возвращает значение `Возврат` (для процедуры — `Неопределено`) И финальные
  значения слотов параметров — следующий этап (json-callbacks) обязан читать
  параметр `Отказ` после вызова, закладываем это сразу, чтобы не менять
  сигнатуру потом.
- Поиск имени: регистронезависимо через `to_uppercase()` (так сравнивает
  идентификаторы `bsl-sema`, см. `resolve_snippet_stmts`) по
  `program.function_names`; попадание `i` означает чанк `program.chunks[i + 1]`
  — `function_names` включает и процедуры, и функции. Неизвестное имя и
  несовпадение арности (`args.len() != chunk.n_params`) — перехватываемый
  `RtError` с русским текстом (подходящий существующий вариант, например
  `DynamicError`, либо новый вариант — но тогда с exhaustive-обработкой во
  всех `match` по `RtError`), не паника: имя приходит из пользовательских
  данных.
- Исполнение — по образцу неалиасного пути `run_dynamic_snippet`, но без
  текстовой прослойки и без `SnippetCache` (чанк уже скомпилирован):
  собрать стек фрагмента `[арг0..аргN-1]`, дорастить до `chunk.n_regs`
  (`push_own_registers` или `resize`), за регистрами положить копию
  модульного блока из `stack` по `program.module_base`, поднять `Program` с
  теми же `chunks`/`names`/`shapes`/`function_names`/`module_vars` и
  `module_base`, указывающим за регистры, и запустить `drive(...,
  func_id, ...)`. После завершения перенести модульный блок назад в `stack`
  (мутации модульных переменных вызванной функцией обязаны пережить вызов —
  та же дисциплина, что в `run_dynamic_snippet`).
- Обернуть вход в `DynamicDepthGuard::enter()`: вызов по имени — такой же
  вложенный `drive` на стеке Rust, как `Выполнить`, и рекурсия через будущие
  колбэки не должна валить процесс мимо `Попытка`.
- Аргументы передаются по значению (алиасов на слоты вызывающего у рантайма
  нет); наблюдаемость изменений — через возвращаемые финальные значения
  слотов параметров. Зафиксировать это в rustdoc русской технической прозой.
- Маркеры `НЕ ИЗМЕРЕНО` на этом этапе не нужны: API внутренний и напрямую
  платформой не наблюдаем; платформенная семантика (порядок обхода функции
  восстановления, `Отказ` и т.д.) измеряется на следующем этапе
  json-callbacks, где появится наблюдаемое поведение.

## ACCEPTANCE:

- `cargo test -p bsl-vm call_module_function` — новые юнит-тесты, все обязаны существовать и проходить:
  - `call_module_function_by_name_returns_value` — модуль с `Функция Удвоить(х) ... Возврат х * 2; ... КонецФункции`, вызов по имени в ДРУГОМ регистре («уДВОИТЬ») с аргументом 21 даёт 42;
  - `call_module_function_passes_several_args` — функция от трёх аргументов, проверка порядка;
  - `call_module_function_on_procedure_returns_undefined` — вызов процедуры даёт `Неопределено`, а мутация её параметра видна в возвращённых финальных значениях слотов;
  - `call_module_function_mutates_module_var` — процедура пишет в модульную переменную, изменение видно в `stack` вызывающего после возврата;
  - `call_module_function_unknown_name_is_rt_error` — неизвестное имя даёт `Err(RtError...)`, не панику;
  - `call_module_function_wrong_arity_is_rt_error` — неверное число аргументов даёт `Err(RtError...)`.
- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` — зелёные.
