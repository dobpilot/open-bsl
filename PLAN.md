# План итерации

## TASK_ID: json-callbacks

## DIFFICULTY: hard

## TASK: Реализовать функции преобразования/восстановления `ЗаписатьJSON`/`ПрочитатьJSON` поверх `call_module_function`, сняв заглушку «появятся позже».

## CRATE(S):
- `bsl-rt`: `src/json.rs` (протаскивание колбэка в `serialize`/чтение; сегодня несериализуемое значение — это `unsupported_value_error(has_convert_fn)`, `json.rs:2431`/`2433`), `src/builtin.rs` (разбор колбэк-аргументов вместо `reject_unsupported_json_callback_args`, `builtin.rs:855`, вызываемой на `args[4..8]` для `ПрочитатьJSON` в `builtin.rs:922` и на `args[4..6]` для `ЗаписатьJSON` в `builtin.rs:931`), при новых вопросах — `src/open_questions.rs`.
- `bsl-vm`: `src/lib.rs` — `call_builtin_with_format` (`lib.rs:1822`) получает VM-контекст и перехватывает `ReadJson`/`WriteJson` с непустым именем колбэка ДО делегирования в `bsl_rt::call_builtin_fn_ctx`; места вызова — `drive` у `Instr::CallBuiltin` (`lib.rs:1123`) и JIT-шим `shim_call_builtin` (`jit/mod.rs:734`, вызов на `jit/mod.rs:756`).
- Фикстуры/замеры: `tests/conformance/fixtures/json-callbacks.bsl` + `.expected` (только с платформы), при новых `НЕ ИЗМЕРЕНО` — `tests/conformance/measure/measure-all.bsl`.

## APPROACH:

- **Раскладка аргументов — по факту кода, не по памяти.** `ЗаписатьJSON`: `args[3]` — имя функции преобразования (непустое имя УЖЕ принимается и превращается в `has_convert_fn`, `builtin.rs:939` — эта измеренная семантика не меняется), `args[4..6]` — модуль и дополнительные параметры, сейчас отвергаемые заглушкой. `ПрочитатьJSON`: `args[4..8]` — имя функции восстановления, модуль, дополнительные параметры, `ИменаСвойствДляФункцииВосстановления`. `arity_range` обеих функций эти позиции уже включает — `bsl-syntax`/`bsl-sema` не трогаются.
- **Направление зависимостей.** `bsl-rt` не видит `bsl-vm`, поэтому вызов по имени приходит сверху замыканием. В `bsl-rt` завести тип колбэка (`&mut dyn FnMut(&str, Vec<BslValue>) -> RtResult<(BslValue, Vec<BslValue>)>` — имя + аргументы → (значение `Возврат`, финальные слоты параметров)) и структуру-спецификацию, разбираемую из хвостовых аргументов; второй элемент пары — канал для `Отказ` (аргументы в `call_module_function` идут по значению, запись в параметр наблюдаема только через возвращаемые финальные слоты — см. PROGRESS.md итерации 1).
- **Точка перехвата — общая для интерпретатора и JIT.** Расширить `call_builtin_with_format` параметрами `program: &Program` и `stack: &mut [BslValue]` (сигнатура `call_module_function`, `lib.rs:1433`, берёт именно срез; оба значения доступны и в `drive`, и в `shim_call_builtin`; `CallArgs` владеет копиями аргументов, так что повторное `&mut` заимствование стека законно). Ветки `ReadJson`/`WriteJson` при непустом имени колбэка строят замыкание над `call_module_function` и зовут новые входы `bsl-rt`; путь `call_builtin_fn_ctx` без VM-контекста оставляет понятную ошибку (переформулировать «появятся позже» — колбэки требуют исполняющей VM).
- **Семантика — по статье 16.2, закрывается замером, а не пересказом.** Функция преобразования: сигнатура `(Свойство, Значение, ДополнительныеПараметры, Отказ)`, зовётся ТОЛЬКО на несериализуемом значении (лень измерена на этапе 0 и не меняется); `Отказ = Истина` из финального слота → та же ошибка типа, что и без функции; возвращённое значение сериализуется обычными правилами. Функция восстановления: `(Свойство, Значение, ДополнительныеПараметры)`; непустой массив `ИменаСвойствДляФункцииВосстановления` сужает вызовы до перечисленных свойств. Ошибки самого вызова (нет такой функции, не то число параметров) — `RtError` из `call_module_function`, перехватываемый `Попытка`; тексты не глотать.
- **Сначала пробы, потом код.** Прогнать через `run-on-1c.sh` (~6 с) пробы на всё, что решает дизайн: что платформа принимает в `МодульФункции*` из модуля формы (`Неопределено` против `ЭтотОбъект` — от этого зависит текст фикстуры, обязанный исполняться одинаково на обеих сторонах); что приходит в `Свойство` вне объекта (элемент массива, верхний уровень); что делает платформа, если функция преобразования вернула снова несериализуемое; для каких позиций документа зовётся функция восстановления — таблица статьи на 24 позиции оформляется фикстурой. Каждая проба — в `Попытка` (модальное окно = таймаут 180 с). Решение, не закрытое замером, — тройка `НЕ ИЗМЕРЕНО(JSON.*)` + `open_questions.rs` + одна строка в `measure-all.bsl`.
- **Тесты снизу вверх.** Юнит-тесты в `bsl-rt` с mock-замыканием на Rust (без VM): лень вызова функции преобразования, ветка `Отказ`, порядок и фильтрация вызовов функции восстановления, ошибки колбэка не проглатываются. Сквозные тесты в `bsl-vm` через `drive` на BSL-скрипте с настоящими функциями модуля. Фикстура `json-callbacks.bsl` трассирует вызовы через `Сообщить`; её `.expected` — ТОЛЬКО прогон `run-on-1c.sh`, никогда не вывод этого интерпретатора; попав в корпус, она автоматически покрывается JIT-сверкой `the_jit_agrees_with_the_interpreter_on_every_script`.
- Дисциплина проекта: `RtError` вместо `unwrap` на путях пользовательских данных; измеренные семантики этапа 0 (ошибка типа без функции, лень записи, немедленность чтения, `has_convert_fn` в тексте ошибки) не менять; комментарии — русской технической прозой.
