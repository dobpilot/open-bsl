# Нативные функциональные опции над константой

Платформа 1С 8.3.27.2342, отдельная файловая база
`/tmp/open-bsl-functional-option-constant-1009-ib`, 2026-10-09.
Штатные Designer `/DumpCfg` и `/DumpConfigToFiles` выполнены после
контроля `../measure-functional-option-constant.bsl`; нативный ответ
сохранён в соседнем `.platform.txt` (14 строк, без SETUP_ERROR).

CF содержит целиком собственную тестовую конфигурацию. XML — независимая
выгрузка корня, константы и двух опций: Location совпадает, привилегированный
режим различается. SHA256SUMS относится к неизменённым байтам выгрузки.
Приложенный XML не является результатом декодера SDK.

Исходная структура булевой константы взята из нативной фикстуры
open-sdbl `tests/fixtures/access/native-095/ProbeConstant.xml`, переименована
в ЗначениеОпцииПробы. XML функциональных опций подготовлен для платформы;
его принятая форма дополнительно подтверждена обратной штатной выгрузкой.
GUID не происходят из рабочих конфигураций пользователей.

Измерено: начальное значение No (Boolean), чтение Yes после записи True и
No после записи False; лишняя структура параметров игнорируется; оба
псевдонима вызова и другое написание регистра имени опции работают.
Неизвестная опция вызывает исключение. Полные имена: Constant и
FunctionalOption при английском ScriptVariant. Контроль не доказывает
политику прав разных пользователей, различия исполнения привилегированных
опций, параметризованные источники или схему SQL-хранения константы.
Рабочие базы demo/buh/unf не менялись.
