# Нативные параметризованные функциональные опции справочника

1С 8.3.27.2342, отдельная файловая база
`/tmp/open-bsl-functional-option-catalog-iteration-1009-ib`, 2026-10-09.
CF и XML получены штатными Designer `/DumpCfg` и `/DumpConfigToFiles`
после контроля `../measure-functional-option-catalog.bsl` (18 строк,
без CATALOG_SETUP_ERROR). SHA256SUMS проверяет исходные байты выгрузки.

Справочник создан из собственных тестовых XML репозитория. Два его
реквизита — Булево и Число, оба ForItem. Опции ссылаются на разные
реквизиты; один параметр ссылается на сам справочник. В своей базе
созданы два элемента и группа. Рабочие demo/buh/unf не затрагивались.
Привилегированный режим обеих опций true; права разных пользователей
и режим false этим контролем не проверены.

Измерено: полная ссылка даёт False/True и число 20; неполные параметры
дают дизъюнкцию булевых значений, но исключение для числовой опции.
Пустая ссылка для обеих опций даёт Boolean:No; группа с неприменимым
реквизитом даёт Null. Неизвестный ключ структуры не ограничивает отбор.
Использование параметра — коллекция Metadata object property values
collection, Count=1, обход возвращает метаданные справочника;
индекс [0] отклоняется. XML независимо показывает Use/MDObjectRef.

Первое расширение контроля ошибочно использовало [0] и остановилось;
6-строчный ответ сохранён в
`/tmp/open-bsl-functional-option-catalog-index-rejection-1009.platform.txt`.
Финальный исходник перехватывает этот отказ отдельно и использует обход;
18-строчный эталон снят заново, вручную не исправлялся.

Периодические регистры, несколько измерений, несколько связанных
объектов параметра и политика кэширования здесь не измерены.
