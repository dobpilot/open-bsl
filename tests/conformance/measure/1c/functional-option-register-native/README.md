# Нативные функциональные опции непериодического регистра

Платформа 1С 8.3.27.2342, отдельная файловая база
`/tmp/open-bsl-functional-option-register-1009-ib`, 2026-10-09.
Контроль `../measure-functional-option-register.bsl` завершился с 17 строками
без REGISTER_SETUP_ERROR. CF/XML выгружены штатными Designer `/DumpCfg`
и `/DumpConfigToFiles` после пробы. SHA256SUMS проверяет семь файлов.

Собственная XML-заготовка построена из document-movements-register.xml:
WriteMode=Independent, Nonperiodical, два числовых измерения, булевый и
числовой ресурсы. Две опции связываются с ресурсами, два параметра — с
разными измерениями. Обратная выгрузка независимо подтверждает эти связи,
режим записи и периодичность. Проба записывает только три собственные
строки (1,1,false,10), (1,2,true,20), (2,1,false,30). Рабочие базы не менялись.

Измерено: полный отбор возвращает значения ресурсов; частичный булевый
отбор вычисляет OR только подходящих строк. При неполном наборе параметров
числовой опции платформа выдаёт исключение, в том числе при одной
подходящей строке. Полный отбор без совпадения возвращает Boolean:No
даже для числовой опции. При пустом регистре без параметров булева опция
false, числовая вызывает исключение о неполных параметрах.

Это не доказательство семантики периодического регистра, RLS, политики
кэширования, привилегированного режима при разных пользователях или
многосвязного Use одного параметра. Оба флага PrivilegedGetMode здесь true.
