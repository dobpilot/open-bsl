# Измерения файлового API

`file-object.bsl` — начальные исследовательские пробы, не готовый oracle.
Состав и источники: [инвентаризация Файл](../../../../docs/research/compatibility/file-interface-inventory-2026-09-09.md).

Перед платформенным запуском записать версию, ОС, literal/effective compatibility,
клиентский или серверный контекст, часовой пояс и рабочий каталог. Один
серверный запуск не закрывает клиентские методы и наоборот. Измеритель
создаёт собственный каталог по выданному временному имени; изменение атрибутов
и очистка ограничены им. При ошибке очистки сохранить путь для ручной проверки.

В выводе обязательны `file.begin` и `file.end`; `file.setup_error` означает,
что пробы существующего файла не выполнены, даже если конец достигнут.
Ошибки отдельных проб записываются, а не считаются успешными результатами.
Сырые сообщения ошибок могут содержать пути и различаться между платформами;
нормализацию oracle определить после просмотра реального результата.

Исследовательские идентификаторы отделены от реестра OPEN_QUESTIONS.
До внедрения неизмеренной семантики необходимо добавить соответствующую
тройку: маркер в Rust, запись реестра и уникальную строку канонического
измерителя. Наличие этого скрипта само по себе такой тройкой не является.

Проверка оболочки без 1С:

```sh
cargo run -p bsl-cli -- tests/conformance/measure/filesystem/file-object.bsl
```

Вывод open-bsl нельзя сохранять как `.expected` или платформенный oracle.
Группа `directory.*` проверяет тип, существование, размер каталога и путь
с завершающим разделителем. Группа `refresh.*` использует один объект `Файл`
до создания файла, после записи, перезаписи и удаления: она различает живые
сведения и снимок метаданных. `refresh.error` означает незавершённую группу,
а не результат оставшихся проб. `file.scratch` сохраняет путь собственного
каталога для проверки при неудачной очистке.

Матрица пока не покрывает весь план; следующие группы — ссылки,
ошибки доступа и аргументов, асинхронные методы, поиск, удаление и сроки жизни.

`file-object-io-edges.bsl` отделяет лексическое имя `Файл` от операционного
пути на 22 сочетаниях NUL и выбранных управляющих/пробельных символов.
Каждый случай использует собственный временный корень; вывод не содержит
самих управляющих символов. Серверный oracle и разбор сохранены в
`file-object-io-edges.platform.txt` и отчёте
`docs/research/compatibility/file-object-io-edges-server-2026-09-17.md`.

`file-read-io-edges.bsl` проверяет тот же операционный путь у трёх
читателей: `Новый ДвоичныеДанные`, `Новый ФайловыйПоток` и
`ФайловыеПотоки.ОткрытьДляЧтения`. Одиннадцать серверных случаев сохранены
в `file-read-io-edges.platform.txt`; контекст, хеши и найденный отдельный
отказ открытия каталога разобраны в
`docs/research/compatibility/file-read-io-edges-server-2026-09-17.md`.

`file-create-directory-edges.bsl` различает физический путь создания через
последующее удаление базового имени. Одиннадцать серверных случаев конечных
управляющих символов сохранены в одноимённом `.platform.txt`; отчёт —
`docs/research/compatibility/file-create-directory-edges-server-2026-09-17.md`.

`file-delete-more-types.bsl` безопасно проверяет десять дополнительных типов
маски удаления на отдельных временных деревьях. Oracle и восстановление
разобраны в `docs/research/compatibility/file-delete-more-types-server-2026-09-17.md`.

`file-mask-extensions.bsl` проверяет 40 изолированных случаев чистого
сопоставления: двенадцать POSIX-классов, отрицание, пять escape-форм и четыре
повреждённые формы. Имя со звёздочкой намеренно исключено как особый
`sfile://`-случай. Oracle и граница вывода разобраны в
`docs/research/compatibility/file-mask-extensions-server-2026-09-17.md`;
последующий `file-search-sfile` закрыл границу с `*` и `\`, оставив правила
отбора специальных объектов в `FIND.TRAVERSAL`.

`file-search-sfile.bsl` проверяет внешнее дерево ОС с шестью положениями
звёздочки, вопросительным знаком и обратной косой чертой. Для серверной 1С
placeholder заменяется абсолютным host-путём; локальный fallback нужен только
для исполнимости той же оболочки в open-bsl. Oracle, снимок дерева и исходная
неоднозначность вопросительных масок разобраны в
`docs/research/compatibility/file-search-sfile-server-2026-09-18.md`.

`file-search-sfile-selection.bsl` продолжает эту пробу матрицей из 208
сочетаний тринадцати физических имён со звёздочкой и масок. Она фиксирует
отдельный выбор `sfile` для литеральных, экранированных, чисто вопросительных
и смешанных wildcard-масок. Oracle, внешний снимок и граница оставшегося
`FIND.TRAVERSAL` разобраны в
`docs/research/compatibility/file-search-sfile-selection-server-2026-09-18.md`.

`file-search-sfile-directory.bsl` проверяет физический каталог `a*` с
вложенным файлом. Рекурсивный поиск не входит в такой каталог независимо от
совпадения маски; oracle, внешний снимок и исправленное расхождение разобраны
в `docs/research/compatibility/file-search-sfile-directory-server-2026-09-18.md`.

`file-search-sfile-links.bsl` повторяет выбор и рекурсию для имени `a*`,
которое является ссылкой на каталог, файл либо отсутствующую цель. Все три
вида дают один специальный результат и никогда не открывают цель. Отчёт —
`docs/research/compatibility/file-search-sfile-links-server-2026-09-18.md`.

`file-object-host-edges.bsl` проверяет четыре основных метода `Файл` на
обычном файле, каталоге, FIFO, Unix-сокете и пяти классах отказа metadata,
а также свойства восьми корневых форм. Oracle и исправленные правила разобраны в
`docs/research/compatibility/file-object-host-edges-server-2026-09-18.md`.

`file-object-devices.bsl` проверяет те же четыре метода на пяти символьных
устройствах Linux. Oracle и измеренная классификация описаны в
`docs/research/compatibility/file-object-devices-server-2026-09-18.md`.

`file-write-io-edges.bsl` проверяет фактические байты после четырёх способов
открытия потока на запись для одиннадцати управляющих путей. Все 44 результата
совпали без изменения runtime; отчёт —
`docs/research/compatibility/file-write-io-edges-server-2026-09-18.md`.

`file-text-writer-io-edges.bsl` проверяет те же одиннадцать путей для
`Новый ЗаписьТекста` по BOM базового файла. Отчёт —
`docs/research/compatibility/file-text-writer-io-edges-server-2026-09-18.md`.

`file-json-io-edges.bsl` проверяет файловые входы `ЧтениеJSON` и
`ЗаписьJSON` по значению и байтам базового файла. Один зависающий путь чтения
каталога исключён из oracle; 21 безопасный случай описан в
`docs/research/compatibility/file-json-io-edges-server-2026-09-18.md`.

`file-textdoc-io-edges.bsl` проверяет `ТекстовыйДокумент.Прочитать/Записать`
по тексту и байтам базового файла. Отчёт —
`docs/research/compatibility/file-textdoc-io-edges-server-2026-09-18.md`.

`file-xml-io-edges.bsl` проверяет файловые входы `ЧтениеXML` и `ЗаписьXML`
по имени элемента и байтам базового файла. Отчёт —
`docs/research/compatibility/file-xml-io-edges-server-2026-09-18.md`.

`file-xdto-factory-io-edges.bsl` проверяет файловый вход
`СоздатьФабрикуXDTO` по успешному разбору минимальной XSD. Отчёт —
`docs/research/compatibility/file-xdto-factory-io-edges-server-2026-09-18.md`.

`file-spreadsheet-io-edges.bsl` проверяет `ТабличныйДокумент.Прочитать/Записать`
по тексту ячейки и факту изменения базового MXL. Отчёт —
`docs/research/compatibility/file-spreadsheet-io-edges-server-2026-09-18.md`.

`file-archive-io-edges.bsl` проверяет восемь файловых входов reader/writer:
конструктор и `Открыть` для ZIP- и Archive-типов. Reader проверяется
по числу элементов, writer — по изменению базового файла. Отчёт —
`docs/research/compatibility/file-archive-io-edges-server-2026-09-18.md`.

`file-archive-content-io-edges.bsl` проверяет источник `Добавить` и каталог
`ИзвлечьВсе` по составу архива и фактическому месту распаковки.
Отчёт — `docs/research/compatibility/file-archive-content-io-edges-server-2026-09-18.md`.

`file-time-string-arguments.bsl` проверяет 39 строковых форм для каждого из
двух setter-ов времени `Файл`: длины и компоненты, нулевые формы, краевые
пробелы, разделители и положение NUL. Каждый случай имеет отдельный файл и
после вызова читает обе даты, поэтому ошибка без мутации отличима от частичной
записи. Отчёт —
`docs/research/compatibility/file-time-string-arguments-server-2026-09-18.md`.

`file-search-more-mask-types-async.bsl` проверяет на тонком клиенте десять
дополнительных объектных типов маски одновременно для sync/Async. Девять
безопасных строковых представлений дают прямое совпадение, дата — безопасный
нулевой контроль без фиксации локали. Отчёт —
`docs/research/compatibility/file-search-more-mask-types-client-2026-09-17.md`.

`file-delete-more-types-async.bsl` повторяет десять объектных типов для
асинхронного удаления и проверяет фактическое состояние дерева после Ждать:
девять файлов удалены, контрольная дата сохранена, корень остаётся. Отчёт —
`docs/research/compatibility/file-delete-more-types-async-client-2026-09-17.md`.

`file-create-directory-relative-forms-async.bsl` проверяет двенадцать
составных форм только из `.`, `..` и разделителей одновременно для sync/Async.
Они ссылаются только на существующие каталоги; Async обязан вернуть исходную
строку. Отчёт —
`docs/research/compatibility/file-create-directory-relative-forms-client-2026-09-17.md`.

Текущий платформенный маршрут — прямой `1cv8`, без Unica, на серверной
`localhost/test`. Резервные CF/XML и подготовленная копия конфигурации
сохранены в `/tmp/open-bsl-files-platform-7xEx8x`; это временные локальные
артефакты, не oracle. После явного разрешения пользователя выполнена новая
сессия `/tmp/open-bsl-files-approved-rBiijg` со свежей резервной копией:
серверные пробы завершены, исходная конфигурация восстановлена, XML совпал
побайтно, кроме служебного ConfigDumpInfo.xml.

`file-object.platform.txt` — сырой вывод этой сессии 1С, не open-bsl.
Контекст, контрольные суммы и ограничения приведены в
[отчёте измерения](../../../../docs/research/compatibility/file-object-server-2026-09-09.md).

`file-globals.bsl` проверяет временные расширения, создание каталогов,
начальные случаи поиска и удаление по маске. Сырой результат серверной 1С —
`file-globals.platform.txt`; [разбор результатов](../../../../docs/research/compatibility/file-globals-server-2026-09-09.md).
Каждый измеритель требует отдельного запуска; глобальный измеритель использует
те же маркеры начала, конца и ошибки подготовки, но не заменяет пробы объекта.
