# Сторонние библиотеки двойников

Здесь лежит чужой код, нужный только двойникам бенчмарков на Lua. К самому
интерпретатору он отношения не имеет и в сборку не попадает.

## `slaxml.lua`

SLAXML 0.8 — потоковый (SAX-подобный) разборщик XML на чистом Lua.

* происхождение: <https://github.com/Phrogz/SLAXML>, файл `slaxml.lua`
  ветки `master`;
* автор: Gavin Kistner, © 2013–2018;
* лицензия: MIT (заголовок сохранён в самом файле), совместима с GPL-3.0
  этого репозитория.

Почему файл лежит в репозитории, а не ставится через luarocks: рокспек
`slaxml-0.8-1` ссылается на git-тег `v0.8.1`, которого в upstream больше
нет, и установка обрывается на клонировании. Вместо инструкции, которая не
работает, здесь лежит ровно тот файл, который меряется.

В системе есть ещё одна копия SLAXML — `/usr/share/nmap/nselib/slaxml.lua`
из пакета nmap, — но это ИХ адаптация («NSE implementation of SLAXML») с
собственными правками, и мерить её вместо upstream было бы подменой
предмета.

### Правка: имена на кириллице

Файл НЕ стоковый — в нём пять правок, каждая помечена комментарием
`ПРАВКА open-bsl`. Все они делают одно: расширяют класс символов в шаблонах
ИМЁН элементов и атрибутов старшими байтами UTF-8.

Стоковый SLAXML такие имена не разбирает вообще. Шаблон имени у него —
`[%a_][%w_.-]*`, а `%a` в Lua совпадает только с ASCII-буквами, поэтому на
`<контрагенты>` разбор молча даёт ноль узлов, а на первом же атрибуте с
кириллическим именем падает: «Was in an element and couldn't find attributes
or the close». Кириллический ТЕКСТ при этом разбирается нормально —
затруднение ровно в именах.

Обойтись без правки было нечем. Документ бенчмарка весь на кириллице, потому
что таков реальный обмен 1С и потому что форма записи у пары `xml_*`
совпадает с парой `json_*`. Переписать документ латиницей значило бы дать
Lua на разбор не тот документ, что остальным колонкам.

Сама правка механическая: `[%a_]` -> `[%a_\128-\255]` и `[%w_.-]` ->
`[%w_.\128-\255-]` (дефис в классе Lua обязан стоять последним, иначе
`.-\128` читается как диапазон). Алгоритм разбора она не трогает, так что
замер остаётся замером SLAXML, — но называть измеренное «стоковым SLAXML»
было бы неверно, отсюда этот раздел.
