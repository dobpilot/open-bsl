### Численные задачи `numeric_precision`

Запуск: `./benchmarks/run.sh numeric_precision 3`. Сценарий подхватывается
автоматически; последняя строка каждого двойника — общее время девяти задач
в миллисекундах, включая печать результатов. Основная повторяющаяся нагрузка —
гармонический ряд; это не отдельный замер скорости каждого из девяти вычислений.
Для просмотра результатов запускайте соответствующий `.bsl`, `.lua` или `.py`
напрямую: `run.sh` выводит только время.

Формулы и порядок операций перенесены из исходного примера с согласованной
поправкой: новое приближение Ньютона и следующий член арктангенса округляются
до 27 дробных знаков во всех трёх версиях. Без этого в текущем BSL дробный
хвост продолжает расти, и исходные условия остановки не обеспечивают завершение.
Python использует `float`, Lua — штатные двоичные числа, BSL — числа своего
runtime. Текстовый вывод между этими числовыми моделями не обязан совпадать:
в частности, малая разность больших чисел может потеряться. В рядах e и
арктангенса сохранена остановка по обнулению члена, а не по неизменности суммы;
число итераций зависит от числовой модели. У Ньютона сохранена остановка по
равенству соседних округлённых приближений. Двоичные двойники при округлении
не приобретают 27 знаков точности. Поэтому времена нельзя трактовать как скорость
получения одинаковой точности. Lua измеряет процессорное время через `os.clock`,
Python и BSL — прошедшее время, как в существующих двойниках.

Строки `EXPECTED` из исходного примера не используются как утверждения:
это не измеренный вывод платформы 1С. Платформенный результат не снимался,
`.expected` и `combined.platform.txt` не создаются и не обновляются.

## Результаты

Замеры от 2026-09-08: `./benchmarks/run.sh`, медиана пяти прогонов;
тяжёлые сценарии (`background_jobs`, `csv_write*`, `table_compare`,
`table_compare2`, `table_save_load`) — трёх. Release-сборка на основе
`22fa7c0`, Intel Core i5-8250U, Linux x86-64. Полный вывод с версиями сред
и результатами сверки CSV: [протокол прогона](results-optimize-2026-09-08.txt).

Колонка `--optimize` измерена заново с этим ключом, без `--jit`.
Колонка 1С — прежние измерения из `1c/combined.platform.txt`, платформа
в этом прогоне не запускалась. `ошибка` означает неуспешный запуск,
прочерк — отсутствие двойника, среды или сохранённого замера 1С.
Это последовательный прогон на рабочей машине, не чередующееся A/B-измерение;
