# Микробенчмарки

## Сценарии

| Сценарий | Что измеряет |
|---|---|
| `background_jobs` | Масштабирование CPU-bound фоновых заданий: 2 400 000 строк `ТаблицаЗначений` делятся между 1, 2, 4, 6, 8, 12, 16, 24, 32, 48, 64, 128 и 256 заданиями. Сценарий повторяет [нагрузку `ТестПроцессораКластера1С`](https://github.com/dobpilot/1c_benchmark/blob/master/CpuBenchmark/src/CommonModules/%D0%A2%D0%B5%D1%81%D1%82%D0%9F%D1%80%D0%BE%D1%86%D0%B5%D1%81%D1%81%D0%BE%D1%80%D0%B0%D0%9A%D0%BB%D0%B0%D1%81%D1%82%D0%B5%D1%80%D0%B01%D0%A1/Module.bsl); в однофайловую сборку 1С не входит, потому что цель должна быть общим модулем конфигурации. |
| `bmp_rotate` | Поворот 32-битного BMP 600x400 на 90°: 240 000 пар `ПолучитьСрез`/`Записать` над `БуферДвоичныхДанных` плюс сборка заголовков. |
| `call_overhead` | 1 000 000 вызовов пользовательской функции с одним сложением. |
| `cbr_rates` | Два сетевых GET-запроса через неизменённый Connector 2.6.0 к сервису курсов ЦБ, разбор XML и JSON и сверка курсов USD, EUR и CNY. Требует доступа к `www.cbr-xml-daily.ru`; задержка сети входит в результат. Lua-двойнику дополнительно нужны LuaSocket и LuaSec. |
| `csv_write` | Запись 300 001 строк CSV по 21 полю, 42 вызова записи на строку. |
| `csv_write_batched` | Та же выгрузка CSV, но строка собирается один раз и записывается одним вызовом. |
| `edata_writer` | Выгрузка EnterpriseData 1.0.1 фабрикой XDTO: 1000 «Документ.ЗаказКлиента» по пять строк товаров каждый со случайными ссылками-УИД, «ЗаписатьXML» фабрики в файл сообщения обмена 5,4 МБ. Фабрика по двум XSD из `data/` (494 КБ, 348 масок `xs:any`) строится вне замера; размер выгрузки совпадает с платформенным байт в байт (формат записи зафиксирован побайтным сличением детерминированной редакции сценария). |
| `empty_for` | Накладные расходы пустого числового цикла: 10 проходов по 1 000 001 итерации. |
| `goto_bench` | 2 000 000 проходов по горячему графу из восьми блоков: цепочки условных и безусловных `Goto` с контрольной суммой. |
| `invoice_doc_generator` | Формирование расходной накладной на 100 000 позиций из MXL-макета через `ТабличныйДокумент`: `Прочитать` платформенного `.mxl`, `ПолучитьОбласть`, заполнение параметров и `Вывести` областей. Замеряет четыре фазы — генерацию табличного документа и сохранения в MXL, PDF и XLSX (каждая печатается отдельно); контракт — сумма всех четырёх фаз в миллисекундах. |
| `json_parse` | 3 разбора документа JSON на 10 000 записей контрагентов (5 653 941 код-юнит, вложенность в четыре уровня) через `ПрочитатьJSON`. |
| `json_write` | Порождение того же документа через потоковую `ЗаписьJSON`, 3 прохода. |
| `pi_leibniz` | 1 000 000 членов ряда Лейбница; точная десятичная арифметика BSL. |
| `pi_leibniz_15` | Тот же ряд с округлением до 15 знаков на каждой итерации. |
| `regexp` | Три шаблона regex-benchmark (почта, URI, IPv4) по многоязычному тексту 6,5 МБ (`data/input_regexp.txt`), по одному `СтрНайтиВсеПоРегулярномуВыражению` на шаблон; счёт всех совпадений — 92, 5301 и 6. |
| `str_concat` | Десятикратная сборка строки из 3 000 фрагментов конкатенацией. |
| `str_index` | Посимвольный проход по строке из 330 000 кириллических код-юнитов через `Сред(s, i, 1)` + `КодСимвола`: измеряет стоимость позиционной индексации — операции O(1) на код-юнитах UTF-16, которая на UTF-8 ушла бы в линейный поиск границы символа. |
| `xml_parse` | 3 обхода документа XML на 10 000 записей контрагентов (6 854 005 код-юнитов, 540 002 узла, 100 000 атрибутов) потоковым `ЧтениеXML`. |
| `xml_write` | Порождение того же документа через потоковую `ЗаписьXML`, 3 прохода. |
| `zip_read` | Распаковка `data/zip-corpus.zip` (2,3 МБ сжато, 7,3 МБ исходных, три записи deflate) через `ЧтениеZipФайла.ИзвлечьВсе`: inflate и файловый вывод. Контроль — сумма размеров распакованных файлов. |
| `zip_write` | Упаковка `input_regexp.txt` + двух XSD (7,3 МБ исходных) в ZIP через `ЗаписьZipФайла`: deflate и сборка контейнера. Контроль — сумма `РазмерНесжатого` элементов записанного архива (сжатый размер у разных deflate расходится, сверять его нельзя). |
| `str_find` | 500 поисков подстроки в конце строки длиной около 215 000 символов. |
| `simple_parquet_reader` | Разбор файла parquet на 100 000 строк и четыре колонки (Thrift-подвал, цепочки страниц PLAIN, распаковка IEEE 754 вручную) в `ТаблицаЗначений`. |
| `table_compare` | Сравнение двух `ТаблицаЗначений`: 18 колонок, 4 измерения, 50 000 внешних циклов генерации (900 000 строк на таблицу) и свёртка по всем колонкам. |
| `table_compare2` | Разница двух `ТаблицаЗначений` по обезличенному профилю реальной выгрузки: 564 564 + 483 939 строк, пять колонок, уникальный на строку ключ, «Свернуть со знаками». |
| `table_save_load` | `ТаблицаЗначений` в 564 564 строки через `ЗначениеВФайл`/`ЗначениеИзФайла` (файл ~130 МБ) с проверкой тождественности повторной сериализации. |
| `table_sort` | Три сортировки и линейный поиск в `ТаблицаЗначений` из 100 000 строк. |
| `table_total` | Заполнение 200 000 строк и 50 вызовов `Итог` по числовой колонке. |
| `textdoc_invoice` | Формирование `ТекстовыйДокумент` по макету расходной накладной с 100 000 позициями. |

## Результаты

Колонки open-bsl пересняты **23 октября 2026 года** на AMD Ryzen 9 5900X
(12 ядер, 24 потока), Linux 7.2.9: текущий `main` `a590b73f`, медианы
чередующегося A/B против прошлого `main` `b81bfbdf` — пять пар, для
background_jobs, csv_write, csv_write_batched, table_compare, table_compare2 и
table_save_load три. 516 запусков, контрольный вывод и проверяемые файлы
совпали; cbr_rates не измерен — сервис курсов был недоступен.

Колонки Lua, LuaJIT, Python и OneScript — прежние, от **20 сентября 2026**:
Lua 5.4.8, LuaJIT 2.1.1767980792, CPython 3.14.7, OneScript 2.1.0, медианы
пяти (для тяжёлых сценариев трёх) последовательных прогонов. Версии этих
рантаймов с тех пор не менялись. Между сеансами машина уходит до 15% (см.
[дрейф](../docs/research/performance/full-ab-2026-10-23/drift.csv)), поэтому
соотношение open-bsl с другими рантаймами по этой таблице — грубое.

**1С не переснималась:** последняя колонка — результаты **8 сентября 2026**
для 1С 8.3.27.2342 из [combined.platform.txt](1c/combined.platform.txt).
`background_jobs` — отдельный серверный запуск на
`Srvr="localhost";Ref="test";`, [вывод](1c/background_jobs.server.platform.txt).
Это историческое сравнение, не одновременный A/B с платформой.
Проверки корректности ожиданий сохранены отдельно:
[1С](../docs/research/compatibility/job-wait-2026-09-08/background_jobs.verified.platform.txt),
[open-bsl](../docs/research/compatibility/job-wait-2026-09-08/background_jobs.verified.open-bsl.txt),
[optimize](../docs/research/compatibility/job-wait-2026-09-08/background_jobs.verified.open-bsl-optimize.txt).

## Сравнение с прошлыми замерами

Чередующийся A/B 23 октября: прошлый `main` `b81bfbdf` — код, на котором сняты
замеры 20 сентября, — против текущего `main` `a590b73f`. Медианы — в
миллисекундах. Δ — **среднее попарное** current/прошлый − 1, а не отношение
медиан; минус — быстрее, плюс — медленнее. `≈` отмечает диапазон пар,
содержащий ноль. Это диапазон наблюдений, не доверительный интервал.
Сценарии порядка 1–2 мс по проценту не оцениваются; сетевой `cbr_rates` не
измерен — сервис был недоступен.
