- [x] 3.5 Чередующийся A/B, воспроизводится из репозитория:

  ```bash
  ./benchmarks/perimeter-cost.sh HEAD 9
  ```

  Сторона «без проверок» получается вырезанием блока между якорями
  «НАЧАЛО/КОНЕЦ ОБЩИХ ПРОВЕРОК» в `image.rs`; переключателя для этого в
  продукте нет намеренно — выключаемая проверка образа есть способ
  однажды выключить её случайно. Обе стороны собираются в отдельных
  worktree и своих каталогах сборки.

  Числа ПЕРЕСНЯТЫ после того, как к периметру добавились границы
  регистров, модульных слотов и номеров констант: прежние +0,007/+0,173 %
  относились к одной лишь проверке свежести и устарели.

  Девять пар, `instructions:u`:

  | Сценарий | Δ инструкций |
  |---|---:|
  | `empty_for` (канарейка старта) | −0,007 % |
  | `goto_bench` | +0,000 % |
  | `call_overhead` | +0,000 % |
  | `cbr_rates` (144 чанка) | +0,208 % |
  | `simple_parquet_reader` (самый короткий прогон) | +0,268 % |

  Оговорка о разбросе, без которой числа читались бы точнее, чем они
  есть: на пяти парах те же два многочанковых сценария давали +0,363 % и
  +0,608 %, то есть прогонный разброс сопоставим с самим эффектом.
  Утверждать стоит лишь порядок — доли процента на коротком запуске с
  сотней чанков и неотличимо от нуля на всём остальном, — и он тому, чего
  ждёшь от разовой проверки, отвечает.

  Метрика `instructions:u`, а не такты: замеры шли при load average от 4
  до 7, и такты вердикта не выдержали бы. Она же стояла в прежнем
  замере, так что числа сравнимы.

## 6. Что вскрыл перевод

- [x] 6.1 Фрагмент `Выполнить`/`Вычислить` оставался БЕЗ ячеек
  инлайн-кэша: их заполнял литерал компилятора, а финализация
  программы до одиночного чанка не доходит. Проверка образа отвергала
  такой фрагмент — поймано тестами REPL.
- [x] 6.2 Устранение копий удаляло ячейки кэшей вслепую. Проходы над
  готовым байт-кодом идут ДО финализации, то есть таблиц может ещё не
  быть. Защита по длине была промежуточной и снята: проход производные
  таблицы больше не трогает вовсе, а его контракт прямо объявляет их
  недействительными и требует финализации. То же у `const_propagate`:
  инструкций он не удаляет, но меняет их эффекты, и разметка, посчитанная
  до, утверждала бы независимость для прежней редакции.

## 8. По замечаниям ревью

- [x] 8.1 Финализация СБРАСЫВАЕТ инлайн-кэши, а не сохраняет прогретые:
  ячейка помнит форму и слот, но не имя поля, поэтому пережившая правку
  инструкций запись вернула бы слот прежнего свойства при совпавшей
  форме.
- [x] 8.2 `finalize_lone_chunk_unbundled` очищает разметку: на уже
  финализированном чанке «без бандлов» вопреки имени означало «с
  прежними бандлами».
- [x] 8.3 Проверка модульных слотов спрашивает ЕДИНСТВЕННУЮ таблицу
  эффектов (`ModSet::One`), а не второй разбор по опкодам.
- [x] 8.4 `corrupt_program` в `bsl-vm` финализируется: прежде периметр
  отказывал на длине инлайн-кэша раньше проверяемого дефекта, и тесты
  проходили по посторонней причине.
- [x] 8.5 Утверждение о полноте `verify` было снято как неверное:
  `LoadConst` вне таблицы констант и регистровые операнды периметр тогда
  не проверял. С тех пор оба закрыты (пункты 9.1–9.4), и полнота больше
  не голословна: границы регистров, констант и модульных слотов
  проверяются до первой инструкции.
- [x] 8.6 Тест размотки в `bsl-vm` перестал быть пустым: финализация
  после ВСЕХ правок плюс явная предпосылка. Она сразу нашла и второй
  посторонний отказ — длину таблицы экспорта. Позже предпосылка
  перевёрнута (пункт 9.5): периметр эту порчу ОТВЕРГАЕТ, поэтому образ
  исполняется мимо него, а требуется точный текст с обеих сторон.
- [x] 8.7 Финализация стала единственным писателем производных таблиц и
  внутри крейта: разбор листинга больше не заполняет `touches_objects` и
  кэши, а устранение копий их не поддерживает — за ним всё равно идёт
  финализация.
- [x] 8.8 Отдельный зуб на сброс `method_cache`: требование о двух
  кэшах проверялось одним.

## 9. Регистровые границы

- [x] 9.1 В таблицу эффектов заведён ОТДЕЛЬНЫЙ набор `addressed_regs`:
  операнды, которые инструкция действительно адресует. Насыщение
  (`RunDynamic` объявляет все 256 регистров) и проекция модульных слотов
  на `0..overlap` туда не входят — ни то ни другое не утверждает, что
  регистр существует.
- [x] 9.2 Проверка регистровых границ добавлена в проверку образа —
  через ту же таблицу эффектов, без второго разбора по опкодам, и
  граница СТРОГАЯ: сам кадр, без расширений.
- [x] 9.3 Оба контрпримера оформлены тестами и проверены на зубы
  воспроизведением прежнего поведения: `RunDynamic { src: 250 }` при
  кадре в один регистр и `Move { dst: 1 }` при двух модульных
  переменных.
- [x] 9.4 Номер константы проверяется через узкий наблюдатель
  `Instr::const_index` (образец — `jump_target`): исчерпывающий по
  опкодам, один на проект, второго разбора не заводит.
- [x] 9.5 Связывание разделено на периметр и собственно связывание, и
  тест размотки исполняет образ приватным путём МИМО периметра. Держать
  ради теста дыру в проверке образа нельзя, а проверять размотку надо:
  рантайм-стражи остаются вторым рубежом и обязаны возвращать ошибку, а
  не паниковать.
- [x] 9.6 Требование записано в дельта-спеку, а не только галочками.

## 10. По замечаниям ревью

- [x] 10.1 Три общие проверки слиты в ОДИН проход, эффекты считаются
  однократно: `addressed_regs` от пересечения не зависит по построению, а
  `ModSet` несёт номер слота, а не проекцию, — поэтому `None` и дешевле.
- [x] 10.2 Прямые разборы `AddConst` и слитых переходов удалены:
  требование о единственном источнике теперь выполнено буквально.
  Диагнозы стали общими — осознанная потеря точности формулировки в
  обмен на то, что новый слитый опкод попадёт под проверку сам.
- [x] 10.3 Тест размотки требует ТОЧНЫЙ текст отказа с обеих сторон — и
  от периметра, и от рантайм-стража. Он дважды бывал зелёным по
  постороннему поводу, и `is_err()` вернул бы его в то же состояние.
