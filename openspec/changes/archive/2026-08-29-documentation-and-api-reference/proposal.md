# Структура документации и справочник BSL API

## Зачем

Документы лежат одним плоским списком и смешивают текущую архитектуру,
справочник, активные планы, измерения и завершённые проекты. Перечень DSL API
также приходится восстанавливать по исходным таблицам компонентов. Ralph
дублирует управление текущей задачей и больше не нужен.

## Что меняется

- Документы получают каталоги по назначению и единый вход `docs/README.md`.
- В репозитории появляется стандартная структура OpenSpec.
- Ralph и его инструкции удаляются.
- `bsl-cli --emit-api-reference [выход.md]` выдаёт детерминированный Markdown
  из runtime-дескрипторов стандартной сборки.
- Сгенерированный справочник хранится в `docs/reference/bsl-api/api.md` и
  проверяется на рассинхронизацию тестом.

## Вне границ

- Переписывание содержания исторических планов.
- Установка глобального OpenSpec CLI или добавление Node-зависимости в проект.
- Ручные описания семантики каждого метода: для них создаётся место, но
  наполнение выполняется отдельными изменениями.
