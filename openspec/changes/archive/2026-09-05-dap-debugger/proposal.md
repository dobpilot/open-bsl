# Отладчик по протоколу DAP в `bsl-cli`

## Зачем

Отладить BSL-скрипт сейчас нечем: есть печать листинга и `Сообщить`.
Debug Adapter Protocol — то, чем говорят редакторы (VS Code, JetBrains,
neovim), и реализовав его один раз, получаем поддержку во всех сразу.

Задача решается в `bsl-cli`, а не в фасаде: отладчик — свойство ЗАПУСКА,
а не встраивания. Хост, встроивший движок, отлаживает своим способом.

## Что меняется

- Три ключа: `--debug` включает отладку, `--debug-host <адрес>` и
  `--debug-port <порт>` задают, где слушать. По умолчанию `127.0.0.1` и
  `4711`.
- `bsl-cli` поднимает TCP-сервер DAP, ждёт подключения редактора и
  ведёт сеанс: точки останова, шаги, стек, переменные, вычисление
  выражения.
- `bsl-vm` получает крючок отладчика — по образцу компилятора фрагментов
  `Выполнить`, который уже лежит в контексте прогона по той же причине:
  «принадлежит ПРОГОНУ, а не программе; VM его зовёт, но не реализует».
- Крючок зовётся из ВНЕШНЕГО цикла исполнения, никогда из `step`.
- Отладочный прогон идёт непучкованным и без сцепления линейных цепочек.
  Оба состояния уже законны: пустая разметка бандлов проходит периметр, а
  `merge_linear` — обычный рантайм-флаг.
- В `bsl-cli` появляется `serde_json`.

## Умолчания и почему такие

`--debug-host` по умолчанию `127.0.0.1`. Сервер отладки платформы
(`dbgs` из 8.3.27) слушает `0.0.0.0` — измерено запуском с `--notify`, —
но здесь это расхождение сознательное: отладчик вычисляет произвольный
BSL, то есть открытый наружу порт равен удалённому исполнению кода без
аутентификации. Наружу — только явным ключом.

`--debug-port` по умолчанию `4711`. Порт 1550 отпадает: измерено, что
именно его занимает `dbgs`, а совместимость с платформой — цель проекта,
а не повод с ней столкнуться.

## Вне границ

- Транспорт stdio, обычный для DAP, когда редактор запускает адаптер
  подпроцессом. Здесь он не годится: `Сообщить` пишет прямо в stdout, на
  чём держится конформанс-раннер, и разделять эти потоки — отдельная
  задача с собственной ценой.
- Аутентификация и пароль сеанса. Пока слушаем петлю, добавить нечего;
  вместе с разрешением слушать сеть вопрос придётся открыть заново, и
  это сказано здесь, чтобы не забылось.
- Отладка фоновых заданий и нескольких модулей конфигурации: сеанс ведёт
  корневой прогон.
- Совместимость с отладчиком 1С. Другой протокол, другой инструмент;
  никакой платформенной семантики это изменение не трогает.
- Условные точки останова, точки останова по данным, `Отладка.Стоп`.
