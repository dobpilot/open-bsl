# Design

Vendor source: platform-syntax-help:syntax-context:objects/catalog125/catalog126/object128/methods/Select254.html, native installation 8.3.27.2342, Russian locale. Select accepts four optional parameters: parent, owner, one-field indexed filter, order. Default ordering follows the catalog's default presentation. It returns an owned CatalogSelection type.

Measure empty and populated iteration, before/after-current access, aliases, default ordering and argument handling on a private file infobase before implementation. Reuse the existing query request and principal-bound adapter; SQL remains inside the existing provider. Preserve rights and RLS handling. Unsupported operations must fail explicitly rather than fabricate data. Expand only to measured behavior necessary to execute the reached original code; this does not replace the interpreter or resolver.

The empty-selection native oracle contains seven rows: the owned Russian/English type aliases agree; Ref reads as the empty reference before iteration and after exhausted empty iteration; Next repeatedly returns false; explicit Undefined defaults and empty order are accepted. Do not apply query-result current-row errors to catalog selection.

The first populated probe shows Undefined for Code, Description and DeletionMark before iteration, unlike the empty owned Ref. Default AsDescription ordering yields Alpha then Zulu, including the deletion-marked row. Explicit descending description ordering yields Zulu then Alpha; a Code filter selects Alpha. After reaching false the last row remains readable, but another Next returns true; a follow-up probe checks whether it restarts iteration. Preserve this catalog-specific behavior rather than copying query-result cursor assumptions.

The follow-up native probe confirms restart from the first row after Next returns false; the second traversal again reaches the second row and false, then restarts. Store the readable current row separately from the next-row position. Add configuration-owned selection type descriptors and expose catalog_selection_types() on MetadataCatalog for SessionFactory registration, without graph materializers for mutable cursors.

The native argument probe accepts an empty filter, rejects two fields or nonindexed/unknown fields, and accepts unknown sort-direction words. Parent and owner arguments of various types are accepted for the nonhierarchical catalog without an owner; do not infer this for hierarchical or subordinate catalogs. Owner applicability is not yet projected in MetadataCatalog, so nondefault owner arguments remain an explicit unsupported boundary until that metadata is available. A follow-up populated probe measures ordering for unknown direction.

The separate hierarchical native probe has six rows: no parent selects Child, Group, Root; the own empty reference selects Group and Root; the fixed group reference selects Child; Number, Null and String are rejected. Implement an own-reference parameterized Parent predicate only when hierarchy is acquired as true. A known nonhierarchical catalog ignores the parent argument as previously measured; unknown hierarchy remains explicit failure when the argument is supplied.
