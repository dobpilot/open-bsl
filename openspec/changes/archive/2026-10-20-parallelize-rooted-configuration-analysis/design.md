# Design
Use scoped standard-library threads, without dependencies or unsafe trait implementations. Native preparation defaults to at most two workers, capped by available parallelism. OPEN_BSL_PREPARE_THREADS=1 selects sequential preparation; 2 requests two workers, still capped by available parallelism. Other values use the default. The calling thread is one worker; if the helper cannot be created, it completes the queue sequentially without introducing a new compilation error. The helper uses an 8 MiB stack matching the existing parser depth calibration, preserving its deep-nesting diagnostic rather than overflowing the smaller default thread stack. WebAssembly stays sequential and does not create threads.

Only pure parser/resolver work crosses threads. Share immutable sources, export surfaces, preprocessing symbols and the function-pointer registry; send owned export descriptions and resolved bodies. Each worker releases syntax and the full temporary import environment before returning a resolved body. Keep the existing common import backing shared.

Process selected work in bounded windows of four queued modules. Within a window workers dynamically claim indices. The coordinator consumes results in original queue order, checking explicit imports and appending explicit then resolved dependencies exactly as before. Never resolve an unselected module merely to discover parallel work. Export results are likewise consumed in recipe order. A later worker finishing first cannot choose the diagnostic. Speculative work is bounded to already-selected modules in the current window.

Recheck deferred errors against the pruned environment in module order, using the same bounded analysis helper. Retain cycle-error precedence on a recheck failure. Entry-source discovery, module numbering, initialization ordering, code generation, verification, runtime State and database sessions remain sequential. Bytecode contains Rc values and is not transferred between threads; do not add unsafe Send/Sync or public verifier APIs.

New tests compare sequential and parallel preparation, whole images, error order, reachability and deferred failures. This is execution scheduling of an existing compiler contract, not new 1C semantics; no unmeasured-platform decision is introduced. Measure the same release binary with one and two preparation workers in alternating sequential CLI processes on BUH, retaining phase timings, memory samples and identical output checks. Keep existing readonly and memory guards. No concurrent CLI processes or background builds during these measurements.

## Non-Send numeric literals
ResolvedProgram also contains BslNumber, whose arbitrary precision storage uses Rc. Introduce an opaque SendableResolvedProgram in bsl-sema, with consuming into_sendable/into_resolved methods. Share the IR type declarations through one include file; instantiate a private transfer tree with canonical owned numeric strings. Exhaustive bidirectional structural conversion preserves all fields and forces new variants to be handled. Parse canonical numbers only when returning to the coordinator. Keep original public IR declarations, runtime arithmetic and Rc ownership unchanged. This adds a small Rust transfer API, not a second parser or interpreter, new dependency, or runtime number representation.
