# Design

The Config class correction is a separate bug fix under the existing exchange-plan projection requirement. It retains 24 previously omitted module sources and exposes the existing manager surface gap. This change adds only the reached declarations and empty reference, rather than implementing the full exchange subsystem.

Read the full vendor pages for ExchangePlanManager.EmptyRef and CreateNode. CreateNode has zero arguments and is a function; declaring it lets the current semantic receiver mechanism compile dormant code. Invocation fails explicitly because the host does not implement exchange-plan node objects. This deliberate host limitation is not presented as native successful behavior.

EmptyRef reuses the existing configuration-reference value with zero UUID and an owner-specific ExchangePlanRef type. Before implementation, measure the native aliases, type identity, emptiness, formatting and cross-plan equality in an owned scratch filebase. Do not infer missing observations from catalogs or documents. The reached additional methods are bounded below.

The next original compilation reaches ThisNode in IntegratedSystems. Reading that exact module also reveals an implicit GetRef(UUID) beside CreateNode. These are reached source declarations, not speculative coverage of the entire manager. ThisNode remains an explicit unsupported operation because no current-node value has been acquired. GetRef reuses the existing configuration reference constructor only after separate native controls establish supplied UUID, omitted/Undefined UUID, type, alias, emptiness and invalid-argument behavior. Node reads and persistence remain outside scope.

Platform methods keep their existing precedence over exported manager-module functions, including implicit receiver calls; no change to general global-name resolution is needed. No new runtime value engine, store, connection registry or external dependency is introduced.
