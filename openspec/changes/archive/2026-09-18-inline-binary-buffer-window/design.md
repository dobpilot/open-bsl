# Решение

Один `Rc<BslObject>` владеет окном через `RefCell<BinBufData>`.
Клон BSL-значения удерживает тот же объект. Новый срез создаёт новый
объект-окно, но удерживает прежний `Rc<RefCell<Vec<u8>>>` хранилища.
Время жизни байтов не зависит от исходного объекта, порядок байтов
остаётся свойством окна. Копирование с перекрытием не меняется.

Основание семантики — уже измеренные строки `measure-binbuf.platform.txt`:
«срез после правки источника», «запись в срез», «копия после правки источника».
Новые предположения о платформе не вводятся.

Сравнение — с текущим снимком до изменения, не с main: 5 чередующихся пар
`bmp_rotate` в обоих режимах, отдельный счётчик аллокаций. Фиксируются также
размеры BslValue/BslObject, чтобы не скрыть удорожание остальных объектов.
