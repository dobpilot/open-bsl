# Design

Primary vendor source: platform-syntax-help:syntax-context:objects/catalog125/catalog126/object128/methods/FindByAttribute252.html, installation 8.3.27.2342, Russian locale. The signature has two required and two optional arguments: attribute name, value, parent and owner. Missing match returns an own empty reference; multiple matches return one, without a specified choice. String matching is exact. Storage and unlimited-length string attributes are excluded.

Measure existing/missing matches, standard versus own fields, case handling, value conversion and optional arguments before runtime code. Use acquired names and the existing QueryRequest/DataAccess path; parameterize values. Do not invent attribute type eligibility when acquisition cannot establish it. Reuse catalog selection's measured parent behavior only after verifying this method independently. Owner metadata remains an explicit pending acquisition requirement.

Native probe preserves 11 rows. Own bounded attribute lookup returns an own filled reference; attribute names are folded. Lowercase value abc does not match AbC, while trailing-space AbC does match. Missing, Undefined, Null and Number return an own empty reference. Standard Code and Description, and an unknown attribute name, are rejected by this method. Do not reuse selection's standard-field whitelist or assume database default text equality suffices. Measure remaining optional arguments and verify SQL adapter string comparison before implementation.

The extended native oracle has 19 rows. A leading space does not match. Parent/owner arguments are ignored by the nonhierarchical catalog without owners. A numeric attribute-name argument fails. An ordinary native query has the same exact/case/trailing-space results (1/0/1), so string-comparison compatibility belongs to the adapter query path too, not just the manager method.

The conversion probe extends the oracle to 24 rows by adding records with String values 17 and empty String. Number 17 does not match String 17; Undefined and Null do not match empty String. A String argument does match each; Array is rejected. The ordinary query with Number 17 returns zero rows too. No coercion to a column default or textual representation is allowed.

The existing SDK supports TRIMR through dialect-specific rtrim rendering. Use it for String comparison after validating acquired field kind and bounded length. Introduce a narrow public FindByAttributeRequest and DataAccess::find_by_attribute defaulting to explicit unsupported failure. The provider adapter owns field-type eligibility and query construction using its existing MetadataSnapshot and execute_text pipeline. ORM owns receiver binding, acquired attribute-name lookup and validation of the returned own reference. This avoids projecting a second type system into ORM or bypassing rights/RLS; generic query execution remains unchanged. The default trait method keeps existing adapters source-compatible and cannot fabricate an empty match.

Undefined lookup values must use the SDK-supported typed НЕОПРЕДЕЛЕНО literal, not the generic scalar parameter conversion (which deliberately rejects Undefined), and not a Null substitute. Actual execution still goes through execute_text with rights and RLS. A focused compiler test covers String, Number and Boolean scalar operands without an IS NULL rewrite; real field execution remains to be verified independently.

The dedicated hierarchical native probe preserves six parent outcomes: omitted and Undefined search without parent restriction; own empty reference searches the root; the concrete group restricts lookup to that group; Number and Null are rejected. These results independently confirm this method rather than borrowing Select semantics.

The live UNF adapter probe stops before SQL because the real metadata requires the data-separation session parameter ОбластьДанныхЗначение. Its minimal session intentionally does not invent that parameter. This proves the separation check is preserved, not that database lookup succeeded. Full original-session initialization and an actual SQL result remain outstanding.

The typed native fixture has Number, Boolean, Date and own catalog Reference attributes. All four find their stored same-kind values. String 17 does not match any of the four, and Undefined/Null return the own empty reference. The 16-row oracle is preserved separately. This establishes eligibility and the tested cross-kind outcomes without projecting values from SQL or interpreter output.

The live probe exposed an early compilation defect: the type-inspection SELECT compiled outside the normal lazy-session path, so separator diagnostics escaped before SessionRuntime could initialize parameters. Replace that probe with the SDK existing queryable_fields projection and identify the acquired FieldId, accepting a single physical member only. This reads existing field types without SQL generation or copying a type decoder. Composite physical layouts fail explicitly; actual lookup still uses execute_text and its lazy parameter path.

# Complete empty owner metadata correction

The current SDK and ORM projection can represent an explicitly complete empty owner list. For that known unowned profile, the measured fourth argument is ignored, including Number, as the retained native control specifies. Unknown ownership and actual subordinate catalogs keep the explicit unsupported boundary. This is a correction within the accepted measured lookup behavior, not a guessed implementation of subordinate lookup. The SQL fixture supplies the exact false hierarchy flag and empty owner list from the retained XML; it does not claim to verify their Config decoding.
