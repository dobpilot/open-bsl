## Реальный процесс вместе с отменой задания

`crates/open-bsl/tests/application_system.rs` проверяет существующий контракт
без изменения продуктового кода: один worker, direct/Выполнить глубиной 3
и complete/cancel/shutdown. SystemApplicationLauncher запускает реальную
Rust-программу из общего `tests/support/application_system.rs`, без shell.
Ребёнок сообщает PID и ждёт разрешения теста; до разрешения проверяются
соседнее задание и остановка BSL-ожидателя, затем ребёнок продолжает работу
и возвращает 17. Обёртка sink наблюдает результат настоящего wait, после
которого PID отсутствует в /proc. Это проверка Linux-host, не замер 1С.

Новый OpenSpec-контракт не требовался: добавлены тесты принятых требований.
Общая дочерняя программа используется и прежними тестами bsl-rt;
её аварийный таймаут увеличен до 15 секунд для проверок cancel/shutdown.
Полный workspace, Clippy/rustdoc с запретом предупреждений, fmt,
git diff --check, API reference и строгий OpenSpec прошли. Логи —
`/tmp/open-bsl-real-job-process-{host,tests,workspace,clippy,doc,api}.log`.

## Сохраняемое исполнение динамического фрагмента

Красный тест `runapp_wait_frees_a_single_worker_and_survives_cancellation_and_shutdown`
в варианте `Выполнить` подтвердил блокировку единственного worker:
`/tmp/open-bsl-dynamic-park-red.log`. Причина — вложенный `drive_linked`
с неограниченным ожиданием внутри RunDynamic.

Фрагмент хранит подготовленную Program, собственный ProgramExecution,
scope и координаты возврата в AsyncState родителя. Ссылки на host/registry
между poll не сохраняются; компоненты повторно связываются при опросе.
Пока фрагмент активен, остальные задачи родительского execution не исполняются.
Finite poll передаётся дочернему execution вместе с принудительным квантованием
worker, отменой и waker. Завершённый фрагмент возвращает существующие локальные
слоты и значение; состояние модульных переменных возвращается также при ошибке.
Перенос локальных после ошибки не меняется относительно прежнего пути.

Подготовка фрагмента и перенос результата остаются единственными реализациями.
Блокирующий вход отладочного вычисления использует их же, доводя дочерний
execution до конца. Существующий счётчик глубины применяется при подготовке
и каждом вложенном poll; сессии не делят его через thread_local. Файловые
обещания фрагмента по-прежнему принадлежат внешнему execution.
Новых opcode, serialized-полей и небезопасной передачи Rc между потоками нет.

Дополнительный красный тест выявил поглощение Canceled неиспользуемым
обещанием async-функции после возврата корневого тела:
`/tmp/open-bsl-dynamic-cancel-red.log`. В этой точке отмена теперь
распространяется на весь execution, не превращаясь в результат одного
обещания. Целевой тест —
`canceling_a_dynamic_async_task_after_root_return_is_not_success`.

После исправления прошли полный workspace, включая plain/optimize всего
корпуса и реестр измерений, Clippy/rustdoc с запретом предупреждений,
fmt, git diff --check, регенерация API reference и 11 строгих проверок
OpenSpec. Итоговый полный лог —
`/tmp/open-bsl-dynamic-park-workspace-final.log`; целевые логи —
`/tmp/open-bsl-dynamic-park-application.log` и
`/tmp/open-bsl-dynamic-cancel-test.log`.

## Подключение процедурного RunApp

Резолвер по-прежнему запрещает RunApp в выражении исходного BSL. Для
оператора с четвёртым аргументом Local/ModuleVar/ImportedVar он создаёт
обычное Assign с внутренним CallBuiltinFn в правой части. Тем самым запись
видна SSA и раскладке регистров; не нужны новый opcode или скрытый by-ref
в VM. Все четыре входных выражения вычисляются один раз слева направо,
а присваивание происходит только после успешного вызова. Для литерала
результат отбрасывается. Измеренные поле и индекс резолвер также оборачивает в Assign.
Кодоген резервирует четыре смежных регистра вызова, вычисляет первые три, затем один раз
сохраняет объект/индекс и после возврата host записывает результат по этому адресу.
Пропуски cwd и wait нормализуются в пустую строку и Ложь, явное
Неопределено сохраняется и отвергается обработчиком.

Builtin RunApp использует ApplicationSync и для wait=false: теперь VM
получает подтверждение spawn/передачи документа, не теряя ошибку ассоциации.
SystemApplicationLauncher сохраняет подтверждение попытки spawn перед
возвратом submit: даже RunAppAsync без последующего Ждать не теряет запуск
при выходе CLI. Это включает подготовку и создание процесса, но не ожидание
его завершения или передачи gio. Последнее идёт через парковку VM и sink;
для executable без ожидания это Started сразу после spawn,
а wait/reap продолжается независимо. Ошибка spawn доставляется через sink;
создание наблюдателя может отказать до принятия. BSL при ожидании отображает
NotFound отсутствующего executable в измеренный 127; прочие
ошибки host и завершение без числового кода дают явную ошибку без записи
выходного параметра. Это не установление полной эквивалентности shell 1С.
Пустая команда завершается без процесса с кодом 0 при ожидании; отсутствие
сервиса host всё равно отвергается. Разбор строки пока Unix-only.

CLI подключает SystemApplicationLauncher для исходного/текстового байт-кода
и REPL; embedding по-прежнему не получает процессный сервис автоматически.
Само подключение не завершало открытие документов; Linux-реализация
добавлена следующим этапом ниже. Windows-разбор, дополнительные
преобразования аргументов и native cwd остаются в объёме плана.

Этап проверен семью BSL/fake-host тестами и тремя реальными CLI-тестами,
включая исходник/листинг с plain/optimize, REPL и продолжение дочерней
программы после выхода CLI. Полный workspace (включая сравнение всего
корпуса plain/optimize и реестр измерений), Clippy/rustdoc с запретом
предупреждений, fmt, API reference и строгая проверка OpenSpec прошли.
Логи: `/tmp/open-bsl-runapp-{tests,cli,workspace,clippy-final,doc,api}.log`.

## Парковка при ожидании приложения

`PendingHostCall::ApplicationSync` переносит структурированный запрос, Arc
launcher и две функции преобразования: завершения и отказа принятия.
Преобразование завершения выполняется только в потоке VM с RuntimeShapes;
через Send-канал передаются ApplicationExit либо io::Error, не BslValue/Rc.
Этот этап не выбирает BSL-семантику отсутствующего кода, ошибки spawn или
выходного аргумента: их определит обработчик RunApp, передающий mapper.

VM переиспользует SyncWait: заморожен весь execution, но не worker.
Результат доставляется с ExecutionToken/PromiseId и пробуждением драйвера.
HostPromise хранит необязательный отменяемый handle: для HTTP/файлов он
сохраняется, для приложения отсутствует. Фиктивный RequestHandle не вводится.
Отказ submit не оставляет обещания или парковки; поздний sink после сброса
execution не влияет на следующий запуск. Владение дочерним процессом
остаётся у launcher. Строковый компонентный путь без VM доводит тот же
PendingHostCall блокирующе, как уже делает для HTTP.

Формат байт-кода и горячая диспетчеризация этим этапом не меняются.
До подключения BSL RunApp проверяются отдельные scheduler/компонентные
тесты: отложенный и немедленный sink, отказ принятия, ошибка завершения,
потеря ожидателя, пробуждение и материализация в вызывающем потоке.

Запись `КодВозврата` сделана видимой анализу `bsl-compiler/src/ssa.rs`
через Assign, как описано выше. Одного скрытого write-back в VM или
позднего Move было бы недостаточно: CallBuiltinFn несёт только входные
выражения. Проверены локальная/модульная/импортированная переменные,
параметр по ссылке, ошибка до записи, литерал и plain/optimize.
Динамический вызов проверен отдельно: `snippet.rs` сохраняет фрагмент между
опросами. Проверены вложенные Выполнить/Вычислить, перенос слотов после
завершения, ошибки, отмена и shutdown при одном worker. Блокирующий вход
сохранён только для отладочного вычисления в остановленном кадре.

Проверки этапа парковки завершены: шесть целевых тестов, полный workspace,
Clippy и rustdoc с запретом предупреждений, fmt, git diff --check,
регенерация API reference и 11 строгих проверок OpenSpec. Логи —
`/tmp/open-bsl-application-wait-{unit,workspace,clippy,doc,api}.log`.
Это приёмка инфраструктуры ожидания, не всего BSL-запуска.

## Разбор Unix-команды без shell

ApplicationTarget::from_unix_command_line строит только Executable и не
выполняет I/O. Используются одинарные/двойные кавычки и backslash по правилам
[POSIX quoting](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_02),
но не язык shell: нет подстановок, glob, переменных окружения, комментариев,
перенаправлений или запуска команд. Разделители вне кавычек — пробел, табуляция
и LF; backslash-LF удаляется. В двойных кавычках backslash снимается только
перед $, обратной кавычкой, двойной кавычкой, backslash и LF; перед остальными
символами сохраняется. Метасимволы вне кавычек остаются обычным текстом.
ANSI-C quoting не поддерживается как отдельная форма.

Результирующие аргументы сразу переходят в существующий SecretString.
Диагностики не содержат входную строку. Имя метода явно ограничивает синтаксис
Unix; политика Windows не выводится из этого разбора. Небольшой разборщик
кавычек не дублирует BSL-лексер с другой грамматикой и не вводит внешний crate.
Это намеренный контракт запуска open-bsl без shell, не воспроизведение
измеренной shell-интерпретации серверной 1С. Выходные аргументы и парковка VM
остаются отдельными задачами; сам разбор не запускает процесс.

Проверки этапа завершены: полный workspace, Clippy и rustdoc с запретом
предупреждений, fmt, git diff --check, регенерация API reference и все 11
строгих проверок OpenSpec. Логи —
`/tmp/open-bsl-command-line-{tests,workspace,clippy,doc,api}.log`.

Применяется [общий дизайн серии](../extend-filesystem-operations/design.md)
в части «Запуск программ и документов». Локальные delta и tasks задают объём отдельной приёмки.
Перед независимым архивированием сохранить относящиеся решения здесь
и обновить ссылку, если общий дизайн уже перенесён в архив.

## Host-граница

В bsl-rt добавлены ApplicationTarget (executable с argv либо document),
ApplicationRequest с cwd, ApplicationExit с необязательным нативным кодом,
ApplicationLauncher и одноразовый Send ApplicationCompletionSink.
Это политика host, не воспроизведение пока не измеренного BSL-преобразования
командной строки/кода завершения. SecretString переиспользуется для argv:
отладочная запись не раскрывает аргументы. Новых зависимостей нет.

HostEnv хранит необязательный Arc сервиса, StateBuilder внедряет его явно.
По умолчанию сервиса нет, включая HostEnv::process; стандартный CLI подключает
реальный адаптер отдельно. submit не должен ждать завершения дочернего
процесса в BSL-worker. При отказе принятия возвращается io::Error без sink;
после принятия host один раз доставляет завершение и отвечает за reap даже
после исчезновения BSL-ожидателя. HTTP RequestHandle не переиспользуется:
он отменяет операцию при Drop, что противоречит согласованному запуску.

SystemApplicationLauncher запускает executable через std::process::Command.
Сначала создаётся поток наблюдателя, затем в нём дочерний процесс: отказ
создания потока не оставляет уже запущенную программу без владельца.
Наблюдатель получает статус через wait независимо от жизни получателя sink.
Ошибка spawn доставляется через sink после принятия запроса. Документы
на Linux передаются через gio с отдельным результатом DocumentOpened;
запрос ожидания отвергается до запуска gio.
Реальный дочерний тест проверяет argv, cwd, код 17, отсутствие программы
и продолжение работы с последующим reap после потери получателя на Linux.

Парсер Unix-команды, парковка VM, BSL RunApp, by-ref КодВозврата и CLI
реализованы, включая Linux-ассоциации. None в ApplicationExit
не преобразуется инфраструктурой в выдуманный ноль: mapper RunApp выдаёт
явную ошибку без записи выходной переменной.

## Ожидание документа: принятое решение

Для реализации запрос получает явный wait_for_exit, а результат сервиса —
варианты запуска процесса, завершения процесса и передачи документа.
Это разделяет подтверждение запуска executable без ожидания и его поздний
reap; прежний ApplicationExit остаётся носителем настоящего exit status.
VM ожидает только соответствующее подтверждение через существующую парковку,
включая вызов без ожидания приложения. Ошибки передачи не теряются в sink.

Linux-адаптер открывает документы через gio open с отдельным argv, без shell.
Явный Document трактуется как локальный путь; относительный путь разрешается
от рабочего каталога запроса, перед gio становится абсолютным и потому не
может стать опцией или URI. В RunApp одиночное имя существующего обычного
файла без executable-битов трактуется как документ; классификация выполняется
в host, не через виртуальную FileSystem. Дополнительные аргументы сохраняют
запуск executable. Это выбранная политика Linux-host, не замер парсинга 1С.
Остальные платформы явно отказывают документам до запуска.

[Изолированная проба Linux-host](../../../docs/research/compatibility/document-association-host-2026-09-09.md)
показала: gio open завершился с кодом 0 до завершения обработчика документа.
Нельзя использовать его статус как ApplicationExit приложения. Пользователь
подтвердил разделение передачи документа и завершения приложения: без
ожидания успешная передача считается успехом, а недоступное достоверное
ожидание явно отклоняется. Отказ ожидания проверяется до открытия документа,
чтобы ошибка не сопровождалась непрошенным запуском. Linux-реализация
проверяется изолированной ассоциацией; прочие ОС остаются вне этой приёмки.

## Серверный контекст: измерение вместо предположения

[Проба 8.3.27.2342 на localhost/test](../../../docs/research/compatibility/file-runapp-server-2026-09-09.md)
подтвердила синхронный запуск с ожиданием и без него в серверной процедуре
управляемой формы. Отсутствующая программа дала код 127 без исключения.
Безусловный серверный отказ не является допустимым эталоном для этого
контекста. Нужны уточняющие пробы преобразований и командной строки;
Rust-ошибку spawn нельзя механически переносить в BSL-исключение.

[Уточняющая проба](../../../docs/research/compatibility/file-runapp-details-server-2026-09-09.md)
подтвердила Неопределено в выходной переменной без ожидания, строгий отказ
для явных Неопределено/0/1/Null вместо булева ожидания и сохранение переменной
при этих отказах. Пропуск третьего аргумента отличается от Неопределено.

Та же проба исполнила shell-операторы и `exit 17`. Это противоречит требованию
open-bsl без неявного shell. Решение передано пользователю; до его ответа
действует прежний запрет, но он не объявляется эквивалентностью серверной 1С.
Прямой argv API host не меняется автоматически вслед за этим измерением.

Дополнительная [клиентская sync-проба](../../../docs/research/compatibility/file-runapp-context-comparison-2026-09-17.md)
отделила контекст от формы метода. Обычные коды, отсутствие ожидания, строгие
ошибки типов, кавычки и shell-последовательность совпали с сервером. Однако
отсутствующая программа и `exit 17` в клиенте дали `Неопределено`, а
несуществующий cwd — 0. Поэтому код 127 остаётся выбранной server-like
семантикой поддержанного CLI-контекста, а не общим контрактом платформы.
