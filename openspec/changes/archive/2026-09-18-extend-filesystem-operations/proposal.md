# Дополнить файловые операции и временные файлы

## Why

В open-bsl отсутствуют поиск и создание каталогов на уровне BSL, объект
`Файл` и запуск приложения; существующее удаление не принимает маску.
Временное имя уже есть, но не покрыты документированные расширения,
каталог временных файлов, жизненный цикл и временный файловый поток.

Сопоставление выполнено по полной справке Unica 8.3.27.2342:
[анализ, источники и текущий код](../../../docs/research/compatibility/files-api-2026-09-09.md).
Справка задаёт кандидатов требований, но не заменяет измерение на 1С.

## What Changes

- Добавить полный синхронный интерфейс `Файл`, `НайтиФайлы`, `СоздатьКаталог`;
  дополнить `УдалитьФайлы` маской без потери прежнего контракта.
- Дополнить временные файлы: расширения `ПолучитьИмяВременногоФайла`,
  `КаталогВременныхФайлов`, выбор TEMP → TMP → системный каталог.

Остальной согласованный объём выделен в отдельно принимаемые изменения:

- [Временный поток и очистка](../extend-temporary-file-lifecycle/proposal.md):
  переход память → диск, callback host, очистка перед штатным выходом CLI,
  без восстановительной очистки после уничтожения процесса.
- [Запуск](../add-host-application-launch/proposal.md): программы и документы
  по ассоциации, CLI без разрешающего флага, отмена ожидания без завершения программы.
- [Асинхронные операции](../extend-filesystem-async/proposal.md): все варианты
  из анализа и полный асинхронный интерфейс `Файл` по инвентаризации Unica.

Основная реализация — в `bsl-rt`, временный поток — в `bsl-stream`,
жизненный цикл и подключение host — в `open-bsl`, стандартная очистка — в CLI.
Новый файловый crate не вводится. Общие решения серии находятся в `design.md`.

## Scope

Первая измерительная среда — установленная Linux 1С 8.3.27.2342;
режим совместимости и клиент/сервер фиксируются для каждой пробы.
Другие ОС, 8.5, FTP/HTTP-пути, веб-расширения, клиентские диалоги и
`Начать...` с `ОписаниеОповещения` не включаются молча в обещание совместимости.
`КомандаСистемы` исследована как отличие, не как замена `RunApp`.

## Status

План согласован пользователем 2026-09-09 после `grilling`; реализация начата
с выбора TEMP/TMP стандартным host. Полная инвентаризация страниц `Файл`
выполнена, начальные пробы подготовлены; платформенные измерения ещё нужны. Изменение
наблюдаемого API требует OpenSpec до реализации. Действующие specs и
сгенерированный API reference этой работой не меняются. Новые внешние
зависимости не предлагаются; если выяснится необходимость, согласовать отдельно.

До интервью исходный вариант прошёл строгий OpenSpec, fmt, Clippy и workspace
tests. После разделения `openspec validate --all --strict` прошёл для всех
четырёх изменений и действующих specs; `git diff --check` также прошёл.
Эти проверки не доказывают реализацию новых методов:
платформенные измерения остаются задачами плана.

Первый шаг реализации: `cargo fmt --all -- --check` и Clippy прошли;
workspace tests прошли с разрешёнными localhost-сокетами. Первоначальный
sandbox-прогон остановился на отказе открытия HTTP-сокета, не на файловом тесте.
Публичные BSL-дескрипторы не менялись.

Второй шаг: прежний ZIP-сопоставитель вынесен без изменения тела алгоритма
в `bsl_rt::simple_mask_matches`; разбор путей остался в ZIP. Все 48 ZIP-тестов
прошли. BSL API reference регенерирован и не изменился: новый helper — Rust API,
не BSL-метод. Файловые классы символов пока не добавлялись и не считаются
реализованными вместе с этим переносом.

Третий шаг: добавлен host-метод `FileSystem::temporary_directory` с default
`Unsupported`. Системный адаптер использует общий с `temporary_path` выбор
TEMP/TMP, проверяет наличие каталога без его создания. Тесты пользовательской
ФС и семи вариантов окружения прошли. Это подготовка host-границы:
BSL-функция `КаталогВременныхФайлов` ещё не добавлена, её нормализация и
платформенные ошибки остаются предметом измерения.

Проверки третьего шага завершены: fmt, Clippy (`--workspace --all-targets`,
`-D warnings`), rustdoc (`-D warnings`), `cargo test --workspace` и строгий
OpenSpec прошли. Полный прогон завершился с кодом 0; лог этой машины —
`/tmp/open-bsl-temp-directory-workspace.log`. API reference регенерирован
без изменений. Это регрессионные ворота текущего host-изменения, не приёмка
ещё не реализованных BSL-методов и не замена платформенного oracle.

После двух серверных измерений добавлен `СоздатьКаталог / CreateDirectory`
через файловую возможность и существующий `FileSystem::create_dir_all`;
после измерения типов форматирование выделено в `HostEffect::FileCreate`.
Проверены регистрация, арность, процедурность, виртуальный host, ловимый
отказ host, создание родителей, повторное создание и сохранность обычного
файла при конфликте. API reference регенерирован. Граничные пути и типы
аргументов первоначально были зарегистрированы как
`CREATEDIR.PATH_SEMANTICS`; последующие изолированные server/client-пробы
закрыли вопрос общим форматированием `Строка` и тремя пустыми отказами.

Полный workspace-прогон после `СоздатьКаталог` завершился с кодом 0
(`/tmp/open-bsl-create-directory-workspace.log`). Следующим шагом добавлена
`КаталогВременныхФайлов / TempFilesDir`: нулевая арность, строковый результат
с разделителем из той же ФС, вызовы только через host. Целевые тесты
виртуальной ФС, отказа host и восьми вариантов системного окружения прошли;
проверено отсутствие дублирования завершающего разделителя. Справочник API
регенерирован. Приоритет TEMP/TMP и ошибка недоступного каталога остаются
согласованной политикой open-bsl, не объявляются измеренным правилом 1С.

Workspace-прогон после `TempFilesDir` завершился с кодом 0
(`/tmp/open-bsl-tempfilesdir-workspace.log`). Подготовлен следующий слой
для объекта `Файл`: FileMetadata теперь различает обычный файл, каталог и
иной объект, хранит необязательный размер. Старые конструкторы сохранены.
Целевые тесты проверили отсутствие выдуманного размера, реальный размер,
следование по ссылке и классификацию Unix-сокета. Это host-контракт;
конструктор и методы BSL-объекта `Файл` ещё не добавлены.

Следующий шаг подключил объект `Файл` к core-дескриптору без отдельного
crate: конструктор, пять строковых свойств только для чтения и методы
Существует/ЭтоФайл/ЭтоКаталог/Размер. Объект хранит Rc своей ФС и перечитывает
метаданные; неизвестный размер не заменяется нулём. Тесты виртуальной ФС
и измеренных свойств прошли. Исследовательский скрипт теперь выполняет
базовые пробы на реальной ФС; plain/optimize совпали, исключая случайный
scratch-путь. Атрибуты и время пока отсутствуют. Граничные решения
отмечены `FILE.EDGE_BEHAVIOR` с реестром и пробой; полный интерфейс
и вся серия остаются незавершёнными.

Добавлен `FileSystem::set_modified` с отказом `Unsupported` по умолчанию
и системной реализацией через `FileTimes`. Host принимает секунды UTC,
включая отрицательные; metadata больше не теряет время до epoch.
Проверены сохранность данных и времени доступа, отсутствующий путь,
округление дробной секунды до epoch, установка через ссылку и на каталог
Linux. Целевые тесты прошли после подтверждённого red на отсутствии метода;
48 ZIP-тестов, Clippy, rustdoc и строгий OpenSpec также прошли. Полный
workspace-прогон запущен отдельно (`/tmp/open-bsl-file-time-workspace.log`).
BSL-методы времени ещё не подключены: преобразования зоны и диапазона
требуют следующих серверных проб. Новый host-контракт не является oracle 1С.

Этот workspace-прогон завершился с кодом 0. Следующий прямой серверный
замер сохранён в `file-times.bsl` / `file-times.platform.txt`; разбор —
`docs/research/compatibility/file-times-server-2026-09-09.md`. Конфигурация
восстановлена, XML-проверка прошла. Выявлены различия дат до epoch и краёв
диапазона, принятие строкового аргумента и несовпадение режима совместимости
в XML с результатом запроса в сеансе. Эти вопросы остаются открытыми,
BSL-время пока не реализовано.

После пограничного замера подключены четыре BSL-метода времени; API reference
регенерирован и проверен. Тест host сначала падал на UnknownMethod, затем
прошёл: 25 тестов окружения и три проверки реестра зелёные. Проверены
строковые аргументы, зона host, сохранность данных, неизвестное время,
процедурность setter и измеренное отрицательное UTC-время. Clippy прошёл.
Plain/optimize пограничного измерителя совпали без случайного scratch-пути.
Нулевые календарные поля остаются известным расхождением под
`FILE.TIME_EDGE_BEHAVIOR`; интерфейс не объявлен полностью совместимым.
Общий прогон: `/tmp/open-bsl-bsl-file-times-workspace.log`.

Этот прогон завершился с кодом 0. Следующий шаг исправил расширения
временных имён по `file-globals.platform.txt`: `.tmp` по умолчанию,
точка перед непустым расширением, сохранение пустого и разделителей.
Системный host резервирует первый компонент имени вместо полного пути;
это позволяет `.a/b` без создания родителей и сохраняет чужие объекты
при коллизии. Оба целевых теста сначала воспроизвели прежние ошибки,
затем прошли; Clippy и регенерация API reference также успешны.
Повторный исследовательский скрипт подтвердил окончания имён на реальной
ФС. Это не завершает очистку, временные потоки или остальную серию.

Workspace-прогон временных суффиксов завершился с кодом 0
(`/tmp/open-bsl-temp-suffix-workspace.log`). Подготовлена host-граница
атрибута «Только чтение»: FileMetadata хранит Option<bool>, старые
конструкторы оставляют None, set_read_only имеет default Unsupported.
Unix-адаптер снимает биты записи при установке, при снятии добавляет только
запись владельцу. Тесты red/green подтвердили сохранность данных и остальных
прав, работу через ссылку и отсутствие создания файла при ошибке пути.
Это политика Rust-host; BSL-обёртки и детали chmod оригинальной 1С ещё
не объявлены реализованными этим шагом.

Следующий серверный замер атрибутов и внешние mode-снимки сохранены в
`file-attributes.*`, разбор — `file-attributes-server-2026-09-09.md`.
Конфигурация восстановлена, XML-проверка прошла. Выявлено расхождение
host-прототипа: 1С меняет только бит 0200, сохраняя запись группе/остальным.
Исправлены setter и metadata.read_only; тест 0660 -> 0460 прошёл red/green.
Также измерены Linux-невидимость `.hidden`, число 1, строка «Ложь»,
Неопределено и отсутствующий путь. BSL-обёртки атрибутов ещё не подключены.

Подключены ПолучитьТолькоЧтение/GetReadOnly и процедурный
УстановитьТолькоЧтение/SetReadOnly. Тест виртуального host прошёл после red
на UnknownMethod: проверены свежий атрибут, его неизвестность, измеренные
аргументы, сохранность данных, процедурность и отсутствие создания missing.
Граничные аргументы на этом этапе ещё оставались зарегистрированным
вопросом; реестр, маркер и измерительная строка были согласованы.
Невидимость ещё не подключена, полный синхронный интерфейс оставался
незавершённым.

Подготовлен host для невидимости: FileMetadata.hidden необязателен,
FileSystem::set_hidden имеет default Unsupported. Linux-адаптер сообщает
false и проверяет наличие пути при установке, не меняя имя, права или данные.
На других ОС default остаётся отказом. Целевые тесты выполнили red/green;
семь тестов metadata/temporary_directory прошли в отдельной сборочной
директории, не меняя артефакты работающего полного прогона. BSL-члены
невидимости остаются следующим шагом, а не считаются готовыми вместе с host.

Подключены ПолучитьНевидимость/GetHidden и процедурный
УстановитьНевидимость/SetHidden. Виртуальный host-тест прошёл после red
на UnknownMethod; проверены неизвестный атрибут, изменение через тот же
объект, отказ Неопределено, процедурность, отсутствие переименования и
создания missing. Все 28 тестов host-окружения, реестр и Clippy прошли.
API reference регенерирован; plain/optimize исходного file-object.bsl
совпали без случайного scratch-пути. Полная совместимость и серия на этом
этапе оставались открытыми, включая аргументы атрибутов и
FILE.TIME_EDGE_BEHAVIOR. Последующие измерения закрыли строковую грамматику
и порядок отказов атрибутов; локализованный текст ошибки относится к общей
диагностике runtime, а не к файловому API.

Следующий шаг добавил файловый диалект масок с общим для ZIP циклом
сопоставления. Новый тест сначала не компилировался без file_mask_matches,
затем подтвердил 260 одиночных платформенных случаев. Все 48 ZIP-тестов
и три проверки реестра прошли. На этом этапе дополнительные POSIX-классы и
экранирование оставались `FILE.MASK_EXTENSIONS`; последующие
`file-mask-extensions` и `file-search-sfile` закрыли чистый сопоставитель и
перенесли неизмеренный отбор специальных объектов в `FIND.TRAVERSAL`.
Матрица `file-search-sfile-selection` затем измерила 208 сочетаний и закрыла
отбор для имён и масок своей области; каталоги со звёздочкой, иные формы
`sfile`, ошибки и циклы остались в `FIND.TRAVERSAL`.

Полный workspace-прогон сопоставителя завершился с кодом 0
(`/tmp/open-bsl-file-masks-workspace.log`). Для следующего шага выделена
внутренняя фабрика File из пути, Rc ФС, Rc зоны и проверенного разделителя;
BSL-конструктор использует её, сохраняя прежнюю проверку host-разделителя.
Это внутренний рефакторинг в рамках активного изменения, не новый BSL API.
12 файловых host-тестов прошли до и после, Clippy успешен. FindFiles
ещё не подключён: нужны отдельный вход с владением сервисами и передача
существующего флага отмены VM в обход.
