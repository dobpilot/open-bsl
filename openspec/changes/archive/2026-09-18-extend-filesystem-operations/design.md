# Решения и последовательность

## Конечный разделитель и защитное удаление

Security-проверка 2026-09-16 воспроизвела удаление содержимого цели
каталога-ссылки при пути selected/: symlink_metadata разрешал такой путь
как каталог до существующей проверки типа ссылки. Удаление selected без
разделителя сохраняло цель. Это дефект уже выбранного no-follow, не повод
переносить в host измеренное следование серверной 1С.

На Unix до metadata удаляются только конечные / непустого некорневого
пути; исходное наличие разделителя сохраняется отдельно. Для обычного
файла оно даёт NotADirectory без удаления, для ссылки удаляется сама
ссылка. Внутренние компоненты, точки, пробелы и .. не нормализуются.
Корневой путь из одних / не превращается в пустую строку. Windows-ветка
не меняется: нельзя обрезать C:\\ до C: и выдавать это за ту же операцию.
Стандартный host по-прежнему не ограничивает родительские компоненты
разрешённым корнем; комментарий с обещанием защиты sandbox исправляется.
Это не системный токен владения временным файлом и не доказательство
невозможности конкурентной подмены произвольного объекта по тому же имени.

## Преобразование флага рекурсии

file-search-recursion-arguments 2026-09-16 подтвердил 56 серверных
RU/EN-случаев. Четыре расхождения — строки Да/Нет: платформа их отвергает,
а общий as_condition принимает. Используется уже измеренный подготовитель
булева аргумента из file, расширенный до внутреннего общего помощника
с именем операции для ошибки; второй разбор булевых слов не вводится.
Обычные условия BSL не меняются. Последующий
file-search-access-order подтвердил проверку третьего аргумента до
I/O. Корневой `PermissionDenied` при допустимой рекурсии даёт пустой
массив; в async-варианте ошибка аргумента попадает в обещание и
наблюдается на `Ждать`. Политика скрытия отказа передаётся в общий обход
явно и включена только для НайтиФайлы; УдалитьФайлы по маске по-прежнему
возвращает ошибку host. Аргументы поиска закрыты общим форматировщиком и
измеренным условным преобразованием; локализация диагностик остаётся общей.

## Преобразование аргументов атрибутов

file-attribute-arguments и file-attribute-arguments-async 2026-09-16
подтвердили по 224 случая на сервере и клиенте localhost/test. В обоих
контекстах строки Да/Нет отвергаются setter, хотя общая as_condition
принимает их. До исправления различались 16 результатов каждого сценария.
В file вводится общий подготовитель аргумента четырёх sync/async-входов:
он отклоняет эти условные псевдонимы; после дополнительного измерения тот
же подготовитель обслуживает все sync/Async/Begin-входы. Поведение Если
не меняется. Асинхронный отказ, как прежде, сохраняется в обещании.
Дополнительный серверный file-attribute-string-edges 2026-09-17 уточнил
сам преобразователь: VT, FF, U+001C…U+001F, U+0085, NBSP, U+2028 и U+2029
снимаются вокруг слова, U+200B сохраняется, а yes/no принимаются только
setter-ом атрибута. Поэтому setter-ы используют отдельный словарь, а общий
as_condition и boolean_argument рекурсии не расширяются. Порядок относительно
отказа доступа измерен. Английские тексты платформы зависят от локали и не
подменяют общую русскую модель `RtError` локальными строками файловых
setter-ов. Это измеренное отличие диагностики, а не открытый вопрос семантики.

## Поздние несовпавшие и несколько оборванных ссылок

file-search-late-links 2026-09-16 проверил 128 RU/EN-вызовов на четырёх
деревьях: восемь масок, с рекурсией и без. Текущий алгоритм совпал со всеми
результатами, включая порядок; изменения обхода не потребовались.
Несовпавшая оборванная ссылка прекращает выбор позднейших каталогов,
но не выдачу совпадений. Следующая совпавшая оборванная ссылка прекращает
выдачу даже после допущенной первой ссылки. Уже выбранные каталоги остаются.
Проверяемый host воспроизводит сохранённый порядок read_dir, а не текущий
порядок файловой системы машины. Измерение не обобщается на PermissionDenied,
циклы и сочетания с пробельными именами; FIND.TRAVERSAL остаётся открытым.

## Поиск пробельных имён после смешанных деревьев

file-search-spaces.platform.txt отделяет результат поиска от ошибок
ЭтоКаталог нормализованного объекта. Поиск обрезает конечные пробельные
символы только у входного пути, не у маски. Рекурсия сохраняет классификацию
исходной записи: обычный файл с пробелом не порождает лишний обход каталога-
двойника. Для выбранного каталога обрезается конец пути, дубликаты сохраняются.
NotFound/NotADirectory после такого изменения имени пропускают этот спуск,
не ранее полученные результаты и не соседние каталоги. Другие ошибки и
ошибки неизменённого пути остаются явными. Это не новая политика удаления:
непустая маска удаления по-прежнему использует исходные пути host, без
обрезания, и не спускается рекурсивно через поиск. Общий алгоритм и прежние
правила оборванных ссылок сохраняются.

file-path-whitespace подтверждает 35 символов в четырёх позициях. Набор
обрезания совпадает со std char::is_whitespace плюс U+001C…U+001F;
новая копия таблицы Unicode не нужна. Лексический FilePath обрезается после
сворачивания разделителей, а входной путь поиска — до I/O без сворачивания
конечного разделителя. Таким образом padded<SPACE>/ остаётся адресом
физического каталога, хотя ПолноеИмя соответствующего Файл обрезается.
Нормализация аргумента СоздатьКаталог остаётся отдельным, ранее измеренным
потребителем разбора; новая таблица лексического обрезания не переносится
в неё без замера. Удаление с маской продолжает получать исходные пути.

## Создание каталогов после замера 2026-09-16

Серверные file-create-paths и клиентские file-create-paths-async подтвердили
сворачивание точек/разделителей до I/O, отказ пустой строке и star*, окончание
файлового пути на первом NUL. Асинхронный результат сохраняет исходную строку.
Общий create_directory_path использует существующий file::normalize_path,
разделитель берёт у того же host. Публичный FileSystem::create_dir_all не
меняется: BSL-нормализация не переносится в системный адаптер и ZIP.
Нормализация не обращается к metadata, поэтому устранённый через .. обычный
файл не препятствует созданию. NUL ограничивает только путь операции, не
лексические свойства объекта Файл. Новых зависимостей и формата байт-кода нет.
Пробелы, двоеточие и точность побочных эффектов отдельно проверяются внешним
снимком file-create-layout; вывод НайтиФайлы сам по себе не доказывает имя ОС.
Снимок до выхода подтвердил удаление конечного ASCII-пробела как при создании,
так и в ПолноеИмя; внутренние и начальные пробелы сохраняются. Последующий
серверный `file-create-directory-edges` отделил физический путь созданием,
удалением базового имени и подсчётом остатка: NUL, TAB, LF, CR, SPACE, U+0085
и NBSP снимаются, а U+0001, U+007F, U+200B и U+FEFF сохраняются. Поэтому
создание теперь использует общий `prepare_file_operation_path`, уже
измеренный для файлового I/O, вместо отдельного неполного обрезания.
Серверный `file-create-directory-roots` дополнительно отделил контракт от
общей нормализации: `.`, `./`, `..` и `../` успешны как no-op, хотя их
нормализованный путь пуст. Его первоначальный вывод о no-op объекта Файл был
неполным: проба проверяла только путь внутри объекта. Изолированные клиентская
и серверная пробы типов затем проверили также `Строка(Файл)` и доказали, что
sync и async создают буквальный каталог с этим именем, как и для остальных
измеренных непустых представлений. Оба контекста используют общий
форматировщик; async дополнительно возвращает исходное значение.
Поиск по каталогу с конечным пробелом и sfile-представление звёздочки остаются
отдельными расхождениями, не исправляются изменением семантики создания.
Последующие пробы типов, относительных форм и частичных отказов закрыли
CREATEDIR.PATH_SEMANTICS. Внешний снимок `file-create-layout` отдельно подтвердил,
что двоеточие сохраняется в физическом имени; sfile возникает в наблюдении
через `Файл`/поиск, а не меняет результат создания.

Последующий клиентский `file-create-directory-relative-forms-async` измерил
ещё двенадцать составных форм только из `.`, `..` и разделителей. Все sync
вызовы успешны; Async возвращает исходную строку без нормализации. Десять
относительных форм до исправления сворачивались в пустой операционный путь и
ошибочно отвергались. Они вместе с `/./` и `/../` теперь распознаются точным
измеренным списком до host; правило не расширено на произвольные комбинации.

Серверный `file-create-directory-failures` измерил два частичных отказа на
Linux. Компонент длиной 300 байт возвращает ошибку после создания допустимого
префикса; `PermissionDenied` внутри существующего каталога не создаёт
ребёнка. Системный host сохраняет обычную семантику `create_dir_all` без
отката. После этого частичные отказы закрыты измеренными Linux-сценариями;
преобразование прочих типов остаётся отдельным вопросом.

## Оборванные ссылки после замера средней позиции

`file-search-broken-middle.platform.txt` подтверждает раздельное прерывание
совпадений и списка каталогов рекурсии. Обход хранит для каждого уровня
два признака завершения и число совпадений. Только NotFound metadata
сообщённой host ссылки включает эти правила; остальные ошибки передаются.
Измеренные специальные маски * и *.* не включают первую оборванную ссылку;
прочие измеренные маски допускают её как первую совпавшую запись.
Правило фильтрации перед проверкой последующих не совпавших ссылок и
прочие ошибки остаются в FIND.TRAVERSAL, не объявляются полностью измеренными.
Общий выбор удаления использует тот же обход. Эффекты оборванных ссылок при
удалении измерены отдельно; намеренный no-follow системного host сохраняется
как согласованное защитное отличие от 1С.

## Рекурсия после контрольного замера ссылок

`file-search-link-controls.platform.txt` подтвердил выдачу совпадений текущего
каталога перед спуском и следование по существующей ссылке на каталог.
Обход остаётся итеративным: стек ожидающих каталогов с глубиной, временный
список детей текущего уровня; порядок host не сортируется.
DirEntry получает отдельный сообщаемый host признак ссылки, не меняющий
is_dir для ZIP. Metadata цели требуется только для сообщённой ссылки при
рекурсии; прежние host не получают дополнительных запросов для обычных записей.
Первоначальное правило NotFound «только отсутствие спуска» заменено после
замера средней позиции правилами раздельного прерывания, описанными выше.
Остальные ошибки передаются. Глубина 256 и предел 1 000 000 элементов защищают
также циклические ссылки. Последующая серверная проба цикла каталога с
80-байтовым именем ссылки дала на обеих сторонах 42 результата до Linux
`ELOOP`: уже собранный массив сохраняется по измеренному правилу оборванной
ссылки. Это не измеряет собственные защитные пределы и иные формы циклов.

## Уточнение конструктора по серверному замеру 2026-09-10

`file-constructor.platform.txt` подтвердил арность 0–1 и преобразование
проверенных нестроковых аргументов общей Строка. Без аргумента путь пуст.
Общий с ИнициализироватьАсинх разбор пути отбрасывает лишние относительные
родители и сохраняет измеренные пути, состоящие только из разделителей.
Это изменение лексических полей; I/O для NUL, необычных корней и подобных
имён отдельно не измерялся. FILE.EDGE_BEHAVIOR остаётся открытым для прочих
классов объектов, форм корня и ошибок доступа. ФС процесса не подставляется
вместо host, новые алгоритмы разбора или зависимости не добавляются.

## Операционный путь Файл по серверному замеру 2026-09-17

`file-object-io-edges.platform.txt` отделил лексическое имя от пути I/O.
NUL сохраняется в `ПолноеИмя`, но `ДвоичныеДанные.Записать` и методы
метаданных используют только префикс до NUL. Измеренные конечные пробельные
символы удаляются до обращения к host. Реализация переиспользует
`normalize_path` и `trim_path_end`; отдельный парсер или нормализация внутри
`SystemFileSystem` не вводятся. Поэтому то же правило проверяется виртуальным
host и остаётся общим для синхронных, Async- и Begin-методов `Файл`.

Дополнительный `file-read-io-edges.platform.txt` подтвердил то же правило
для `Новый ДвоичныеДанные`, `Новый ФайловыйПоток` и
`ФайловыеПотоки.ОткрытьДляЧтения`. Один публичный Rust-помощник базового
runtime получает разделитель у host и готовит путь; `bsl-stream` использует
его перед общим открытием, сохраняя исходную строку в лексическом имени
потока. Так нормализация не дублируется между компонентами и не переносится
в `SystemFileSystem`.

Замер не закрывает ошибки доступа, записывающие режимы потоков как отдельные
сценарии, иные I/O-конструкторы, необычные корни и полный набор управляющих
символов. `FILE.EDGE_BEHAVIOR` сохраняется для этого остатка.

## Статус и источники

Дополнительный замер `file-delete-types.platform.txt` от 2026-09-10
подтвердил строковое преобразование числовой, булевой, массивной и
структурной маски удаления; Null действует как пустая маска. Подготовка
маски должна использовать существующий BSL-форматировщик, а не Rust Display
или его копию. VM использует новый вход `call_builtin_delete_files_formatted`;
общая подготовка принимает необязательный форматировщик, общий обход не
дублируется. Существующий публичный Rust-вход
`call_builtin_files` и прежний `call_builtin_delete_files` сохраняются
совместимыми и строгими по типу маски. Асинхронная подготовка использует
форматировщик после отдельного клиентского замера file-delete-async-types;
серверный синхронный замер сам по себе не доказывает клиентское поведение.
Позднейший file-delete-more-types-async подтвердил ещё десять объектных типов:
девять масок удалили файл с безопасным строковым представлением, дата была
принята на контрольном имени; во всех случаях корень сохранён и обещание
вернуло Неопределено. Локализованный текст даты не фиксируется этим контрактом.
Первый аргумент остаётся за
границей этого замера. Подробности и восстановление базы зафиксированы в
`docs/research/compatibility/file-delete-types-server-2026-09-10.md`.

Это план, а не разрешение немедленно менять runtime или запускать программы.
Исходное сопоставление и локаторы Unica находятся в
`docs/research/compatibility/files-api-2026-09-09.md`.
Новые граничные правила НЕ ИЗМЕРЕНО. До внедрения правила требуются oracle
либо оформленная тройка по AGENTS.md: маркер в коде, реестр вопроса и ровно
одна измерительная строка. Не создавать фиктивный oracle из open-bsl.
В планировании исходники/реестр не меняются только ради предположений.

Решения Q1–Q15 подтверждены пользователем 2026-09-09 после `grilling`.
Это согласование плана, не результатов измерения и не начало реализации.
План состоит из четырёх отдельно принимаемых изменений: файловое ядро
и временные имена; временный поток и очистка; запуск; асинхронные варианты.
Общий режим «клиент/сервер» для всего движка не вводится. Обязательная
платформенная приёмка сначала на Linux; поддержка сборки на других ОС
сохраняется без неизмеренного обещания совместимости.

## 1. Сначала измерения и границы

Повторяемый `run-on-server-1c.py` предназначен только для разрешённой
localhost/test и требует явного --allow-config-mutation. Он не запускает
службы и не использует Unica. Свежий каталог прогона сохраняет CF, исходный,
измерительный и восстановленный XML, исходный вывод и логи. После накладки
существующего cfg-src и генерации формы повторная XML-выгрузка проверяет,
что конфигурация не изменилась во время подготовки. Требуется отсутствие
параллельного редактирования конфигурации: эта проверка не является блокировкой.
При разных UID серверу через POSIX ACL выдаётся только проход к `io/`
и доступ внутри него; CF и каталоги XML остаются приватными. Ошибка ACL
останавливает подготовку до native-команд, общий доступ на запись не выдаётся.

Флаг необходимости восстановления выставляется до LoadConfigFromFiles,
включая его частичный отказ. Любая последующая ошибка или перехваченный
SIGINT/SIGTERM запускает LoadCfg исходной копии, UpdateDBCfg и сверку XML,
исключающую только корневой ConfigDumpInfo.xml. Дочерняя группа native
останавливается до восстановления при таймауте/сигнале. SIGKILL не обещает
автоматического восстановления; CF и журнал остаются для ручной операции.
Пустой вывод, отсутствующие/повторные/переставленные file.begin/file.end
или file.setup_error/file.cleanup_error не считаются успешным замером.
Нормализованный platform.txt публикуется только после проверки восстановления;
общий platform.tsv и oracle репозитория автоматически не обновляются.

Этот этап проверяется offline-двойником native-команд с отказами каждого
шага. Он не подменяет реальный запуск и приёмку самого измерителя на 1С.
Все 17 тестов генератора/runner, полный workspace, fmt, Clippy, rustdoc
с запретом предупреждений, git diff --check и 11 строгих проверок OpenSpec
прошли. Логи: `/tmp/open-bsl-server-runner-tests-native-acl.log` и
`/tmp/open-bsl-server-runner-{workspace,clippy,doc}.log`.
После запуска кластера пользователем 2026-09-15 выполнены три реальных
round-trip: file-globals и две пробы срока жизни. Все подтвердили восстановление
CF/БД и совпадение XML. Повторный file-globals совпал с прежним oracle после
нормализации случайной части временных имён. Отчёт и исходные результаты —
docs/research/compatibility/file-temp-return-server-2026-09-15.md.
Offline-тесты и реальные прогоны остаются разными основаниями приёмки.

На реальной платформе выполнять пробы в новом частном scratch-каталоге,
созданном для сеанса; подготовка, manifest и очистка ограничены этим корнем.
Не удалять общий temp-каталог, корень workspace и пользовательские файлы.
Симлинки проверять на специально созданных соседних деревьях, не на реальных
данных. Ошибки отдельных проб перехватывать, всегда записывать завершающий
маркер; пустой результат не считать успехом. Клиентские и серверные пробы
разделить. Проверка очистки после завершения требует внешнего наблюдателя,
а не ожидания внутри того же живого сеанса.

| Группа | Минимальные различающие случаи |
|---|---|
| Объект пути | Относительный/абсолютный путь, каталог, отсутствующий путь, ссылка; `ПолноеИмя`, существование и тип до/после изменения ФС; регистр и разделители |

| Создание | Существующий каталог, файл вместо каталога, отсутствующие родители, относительный путь, запрещённое имя, нет доступа |

| Временный поток | Создание host-файла до записи/ИмяФайла; тип, позиция, чтение/запись/seek/truncate; default 65535/8192 и буферизация; ноль, отрицательные/дробные/огромные параметры; ошибка создания/записи, close/drop и повторный close |

Общие пробы должны исполняться на обеих сторонах. Ещё неизвестные методы
проверять через `Вычислить`/`Выполнить` в `Попытка`, чтобы неподдерживаемый
метод не сорвал компиляцию всего измерителя. В новых сценариях не использовать
имена переменных, совпадающие со свойствами управляемой формы.

Первые серверные результаты сохранены в `file-object-server-2026-09-09.md`
и `file-globals-server-2026-09-09.md` под `docs/research/compatibility/`.
Они ещё не закрывают матрицу. В частности, `?.txt` не совпал с `я.txt`,
поэтому существующий посимвольный ZIP-сопоставитель нельзя объявить готовой
реализацией файлового поиска. Выдача временного имени с `a/b` успешна в 1С,
а нынешнее резервирование полного имени в host её отвергает: перед изменением
нужно явно уточнить гарантии host-контракта, а не исправлять только точку
перед расширением.

Дополнительное смешанное дерево исследовано в file-masks-server-2026-09-09.md.
Необычные имена `a*`, `a?`, `a\b` сопровождаются сокращением массива
результатов; это ещё не объяснено чистым сопоставлением маски. Перед
расширением общего механизма нужны обычное дерево и singleton-пробы,
чтобы отделить диалект от нормализации/сравнения файловых объектов.

Это разделение выполнено в file-masks-single-server-2026-09-09.md:
300 запросов подтвердили байтовый `?` и ASCII-классы в обычных именах.
Файл `a*` даёт особый результат sfile:// и требует отдельного правила
результатов поиска; он не используется как oracle чистого сопоставителя.
Общий механизм должен сохранить Unicode-скалярный ZIP-диалект и добавить
измеренный байтовый файловый диалект, не копируя цикл со звёздочкой.

Добавлен `file_mask_matches` рядом с `simple_mask_matches`. Общий
двухуказательный цикл получает правило совпадения единицы; ZIP использует
Unicode-скаляр, файловый диалект — байт с разбором скобочного класса.
260 одиночных результатов сверяются непосредственно с сохранённым oracle;
особый a* исключён из этой проверки по описанной границе чистой маски.
Отдельный `file-mask-extensions` затем подтвердил на серверной 1С все
двенадцать реализованных POSIX-классов, отрицание, пять надёжно создаваемых
escape-форм и четыре повреждённые формы. Все 40 результатов побайтно совпали
с open-bsl. Имя со звёздочкой исключено: платформа представляет его через
особый `sfile://`, поэтому такая проба не является свидетельством чистого
сопоставителя. Последующие матрицы `file-search-sfile` и
`file-search-sfile-selection` подтвердили, что
литеральные `*` и `\` относятся соответственно к слою sfile и разбору пути,
а не к обычным именам чистого сопоставителя. Поэтому `FILE.MASK_EXTENSIONS`
закрыт разделением областей; неизмеренные формы sfile остаются в
`FIND.TRAVERSAL`.

Отдельный `file-search-sfile` создал дерево средствами ОС и измерил `*`,
`*a`, `a*`, `a*b`, `a**`, `a*.txt`, `a?` и `a\b`. Все имена со звёздочкой
получили двойной префикс `sfile://`, потеряли каталог в результате поиска,
усекли `Имя` до первой звёздочки и перестали указывать на физический файл.
При этом маска `*` не выдала ни одного из них, а вопросительные маски дали
разный результат для `a*` и `a**`. Следующая матрица из 208 случаев
установила отдельное правило отбора: маска с литералом использует байтовый
сопоставитель, чистые `?` требуют точной длины не меньше трёх, чистые и
смешанные `*`/`?` без литерала не совпадают, а экранированная звёздочка
литеральна. Поиск создаёт специальный объект без каталога, но удаление
сохраняет физический путь и обычный сопоставитель. Прямой поиск пути со
звёздочкой без маски пуст и не запрашивает metadata. `a?` осталось обычным
файлом; `a\b` подтвердило разбор обратной косой черты как разделителя и
сохранение защитного отказа open-bsl от host-имени, выходящего из каталога.
Отдельная проба физического каталога `a*` показала, что серверная 1С никогда
не входит в него при рекурсивном поиске. Это верно и для масок `*`/`*.txt`,
которые не выбирают сам специальный объект; open-bsl поэтому исключает такую
запись из стека каталогов, не меняя отбор текущего уровня и удаление.
Матрица ссылок подтвердила ту же границу для `a*`, ведущего на каталог, файл
или отсутствующую цель: вид цели не наблюдается через специальный объект и
не разрешает рекурсивный спуск. Текущий алгоритм уже совпал после запрета
спуска в специальную запись; отдельного правила следования не добавлено.

Результаты поиска создаются тем же внутренним конструктором пути, что и
Новый Файл: он принимает Rc ФС и часового пояса, не получает их из глобального
окружения. Старый публичный call_builtin_files с заимствованной ФС сохраняется.
Для поиска нужен отдельный вход с владением сервисами; отмена должна проходить
через существующий cancel_flag VM, а не новый независимый источник отмены.

Добавлен Rust-вход `find_files`: итеративный обход в глубину сохраняет порядок
итератора host и привязку каждого объекта к Rc ФС и зоны. Callback проверяется
до I/O и между элементами. Некорректные имена элементов host отвергаются до
построения дочернего пути.
Оба разделителя, включая обратную косую черту на Linux, запрещены в имени
элемента: конструктор Файл нормализует оба и иначе мог бы вернуть объект
с путём вне каталога обхода. Это защитное отличие от измеренного a\b в 1С.
Защитные пределы open-bsl — 256 уровней каталогов и 1 000 000 просмотренных
элементов; превышение не возвращает частичный массив.
Это не измеренные ограничения 1С. Ошибки обхода пока передаются вызывающему,
ссылки на каталоги не обходятся по признаку DirEntry. Неизмеренные правила
собраны в FIND.TRAVERSAL. Builtin RU/EN подключён через отдельный эффект
FileSearch и вход call_builtin_find_files, не меняющий прежний call_builtin_files.
HostIo передаёт существующий cancel_flag исполнения, в том числе во вложенный
обратный вызов компонента. Тест устанавливает флаг внутри итератора host и
проверяет неловимый Canceled. Граничные аргументы впоследствии закрыты
серверной и клиентской матрицами типов и порядка ошибок.
Conformance file_search сверяет количества десяти результатов с сохранёнными
find.* строками file-globals.platform.txt. Отдельный file-search-order
сверяет измеренный host-порядок и последовательность уровней.

Матрица `file-object-host-edges` уточнила системные metadata. Linux FIFO и
Unix-сокет в 1С являются файлами с размером 0, но не каталогами; системный
адаптер распознаёт измеренные классы явно, не обобщая правило на остальные
специальные Unix-объекты. Более поздняя матрица символьных устройств
расширяет этот список ниже.
`Существует` скрывает измеренные NotFound, ELOOP, ENOTDIR, ENAMETOOLONG и
PermissionDenied, тогда как `ЭтоФайл`, `ЭтоКаталог` и `Размер` сохраняют
исключение. Произвольная Other-ошибка не скрывается без измерения. Пустые,
точечные и корневые формы пути уже совпали и закреплены тем же oracle.
Отдельная матрица четырёх записывающих потоков подтвердила общий операционный
путь по фактическим байтам: NUL и шесть краевых пробельных символов снимаются,
U+007F/U+200B/U+FEFF сохраняются, а NUL в начале конечного компонента ведёт к
отказу каталога. Изменение runtime не понадобилось.

Матрица `file-object-devices` отдельно измерила пять символьных устройств
Linux: `/dev/null`, `/dev/zero`, `/dev/full`, `/dev/random` и `/dev/urandom`.
Серверная 1С считает каждое файлом, не каталогом, с размером metadata 0.
Системный адаптер поэтому дополнительно распознаёт только
`FileTypeExt::is_char_device`; блочные устройства и другие Unix-типы без
oracle не обобщаются.

Конструктор `ЗаписьТекста` первоначально обходил общий операционный путь и
передавал host исходную строку. Матрица `file-text-writer-io-edges` тем же
способом, что и потоковые пробы, различила базовый файл по трёхбайтовому BOM:
1С снимает NUL и шесть измеренных краевых пробельных символов до открытия,
но сохраняет U+007F, U+200B и U+FEFF. Конструктор теперь вызывает существующий
`prepare_file_operation_path`; отдельного нормализатора не введено.

Оба файловых входа JSON также первоначально миновали общий helper. Матрица
`file-json-io-edges` проверила чтение по фактическому значению и запись по
байтам базового файла. Для 21 безопасного случая действует тот же набор
снятия и сохранения символов. `ЧтениеJSON.ОткрытьФайл` и
`ЗаписьJSON.ОткрытьФайл` нормализуют имя через файловую систему, сохранённую
в объекте. Чтение каталога после начального NUL на платформе зависло до
таймаута, поэтому этот случай за oracle не выдан и в успешную матрицу не
включён.

`ТекстовыйДокумент.Прочитать/Записать` имел тот же прямой доступ. Матрица
`file-textdoc-io-edges` различает запись по UTF-8 BOM с числом 1 и чтение по
возвращённому тексту. Все 21 безопасный случай повторили правило JSON и
потоков; оба метода теперь вызывают `prepare_file_operation_path` через
файловую систему документа.

Файловые входы `ЧтениеXML` и `ЗаписьXML` повторили тот же результат. Reader
проверяется по имени первого элемента, writer — по BOM и сериализованному
`<a/>`. Оба объекта теперь нормализуют имя через собственную файловую систему
перед чтением либо сохранением пути до `Закрыть`.

Глобальная `СоздатьФабрикуXDTO(Путь)` читает XSD отдельным входом и потому
не получила исправление `ЧтениеXML` автоматически. Десять суффиксов
подтвердили тот же операционный путь. Фабрика нормализует имя до чтения,
сохраняя прежнюю host-изоляцию и перевод ошибки в `RtError::Xdto`.

`ТабличныйДокумент.Прочитать/Записать` также изначально обходили
общий helper. Матрица `file-spreadsheet-io-edges` различает запись
по изменению размера базового MXL, а чтение — по тексту первой
ячейки. Все 21 безопасный случай повторили правило JSON, XML и
`ТекстовыйДокумент`; оба метода теперь вызывают
`prepare_file_operation_path` через файловую систему документа.

Архивные reader/writer имеют по два BSL-типа и два входа — конструктор
и `Открыть`. Матрица `file-archive-io-edges` проверила все восемь путей:
все они повторяют общее правило. Reader нормализует строку в `read_source`
перед host-чтением. Writer сохраняет исходную цель в состоянии и нормализует
её в `writer_write` непосредственно перед host-записью. Потоковые цели не меняются.

`Добавить` и `ИзвлечьВсе` также повторили правило на десяти суффиксах.
Источник `Добавить` нормализуется до обхода; каталог распаковки — до
сборки итоговых имён. Ранее измеренный завершающий `/` у `Добавить` остаётся
сигналом маски `*`; неизмеренные сочетания разделителя и краевых пробелов
не подменяются общим правилом.

`file-pdf-io-edges` выявил узкое исключение из общего правила.
`ДокументPDF.Прочитать` завершает имя по NUL, а `Записать` с таким
именем отказывает; оба метода снимают шесть измеренных конечных
пробельных символов. Чтение вызывает `prepare_file_operation_path`; запись
пользуется им только при отсутствии NUL, чтобы ошибку вернул тот же host.

Конструкторы `СертификатыУдостоверяющихЦентровФайл` и
`СертификатКлиентаФайл` первоначально читали имя напрямую через host.
Матрица `file-http-certificate-io-edges` подтвердила для обоих общий reader-путь:
NUL и шесть краевых пробельных символов снимаются, U+007F/U+200B/U+FEFF
сохраняются. Оба конструктора теперь нормализуют имя тем же `FileSystem`
до чтения байтов; немедленный разбор сертификата по-прежнему не добавлен.

Замеры file-search-edges и file-search-types уточнили ошибки корня и аргументы.
NotFound/NotADirectory корня с маской дают пустой массив. Пропущенная рекурсия,
включая пропуск запятой, получает Ложь в резолвере; явное Неопределено остаётся
ошибкой. Путь и маска проходят BSL-форматировщик, переданный из VM через
call_builtin_find_files: он уже обслуживает Строка и не создаёт зависимости
bsl-rt от bsl-format. Дополнительный клиентский замер подтвердил одинаковое
принятие десяти объектных типов sync/async; девять безопасных представлений
совпали с созданным именем, дата принята и дала ноль на контрольном имени.
Текст даты и Типа зависит от локали клиента (`String` против `Строка`), поэтому
файловый oracle не фиксирует его. Прочие типы и порядок ошибок ещё не закрыты.

## 2. Единая файловая граница

Переиспользовать `FileSystem::{metadata,read_dir,create_dir_all,open,remove_path}`.
Не вводить вторую ФС и не делать прямой `std::fs` в BSL-обёртках.
Новый объект `Файл` привязать к ФС создавшего его сеанса. В объём входит
полный интерфейс типа, а не только методы, необходимые поиску. Перед кодом
составить полный перечень по Unica с RU/EN-именами, арностями, доступностью,
свойствами и методами, включая асинхронные; прочитать страницы и измерить
каждый контракт. Асинхронные члены входят в четвёртое изменение серии.
Не имитировать неподдерживаемые сведения нулями. Исходный `FileMetadata`
содержал только признак каталога и время изменения. Для объекта `Файл`
добавлены явный `is_file`, конструктор `other` и необязательный `size` с
`with_size`; прежние `file`/`directory` сохраняются с неизвестным размером.
Стандартный адаптер заполняет размер и различает обычный файл и прочие
виды объектов, не угадывая вид через отрицание `is_dir`.

Время изменения проходит через `FileSystem::set_modified(path, unix_seconds)`:
целые секунды UTC, безопасный `Unsupported` по умолчанию. Системный адаптер
использует `std::fs::FileTimes`, не копирует содержимое и не меняет время
доступа. Чтение времени до Unix epoch сохраняет знак и округляет дробную
секунду вниз. Это контракт Rust-host, не вывод о диапазоне дат или правилах
часового пояса 1С; BSL-преобразования требуют отдельных измерений.

Серверный замер `file-times-server-2026-09-09.md` показал +3 часа для
дат 2020 года, но искажение UTC-дат до epoch и пустое местное представление
на краях диапазона. До подключения BSL-методов нужны тип/поля результата
и внешнее чтение mtime; эти наблюдения не переносятся в Rust-host как правило.

Продолжение `file-time-edges-server-2026-09-09.md` подтвердило разные
mtime у UTC/local setter до epoch, нулевые календарные поля UTC-getter
для минимальной даты и запись mtime -1 для местной даты в пропуске зоны.
Общий обратный timezone-конвертер не считается совместимой реализацией
файлового setter без обработки этих правил. Принятие обычных строковых дат
подтверждено отдельной пробой с изменением прежнего значения.

Подключены четыре метода времени. Объект сохраняет Rc часового пояса
создавшего сеанса рядом с Rc ФС. Getter перечитывает metadata; отсутствие
времени — явный отказ. Обычные строки разбираются существующим parse_digits.
Переполнение UTC-счётчика реализовано на BSL-границе, локальное время —
через существующий TimeZone с дополнительной проверкой пропуска (mtime -1).
Весь диапазон этого переноса и непредставимые нулевые календарные поля
остаются `FILE.TIME_EDGE_BEHAVIOR`: реестр и единственная безопасная проба
добавлены. В двух минимальных случаях пока вызывается исключение вместо
платформенного Date с полями 0-0-0; полная задача времени не закрыта.

`file-time-string-arguments` позднее закрыл измеренную строковую границу
setter-ов: после первого NUL снимаются SPACE, TAB, LF, CR, U+0085 и NBSP,
но не U+200B/U+FEFF; принимаются ровно 8 или 14 цифр, причём обе полностью
нулевые формы означают пустую дату. Это отдельный преобразователь Файл:
общий конструктор Дата не получает файловое исключение для восьми нулей.
Отказ не меняет прежний `mtime`; правило одинаково для local и UTC setter.

Два серверных прогона file-zero-date 2026-09-17 уточнили причину: local_min
и utc_min с одинаковыми нулевыми полями различаются как значения и ключи,
а их разность составляет -9016.8384 секунды. Оба сравниваются больше пустой
даты, но вычитание пустой даты отрицательно. Один sentinel и нормализация
к empty() отвергнуты этим oracle. Точный внутренний алгоритм из этих двух
случаев не выводится: прежде изменения BslDate нужны соседние границы,
проверки арифметики и аудит потребителей целых секунд. Публичные Rust-методы
seconds/from_seconds/diff_seconds не меняют единицы скрыто. Формат байткода
пока не меняется. Измеренные внутренняя, XML- и JSON-сериализации нормализуют
оба значения к пустой дате; хранение и копирование в VM не должны терять их
различие.
Подробные результаты и оставшиеся проверки:
docs/research/compatibility/file-zero-date-server-2026-09-17.md.

Следующий этап выделяет необходимую основу — обычную дату с долями секунды.
file-date-neighbors и file-date-precision подтвердили шаг 1/10000, округление
половины от нуля, сравнение дробных значений и ограничение арифметики диапазоном
до последней доли секунды 9999 года. BslDate остаётся одним 64-битным значением,
но хранит такты; seconds/from_seconds сохраняют единицу «секунды».
Для точного обмена добавляются ticks/from_ticks; checked shift_seconds остаётся
проверяемым Rust-методом, а измеренное насыщение применяется в BSL-операциях.
diff_seconds сохраняет целочисленный Rust-результат с усечением разности к нулю;
BSL-вычитание использует точное BslNumber, без f64 и новой десятичной реализации.
Позднейший date-shift-limits измерил огромные аргументы: после округления
в такты платформа использует младшие 64 бита как знаковое целое, затем
насыщает календарный результат. Нулевые поля не нормализуются в empty() внутри VM.

Константы байткода должны сохранять доли: формат 33 записывает после «Дата»
целое число тактов 1/10000 секунды вместо целых секунд. Смена единицы явная,
старый формат отвергается по заголовку. Поля обычной даты и публичные методы
секунд не меняют единицы вместе с форматом. Календарь, форматирование и внешние
сериализаторы проверяются отдельно: разрешение календарных полей не доказывает
разрешение хранимого значения.

Разместить объект и общую семантику путей в узком модуле `bsl-rt`,
дескрипторы подключить к существующей core-библиотеке. Глобальные функции
добавлять через одну таблицу `BuiltinFn`, арности, `host_effect` и штатную
диспетчеризацию. Методы объектов — только через `MethodDescriptor`.
Новые host-методы должны иметь безопасный отказ по умолчанию, чтобы чужая
in-memory ФС не начала неожиданно обращаться к диску процесса.

Атрибут `read_only` в FileMetadata необязателен, старые конструкторы
сохраняют None. `set_read_only` по умолчанию возвращает Unsupported.
Unix-адаптер снимает 0200 при установке и добавляет только 0200 при снятии:
снятие атрибута не должно открывать запись группе и остальным. Это явная
политика системного host, уточнённая замером file-attributes.platform.txt:
0660 -> 0460, 0777 -> 0577; getter в этих случаях возвращает Истина.
Атрибут отражает отсутствие записи владельцу, не полный access-check;
другие владельцы и ACL остаются за пределами этого замера.
Подключены GetReadOnly/SetReadOnly и русские имена. Getter перечитывает
host-атрибут; None вызывает исключение. Setter процедурный, преобразование
Булево/числа 1/строки «Ложь» и отказ Неопределено проверены по измерению.
Отдельный преобразователь принимает измеренные Истина/Ложь, True/False,
yes/no и окружающие Unicode-пробелы, но отвергает Да/Нет и U+200B.
Строковая грамматика и порядок отказов измерены. Точный текст ошибки остаётся
общим контрактом диагностики runtime, а не отдельным файловым вопросом.

Невидимость также проходит через host: необязательное поле hidden и
set_hidden с default Unsupported. Только Linux-адаптер сообщает false,
включая `.hidden`, и выполняет setter как проверку существования без
переименования или изменения прав. Это измерено в file-attributes.platform.txt;
другим ОС этот результат не приписывается, пользовательский host может
предоставить собственный изменяемый атрибут.
BSL-члены GetHidden/SetHidden и русские имена подключены к этой границе.
Setter процедурный; неизвестные сведения и неподдерживаемая установка
остаются ловимыми ошибками. Виртуальный host проверен с изменяемой
невидимостью: Linux-константа не зашита в объект Файл.
Содержимое, остальные биты прав и цель символьной ссылки сохраняются.

Новый crate для файловых операций не нужен. `bsl-rt` владеет файловым
host-контрактом, системным адаптером, объектом `Файл`, поиском, масками,
удалением, каталогами и временными именами. `bsl-stream` владеет временным
потоком. `open-bsl` связывает жизненный цикл `State` и вызовов с учётом
ресурсов и callback host; `bsl-cli` предоставляет стандартную очистку.
Контракт запуска размещается на host-границе `bsl-rt`, подключение сервиса —
в `open-bsl`/CLI; compiler/VM отвечают только за выходной аргумент и ожидание.
Полноценный sandbox разрешённых корней не входит в эту серию: ограничения
доступа обеспечивает host, `SystemFileSystem` не объявляется sandbox.

## 3. Поиск, маски, удаление и каталоги

Вынести пригодную основу `bsl-zip::archive::writer::mask_matches` на общий
уровень `bsl-rt` и расширять её по измеренному файловому диалекту. ZIP
продолжает использовать свой измеренный диалект; не включать ему новые
классы символов автоматически. Это один общий механизм, не две копии.
Не переносить ZIP-нормализацию разделителей в файловый API без замера.

Первый шаг — дословный перенос сопоставителя в закрытый модуль `mask`
`bsl-rt` с экспортом `simple_mask_matches` через фасад. Это Rust-helper,
не новый BSL-член; его простой диалект не объявляется диалектом FindFiles.
`split_pattern` остаётся в ZIP. До и после переноса проверяются прежние
ZIP-тесты; новый файловый диалект требует следующих измерений и задач.

Сначала создание и объект пути, затем поиск, затем удаление по маске.
Порядок обхода/результата, обработка ссылок и частичных отказов — по oracle;
не сортировать и не пропускать ошибки для удобства теста. Обход должен иметь
проверки отмены и ресурсные пределы, не допускать бесконечного цикла ссылок.
Пределы open-bsl документировать отдельно от совместимости 1С.
Удаление через host не должно расширять полномочия; не строить команду shell.
Измерение file-delete-masks.platform.txt подтвердило выбор непосредственных
детей и удаление подходящего каталога целиком; непустая маска сохраняет корень,
пустая/Неопределено удаляет сам путь. В file_search выделен общий find_paths:
НайтиФайлы оборачивает пути в объекты, удаление передаёт исходные пути remove_path.
FileDelete использует существующую проверку отмены HostIo между операциями.
Старый call_builtin_files и байт-код с count=1 сохраняются. Нестроковые маски
проходят общий форматировщик `Строка`; точное представление новых типов
принадлежит общему контракту форматирования, а не дублируется файловым API.
Серверный `file-delete-partial-failure` позднее подтвердил отсутствие отката:
оба обычных файла удалены до ошибки на непустом каталоге с правами `000`,
закрытый каталог сохранён. Детерминированный host-контракт дополнительно
останавливает последовательность на первом `remove_path`. Гонки определены
явно: один снимок целей, поздние записи не удаляются, исчезнувшая выбранная
цель завершает вызов ошибкой без повторного перечисления и отката.
Проверку документированного запрета удаления read-only измерить отдельно:
нельзя считать произвольный результат системного удаления доказательством
этого правила. При необходимости добавить сведения/операцию к host-контракту;
текущего `FileMetadata` для проверки атрибута «Только чтение» недостаточно.
Намеренное удаление самой ссылки вместо целевого дерева сохраняется до
отдельного решения с указанием отличия. Проверки безопасного host покрывают
также `..`, абсолютные пути и ссылки в родительских компонентах.

Замер file-delete-links.platform.txt от 2026-09-10 подтвердил отличие:
1С очищает цель каталога-ссылки и оставляет ссылку, а при прямом удалении
оборванной ссылки оставляет её. По точной маске оборванная ссылка удаляется.
Пустая маска для содержащего ссылки дерева может завершиться ошибкой после
частичного удаления. Подробности — file-delete-links-server-2026-09-10.md.
Пользователь выбрал сохранить намеренный no-follow, поэтому измеренное очищение
целевого дерева 1С не воспроизводится. Это зафиксированное защитное отличие, а не
незакрытый вопрос.

## 4. Временные имена, каталог и владение

Нормализацию расширения разместить на уровне BSL, не менять дословный
контракт `FileSystem::temporary_path` незаметно для Rust-потребителей.
BSL добавляет точку перед непустым расширением без начальной точки,
по умолчанию передаёт `.tmp`; пустое расширение остаётся пустым.
В системном адаптере резервируется первый компонент сгенерированного
имени, а не всё имя с суффиксом: `a/b` не требует создания каталога `.a`.
`create_new` отвергает существующий первый компонент, включая ссылку и
каталог; резервирование удаляется до возврата. Дословный host-суффикс
сохраняется. Это не обещание атомарного последующего открытия файла.
Отдельный host-метод возвращает temp-каталог: общий BSL-код не вызывает
`std::env::temp_dir`. Обработка коллизий и пространство имён остаются у host.

`FileSystem::temporary_directory(&self) -> io::Result<String>` имеет
безопасный default `Unsupported`. Стандартный адаптер использует тот же
выбор пути, что и `temporary_path`, но не резервирует имя: проверяет metadata
каталога и возвращает путь без BSL-нормализации разделителей. Эта проверка
не гарантирует возможность записи; её проверяет последующее открытие файла.
Выбор окружения остаётся при каждом обращении, как в `temporary_path`;
замораживание относительного TEMP в момент создания host не добавляется.

Стандартный host выбирает первую непустую переменную `TEMP`, затем `TMP`,
а при отсутствии обеих — системный временный каталог. При некорректном
выбранном пути ошибка возвращается операцией, требующей этого каталога;
не создавать его автоматически и не переключаться молча на другой путь.
Пользовательская ФС сохраняет управление своим временным каталогом.
Момент разрешения относительного env-пути остаётся техническим вопросом
до уточнения host-контракта; предложенная фиксация при создании host
не считается отдельно подтверждённым решением пользователя.

Для открытого временного файла нужна атомарная host-операция, возвращающая
дескриптор и владение очисткой; разрыв между выдачей имени и открытием
недопустим. Уже существующее краткое резервирование имени не решает эту задачу.
Не вводить отдельную генерацию случайных имён поверх существующей.

Учёт файлов ОС отделить от `TempStorageSession`. `State` соответствует
сеансу, каждый `run/exec` — вызову; конец вызова сам по себе не требует
немедленного удаления. Runtime собирает список принадлежащих ему временных
файлов и передаёт его в callback, предоставленный host. Host отвечает
за удаление. CLI вызывает очистку после завершения BSL-программы до выхода
процесса, включая штатно обработанный выход после ошибки BSL.
Ошибка автоматической очистки диагностируется, но не меняет результат BSL;
ошибки явного `УдалитьФайлы` определяются отдельно по измерениям.
После принудительного уничтожения процесса его файлы не очищаются,
в том числе при следующих запусках. Устойчивый реестр аварийных остатков,
восстановительная очистка и внешний демон не входят в контракт.
Эта политика open-bsl не выдаётся за воспроизведение сроков серверной 1С:
платформенные сроки и наблюдаемые отличия фиксируются измерениями отдельно.
Удалять лишь учтённые собственные объекты, не сканировать и очищать весь temp.
Само сохранённое имя не доказывает владение текущим объектом по этому пути:
проверить переименование, подмену файла и ссылку перед отложенной очисткой.
Протокол владения не должен удалять чужую замену первоначального файла.

## 5. Временный файловый поток

Расширить `bsl-stream::StreamData`/существующий backing, сохранив тип
`ФайловыйПоток`. После нативного наблюдения пользователь подтвердил
немедленное создание host-файла — до записи и получения ИмяФайла.
Прежняя модель перехода с памяти на диск по порогу отменена; возможная
буферизация не меняет момент создания. Используется та же host-ФС.
Не подменять результат публичным `ПотокВПамяти`.
Владение cleanup и поведение `Закрыть`/drop определить по отдельным пробам.
Проверить создание файла до записи, сохранность байтов/позиции и отказ
создания при недоступном выбранном временном каталоге.

## 6. Запуск приложения — решение до кода

Реальный запуск — отдельная host-возможность CLI/embedding, не обещающая
серверную совместимость. Стандартный CLI всегда предоставляет возможность
запуска, без дополнительного разрешающего флага. Встраивающее приложение
задаёт сервис через host; отсутствие сервиса приводит к явному отказу.
Файловая виртуализация сама по себе не ограничивает права дочернего процесса.

Выделить сервис запуска в `HostEnv`/host-профиле. `RunApp`
запускает без shell; `КомандаСистемы` в этот этап не включена. Не изобретать
универсальный разбор командной строки по пробелам: проверить кавычки и правила
ОС. Открытие по ассоциации — отдельная операция/возможность; без GUI или
ассоциации нужен явный отказ, не молчаливый «успех».

Четвёртый аргумент `КодВозврата` — отдельная работа compiler/VM: текущие
глобальные builtin получают значения, а не ссылки на переменные вызывающего.
Использовать существующие механизмы ссылочных аргументов там, где применимо;
перед изменением формата/публичного ABI дополнить соответствующие delta.
Проверить локальную/модульную переменную, пропущенный аргумент, ошибку запуска
и тип вызова «процедура». Не подменять выходной аргумент возвращаемым значением.

Ожидание процесса не должно навсегда занять единственный worker. Переиспользовать
имеющийся механизм парковки/host-ожиданий. Отмена BSL-ожидания не завершает
внешнюю программу. Освобождение ресурсов наблюдения и получение статуса
завершившегося процесса обеспечиваются независимо от живого BSL-задания.
Никакой интерпретации shell-метасимволов и передачи секретов в журналы.

## 7. Асинхронность и приёмка

После синхронного ядра — `НайтиФайлыАсинх`, затем клиентские варианты удаления,
создания каталога, temp-каталога, запуска, временного потока и полный набор
асинхронных членов `Файл` по инвентаризации Unica в согласованном
контексте. Переиспользовать VM promises, `PendingHostCall` и планировщик,
не городить второй event loop. Различать `Обещание<Строка>` создания каталога
и `Обещание<Неопределено>` удаления. Возможность suspending-глобальных
функций проверить до выбора ABI; текущий suspending-дескриптор относится к методам.

Для каждого этапа: измеритель → сохранённый oracle → падающий тест → реализация
→ одинаковое BSL-поведение plain/optimize/байткод. Регрессии ZIP, потоков,
Connector, виртуальной ФС и фоновых заданий обязательны. Производительность
не заявлять без чередующегося A/B. Перед закрытием: fmt, Clippy, workspace
tests, rustdoc, реестр измерений, генератор API, строгий OpenSpec; затем review,
перенос delta и архивирование. План не считать реализованным после одного
поиска файлов или одного успешного процесса.
