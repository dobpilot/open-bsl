# Проектирование

## Решение

JIT удаляется целиком, включая платформенную реализацию и заглушку для других
архитектур. `ProgramExecution` всегда исполняет байт-код интерпретатором,
поэтому больше не хранит таблицы нативных чанков и всегда может сцеплять
линейные бандлы.

Параметр `JitMode` удаляется из всех входов `bsl-vm`. Фасад `open-bsl` больше
не хранит флаг в состоянии и не предоставляет `StateBuilder::jit`. Это лучше,
чем оставить игнорируемый параметр: такой API обещал бы режим, которого нет.

CLI удаляет строку `--jit` из единственной таблицы команд. Неизвестный ключ
должен завершать запуск ошибкой. В benchmark второй прогон того же release-
бинарника выполняется с голым `--optimize`, то есть со всеми доступными
проходами, и сохраняет отдельный результат тяжёлых сценариев для побайтной
проверки.

## Проверки

- тест CLI подтверждает, что `--jit` больше не принят и отсутствует в help;
- полный conformance-корпус сравнивает обычный прогон с `--optimize`;
- тесты VM и фасада проходят без оси JIT;
- поиск по актуальному коду и документации не находит публичного JIT;
- полный benchmark заново заполняет столбец `bsl-cli --optimize`.

Исторические документы в `docs/archive`, архивные OpenSpec changes и отчёты
измерений не переписываются.
