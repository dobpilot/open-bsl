# Удалить JIT и сравнивать оптимизатор в benchmark

## Зачем

Экспериментальный JIT дублирует часть исполнительного контура, усложняет
публичные API `bsl-vm` и `open-bsl` и при этом поддерживает не весь байт-код.
Для измерения работы самого проекта полезнее сравнивать обычную компиляцию
байт-кода с уже существующим набором проходов `--optimize`.

## Что меняется

- из `bsl-vm` удаляется компиляция байт-кода в машинный код и тип `JitMode`;
- из `open-bsl` удаляется настройка `StateBuilder::jit`;
- `bsl-cli` перестаёт принимать и документировать `--jit`;
- второй столбец `benchmarks/run.sh` запускает `bsl-cli --optimize`;
- актуальные спецификации и документация описывают единственный
  интерпретирующий исполнительный контур.

## Совместимость

Это намеренно несовместимое изменение публичного Rust API и CLI. Семантика
BSL и формат байт-кода не меняются. `--optimize` остаётся явным модификатором
компиляции и не становится режимом исполнения VM.
