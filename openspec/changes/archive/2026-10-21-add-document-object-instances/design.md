# Design

## Explicit number assignment
The acquired numbering scope is a separate optional ORM descriptor from the existing type/length settings, preserving source compatibility of their struct literals. Project the SDK periodicity enum explicitly across the adapter boundary and retain an optional configuration object ID for the numerator. The outer Option represents unknown scope; the numerator Option inside known settings represents an explicitly empty reference. Keep SDK Guid and database types out of ORM-facing callers. This metadata projection enables adapter design but does not itself implement reservations.
The single-parameter event is also separately measured with a String-number document: cancellation and Number assignment succeed for both calls, including P-. Consequently the compiled one-parameter shape is supported for both measured number types, not restricted to Number.
The numeric event is separately measured with a single standard-processing parameter: both calls (including String prefix P-) retain the handler-assigned Number 42, with two event deliveries. Build its call arguments from the compiled parameter count; the measured numeric one-parameter handler receives only the Boolean flag. Its lack of a prefix parameter must not become a VM arity error.
Native probes now preserve eighteen observations for explicit numbering: repeated calls before writes, cancellation and prefix replacement, Year scope with NumberLength 11, and rejection during module initialization. The Year probe was repeated after process termination in the same native database with identical output; concurrent sessions and stored documents remain unverified. Installed Russian syntax help 8.3.27.2342 documents the method and its event; stable document locators are retained in document-new-number-native.md.

Reuse call_configuration_instance_handler and its final parameter values, as Fill already does. Add a narrow DataAccess operation for allocation, receiving MetadataObject, the current principal, BslDate, the final string prefix and CallContext. Its default implementation rejects unsupported allocation, keeping existing adapter implementations source-compatible. The component contains no counter or SQL. Cancellation completes before acquiring an allocator, allowing an original application handler to assign the number itself. Standard allocation returns a Value that is assigned with the existing number setter and qualifier conversion.

The initial implementation must not claim that adapter dispatch completes live allocation. SDK currently lacks acquired periodicity and numerator identity, and no safe interoperable reservation operation is established. Their request is separate from the ongoing section-field and movement-association acquisition. Do not implement a guessed SQL maximum or persist reservation rows in a working infobase. Additional native measurements and an explicit adapter design are required for complete original startup behavior.

## Implementation
Reuse ConfigurationInstance, initialize_configuration_instance and existing runtime property/method dispatch. Each object owns its module variables and receiver; session common modules retain their existing State ownership. Publish the object only after successful initialization; setters and IsNew reject the initializing state. Add a configuration-specific DocumentObject type without reusing CatalogObject identities. Preserve existing same-name manager exports and their original arity to meet additive compatibility.

Metadata must expose known document numbering qualifiers and owned attributes/types. The database source must acquire those from configuration resources, not infer them from physical SQL storage. The SDK currently exposes catalog standard settings but no corresponding document descriptor. Prepare a focused open-sdbl request before depending on absent fields; do not patch the sibling project without the authorized agent workflow. Unknown settings cause explicit acquisition/creation errors, never guessed string defaults.

Fill and further reached object operations require their own native evidence before implementing behavior; their existence is not proof that initialization is complete. Generic table/structure/value adjustment and existing exchange implementations should be reused when their measured contracts match. Creation must not write a database row or manufacture persisted references.

## Owned attribute filling evidence
The native owned-string fixture now establishes post-handler filling: nonempty handler values are preserved, empty fields receive structure values only when FillFromFillingValue permits them, otherwise/missing source fields receive the acquired typed FillValue. ## Owned attribute representation
Reuse facade ColumnType for acquired type constraints and SerializedValueGraph for immutable typed filling values. A descriptor carries stable ID/name, acquired type constraints and separately known/unknown source-filling and filling-default states. MetadataObject keeps an optional complete collection: None is unknown, Some([]) is known empty. Live Rc-backed Values do not enter shared configuration metadata. The graph has PartialEq, so MetadataObject retains PartialEq while dropping Eq; Rust API/ABI compatibility is not required at this development stage. No BSL behavior changes follow solely from this descriptor addition. Acquisition and actual object properties still require implementation and native replay.


## Current string-attribute filling implementation
Concrete documents now retain their own acquired string attribute values. The same VM binds those names in object modules. Fill invokes the measured two/three-parameter private handler on the instance, respects its final StandardProcessing flag, preserves nonempty string values (including a single space), and applies source-field values or the acquired graph filling default to empty fields. Present Undefined/Null source fields differ from absent fields: conversion produces empty strings without replacing them by filling defaults. The measured primitive and catalog-reference extensions are specified below. Other type declarations remain explicit unsupported boundaries; live SDK acquisition and broader typed attributes are unfinished. Existing same-name exported Fill methods retain precedence and arity.

Native `measure-document-fill-replace` establishes that standard filling uses the final FillingData parameter returned by the handler. Keep the original caller structure unchanged when the parameter is reassigned; retain normal shared-structure mutations. Reuse the final parameter vector already returned by the existing VM callback.

The post-correction frozen-source gate passed formatting, workspace Clippy, all workspace tests (335.5 seconds), rustdoc, consumer build, normal core/VM dependency trees and strict validation. Existing regression expectations were unchanged. This proves the current measured implementation, not full startup of the original configurations.

Original UNF compilation next reaches Движения in the ЗаказПокупателя object module. This is a standard context property, not an undeclared application variable. The native empty-document probe establishes eight observations; the subordinate information-register probe establishes thirteen. ## Planned attribute integration boundary
Use the SDK snapshot descriptors after its named-type expansion for document attributes. Re-parsing an individual resource cannot establish the expanded 56-member declaration. Resolve reference type GUIDs through acquired object_reference_type identities, then select the corresponding cached ORM type. Project enumeration filling values only after enumeration members have entered the catalog. Capture filling defaults with the existing value graph and current registered materializers. Preserve unknown declarations and unknown filling values rather than substituting the first member, a name or an empty default. Build these indexes once during factory acquisition, not per Session.

Fixed-length String numbering is exposed as an additive MetadataObject builder flag and getter. Existing DocumentNumberSettings literals retain variable-length String behavior. The document instance pads after existing string conversion/truncation, using UTF-16 length, and applies the same rule at initialization. The SDK adapter preserves its acquired allowed-length flag.

Attribute assembly consumes the catalog through an additive owner-bound builder. It preserves its immutable reference declarations and other configuration properties. The adapter constructs a temporary registered engine only while capturing typed filling defaults; graphs contain type identities and bytes, not the temporary engine or connections. Catalog and type indexes are built once during acquisition. Unresolved declarations are retained as unsupported attribute types, not dropped from the owned collection.
