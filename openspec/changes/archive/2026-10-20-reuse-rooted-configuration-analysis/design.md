# Design

## Phase measurements first
OPEN_BSL_STARTUP_TIMINGS=1 enables tab-separated stderr records `open-bsl.startup<TAB>stage<TAB>elapsed_seconds`. Other values leave output unchanged. CLI stages include acquisition, decoding, access preparation, factory creation, resources, session opening and entry execution. Nested engine stages cover export surfaces, dependency selection, parsing/resolution when applicable, code generation, verification and background image preparation. Parent phases include child durations and must not be summed with them. No secrets, SQL or source text are emitted. The internal façade reporter and CLI reporter only format std::time::Instant durations; no RT/VM dependency or public tracing API is introduced.

Build a timing-only baseline before changing compilation. Preserve its binary, source hashes, guarded run and phase records. Timing calls remain outside VM instruction dispatch.

## Reuse without retaining all syntax
Keep the existing export-surface scan: parse each module, extract declarations, discard its AST. Parse each reached body once during dependency discovery, resolve it, extract dependencies and immediately clear its full import vector. Retain its resolved body for compilation. If pruning removes a visible module, recheck bodies carrying synthesized deferred errors against the final environment: an arity failure may have interrupted dependency registration, and the previous second pass then reported an unknown name instead. Keep this exceptional recheck so diagnostics remain identical. If this recheck fails, retain the original precedence of import-cycle validation over the second semantic pass; the additional cycle check runs only on that failure path. Thus a normal selected body has two parses with distinct purposes and one semantic pass, rather than three parses and two semantic passes; the deferred-error exceptions above retain the necessary final-environment recheck. Avoid caching all unselected ASTs or introducing a second header parser.

Component-access hints only append deferred dependencies; they do not alter the resolved field expression. Their empty aliases must not enter final bytecode imports. Construct final imports from the selected recipe using the same alias-selection helper as semantic imports, preserving self omission, global flags, explicit shadowing and conflict errors. Keep common import backing storage shared.

The original-to-selected mapping changes only module IDs in bytecode Function/Variable links and GetImportedModule operands; link slots, function chunks, variable slots, expression evaluation order, debug lines, names and shapes remain unchanged. Recompute derived bytecode tables after remapping and run the normal image verifier. A missing remap target is an internal configuration error, never a silent fallback. Preserve explicit-import cycle checks and deterministic recipe order.

The non-rooted compilation path stays available as an independent equivalence oracle. New tests compare whole serialized catalogs for an explicitly pruned fixture, including removed leading/interleaved modules, variable links, module-valued expressions, aliases, global exports and component-property dependency hints. Existing regression tests exercise inaccessible modules, deferred name errors, dynamic imports, receivers and initialization ordering.

## Validation and scope
This is representation/work reuse, not a new platform-semantic decision; no new unmeasured-platform marker applies. Full existing tests, optimization-corpus equivalence, consumer build, formatting, Clippy, rustdoc and unchanged RT/VM dependency trees remain required. Original BUH runs use one CLI at a time, READ ONLY database access, readonly filesystem, 10 GiB address space, 8 GiB RSS stop, 3 GiB minimum available host RAM and 1800-second timeout. Compare alternating timing-baseline/candidate runs, retaining all artifacts. No persistent configuration cache, lazy body compilation, visibility change or unrelated API implementation is part of this change.
