# Change: Подготавливать места вызова до запуска VM

## Why

Горячий путь `CallObjectMethod`/`CallObjectProcedure` повторяет
разрешение неизменяемых метаданных и проверки дескриптора.
На benchmark `json_write`, `xml_parse` и `xml_write` этот вызов исполняется
миллионы раз, а профиль показывает рост доли VM-dispatch.

## What Changes

- При создании состояния запуска VM строит по одной записи
  подготовленных метаданных на каждую инструкцию.
- Открытый вызов берёт количество аргументов, классификацию
  имени и признак выходного аргумента из этой записи.
- Мономорфный кэш метода хранит план, уже прошедший
  проверку арности и допустимости результата.

## Impact

- Затронуты `bsl-vm` и спецификация исполнительного контура.
- Публичный Rust/BSL API и текстовый формат байткода не меняются.
- Ошибки образа по-прежнему отвергаются до первой инструкции.
