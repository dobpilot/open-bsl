# Задачи

## Реализация

- [x] Добавить переносимый результат атомарного создания без требования Send к прежнему host API. TransferableTemporaryFile и отдельная операция FileSystem проверены через background_access и реальный worker; default Unsupported, регистрация/отказ закрытого реестра и Drop сохраняют владение без удаления. Прежние Rc-дескрипторы совместимы. Отчёт — docs/research/compatibility/temporary-file-transferable-2026-09-17.md. Это предпосылка CreateTempFileAsync, не его завершение.
- [x] Уточнить доставку позднего результата CreateTempFileAsync при закрытии State. Решение 2026-09-18: штатное закрытие `State`/CLI ждёт уже начатую операцию, регистрирует её право до закрытия реестра и передаёт callback. Прочие host-операции и аварийное завершение не расширяются.

- [x] Подключить синхронное создание временного потока к поддерживающему host: исходные FileSystem/Random/Registry, передача открытого дескриптора без повторного открытия, проверка возможностей до I/O. Семь интеграционных тестов покрывают 70 измеренных вызовов, plain/optimize, source/bytecode, dynamic, чужой/закрытый сеанс, прежний конструктор, ошибку BSL и нарушения host-контракта. Это не системная реализация и не закрытие общего пункта CreateTempFile.
- [x] Измерить ИмяФайла/FileName обычного потока: пять абсолютных форм пути, readonly, сохранение после закрытия, отсутствие у потока в памяти. Нативные восемь строк и conformance-копии сохранены; CF/БД восстановлены и XML сверены. Отчёт: docs/research/compatibility/temporary-stream-host-2026-09-17.md.
- [x] Измерить оба параметра CreateTempFile в RU/EN: 70 вызовов, 32 успеха и 38 отказов. Проверить имя после закрытия и существование носителя; сохранить oracle и восстановление CF/БД/XML. Отчёт: docs/research/compatibility/file-temp-parameters-server-2026-09-17.md.
- [x] Уточнить видимость записи на размерах 1, 8, 8191, 8192, 8193 для шести настроек: 30 совпадений длины/данных исходного потока, 30 отказов независимого чтения с File shared access error, шесть успешных чтений после закрытия. Две первоначальные и уточняющие пары сохранены; CF/БД/XML восстановлены в обоих сеансах. Это не измерение внутреннего размера буфера и не реализация.
- [x] Подключить измеренные правила совместного доступа временного потока в стандартном Linux-host: учёт открытого носителя по device/inode, отказ независимому BSL-чтению до Закрыть и доступ после него. Subprocess-тест проверяет размеры 1/8/8191/8192/8193, исходный дескриптор, background_access, отдельные носители, hard link/rename/подмену и восемь сочетаний plain/optimize, direct/dynamic, source/bytecode. Произвольный embedding-host и другие ОС не подменяются. Отчёт — docs/research/compatibility/file-temp-async-and-sharing-2026-09-17.md.
  - [x] Измерить hard link/rename/подмену на localhost/test: семь наблюдений, CF/БД/XML восстановлены. На Linux учесть открытые системные временные носители по device/inode и проверять независимое FileSystem::read по его дескриптору. Красный/зелёный subprocess-тест покрывает размеры 1/8/8191/8192/8193, фоновой адаптер, отдельные файлы, отсутствие удаления и восемь режимов ДвоичныеДанные до/после освобождения. Сквозной BSL CreateTempFile стандартного host всё ещё требует безопасного права очистки.
- [x] Измерить CreateTempFileAsync на клиенте серверной localhost/test: 32 успеха с тождеством потока при повторном Ждать до/после Close, 36 ошибок параметров при Ждать и два отказа арности без обещания. Oracle из 72 строк и тест полноты сохранены; CF/БД/XML восстановлены. Delta добавлена; runtime Async этим этапом не реализован. Отчёт: docs/research/compatibility/file-temp-async-and-sharing-2026-09-17.md.
- [x] Реализовать CreateTempFileAsync через переносимую host-операцию: worker не получает `Rc`-реестр, а локальный mapper передаёт исходное право очистки и дескриптор в `ФайловыйПоток` без повторного открытия. Все 70 измеренных RU/EN-случаев проверены в plain/optimize и source/bytecode; повторное ожидание сохраняет объект/ошибку, задержанный host не блокирует соседнюю async-задачу. При штатном освобождении execution результат уже начатой операции дожидается и регистрируется до `State::drop`.
- [x] Уточнить границу доверия same-UID для системной очистки. Решение 2026-09-18: доверять процессам того же Unix UID и включить Linux-ресурс; пара inode-check/unlink по-прежнему не объявляется защитой от конкурентной same-UID подмены.
  - [x] Подготовить и после решения о same-UID опубликовать системный Linux-ресурс: атомарный create_new 0600, сохранённые device/inode, отказ удалять подмену и переносимый Send-носитель проверены тестами. `SystemFileSystem::supports_temporary_file_ownership` равен true только на Linux; BSL и CLI используют этот ресурс.

- [x] Добавить нейтральный сеансовый учёт и host-callback: TemporaryFileResource/Registry в bsl-rt, явная очистка и Drop State в open-bsl. Шесть виртуальных host-тестов проверяют пакеты между exec, изоляцию, подмену/переименование, возврат позднего ресурса, отсутствие повторной очистки, повторный вход в учёт и диагностику после ошибки BSL. Системный токен, привязка к атомарному созданию/потоку и стандартный callback CLI этим этапом не реализованы.

- [x] Подтвердить УстановитьРазмер/SetSize на серверной 1С: 20 проверок имён и 130 проб аргументов/состояния. Сохранены stream-resize-methods.* и stream-resize-values.*, оба CF/XML восстановлены и сверены. Выявлено особое поведение потока над буфером: 0 не сокращает, а сокращение до 2 при позиции 5 меняет размер/позицию до ошибки.
- [x] Уточнить связь буферного потока с исходным буфером в 60 последовательных пробах; реализовать SetSize через существующий BufSlice, собственный Vec и FileHandle::set_len. Все 190 проб совпали; добавлены две conformance-фикстуры, unit-тесты отказа выделения и разделяемого диапазона. Процедура в выражении отвергается до мутации. Ещё 18 серверных проб закрыли пустой буфер и reader-прокси; STREAM.RESIZE_EDGES сохраняет только предельные размеры, прочие аргументы и точные ошибки.

- [x] Добавить FileHandle::set_len для открытого носителя: default Unsupported без I/O, системное сокращение/расширение без изменения позиции, нулевые новые байты, отказ read-only дескриптору без изменения файла. Три host-теста прошли; это независимая предпосылка изменения размера потока, не реализация BSL-метода и не выбор модели временного носителя.

- [x] Добавить атомарное создание открытого временного файла; create_temporary_file/OpenedTemporaryFile, Unsupported без I/O, восемь env-сценариев, сохранность данных при коллизии и отказ подмене симлинком. Это не закрывает идентификацию ресурса при последующей очистке.

Пять host-тестов проверяют сохранность данных/позиции, повторную регистрацию в другом сеансе, прежние new/into_parts и отсутствие удаления при Drop. SystemFileSystem пока не предоставляет право очистки; системный токен и подключение потока остаются открытыми.
- [x] Согласовать немедленное создание host-файла по нативному наблюдению; заменить прежнюю модель перехода на диск в delta и дизайне.
