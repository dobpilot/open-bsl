# Инлайн-кэши переезжают из `Chunk` в состояние запуска

## Зачем

`Chunk` — носитель скомпилированного кода, и всё в нём иммутабельно, кроме
двух полей: `prop_cache` и `method_cache` — векторы `RefCell`-ячеек,
которые VM мутирует во время исполнения через `&Program`. Из-за них:

- иммутабельный по смыслу образ несёт мутабельное состояние, и граница
  «код отдельно — состояние исполнения отдельно» проходит не по типам, а
  по соглашению;
- `image::finalize` обязан СБРАСЫВАТЬ прогретые ячейки (кэш не помнит имя
  поля и после правки инструкций врал бы), а `image::verify` — проверять
  «ячейка на инструкцию»; оба правила существуют только потому, что кэш
  лежит не там, где живёт;
- `Program` нельзя разделить между прогонами без оглядки: прогретые ячейки
  одного прогона видны следующему.

Августовский запрет на этот вынос («+53 % тактов на `empty_for`»)
перепроверен 4 сентября 2026 года и не подтвердился: величина была
артефактом раскладки, снятым сценарием, который кэши не читает ни разу.
Настоящая измеренная цена — ~1 % инструкций там, где кэши работают, и до
+3,17 % на диспетчер-плотном `call_overhead` (см.
[`vm-code-layout.md`](../../../docs/architecture/vm-code-layout.md),
разделы перепроверок). Владелец проекта решил принять её: чистая
архитектура важнее 1–3 %. Это изменение — стадия 1 плана
[`bsl-vm-refactor.md`](../../../docs/plans/bsl-vm-refactor.md).

## Что меняется

- Поля `prop_cache`/`method_cache`, методы `Chunk::prop_cache()`/
  `Chunk::method_cache()` и типы ячеек уходят из `bsl-bytecode`. `Chunk`
  становится чистым иммутабельным носителем кода.
- Ячейки заводит прогон: структура `RunCaches` во владении
  `ProgramExecution` — по вектору ячеек на чанк, адресация `(func_id, pc)`.
  Кэши каталожных модулей заводятся при подключении каталога; программа
  динамического фрагмента получает собственные ячейки при каждом запуске.
- Интерпретатор и JIT греют ОДНИ И ТЕ ЖЕ ячейки: `JitCtx` получает
  указатель на `RunCaches`, шимы свойств и открытого метода читают ячейку
  оттуда же, откуда ветка интерпретатора.
- `image::finalize` перестаёт заводить и сбрасывать ячейки, `image::verify`
  перестаёт проверять их длину: инвариант «ячейка на инструкцию»
  обеспечивается конструктором `RunCaches` по построению и становится
  непредставимым для нарушения снаружи.
- Свежий прогон стартует с холодным кэшем: прогрев одного прогона другому
  не виден.

## Вне границ

- **Стадии 2–7 плана** (вынос холодных кластеров `bsl-vm` в модули) —
  внутренние рефакторы без наблюдаемого контракта, OpenSpec-заявки не
  требуют и идут отдельными коммитами по плану.
- **Текстовый формат и `FORMAT_VERSION`** не меняются: кэши никогда не
  сериализовались.
- **Поведение BSL-программ** не меняется ни в одной наблюдаемой точке;
  сверка JIT/интерпретатор и конформанс-корпус обязаны пройти без правок
  ожиданий.
- **Генерируемый справочник BSL API** не задет: меняется Rust-API
  `bsl-bytecode`, а не поверхность языка.
