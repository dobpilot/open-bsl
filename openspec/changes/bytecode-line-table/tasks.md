# Задачи

## 1. Проверка до реализации

- [ ] 1.1 Тест: у скомпилированной со сведениями об отладке программы
  строка каждой инструкции попадает в диапазон строк исходника.
- [ ] 1.2 Тест: без запроса сведений образ совпадает с прежним
  ПОБАЙТОВО на всём корпусе фикстур (печать листинга сравнивается с
  выводом до изменения).
- [ ] 1.3 Тест: таблица длиной не с инструкции отвергается периметром до
  первой инструкции; зубы подтверждаются отключением проверки.

## 2. Позиции во фронтенде

- [ ] 2.1 Оператор AST несёт span первого своего токена.
- [ ] 2.2 Span доходит до `bsl-sema` и до кодогенератора, не меняя
  снимков парсера иначе, чем добавленным полем (снимки `insta`
  пересматриваются осознанно, а не принимаются ради зелёного прогона).
- [ ] 2.3 Перевод смещения в номер строки — один источник, не копия в
  каждом потребителе.

## 3. Таблица в образе

- [ ] 3.1 `Program::lines` и наблюдатель к ней; в `Chunk` поля не
  добавляются.
- [ ] 3.2 Кодогенератор заполняет таблицу, когда сведения запрошены.
- [ ] 3.3 `Chunk::local_names` заполняется у всех чанков при сведениях об
  отладке и по-прежнему только у `uses_dynamic` без них.
- [ ] 3.4 Запрос сведений — параметр сборки в `bsl-compiler` и в фасаде
  `open-bsl`.

## 4. Формат и периметр

- [ ] 4.1 Печать и разбор таблицы; `FORMAT_VERSION` 28 -> 29.
- [ ] 4.2 Круговой текстовый корпус проходит в обе стороны и с таблицей,
  и без неё.
- [ ] 4.3 Периметр отвергает таблицу, длина которой не равна числу
  инструкций чанка, и номер чанка вне таблицы функций.

## 5. Ворота

- [ ] 5.1 `./benchmarks/hot-code-diff.sh <база>`: `step` и `step_cold`
  побайтово те же. Не пройдёт — таблица стоит не там, где решено.
- [ ] 5.2 Сверка JIT с интерпретатором на всём корпусе.
- [ ] 5.3 `cargo fmt`, `clippy -D warnings`, rustdoc, полный workspace.
- [ ] 5.4 Рост образа измерен на корпусе: во сколько раз растёт листинг
  и `.bslc` со сведениями об отладке. Число записывается сюда, а не
  оценивается на глаз.
