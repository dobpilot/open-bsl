# Proposal

## Why

`docs/reference/bsl-api/api.md` перечисляет имена и арности, но не говорит, что делает функция или объект и где лежит её реализация. Читателю приходится искать это в коде вручную, а арность без описания параметров мало что объясняет.

## What Changes

- **BREAKING (формат справочника):** из таблиц `api.md` убирается колонка «Аргументы».
- В строки функций, конструкторов, типов, методов и свойств добавляются колонки «Описание» и «Реализация». Описание — первое предложение doc-комментария реализации, ссылка — путь `crate/src/file.rs` к файлу реализации относительно `crates/`.
- Генератор берёт описание и файл из исходников workspace, находя строку дескриптора по его именам. Имена, псевдонимы, состав типов, методов и свойств по-прежнему берутся только из runtime-дескрипторов.
- Если исходники workspace недоступны, команда завершается ошибкой, а не выпускает справочник без описаний.

### Modified Capabilities
- `bsl-api-reference`: справочник перестаёт печатать арность и получает описание и ссылку на файл реализации из исходников.

## Impact

- `crates/bsl-cli/src/api_reference.rs` — генератор и его тесты.
- `docs/reference/bsl-api/api.md` — перегенерированный снимок; `docs/reference/bsl-api/README.md` — правила обновления.
- Снимок начинает зависеть от doc-комментариев реализаций: правка такого комментария требует перегенерации, и это проверяет существующий тест равенства снимка.
