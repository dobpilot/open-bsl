# Design

## Context

Дескрипторы API (`FunctionDescriptor`, `ConstructorDescriptor`, `MethodDescriptor`, `PropertyDescriptor`, `TypeDescriptor`) несут имена, арность и указатель на функцию, но ни описания, ни места в исходниках. Почти все они записаны литералами структур с открытыми полями — около 1200 мест в крейтах компонентов.

## Goals / Non-Goals

**Goals:** описание и файл реализации в каждой строке справочника без второй таблицы API и без правки всех строк дескрипторов.

**Non-Goals:** писать недостающие doc-комментарии; ссылаться на строку файла; описывать параметры.

## Decisions

- **Исходники читаются при генерации.** Генератор находит корень workspace по `CARGO_MANIFEST_DIR` крейта `bsl-cli` и разбирает `crates/*/src/**/*.rs`, кроме тестовых модулей (`tests.rs`, `*_tests.rs`). Альтернатива — поле с `Location::caller()` в дескрипторах — работает в `const fn` на стабильном Rust, но требует правки всех литералов; поле описания в дескрипторе дублировало бы rustdoc.
- **Строка дескриптора находится по именам.** Ключ строки — её массив имён (`&["Имя", "Name"]`). Кандидаты ищутся сначала в крейте компонента. Если одинаковый ключ встречается в нескольких таблицах (`Количество` у многих типов), выбирается кандидат, в чьём статическом срезе больше других имён той же таблицы дескриптора. Типы находятся по `name` литерала или `TypeDescriptor::new`.
- **Реализация — функция строки.** Из строки берётся идентификатор вызываемой функции (`call: Some(f)`, `get: f`, последний аргумент `MethodDescriptor::…(…, f)`), затем её определение `fn f` — в том же файле, иначе в том же крейте. Ссылка указывает на файл определения; если функция не найдена или имени нет (объявлено без реализации), — на файл строки дескриптора.
- **Описание — первое предложение doc-комментария** функции-реализации, иначе строки дескриптора, иначе определения типа; для встроенных функций и методов — варианта `BuiltinFn`/`BuiltinMethod`. Ссылки rustdoc сводятся к тексту, `|` экранируется. Нет комментария — прочерк.
- **Встроенные методы** ссылаются на `bsl-rt/src/builtin.rs`: их реализация разнесена по типам получателей, и одной функции у метода нет.
- **Без исходников генерации нет.** Иначе тот же бинарник выдавал бы разный справочник в зависимости от того, где запущен.

## Risks / Trade-offs

- [Снимок меняется от правки doc-комментария реализации] → это и есть цель; тест равенства снимка напоминает о перегенерации.
- [Эвристика выбора кандидата ошибается на переиспользованных строках] → кандидаты с одинаковой реализацией дают один ответ; оставшиеся неоднозначности видны в diff снимка и правятся там, где их видно.
