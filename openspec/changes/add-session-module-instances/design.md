# Design

State owns root instance memory and one SessionModules catalog for explicit instances. Module remains immutable compiled code. The facade API is State::instantiate(&Module) -> Result<ModuleInstance, Error>, and ModuleInstance::call(&mut State, name, Vec<Value>) -> Result<(Value, Vec<Value>), Error>. The handle carries session identity and an instance index; no VM program is exposed. Reacquiring a cloned Module in one State returns the same instance. A failed root initialization is not published; retry is an explicit new acquisition and repeats the body, without undoing host or common-module effects.

Reuse ProgramExecution and its scheduler, transferring root memory and the common-module session into each execution and returning them on both success and error. Execution caches and task/promise tokens remain per execution; module memory and identity persist. Exact argument count deliberately excludes omitted/default arguments in this host API. Calling an async export runs its body to completion as the host entry; nested async operations use the existing scheduler. Common-module lazy initialization policy remains unchanged. State::run/start keep isolated catalogs as before. Host API lifetime choices do not claim new 1C semantics. Do not introduce a second interpreter or modify the bytecode format.

Explicit instances accept modules compiled or loaded by the same Engine and configuration (Engine clones are accepted). Weak owner identities prevent per-engine module identifier collisions and accidentally binding a foreign configuration catalog; the existing portable run path is unchanged.
