# Подключение модулей: `//@используй` в bsl-cli и линкующий ABI фасада

> **Статус: план принят по итогам интервью 26.08.2026, работы НЕ НАЧАТЫ.**
> Все развилки закрыты в диалоге (семнадцать вопросов, три раунда); четыре решения,
> всплывшие уже при написании плана, вынесены в раздел «Решения, принятые в плане» —
> они ждут подтверждения либо возражения, остальное зафиксировано.
>
> Проверено против кода этой ревизии: сигнатуры конвейера (`parse_with_symbols` →
> `resolve_program_with_registry` → `compile_program`), устройство `Program`
> (один плоский список чанков, `function_names[i]` ↔ `chunks[i+1]`), `ModuleState`
> как отдельное хранилище размером `module_vars.len()`, путь `GetModuleVar`/
> `AssignModuleVar`/`ArgMode::ByRefModuleVar` из непервых чанков, нерекурсивный
> обход фикстур конформанс-раннером, субпроцессный прогон
> `the_jit_agrees_with_the_interpreter_on_every_script`, механика `@prepend-bsl`
> в `run.sh` и сплайс объявлений в `build-combined.py`.

## Цель

Скрипт, исполняемый bsl-cli, подключает другой файл BSL как модуль под псевдонимом
и зовёт его экспорты только квалифицированно:

```bsl
//@используй(../crates/open-bsl/tests/fixtures/connector-http-2.6.0.bsl как КоннекторХТТП)

Ответ = КоннекторХТТП.Get("https://www.cbr-xml-daily.ru/daily_json.js");
Документ = КоннекторХТТП.КакJson(Ответ);
```

Проблема отражена в `benchmarks/cbr_rates.bsl`: сегодня Connector 2.6.0 подключается
текстовой склейкой `// @prepend-bsl` в `run.sh`, экспорты зовутся неквалифицированно,
у engine нет ни файлового API, ни понятия «второй модуль». Целевое состояние —
`cbr_rates.bsl` с шапкой `//@используй(...)`, склейка на пенсии.

Граница ответственности — решение владельца проекта: **директива `//@use`/`//@используй`
— фича bsl-cli** (разбор синтаксиса, файловая система, пути, циклы, дедуп), а
**open-bsl предоставляет функциональный ABI** — компиляцию набора модулей с
псевдонимами в один `Module`. Engine текста директивы не видит никогда.

## Принятые решения (сводка интервью)

1. **Механизм** — статическая линковка до кодогенерации: sema резолвит
   `Псевдоним.Имя(...)` по таблице экспортов в прямой вызов по индексу чанка,
   арность проверяется статически, опечатка — ошибка компиляции. Слияние уже
   скомпилированных `Program` отвергнуто: пришлось бы перенумеровывать индексы
   чанков, имён и шейпов.
2. **Синтаксис.** Формы `//@use(путь as Псевдоним)` и `//@используй(путь как Псевдоним)`
   равноправны (как русские/английские имена в `BUILTIN_FN_NAMES`). Кавычки вокруг
   пути опциональны (`'...'`, `"..."` или без: путь — всё до ` as `/` как `). Путь —
   относительно каталога импортирующего файла. Директивы допустимы только в шапке,
   до первого оператора или объявления. Несколько директив — можно.
3. **Только квалифицированные вызовы.** Экспорты в глобальное пространство не
   сливаются; `cbr_rates.bsl` переписывается на `КоннекторХТТП.*`.
4. **Семантика модуля.** Приватные `Перем` — поддержаны; `Перем Х Экспорт` —
   поддержана, `Псевдоним.Х` читается И присваивается; тело модуля выполняется
   один раз до верхнего уровня главного скрипта, порядок — пост-порядок обхода
   в глубину (зависимости раньше зависимых, в порядке следования директив),
   каждый модуль ровно один раз.
5. **Вложенность.** `//@используй` внутри импортируемого модуля разрешён; цикл
   импортов — ошибка компиляции; один файл, достижимый по разным путям, — один
   экземпляр (дедуп по каноническому пути): одна инициализация, одно состояние.
6. **`Выполнить`/`Вычислить` и REPL** — не поддержаны (см. «Чего не делаем»).
7. **Ошибки директивы** — все три случая ошибка компиляции с путём и позицией:
   файл не найден; директива синтаксически кривая; директива ниже шапки. Строка,
   начинающаяся с `//@use(` или `//@используй(`, либо валидна и стоит в шапке,
   либо валит компиляцию — молчаливого «это просто комментарий» нет.
8. **Листинг байткода** — имена функций подключённых модулей квалифицируются:
   `КоннекторХТТП.КакJson`.
9. **Бенчмарк.** `cbr_rates.bsl` переводится на директиву; механизм `@prepend-bsl`
   удаляется из `run.sh` полностью (им пользовался только этот сценарий). Колонка
   1С остаётся через `build-combined.py`. Колонка oscript — новый близнец
   `benchmarks/cbr_rates.os` с нативным `#Использовать connector` (библиотека
   ставится из исходников <https://github.com/vbondarevsky/1connector> —
   `opm install connector` из хаба не работает, ставить клонированный репозиторий
   через `opm install -s`; сегодня колонка и так в ошибке — фикстура 1С-версии
   Connector не компилируется oscript из-за `ФабрикаXDTO`, проверено запуском).
   Версия oscript-порта может отличаться от 2.6.0 — близнец обязан давать
   байт-идентичный результат, «тот же наблюдаемый ответ», как lua-близнец с
   vendored slaxml.

## Целевые сигнатуры

### open-bsl: линкующий вход фасада

```rust
/// Единица линкуемой компиляции. `imports` — рёбра «псевдоним → индекс
/// более ранней единицы» в `units`; ссылаться можно только назад, поэтому
/// цикл в этой структуре невыразим. Главный скрипт — отдельный параметр.
pub struct LinkedUnit<'a> {
    pub source: &'a str,
    pub imports: &'a [(&'a str, usize)],
}

impl Engine {
    /// `units` — подключаемые модули в топологическом порядке (пост-порядок
    /// обхода вглубь, как их выстроил вызывающий), `main_imports` — рёбра
    /// главного скрипта. `compile(src)` эквивалентен пустому списку единиц.
    pub fn compile_linked(
        &self,
        units: &[LinkedUnit<'_>],
        main_source: &str,
        main_imports: &[(&str, usize)],
    ) -> Result<Module, Error>
}
```

Валидация в фасаде: индекс ребра меньше номера своей единицы; псевдонимы одного
импортёра не повторяются. Дедуп, канонизация путей и обнаружение циклов — забота
вызывающего (bsl-cli); фасад про файлы не знает по-прежнему ничего.

Конвейер внутри `compile_linked`: распарсить все единицы и главный скрипт с
`preproc_symbols`; посчитать по AST базы (число функций и число модульных `Перем`
каждой единицы — до всякого резолва); отрезолвить единицы в порядке списка, затем
главный скрипт; скомпилировать всё в один `Program` одним вызовом компилятора.

### bsl-sema: экспорты и режим библиотеки

```rust
/// Экспорты отрезолвленного модуля с уже ГЛОБАЛЬНЫМИ индексами слитой
/// программы: функции — индекс чанка + сигнатура для статической арности,
/// переменные — номер слота в общей таблице `module_vars`.
pub struct ModuleExports { /* функции: имя(upper) → (индекс, FuncSig-подобное);
                              переменные: имя(upper) → слот */ }

/// Режим библиотеки: тело модуля резолвится как обычная процедура —
/// обращения к своим модульным переменным идут через `RExpr::ModuleVar`
/// (путь, которым функции пользуются уже сегодня), инвариант «первые слоты
/// top_level.locals» на библиотеку не распространяется.
pub fn resolve_library_module_with_registry(
    items: &[Item],
    registry: &bsl_rt::RuntimeRegistry,
    imports: &[(String, &ModuleExports)],
    func_base: usize,
    var_base: usize,
) -> Result<(ResolvedProgram, ModuleExports), SemaError>;

pub fn resolve_program_with_imports(
    items: &[Item],
    registry: &bsl_rt::RuntimeRegistry,
    imports: &[(String, &ModuleExports)],
) -> Result<ResolvedProgram, SemaError>;
```

Точка врезки одна и проверена: `Псевдоним.Имя(...)` сегодня падает в
`resolve_expr` на базовом имени как `UndefinedVariable` («переменная читается до
присваивания») — понятия «псевдоним модуля» не существует. Новая ветка в
`AExpr::Field`-путях (вызов и доступ к полю): если база — не локальная, не
модульная переменная и есть в таблице импортов, это межмодульное обращение.
Вызов неэкспортной функции, неизвестное имя за точкой, неверная арность —
отдельные варианты `SemaError` с именем модуля и имени.

### bsl-compiler: слитая программа

```rust
pub fn compile_linked_program(
    libraries: &[&ResolvedProgram],
    main: &ResolvedProgram,
) -> Result<Program, CompileError>;
```

Раскладка единственного `Program` (все таблицы — имена, шейпы — общие, интернер
один на всю компиляцию):

- **Пространство индексов функций**: сначала функции единиц в порядке списка
  (базы из подсчёта по AST), затем функции главного скрипта, затем — в самом
  конце — инициализирующие чанки единиц (тела библиотек, скомпилированные как
  процедуры без параметров). `function_names` для функций единиц — квалифицированные
  `Псевдоним.Имя`, для инициализаторов — `Псевдоним.` с пустым именем не выдумывать:
  `Псевдоним.@инициализация` не нужен — см. ниже, инициализаторы получают имя
  `Псевдоним` целиком (это имя не может столкнуться с именем функции, потому что
  в имени функции точки нет, а голый псевдоним функцией не является).
- **`chunks[0]`** — верхний уровень главного скрипта, перед его телом кодоген
  вставляет вызовы инициализаторов единиц в порядке списка (пост-порядок уже
  обеспечен вызывающим). Существующей инструкции вызова процедуры с нулём
  аргументов достаточно — ни одного нового опкода.
- **`module_vars`** — сначала переменные главного скрипта (их номера не
  сдвигаются ни на слот: чем бы ни был контракт зеркалирования стека и
  `ModuleState`, для главного модуля он не тронут), затем переменные единиц.
  `ModuleState::new` увеличивается автоматически — он строится от
  `module_vars.len()`. Тела и функции единиц ходят к своим переменным через
  `GetModuleVar`/`AssignModuleVar`/`ArgMode::ByRefModuleVar` по глобальному
  номеру — путь, которым сегодня ходят функции любого модуля; переменные единиц
  в `top_level.locals` не попадают никогда, поэтому коллизий со слотами кадра
  нулевого уровня не существует по построению.
- **`requirements`** — объединение замыканий всех единиц и главного скрипта,
  `bsl_rt` на нулевой позиции; версии совпадают, потому что всё компилируется
  одним engine с одним реестром.

### bsl-bytecode: точка в имени функции

`text.rs` печатает и разбирает `function_names` с точкой (`Псевдоним.Имя`).
Правится пара `write_instr`/`parse_instr`-соседних мест, где имя функции
печатается и читается, плюс раунд-трип-корпус в
`crates/bsl-compiler/tests/text_round_trip.rs` пополняется слитой программой.
`FORMAT_VERSION` не трогается: расширилась грамматика имени, кодировка
инструкций не менялась. `bundle.rs` не трогается вовсе — новых опкодов нет,
классификация эффектов исчерпывающа и остаётся таковой.

### bsl-cli: препроцессор директив

Новый модуль `use_directives.rs` (имя уточнит реализация) с одной публичной
функцией: по пути главного скрипта прочитать файлы, разобрать шапки, канонизировать
пути (`std::fs::canonicalize`), продедупить по каноническому пути, обнаружить
циклы (стек обхода), выстроить пост-порядок и вернуть готовые аргументы для
`Engine::compile_linked`. Разбор шапки: строки до первого оператора/объявления;
пустые строки и обычные комментарии пропускаются; строка, начинающаяся с
`//@use(`/`//@используй(` в любом месте файла вне шапки, — ошибка. Обе формы,
кавычки по решению 2. Все пути cli, читающие скрипт (`run`, `--emit-bytecode`,
`--jit`), проходят через препроцессор; `--run-bytecode` не проходит — там уже
слитая программа. Таблица `COMMANDS` не меняется: новых флагов нет.

## Этапы

Каждый этап — компилируемое состояние с зелёным `cargo test --workspace`,
`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`.

**Этап 0. ABI и линковка функций.** `LinkedUnit`/`compile_linked` в фасаде,
`ModuleExports` и оба новых входа в sema (пока без переменных и тел — только
функции), `compile_linked_program` в компиляторе, квалифицированные имена в
`text.rs`. Проверка: facade-тест в `crates/open-bsl/tests/` — два модуля строками,
квалифицированный вызов экспортной функции; вызов неэкспортной — ошибка с внятным
текстом; `cargo tree -p bsl-vm -e normal` по-прежнему без `bsl-syntax`/`bsl-sema`;
раунд-трип текстового формата на слитой программе.

**Этап 1. Переменные и тела.** Приватные и экспортные `Перем` единиц, чтение и
запись `Псевдоним.Х`, инициализирующие чанки, порядок инициализации, передача
`Псевдоним.Х` по ссылке в не-`Знач` параметр (`ArgMode::ByRefModuleVar` с
глобальным слотом). Проверка: facade-тесты — тело модуля отработало до главного
скрипта и видело свои импорты; приватная переменная снаружи не видна (ошибка);
запись через псевдоним видна функциям модуля; дважды импортированный модуль
инициализировался один раз и состояние общее.

**Этап 2. Диагностика.** Варианты `SemaError` и ошибок фасада: неизвестный
псевдоним за точкой, неэкспортное имя, арность, дубль псевдонима у одного
импортёра, объявление переменной с именем псевдонима (см. «Решения, принятые в
плане», пункт 1). Проверка: тесты на каждый текст ошибки.

**Этап 3. Препроцессор bsl-cli и конформанс.** Разбор директив, пути, дедуп,
циклы, ошибки решения 7; прогон через `run`/`--emit-bytecode`/`--jit`.
Модули-библиотеки конформанса кладутся в `tests/conformance/fixtures/lib/` —
раннер собирает `*.bsl` нерекурсивно (`scripts_in`), подкаталог тестом не станет.
Фикстуры с `//@используй` ложатся рядом с обычными и автоматически попадают в
`the_jit_agrees_with_the_interpreter_on_every_script` (он гоняет корпус
субпроцессом bsl-cli в обоих режимах). `.expected` пишутся вручную по семантике
этого плана: у платформы 1С аналога директивы нет, это зона расширения — правило
«не генерировать оракул интерпретатором» упирается в отсутствие платформенного
поведения, но сами значения в фикстурах (что печатают функции модулей) выбираются
такими, у которых платформенная семантика уже измерена соседними фикстурами.
Проверка: конформанс зелёный, паритет JIT зелёный, ошибочные случаи — cli-тесты
на текст и ненулевой код возврата.

**Этап 4. Тест с Connector 2.6.0 из отдельного файла** (требование задачи).
Интеграционный тест bsl-cli: скрипт с
`//@используй(../../open-bsl/tests/fixtures/connector-http-2.6.0.bsl как КоннекторХТТП)`
(точный относительный путь выверить от расположения тестового скрипта) зовёт
только чистые функции — gzip/multipart-полезные нагрузки по образцу
`connector_multipart_and_gzip_round_trip_real_payloads` — без сети, сверка stdout.
Проверка: тест зелёный в обоих режимах (интерпретатор и `--jit`).

**Этап 5. Бенчмарк.** По порядку:
1. Переписать `benchmarks/cbr_rates.bsl`: шапка-директива, шесть точек вызова
   четырёх экспортов квалифицировать (`Get`, `КакТекст`, `КакJson`,
   `КакИсключение`).
2. `run.sh`: механизм `@prepend-bsl` (`materialize_bsl`) удалить; для колонки
   oscript — если рядом со сценарием лежит `имя.os`, oscript получает его, иначе
   `.bsl` как сейчас; отсутствие установленной библиотеки `connector` даёт
   обычный пропуск колонки (той же строкой «пропуск», какой печатается при
   отсутствии рантайма).
3. Поставить библиотеку из исходников: клонировать
   <https://github.com/vbondarevsky/1connector> и `opm install -s <клон>`
   (из хаба `opm install connector` не работает); написать `benchmarks/cbr_rates.os` с
   `#Использовать connector` — та же последовательность запросов и то же
   представление курсов; включить в байт-сравнение выходов протокола бенчмарка.
4. `build-combined.py`: регэксп `@prepend-bsl` заменить разбором обеих форм
   директивы; сплайс объявлений как сейчас; в его токенизатор добавить обратную
   перезапись `Псевдоним.Имя(` → `Имя_суффикс(` (последовательность токенов
   «идентификатор-псевдоним, точка, идентификатор, скобка»); суффиксация
   остальных имён — как есть.
5. Регенерация `benchmarks/1c/combined.bsl` и прогон на платформе →
   `benchmarks/1c/combined.platform.txt` (машина с 1С 8.3.27 доступна, цикл
   отработанный).
6. Обновить `benchmarks/README.md` (описание сценария, примечание про oscript-
   близнеца) и перегнать таблицу. Перфоманс-утверждение одно: `cbr_rates`
   интерпретатором и под `--jit` не отличается от базовой ревизии — проверяется
   чередующимся A/B двух бинарников (семантика та же: и склейка, и линковка дают
   один `Program`; VM не тронут, но заявление всё равно измеряется, не выводится).

**Этап 6. Документация.** Раздел «Встраивание» в `README.md` — абзац про

## Чего не делаем

- **`Выполнить`/`Вычислить`**: директива в строке динамического кода лексически —
  обычный комментарий, лексер её снимает до всякого разбора; активной ошибкой её
  не делаем, потому что это потребовало бы научить engine синтаксису cli-директивы
  и сломало бы принятую границу. Заявляем открыто: в динамике директива молча
  игнорируется, импортов там нет.
- **REPL**: без импортов; таскать таблицы экспортов через
  `resolve_repl_stmts_with_registry` — отдельная задача, если понадобится.
- **`НЕ ИЗМЕРЕНО`-маркеры** для самой директивы не заводятся: у платформы нет
  аналога, реестр открытых вопросов — про измеримое платформенное поведение.
  Квалифицированный вызов как форма записи совпадает с платформенным
  `ОбщийМодуль.Метод()`, но семантика подключения — расширение open-bsl.
- **Горячие пути VM** не трогаются вовсе; JIT-шимов не прибавляется (новых
  опкодов нет). Если этап 5 покажет просадку `cbr_rates` — это дефект этапа, а
  не повод для оптимизации VM.

## Решения, принятые в плане (после интервью — на подтверждение)

1. **Имя псевдонима резервируется.** Объявление переменной (локальной, модульной)
   или параметра с именем активного псевдонима — ошибка компиляции. Иначе
   переменная молча затенит псевдоним и `КоннекторХТТП.КакJson(...)` тихо
   превратится в вызов метода значения переменной — класс ошибок, который решение
   7 из интервью выжигает у директив.
2. **Порядок `module_vars` слитой программы: главный скрипт первым.** Его номера
   слотов не сдвигаются ни на слот относительно сегодняшних, контракт кадра
   нулевого уровня для него не тронут; переменные единиц — чистое дописывание в
   хвост таблицы, видимое только через `GetModuleVar`-путь.
3. **Имена инициализаторов в листинге** — голый `Псевдоним` (без выдуманного
   суффикса): столкновение с именем функции невозможно, читается однозначно.
4. **Динамический код** — молчаливое игнорирование директивы-комментария
   (см. «Чего не делаем»), а не активная ошибка.
