# Код конфигурации из XML или EDT с ORM информационной базы

В режиме `--config-db` можно выбрать файловый комплект вместо кода из Config:

```console
bsl-cli --config-db postgres ... --config-xml /path/to/export main.bsl
bsl-cli --config-db postgres ... --config-edt /path/to/project main.bsl
```

Здесь `...` обозначает обычные параметры подключения, пользователя и версии
платформы. Без нового селектора поведение прежнее. Селекторы взаимоисключающие;
после имени скрипта они считаются аргументами скрипта. Отдельное подключение БД
остаётся обязательным: файловый каталог не предоставляет живые данные и права.

Из БД поступают физическая модель ORM, пользователи, роли и действующие права,
RLS, разделение данных и соединения сеансов. Из выбранного каталога поступают
BSL и флаги исполнения модулей, описания объектов, формы и макеты. Локальное
изменение текста роли не изменяет права пользователя базы. Скрипт исполняется
обычным open-bsl, модуль сеанса запускает существующий `bsl-session`.

Проверяется UUID корневого объекта конфигурации, а не имя Config-хранилища.
Постоянные объекты связываются по UUID, виду и имени. При приобретении
подробностей проверяется совместимость реквизитов с моделью БД; дополнительный
реквизит формы не становится полем таблицы. Изменение BSL не требует совпадения
хешей исходников с базой. Ошибка файла не включает подстановку кода из БД.

## Поддерживаемые представления

Читатель Конфигуратора принимает XML-выгрузку версии `2.20` с пространством имён
`http://v8.1c.ru/8.3/MDClasses`. Сохранённые нативные проверки произведены
платформой 1С `8.3.27.2342`. Корень каталога содержит `Configuration.xml`.
Тела находятся в стандартных `Ext/*.bsl`, модуль формы — в
`Ext/Form/Module.bsl`. Для текста принимаются UTF-8 с BOM или без него и
UTF-16 LE/BE с BOM; некорректные последовательности отклоняются.

EDT принимает корень проекта с `src` либо сам `src`, содержащий
`Configuration/Configuration.mdo`. Проверено семейство описаний с пространством
имён `http://g5.1c.ru/v8/dt/metadata/mdclass` и форм
`http://g5.1c.ru/v8/dt/form`. Проверены нативный импорт 1C:EDT 2026.1.3+25 из выгрузки Конфигуратора
и проект 1C-Company/GitConverter (версия IDE последнего не записана в файлах).
Читатель не запускает EDT и не конвертирует проект при исполнении.

Текстовые макеты читаются из `Template.txt`. Табличные — из `Template.xml`
Конфигуратора либо `Template.mxlx` EDT через существующий декодер XML-макета.
Двоичный макет читается как `ДвоичныеДанные`. Для остальных объявленных видов
членство сохраняется, а попытка материализации возвращает явную ошибку, если
соответствующий декодер ещё не поддержан. Формы предоставляют описания и модуль;
нового графического клиента и цикла обработки событий нет.

Распознанный защищённый модуль без BSL использует прежнюю политику экспортных
сигнатур; неизвестный образ отвергается. `--decompile-protected-modules`
применяется к выбранному источнику кода, включая файловый режим.

## Расширения

Каждому применимому расширению требуется явный каталог того же формата:

```console
bsl-cli --config-db postgres ... --config-xml /path/to/main \
  --config-extension 01234567-89ab-cdef-0123-456789abcdef=/path/to/extension main.bsl
```

UUID в аргументе идентифицирует запись расширения базы; UUID конфигурации
внутри каталога отдельно сверяется с нативным корнем этого расширения.
Применимость и порядок остаются правилами БД. Неактивное расширение не меняет
комплект, неизвестный UUID и отсутствующий каталог активного расширения дают
ошибку. Заимствование использует уже поддержанные open-bsl связи SDK;
неизмеренные операции и неподдержанная структурная композиция отклоняются.
Перехваты методов и модуль сеанса расширения этим изменением не добавляются.

## Время жизни

Каталог должен оставаться неизменным, пока живёт фабрика. При индексировании
читаются описания и файловые атрибуты, а BSL, содержимое форм и макетов — при
обращении. При первом приобретении проверяются канонический путь, размер и
время изменения файла до и после чтения. На один ресурс действует предел
256 МиБ. Это обнаружение обычного изменения исходников, а не атомарный снимок
файловой системы. Изменение с сохранением всех проверяемых атрибутов не обещано
обнаруживаться. Уже приобретённое неизменяемое значение остаётся в кэше;
горячая перезагрузка не выполняется. Для новой редакции создайте новую фабрику.

Повторный сеанс использует тот же индекс и неизменяемый кэш, без полного
пересчёта хешей каталога. Из макета каждый вызов создаёт собственный изменяемый
документ. Параметры, объекты и соединения разных сеансов не помещаются в этот кэш.

Нативный `Module.bin` в выбранном каталоге передаётся существующему механизму
защищённых модулей. По умолчанию доступны экспортные сигнатуры с согласованными
заглушками; `--decompile-protected-modules` включает прежнее строгое восстановление
тел. Это не чтение кода из БД. Нераспознанный образ приводит к ошибке, а не к
пустому успешному модулю. У самостоятельных XML/EDT-читателей `module_image`
позволяет хосту получить исходные байты образа; сами читатели его не интерпретируют.
