# Запуск приложения

В Linux CLI запуск доступен без дополнительного флага, в том числе из REPL
и текстового байт-кода. Встраивающий host должен явно предоставить сервис
через `StateBuilder::application_launcher`; по умолчанию его нет. Для
фоновых заданий сервис задаётся в host-профиле задания.

```bsl
Код = Неопределено;
ЗапуститьПриложение("/usr/bin/true", , Истина, Код);
Сообщить(Код); // 0
```

Это процедура: результат записывается в четвёртый аргумент, а не возвращается
из выражения. Поддержаны локальная, модульная и импортированная переменные,
поле и индекс, включая параметр по ссылке. Адрес составной цели вычисляется один раз
после первых трёх аргументов. Необъявленное имя в этой позиции остаётся ошибкой. При успешном
вызове без ожидания выходная переменная
становится `Неопределено`. Пропуск ожидания означает `Ложь`, но явно переданное
`Неопределено` — ошибка. Ошибка вызова сохраняет прежнее значение переменной.

Команда разбирается на executable и argv по Unix-правилам кавычек и
экранирования, без неявного shell. Переменные окружения, wildcard,
перенаправления и shell-операторы не исполняются. Путь и рабочий каталог
относятся к пространству процесса host, а не к виртуальной `FileSystem`.
Запуск shell возможен только как явно указанной программы с её аргументами.
На Linux одиночное имя существующего обычного файла без executable-битов
открывается по ассоциации через `gio open`. Пробелы в имени требуют кавычек
внутри командной строки, например `RunApp("'/tmp/report 1.txt'");`.
Документ должен иметь настроенную ассоциацию, а `gio` — быть доступен в PATH.
Ошибки передачи и отсутствие gio дают исключение. Относительное имя
разрешается от рабочего каталога запроса; утилита получает абсолютный путь
отдельным аргументом. Разбор Windows-команд пока не поддержан.

Для документа поддержана передача без ожидания: успех означает подтверждение
передачи, а не закрытие приложения. Запрос ожидания вызывает явную ошибку
до открытия документа и сохраняет выходную переменную. Для RunAppAsync
ошибка приходит при Ждать. Выходной код gio не выдаётся за код приложения.

С ожиданием возвращается числовой код завершения; отсутствие executable
даёт 127. Это выбранная server-like семантика CLI: на измеренной серверной
1С получен 127, тогда как синхронный клиентский вызов вернул `Неопределено`.
Другие ошибки host и завершение без числового кода дают исключение.
Без ожидания вызов не удерживает VM до завершения приложения; дочерний
процесс может продолжать работу после выхода CLI. Отмена BSL-ожидателя
не завершает дочерний процесс. Прямой синхронный вызов паркует execution,
освобождая worker, в том числе внутри вложенных `Выполнить`/`Вычислить`.
Остальные задачи того же исполнения остаются приостановленными до окончания
синхронного вызова. Отладочное вычисление в остановленном кадре доводится
блокирующе.

Host-интерфейс передаёт `ApplicationRequest::wait_for_exit` и
`ApplicationResult`: `Started`, `Exited(ApplicationExit)` либо
`DocumentOpened`. Без ожидания runtime всё равно получает подтверждение
создания процесса или передачи документа через парковку VM. Для executable
системный host после `Started` независимо продолжает wait/reap.
Внедрённым реализациям `ApplicationLauncher` нужно учитывать этот контракт.
Ошибка NotFound в прежнем протоколе обозначает отсутствующий executable;
отказ ассоциации документа должен возвращать другой класс ошибки.

Асинхронная форма `ЗапуститьПриложениеАсинх`/`RunAppAsync` принимает первые
три аргумента и возвращает обещание, без выходного четвёртого аргумента:

```bsl
Асинх Процедура Пример()
    Код = Ждать ЗапуститьПриложениеАсинх("/usr/bin/true", , Истина);
    Сообщить(Код); // 0
КонецПроцедуры
Пример();
```

При пропущенном или ложном флаге ожидания результат — `Неопределено`.
При истинном — код процесса, но отсутствие executable даёт `Неопределено`,
не синхронный 127. Пустая команда с ожиданием даёт 0, NUL завершает команду
асинхронного вызова. Ошибки типов, подготовки и host приходят при `Ждать`;
ошибки арности — до получения обещания. Повторное ожидание не запускает
процесс заново. Ожидание уступает соседним задачам и worker, включая обещания,
возвращённые из `Вычислить`/`Выполнить`. Отмена не завершает приложение.
Измерен клиентский контекст серверной 1С; серверная доступность не заявляется.
Несуществующий cwd передаётся host без fallback, что отличается от нативной
пробы; неявная оболочка также не добавляется.

Это не полная совместимость с серверной 1С: измеренная платформа исполняет
shell-операторы. Прочие граничные преобразования остаются в реестре
`RUNAPP.EDGE_ARGUMENTS`. Оригинальные измерения сохранены в
[отчёте о RunApp](../../research/compatibility/file-runapp-details-server-2026-09-09.md).
Сопоставление серверного sync, клиентского sync и клиентского async сохранено
в [отдельном отчёте](../../research/compatibility/file-runapp-context-comparison-2026-09-17.md).
