# Оператор `goto`

## Цель

Добавить в open-bsl метки `~Имя:` и операторы `Перейти ~Имя` / `Goto ~Name`, сохранив измеренную семантику 1С и не меняя формат байт-кода.

## Измеренное поведение 1С

Пробы выполнены на реальной платформе 1С 8.3.27.2130.

- Поддерживаются обе формы: `Goto` и `Перейти`.
- Допустимы числовые (`~0`) и именованные (`~IL_0`) метки, прямые и обратные переходы.
- Имена меток регистронезависимы.
- Область меток — тело модуля либо отдельная процедура/функция. Одинаковая `~0` в двух таких областях законна.
- Неизвестная цель и повторное объявление метки не компилируются.
- Ключевое слово допустимо как имя метки (`~Если:`), дробное число — нет.
- Для `Если`, `Пока`, `Для` и `Попытка/Исключение` действует одно правило: переход разрешён в тот же структурный блок или наружу. Переход внутрь вложенного блока и между соседними ветвями не компилируется.

## Платформенный oracle

Контракт находится в `tests/conformance/measure/measure-goto.bsl`, результат реальной платформы — в соседнем `measure-goto.platform.txt`. Негативные пробы выполняются через `Выполнить`: ошибка компиляции ловится и не обрывает платформенный сеанс.

## Реализация

### 1. Синтаксис

- Добавить `TokenKind::Tilde` и его текст в диагностиках.
- Добавить единственную строку `(«Перейти», «Goto», Keyword::Goto)` в таблицу ключевых слов. Это автоматически включит подсветку и автодополнение REPL.
- Добавить `Stmt::Label(String)` и `Stmt::Goto(String)`.
- После `~` принимать идентификатор либо целое десятичное число. Метка заканчивается `:`, а `Goto` — именем цели.
- Проверить `~0:;`, `~IL_0:`, метку без пустого `;`, обе языковые формы и негодные имена.

### 2. Семантика

Перед обычным резолвингом обойти всё тело callable и собрать его метки. Ключом служит имя в верхнем регистре, значением — компактный `LabelId` и измеренный структурный контекст.

Новые виды `SemaError`:

- `DuplicateLabel(String)`;
- `UndefinedLabel(String)`;
- `InvalidGotoTarget(String)` для перехода внутрь запрещённой структурной области.

В `RStmt` передавать `Label(LabelId)` / `Goto(LabelId)`, а не строки. Так компилятор не повторяет именной анализ. Нужно также классифицировать оба узла как не читающие выражений в `core_receivers` и `block_uses_dynamic`.

### 3. Байт-код

Метка не порождает инструкцию: компилятор сохраняет для `LabelId` текущий `pc`. `Goto` порождает уже существующий `Instr::Jump { target: 0 }` и запись для патчинга. После компиляции всего чанка все цели патчатся через существующую проверку `jump_target`.

Новый opcode, изменение `text.rs`, `bundle.rs`, VM, JIT или `FORMAT_VERSION` не нужны: все они уже обрабатывают `Instr::Jump`. После патчинга обычный расчёт бандлов сам выровняет точки входа.

## Benchmark

Предоставленный текст нельзя добавлять как `benchmarks/goto_bench.bsl` буквально:

- `0=1;` как отдельный оператор не компилируется на 1С;
- `0=a_;` читает необъявленную `a_` и тоже не компилируется;
- в буквальной копии `//` и `КонецПроцедуры` стоят на одной строке;
- код не печатает последней строкой число миллисекунд, как требует `benchmarks/run.sh`.

Все ссылки `goto` внутри обеих областей имеют соответствующие метки; граф переходов цел. Перед редактированием нужен исходный валидный файл либо согласованное правило восстановления строк `0=...` / `1=...`; угадывать их семантику нельзя.

Вместо восстановления повреждённого текста:

1. Добавить валидный `goto_bench.bsl` с горячим графом переходов и тем же ключевым свойством нагрузки — большим числом переходов между метками.
2. Вывести checksum для проверки и число миллисекунд последней строкой.
3. Обновить `benchmarks/README.md`, пересобрать `benchmarks/1c/combined.bsl` и снять реальный `combined.platform.txt`.

## Проверка

Минимальная матрица:

- тесты лексера/парсера на обе формы и диагностики;
- тесты sema на область, регистр, дубль, неизвестную цель и структурные границы;
- тесты compiler на прямой/обратный `Jump`, соседние метки, метку в конце чанка и предел `i16`;
- round-trip текстового bytecode на порождённом `Jump`;
- фикстура conformance с прямым, обратным и условным переходом;
- `the_jit_agrees_with_the_interpreter_on_every_script`;
- `cargo fmt --all -- --check`;
- `cargo clippy --workspace --all-targets -- -D warnings`;
- `cargo test --workspace`;
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`.

Для любого утверждения о производительности нужен чередующийся A/B-прогон с baseline-бинарником. Базовая ветка не может запустить новый `goto_bench`, поэтому A/B применяется к существующим control-flow сценариям для проверки отсутствия регрессии.
