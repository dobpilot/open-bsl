# Вид сеанса при запуске из информационной базы

Параметр `--session-kind` применяется вместе с `--config-db` перед путём скрипта:

```console
bsl-cli --config-db postgres --db-host localhost --db-name demo \
  --db-user admin1c --platform-version 8.3.27.2342 \
  --principal Администратор --session-kind web-client script.bsl
```

Допустимы `thin-client` и `web-client`. Без параметра сохраняется тонкий клиент. Выбранный вид передаётся существующей фабрике сеансов; обработчик параметров сеанса по-прежнему исполняется в серверном контексте. Параметр не выбирает клиентский препроцессор и не открывает пользовательский интерфейс 1С.

Пароль базы берётся из `PGPASSWORD` или `MSSQL_PASSWORD`, а не из аргумента командной строки. PostgreSQL проверяет защищённое соединение по умолчанию; `--db-plaintext` остаётся явным разрешением незащищённого соединения для тестового подключения.

Ключ после `script.bsl` остаётся аргументом прикладного скрипта. Неизвестное значение, повтор ключа и применение без `--config-db` до пути отклоняются до подключения.

`background-job` не является допустимым значением этого ключа. Настоящий фоновый сеанс создаётся через родительский API: получает копию параметров родителя и отдельное соединение. Обычный запуск CLI не имитирует такой контекст одним изменением названия режима.

## Соединения текущего хоста

`ПолучитьСоединенияИнформационнойБазы()` возвращает переданный хостом снимок
реальных `Session` текущего процесса open-bsl. Обычный CLI создаёт один
такой сеанс: его номер соединения — `1`, имя приложения — `bsl-cli`, имя
компьютера берётся у текущего хоста. Выбор `web-client` меняет контекст
исполнения, а имя приложения остаётся `bsl-cli`.

Сеансы платформы 1С, служебное соединение чтения метаданных и потоки VM
в этот список не входят. Снимок доступен только при подтверждённом праве
`АктивныеПользователи` выбранного пользователя. Без права вызов завершается
явной ошибкой; привилегированный обработчик инициализации не расширяет
предоставленную хостом возможность.

## Защищённые модули

По умолчанию модули без исходного BSL-текста загружаются как экспортные
заглушки: сохраняются имена, параметры и умолчания, процедуры пустые,
функции возвращают `Истина`. Закрытые методы и инициализация модуля
не включаются. Этот режим не исполняет оригинальную реализацию.
Для экспорта с непрозрачными параметрами и без таблицы умолчаний
заглушка сохраняет их имена и требует все объявленные аргументы. Флаги параметров
не трактуются как платформенные режимы передачи.
Заглушки асинхронных экспортов также синхронны: функции возвращают
`Истина`, а не нативное обещание.

Для восстановления тел перед путём скрипта укажите
`--decompile-protected-modules` вместе с `--config-db`. Тогда используется
строгая декомпиляция: неподдерживаемый образ вызывает ошибку загрузки,
без перехода к заглушкам. Выбранный режим применяется также к расширениям.
Модули с доступным BSL-текстом сохраняются в обоих режимах.

В Rust тот же выбор задаёт `bsl_config_db::LoadOptions` в
`load_with_options`, `load_factory_inputs_with_options` или
`load_factory_inputs_with_metadata_and_options`. Обычные функции загрузки
используют режим заглушек.

## Измерение этапов запуска

`OPEN_BSL_STARTUP_TIMINGS=1` включает диагностические строки в stderr:

```console
OPEN_BSL_STARTUP_TIMINGS=1 bsl-cli --config-db postgres ... script.bsl
```

Формат строки: `open-bsl.startup<TAB>этап<TAB>секунды`. Без значения `1`
строки не выводятся. Диагностика не содержит пароль, SQL и исходники BSL.

Этапы CLI: `cli.acquire` — подключение и получение конфигурации;
`cli.decode` — получение пользователей и декодирование входов фабрики;
`cli.access` — выбор пользователя, права и описание соединения;
`cli.factory` — подготовка фабрики и компиляция; `cli.resources` —
ресурсы конкретного сеанса; `cli.session_open` — открытие сеанса
с вызовом обработчика параметров; `cli.execute` — выполнение скрипта.

Вложенные этапы фасада начинаются с `engine.`: сбор экспортных описаний,
выбор зависимостей, компиляция, проверка образа и подготовка текстового
образа фоновых заданий. В каталоге без корней отдельно выводятся разбор
и разрешение имён. Длительность родительского этапа включает дочерние:
например, `cli.factory` нельзя складывать со всеми `engine.catalog.*`.
Время `cli.session_open` включает подготовку фонового образа, если она
потребовалась обработчику; это не чистое время исполнения BSL.

`--config-db` использует индекс конфигурации: фабрика готовит модуль сеанса,
входной скрипт и достигнутые зависимости. Имена, известные только при исполнении,
вызывают загрузку при первом обращении. Подробные метаданные приобретаются по
обращениям; перечисление коллекций сохраняет полный обнаруженный состав.
Этот индексированный путь пока выполняет подготовку последовательно.

Полная подготовка каталога использует до двух потоков для экспортных описаний
и анализа выбранных модулей, с учётом числа доступных процессоров. Для ограничения
расхода памяти число рабочих потоков не увеличивается автоматически сверх двух.
`OPEN_BSL_PREPARE_THREADS=1` включает последовательную полную подготовку;
`OPEN_BSL_PREPARE_THREADS=2` запрашивает два потока. Остальные значения используют
режим по умолчанию. На WebAssembly подготовка всегда последовательна.
Этот параметр не распараллеливает индексированный путь `--config-db`.
Порядок модулей, диагностики и исполнения от выбора числа потоков не меняется.
Генерация байткода, проверка образа и исполнение сеанса остаются последовательными.
