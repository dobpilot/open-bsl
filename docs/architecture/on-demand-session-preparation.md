# Подготовка конфигурации по обращениям

`SessionFactory::new_with_source` получает индекс `ConfigurationSource`, а не
готовый комплект всех модулей. Индекс сохраняет идентичности объектов и модулей,
их имена, контексты исполнения и расположение ресурсов. Объявления глобальных
экспортов проверяются до публикации фабрики; тела неиспользуемых методов для
этого не компилируются. Полная загрузка снимка остаётся отдельным рабочим путём.

Фабрика готовит модуль сеанса, переданные входные модули и явные импорты.
Обычные статические ссылки связываются по объявлениям: ссылка из невызываемого
метода сама по себе не требует компиляции тела цели. Фактическое обращение к ещё
неподготовленному модулю загружает его через тот же источник и запускает обычные
parser, sema, compiler и verifier open-bsl.
Вычисляемые имена разрешаются при фактическом обращении. Произвольные строковые
константы не превращаются в предполагаемые зависимости.

Подготовленный код кэшируется в фабрике. Идентификаторы модулей остаются
позициями неизменяемого индекса; новая порция кода не перенумеровывает активные
кадры. Проверяется новая порция и её связи, без повторного обхода неизменившихся
общих таблиц. Для проверки связей используется закрытое представление сигнатур:
оно не передаётся VM и не подменяет исполняемый код. Перед публикацией настоящая
программа сверяется с объявлениями и проходит обычную проверку образа и связей.
Полная проверка входного образа байткода сохраняется.

Каждый исполняемый сеанс владеет своими переменными, параметрами, пользователем
и соединением. Кэш фабрики не содержит значений другого сеанса. Пространство
имён VM и привязки полей структур относятся к конкретному исполнению. Программы
сохраняют локальные индексы имён: расширение пространства имён сеанса не требует
копирования программ и не ограничивается 65 536 именами.
Фоновые сеансы используют те же правила подготовки и изоляции.

`DatabaseConfigurationSource` удерживает отдельное соединение фабрики для
адресных чтений. Оно не считается пользовательским исполняемым сеансом.
Начальная загрузка получает корни конфигурации, перечень ресурсов и компактные
заголовки объектов. Коллекции метаданных перечисляют весь обнаруженный состав,
даже если подробности отдельных объектов ещё не приобретены.

Подробности загружаются при обращении к объекту, вместе с зависимыми типами и
данными предопределённых значений. Права, разделители, языки и параметры сеанса
приобретаются как обязательные входы запуска. Ошибка чтения зависимого ресурса
не публикует неполный успешный снимок. Успешный снимок неизменяем и разделяется
через `Arc`; повторное обращение без новых зависимостей возвращает тот же снимок.

ORM-подробности используют отдельные `RuntimeMetadataFacts` SDK: нормализованные
описатели, объекты, значения и настройки разделения. Этот тип не является
готовым снимком запросов и не имеет fingerprint. Рост ORM-фактов не запускает
построение query-индексов и отчёта. Полный `MetadataSnapshot` финализируется
при явном запросе снимка или подготовке запроса; его проверки и fingerprint
остаются прежними. Кэши готовности runtime-фактов и полного снимка разделены,
новый ресурс инвалидирует оба. Ранее полученный снимок не изменяется.

Позиции членов коллекций ORM индексируются один раз в порядке каталога,
отдельно по виду и родителю подсистемы. Длина и числовой индекс не обходят весь
каталог. Корневой список общих реквизитов сохраняет свой явный порядок.

Контексты приёмников приобретаются для реально подготавливаемых тел; явные
импорты могут образовывать группу. Статическая ссылка из невызываемого кода не
включает владельца цели в группу. Подготовка исходников в индексированном пути
пока выполняется последовательно.

Адаптер запросов находит прямые зависимости существующим AST-проходом SDK.
Раскрытые условия RLS могут добавить объекты, отсутствующие в исходном запросе.
Тогда исходный запрос заново подготавливается на расширенном снимке. Проверка
fingerprint подготовленного запроса сохраняется; SQL, контроль доступа и
материализация результата используют один снимок одной подготовки.
