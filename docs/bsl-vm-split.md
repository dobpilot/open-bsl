# Декомпозиция `bsl-vm/src/lib.rs`

## Что в файле на самом деле

6645 строк, но VM — не они. Тестовый модуль занимает 3552 строки (196
тестов), то есть **53 % файла**; рабочего кода — около 3090 строк. Это
меняет постановку задачи: «файл на шесть с половиной тысяч строк» —
наполовину корпус тестов, и его вынос не требует ни одного решения о
раскладке кода.

Рабочая часть по секциям (номера — на момент составления плана):

## Связывающее ограничение: размер здесь измерен

Обычная распайка (волна F в `docs/bsl-rt-abi.md`) была чистым
перемещением с нулевым риском для поведения. Здесь это не так, и причина
записана в самом репозитории:

- `.cargo/config.toml` существует ровно из-за этого: «добавление шимов в
  JIT-модуле однажды замедлило `str_find` на 45 % — при том, что ни
  строкой кода поиск не менялся и `--jit` в том прогоне не участвовал».
  Правка в ДРУГОМ модуле сдвинула укладку кода. Флаг
  `-align-all-functions=5` смягчает это, но не отменяет.
- Комментарии у `step_cold` фиксируют измеренную границу горячего и
  холодного: перенос `CallComponent`/`CreateObject` из `step` в
  `step_cold` дал `call_overhead` с +12,3 % до +4,3 %, `pi_leibniz` с
  +12,1 % до +6,2 %. Три байта разницы в размере однажды замедлили пустой
  цикл в 1,5 раза при неизменном числе инструкций.
- `at`/`reg_load`/`reg_store` прибиты `#[inline(always)]`, а
  `component_prop_get`/`set` и `numeric_for_*` — `#[inline(never)]`. Это
  не стиль, а результат замеров.

Техническая причина, почему модульная граница вообще способна на это:
rustc разбивает крейт на codegen-units ПО МОДУЛЯМ. Перенос функции в
другой файл может увести её в другой CGU, изменив и инлайнинг через
границу, и порядок функций в объектном файле. Для холодного кода это
безразлично; для цикла диспетчеризации — нет.

**Вывод, определяющий весь план: ядро диспетчеризации не режется. Режется
то, что вокруг него.**

## Целевая раскладка

```
crates/bsl-vm/src/
  lib.rs        crate-doc, объявления модулей, реэкспорты,
                Frame/CallArgs, drive_with/drive_linked,
                step, step_cold и их горячие помощники   ← ~1500 строк
  api.rs        run_program*, run_repl_chunk*, call_module_function*,
                run_program_with_host, JitMode           ← ~380
  link.rs       HostIo, LinkedComponents, карты мемоизации,
                resolve_component_*, component_prop_*,
                link_components                          ← ~350
  snippet.rs    run_dynamic_snippet, SnippetCache,
                compile_dynamic_snippet, merge_requirements,
                remap_chunk_libraries, ограничители глубины ← ~430
  unwind.rs     возврат из кадра, поиск обработчика,
                разматывание, err_to_value, массивы       ← ~185
  tests.rs      196 тестов                                ← ~3550
  jit/          как есть
```

`ops` (`add_op`, `binop`, `cmp`, `neg_op`, `call_builtin_with_format`)
СОЗНАТЕЛЬНО остаётся в `lib.rs`: эти функции зовёт и горячий цикл, и
шимы JIT, и именно их инлайнинг измерялся. Вынести их — отдельный
эксперимент с A/B, а не часть распайки.

## Порядок шагов

Каждый шаг заканчивается зелёным `cargo test --workspace`, conformance с
`the_jit_agrees_with_the_interpreter_on_every_script`, fmt, clippy, doc.
Шаги 2–5 дополнительно проходят A/B.

- **Шаг 0. Базовый бинарник.** `cargo build --release -p bsl-cli` на
  текущем коммите, копия отложена. Все дальнейшие A/B — против него.
- **Шаг 1. Тесты → `tests.rs`.** Минус 3552 строки, 53 % файла. Риска для
  раскладки нет: код под `#[cfg(test)]` в релизный бинарник не попадает.
  A/B не нужен. Этот шаг стоит сделать первым и отдельным коммитом — он
  один решает больше половины проблемы.
- **Шаг 2. `snippet.rs`.** Динамические сниппеты (`Выполнить`/`Вычислить`)
  — самый обособленный кусок: своя кэш-структура, свой компилятор, ноль
  вызовов из `step` кроме одной точки входа.
- **Шаг 3. `api.rs`.** Точки входа и `call_module_function*`. Вызываются
  один раз на прогон.
- **Шаг 4. `link.rs`.** Связывание компонентов. Внимание: сюда уезжают
  `component_prop_get`/`set`, помеченные `#[inline(never)]` и зовущиеся из
  четырёх ветвей интерпретатора и четырёх шимов JIT, — этот шаг мерить
  особенно тщательно (`xml_parse`, `json_write`).
- **Шаг 5. `unwind.rs`.** Возврат и разматывание. `do_return_with_value`
  зовётся из горячей ветви `Return`; если A/B покажет сдвиг — вернуть в
  `lib.rs` и оставить там с комментарием, как это сделано с `ops`.

## Протокол проверки для шагов 2–5

Одного «тесты зелёные» здесь мало: цель шага — не изменить поведение
вообще, включая скорость.

1. Чередующийся A/B, медианы пяти проходов, из ВРЕМЕННОГО каталога (не
   из корня репозитория — `csv_write` пишет туда сотню мегабайт и
   выдумывает +24 % шума; это уже стоило одного ложного диагноза).
2. Сценарии: `call_overhead`, `pi_leibniz`, `empty_for` (чистый цикл
   диспетчеризации), `str_find` (тот самый, что однажды уехал на 45 % от
   чужой правки), `xml_parse` и `json_write` (компонентные пути),
   `csv_write` (нативные свойства).
3. Порог: любой сценарий за пределами ±5 % — стоп-сигнал. Дальше
   `perf stat` на обоих бинарниках: одинаковое число инструкций при
   разнице в тактах означает сдвиг укладки, а не смысловую регрессию.
   Лечение в этом случае одно — вернуть перенесённое обратно и записать в
   комментарии, что этот кусок остаётся при цикле по замеру.
4. Результат каждого шага (проценты по сценариям) идёт в сообщение
   коммита. Без цифр шаг считается непроверенным.

## Чего этот план НЕ делает

- Не трогает `step`/`step_cold` и их горячих помощников — их размер и
  границы измерены, и любая перестановка требует своего эксперимента, а
  не распайки заодно.
- Не выносит `ops` — см. выше.
- Не меняет ни одной сигнатуры и ни одного имени: перемещение, видимость
  расширяется до `pub(crate)` только там, где сосед потерял доступ.
  Ревью — `git diff --color-moved=dimmed-zebra`.
- Не трогает `jit/` — он уже отдельным каталогом и импортирует
  внутренности VM явным списком; после переноса этот список станет
  указывать на новые модули, и это единственная правка в нём.

## Ожидаемый итог

`lib.rs` — около 1500 строк: crate-doc, кадр, внешний цикл, диспетчер и
его горячие помощники. То есть ровно то, что и должно лежать вместе,
потому что вместе оно и измерялось. Остальное — четыре файла по 200–450
строк и корпус тестов.

Если A/B заставит вернуть шаг 4 или 5, итог будет ~1900 строк вместо
1500. Это тоже приемлемый результат: файл перестаёт быть свалкой, а
причина, по которой часть кода осталась в нём, будет записана рядом
цифрами, а не вкусом.
