# Запрос на изменение open-sdbl: метаданные объектов документов

## Задача
Добавить в приобретённый описатель конфигурации измеренные настройки стандартного реквизита `Номер`, полный список собственных реквизитов и табличных частей документа. Эти данные нужны `bsl-orm` для исполнения оригинального кода через `Документы.<Имя>.СоздатьДокумент()`. Не реализовывать исполнение BSL или запись документа в SDK.

Текущий `src/metadata/config.rs::ConfigDescriptor` имеет `catalog_standard_attributes`, `catalog_attributes`, `catalog_tabular_sections`, но аналога для документа нет. Не выводить настройки из SchemaStorage, SQL-колонок или BSL исходников. Использовать собственные Config-ресурсы документа; переиспользовать существующие описатели GUID, имён и типов вместо второй системы типов.

## Контракт результата

- Настройки номера: строковый/числовой тип, длина, допустимая длина, а также другие реально необходимые для корректного предоставления номера квалификаторы. Зафиксировать точный набор после сверки с синтакс-помощником и XML. Не добавлять неподтверждённые флаги.
- Полные собственные реквизиты документа в порядке конфигурации: `Option<Vec<Guid>>`, `Some([])` — достоверно пусто, `None` — неизвестно или неполно. Исключить реквизиты табличных частей и общие реквизиты.
- Полные собственные табличные части: тот же контракт полноты. Их реквизиты должны оставаться привязаны к конкретной части в существующей модели.
- Настройки заполнения реквизитов, действительно нужные `Заполнить()`, должны приобретаться из измеренной формы Config: минимальная нативная проба показывает, что простое совпадение имени структуры не гарантирует заполнения стандартного реквизита. Нативные `measure-document-fill-attributes*.platform.txt` теперь подтверждают, что нужны оба свойства `FillFromFillingValue` и типизированный `FillValue`. Начальные значения при создании пустые и отличаются от значений заполнения. Получать GUID/тип ссылочного значения заполнения из конфигурации, не подставлять отображаемое имя. Не выдавать неизвестное значение заполнения за пустое.
- Имена, типы, ссылки и квалификаторы каждого реквизита разрешаются существующими описателями. Не терять составные типы и не подменять их первым физическим SQL-членом.
- Неизвестная форма ресурса не порождает guessed defaults или частичный список с видом полного.
- Общая обработка приобретённых ресурсов одинакова для PostgreSQL и SQL Server; новых соединений для вычисления этих свойств не создавать.

## Проверяемые артефакты
Нативная XML-выгрузка УНФ: `/tmp/open-bsl-unf-query-schema-xml/Documents/Событие.xml`; исходный менеджер вызывает CreateDocument на строках 2405 и 2507. Это потребитель, а не источник свойств.
Нативный минимальный документ: `open-bsl/tests/conformance/measure/1c/cfg-src-document-reference/Documents/ЗамерДокумента.xml`, строковый номер длиной 9. Числовой и отключённый номер дополнительно измерены в `measure-document-object-properties-number.platform.txt` и `measure-document-object-properties-disabled.platform.txt`; при отключённом номере тестовая конфигурация явно задаёт пустой `InputByString`. Для различных собственных типов использовать отдельные тестовые конфигурации; рабочие базы не изменять.
Поведение BSL измерено отдельно в `measure-document-object-properties.platform.txt`; оно не доказывает формат Config. Сопоставление Config и XML выполнить отдельными фикстурами и записать измеренные позиции.

## Процесс и приёмка
Сначала OpenSpec и strict validation. Фикстуры должны доказывать строковый/числовой/нулевой длины номер, пустые и непустые коллекции, составные типы, повреждённые/неизвестные формы. Существующие проверки без ослабления. fmt, Clippy -D warnings, workspace tests, rustdoc -D warnings и strict OpenSpec должны пройти. Документация на русском, спеки на английском. Номер следующего релиза согласовать отдельно; текущий запрос сам по себе не назначает версию и не разрешает менять базу пользователя.

В отчёте перечислить публичные поля/типы, наблюдённые формы, неизвестные случаи и точные команды измерения. Не обещать поддержку форм, для которых нет фикстур.


## Граница потребителя уже подготовлена
В `bsl-orm` доступен `DocumentAttribute`: GUID/имя, типы через существующий `open_bsl::ColumnType`, отдельные неизвестные/известные `FillFromFillingValue` и снимок `FillValue`. `MetadataObject::with_document_attributes` принимает полный список; неизвестная коллекция остаётся `None`. SDK должен отдавать свои чистые декодированные данные; от SDK не требуется зависимость на эти типы ORM или сериализатор BSL. Маппинг в описание ORM выполняет bsl-config-db. Типы ссылочных значений заполнения должны содержать идентичность конфигурации, а не только отображаемое имя.

## Проверка достаточности типов на исходной УНФ

Прямой обход только `Document/ChildObjects/Attribute` штатного XML документа Событие обнаружил 26 собственных реквизитов: 6 строковых, 2 булевых, 2 даты, 9 ссылок на справочники, 4 ссылочных перечисления, 1 ХранилищеЗначения, 1 составной тип «строка или ссылка на справочник» и 1 объявление через `v8:TypeSet` (`ДокументОснование` ссылается на `cfg:DefinedType.ОснованиеСобытия`). Требуется разрешить определяемый тип из конфигурации; нельзя объявлять его пустым типом или Неопределено по отсутствию прямого v8:Type. Значения заполнения: 13 xsi:nil, 6 xr:DesignTimeRef, 6 xs:string, 1 xs:boolean. Это формы XML, а не результаты BSL-присваивания.

Поэтому приобретение только строковых типов недостаточно для оригинального СоздатьДокумент. Сохранить типы ссылок, перечислений, составные и прочие объявления; добавить проверяемые Config/XML-фикстуры для реально встреченных форм. Не интерпретировать xr:DesignTimeRef как строковое отображаемое имя, а xsi:nil — как потерянную настройку. Семантику использования приобретённого значения измеряет ORM отдельно.

## Измеренное значение заполнения перечисления

В штатной выгрузке документа Событие четыре перечисления имеют `FillValue xsi:type="xr:DesignTimeRef"`: например, `Enum.ВариантыВажности.EnumValue.Обычная`. В минимальной нативной конфигурации применяется та же форма `Enum.ЗамерПеречисления.EnumValue.Обычная`; XML находится в `tests/conformance/measure/1c/document-fill-enumerations-default.xml`, а 14 результатов платформы — в `measure-document-fill-enumerations-default.platform.txt` рядом с ним.

При создании значение реквизита пустое, несмотря на настройку заполнения. При `Заполнить` отсутствующее поле источника получает настроенный элемент перечисления; явно переданные `Неопределено`, `Null` и пустая ссылка его не подставляют. Непустое существующее значение сохраняется. ORM воспроизводит все 14 строк с типизированным значением в существующем графе, в двух независимых сеансах. Для этого не нужен новый механизм исполнения или отдельный строковый идентификатор внутри объекта документа.

SDK должен отдавать декодированную идентичность владельца и элемента перечисления вместе с состоянием приобретения `FillValue`. Текст XML показывает логическую цель, но не доказывает расположение соответствующих байтов Config: его надо сопоставить с собственным Config-ресурсом. Не возвращать имя, синоним или строку пути вместо типизированного значения; не принимать неразрешённую ссылку за `xsi:nil`. Данные SDK остаются независимыми от типов и графа open-bsl, преобразование выполняет `bsl-config-db` после проверки владельца и элемента в приобретённом снимке.

Штатный XML `DefinedTypes/ОснованиеСобытия.xml` содержит 54 типа ссылок на документы и 2 на справочники. Сохранить весь объединённый набор, не только первый тип. Данные этого декларативного XML не определяют начальное BSL-значение; оно проверяется на платформе отдельно.

Полный исходный определяемый тип теперь проверен в изолированной базе платформы: `unf-event-basis-defined-type.xml`, генератор минимальных объектов `prepare-unf-event-basis.py`, сценарий `measure-unf-event-basis.bsl` и его `.platform.txt` находятся в `tests/conformance/measure/1c/`. Платформа подтверждает 56 типов и сохраняет тип/UUID во всех 224 присваиваниях и заполнениях. Для SDK это проверяемая граница достаточности: развёртывание именованного типа должно сохранить все 56 членов. Этот стенд не доказывает декодирование Config; его по-прежнему необходимо сопоставить с исходным ресурсом базы УНФ.

Тип `v8:ValueStorage` исходного реквизита `Событие.КартинкиHTML` также измерен на платформе: `document-fill-value-storage.xml`, `measure-document-fill-value-storage.bsl` и 16 строк `.platform.txt`. SDK должен сохранить этот конкретный тип и отдельно состояние nil FillValue; не преобразовывать тип в Unknown или значение по умолчанию в примитивное Неопределено. Начальное значение и правила заполнения создаёт ORM по измеренному поведению, а не декодер Config.

## Сохранённый перечень исходных реквизитов

`open-bsl/docs/research/unf-event-native-attributes.json` содержит все 26 непосредственных реквизитов документа Событие из нативной XML-выгрузки: GUID, имя, прямые типы, именованный набор типов, квалификаторы, FillFromFillingValue и отдельные nil/тип/текст FillValue. Для сверки декодера используйте GUID и весь список типов. В нём шесть DesignTimeRef, а не только четыре ссылки на перечисления. Этот JSON — свидетельство XML, не формат нового SDK API и не обход приобретения Config; runtime не читает его.
