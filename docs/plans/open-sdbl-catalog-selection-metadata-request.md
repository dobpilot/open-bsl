# Метаданные для завершения выборки справочника

Текущая ветка open-sdbl-v9 0.9.5 сообщает иерархию, собственные реквизиты, табличные части и основное представление. Для полной реализации аргументов СправочникМенеджер.Выбрать в bsl-orm нужны дополнительные приобретённые сведения. Ни одного значения нельзя выводить из исходников, имён физических таблиц или отсутствия неизвестного поля.

1. Полный упорядоченный список владельцев справочника: Option<Vec<Guid>>, где Some([]) доказывает отсутствие владельцев, None означает неизвестную/неполную форму. GUID относятся к объектам конфигурации, не к типам ссылок или строкам базы. До декодирования измерить несколько подчинённых и неподчинённых справочников на XML, выгруженном платформой; сохранить обезличенные фикстуры.
2. Признак индексирования собственных реквизитов, достаточный для допуска отбора/порядка. Сохранить неопределённость и различие НеИндексировать, Индексировать, Индексировать с дополнительным упорядочиванием; не определять по наличию индекса СУБД. Тип реквизита уже доступен, новый декодер типов не нужен.
3. Нормативные списки коллекций остаются полными или неизвестными; не выдавать частично найденные владельцы за полный список.
4. Изменения через отдельный OpenSpec до кода, первичный замер Config против XML, тесты известных/неизвестных форм, общая обработка PostgreSQL/MSSQL. Не добавлять SQL в синхронный wrapper и не менять существующую семантику приобретения конфигурации.

В root пока не добавлены фиктивные defaults и не изменён sibling SDK. Запрос фиксирует необходимую границу; версия SDK и ветка следующего изменения здесь не назначаются.
