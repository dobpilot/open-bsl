# Проверка проекции описаний расширений

Аудит 2026-10-02 подтвердил реализацию `project_configuration_extensions`:
описания сортируются по `order`, активные и отключённые идентификаторы
разделяются, неизвестные обязательные поля возвращают
`IncompleteExtensionMetadata`. Версия берётся из `runtime_version`, а
платформенный хеш — из `hash_sum`; частичные `version` и `content_hash`
не подставляются вместо них.

Текущие тесты проверяют выбор активных расширений, порядок применения,
добавление и замену модулей, отказ при неизвестной активности, режимы
безопасности и их неизвестные поля. Тесты ORM отдельно проверяют свойства
и фильтрацию уже построенного снимка через BSL. Это не сквозная проверка
перехода от приобретённого SDK-описания к BSL-объекту.

Попытка такого теста обнаружила границу SDK: `AcquiredExtension` объявлен
`#[non_exhaustive]`, не имеет публичного конструктора и `Default`.
Создать искусственный экземпляр в адаптере нельзя. Непригодный тест удалён;
производственный алгоритм не менялся. Не обходить эту границу через
`unsafe`, вторую копию модели или дополнительный API только ради теста.

Для сквозной проверки использован экземпляр настоящего read-only приобретения
buh. Два активных расширения прошли сравнение SDK-сведений с BSL-свойствами:
версия, платформенный хеш, режим безопасности, РИБ, активность, область действия,
порядок и UUID. Преобразование UUID проверялось обратным вызовом существующего
`Guid::to_1c_bytes`, без второй реализации перестановки байтов. Проверены
счётчики всех, активных и отключённых описаний: `2`, `2`, `0`.

Затем диагностическая программа пыталась восемь раз построить полный каталог
с одним отсутствующим полем. Этот этап остановлен ограничением 360 с;
отрицательные сквозные случаи этим прогоном не подтверждены. Журнал:
`/tmp/open-bsl-extension-projection-096.log`. Предупреждения о трёх нечитаемых
ресурсах сохранены; полное приобретение без пропусков не заявляется.

Преобразование одного описания выделено во внутреннюю функцию без изменения
публичного API, порядка проверок и правил выбора полей SDK. Новый внешний
файл unit-тестов проверяет результат преобразования через BSL, включая
отключённое расширение с именованным профилем, и восемь отсутствующих либо
повреждённых обязательных полей. Все 59 тестов адаптера прошли. Эти проверки
не требуют конструировать непрозрачный SDK-тип или повторно строить весь
каталог. Структурные операции и порядок применения остаются покрыты прежними
тестами; дальнейшее закрытие изменения требует общего прогона workspace.
