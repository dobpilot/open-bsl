# Запрос open-sdbl: условное разделение общего реквизита

Предлагаемая версия: **0.9.14**. База — ветка `fix/data-separator-use-0.9.13`,
коммиты `e07cd83` и `ffbd69e`. Не сливать изменения в main автоматически.

## Причина

Оригинальный тонкий сеанс demo теперь проходит чтение начального
`ОбластьДанныхЗначение`, но останавливается на
`Константы.ОграничиватьДоступЧерезВебСерверы.Получить()`:
`cannot use table: data separator "ОбластьДанныхОсновныеДанные" with independent usage is disabled`.

Разделитель действительно принадлежит таблице константы. Ошибку нельзя
исправлять снятием защиты Independent, исключением константы из разделителя,
подстановкой true use или переписыванием исходника.
Не приобретено отдельное условие использования разделителя.

## Первичные доказательства

В open-bsl см. `docs/research/common-attribute-conditional-separation.md`.
Достигнутый вызов установлен диагностикой адаптера, а не по догадке о позиции.

Ресурс сохранён в
`crates/bsl-config-db/tests/fixtures/common-attributes/6df2bb92-558c-4453-9de4-e4176e8f93dc.deflate`.
Его хвост после состава содержит:

```text
{1,fa44433b-1c44-45a0-9487-47aa092442cf},
{1,041cecfd-cef2-45d9-90e8-afe0d97d2d95},
{1,cc906f05-5ea6-43cb-a084-c4ee51ca4bd5},1,1,0,1,1
```

Первые две ссылки — параметры значения/использования. Третья сопоставляется
приобретённым каталогом константе `ИспользоватьРазделениеПоОбластямДанных`,
физическая таблица `_Const1835`. Форма третьей ссылки должна быть подтверждена
собственной нативной CF/XML парой, а не только этим хвостом.

Полностью прочитанная справка 8.3.27.2342:
`platform-syntax-help:syntax-context:objects/catalog63/catalog272/catalog1506/object1954/properties/ConditionalSeparation9012.html`.
`ОбщийРеквизит.УсловноеРазделение` — булева константа вне состава этого общего
реквизита; её значение задаёт использование разделителя.

Нативный контроль open-bsl:
`tests/conformance/measure/1c/measure-common-attribute-conditional-separation.bsl`
и соседний `.platform.txt`, метка `common-attribute-conditional-separation-5`.
XML общего реквизита — `common-attribute-conditional-separation.xml`, константа
— существующий `functional-option-constant.xml`. Получено:

- Начальное false условие и false use разрешают запрос.
- Запись true условия в том же сеансе немедленно запрещает запрос с false use.
- True use разрешает запрос в заданной области; возвращение false use запрещает.
- Контроль создаёт строки `empty`, A и B. При включённом условии/B выбирается
  `B;`; после выключения условия и установки параметра C выбирается `empty;`.
- Выключенное условие не означает unrestricted: требуется пустая область.

Числовой вариант измерен отдельно:
`measure-common-attribute-conditional-separation-number.bsl` и соседний результат,
метка `common-attribute-conditional-separation-number-1`. Все 21 строки совпадают
по поведению со строковым контролем: включённая область 2 даёт `B;`, выключенное
условие при параметре 3 даёт `empty;`. Пустое значение здесь числовое 0.

## Работа

1. Сначала отдельный OpenSpec change, английские спеки и strict validation.
   Старые архивы не редактировать. Снять/удержать нативную CF/XML пару для
   отсутствующего и заданного общего `ConditionalSeparation`; приобрести
   ссылку на константу через существующий декодер Config.
2. Передать приобретённую ссылку через `DataSeparationSettings` и разрешённый
   `DataSeparation`. Не путать её с `Content.Item.ConditionalSeparation`:
   последний уже имеет отдельный контракт и остаётся отдельной областью.
   Проверить существующий demo fixture и тип/идентичность целевой константы.
3. Дать хосту минимальный типизированный способ передать значение условия
   существующему компилятору запросов. Например, отдельные значения условий
   в `SessionParameters`, с ключом GUID константы; они не становятся BSL
   параметрами сеанса. Выбрать простую форму по существующим приёмам SDK.
   Не создавать новый SQL-генератор или I/O в основном крейте.
4. При неизвестном требуемом значении условия вернуть структурную диагностику
   с идентификатором константы. Это **не** missing-session-parameter:
   open-bsl должен прочитать константу через тот же Session-owned адаптер,
   передать значение компилятору и повторить компиляцию. Старый контракт
   missing use/value сохранить для реально требуемых параметров сеанса.
5. При false условии использовать измеренное пустое значение разделителя,
   не требовать use/value и не выбирать чужие области. При true условии
   сохранить поведение 0.9.13. При отсутствии связи сохранить прежнее поведение.
   Не закреплять значение константы навсегда при первом чтении: изменение
   в том же сеансе действует на следующий запрос по нативному контролю.
6. Проверить два SQL backend, прямой источник, константу, разыменование и
   достигнутые виртуальные таблицы. Неприменимый разделитель не требует условия;
   prepare не требует живых значений. Для неподдержанной формы условия или
   неизвестного пустого значения выдавать явный отказ.
7. Дополнительно измерить ConditionalSeparation для Shared, прежде чем
   переносить на него вывод из Independent. Не объявлять неподтверждённые
   типы/режимы поддержанными. Не расширять работу на authentication/users
   separation, регламентные задания или извлечение исходников.

## Проверки и отчёт

Новых зависимостей нет. Комментарии/rustdoc по-русски. Пройти fmt, workspace
Clippy, workspace tests, rustdoc с `-D warnings`, strict OpenSpec до реализации
и после отдельной архивации. Изменённые старые ожидания показать явно и
обосновать нативным результатом; не ослаблять SQL snapshot corpus.

В отчёте: фактический API для open-bsl, пример структурной диагностики условия,
удержанные нативные артефакты/версии, границы поддержанных режимов, результаты
проверок и хеши двух отдельных коммитов. Изменения прав/RLS и записи констант
здесь не реализовывать: компилятор получает измеренные условия от хоста.

## Дополнительное первичное доказательство Shared

В open-bsl отдельно выполнен `measure-common-attribute-conditional-separation-shared.bsl`
с соседним `.platform.txt` и XML режима IndependentlyAndSimultaneously.
String: false условие/C даёт только `empty;` (count=1), также при false use;
true условие/B даёт `B;`; после возврата true условия при false use —
`A;B;empty;` (count=3). Receipt содержит 20 строк и обе метки, без control_error.
Подробности и предупреждение запуска записаны в исследовании. Shared String
теперь подтверждён отдельным замером; Numeric Shared этим контролем не измерен.
Сохранить различие true-condition/false-use для Independent и Shared.

Numeric Shared теперь также измерен отдельным
`measure-common-attribute-conditional-separation-number-shared.bsl` и соседним
`.platform.txt`: false condition/3 выбирает только empty (0), true condition/2
выбирает B, true condition/false use возвращает все три строки. 20 строк, обе
метки, без control_error; XML и исследование сохранены в open-bsl. Использовать
этот контроль наряду со String, а не выводить Numeric из строкового результата.
