# Собственный нативный замер хранения привязок пользователя

Цель — установить фактические bytes v8users.Data для известных пустых и непустых привязок РазделениеДанных, а также фактическую таблицу/формат сохранённых общих настроек. Две проверки используют одну собственную конфигурацию, но отдельные уникальные ключи и отдельные доказательства.

Использовать 1С8.3.27.2342 и отдельный временный автономный ibsrv с данными только в /tmp. Создать отдельную тестовую PostgreSQL-базу с уникальным именем open_bsl_user_settings_control_1013; demo/buh/unf не изменять. Для конфигурации переиспользовать уже проверенный собственный общий реквизит НаименованиеЯзык1, его параметры и измерительную обработку. Никакие оригинальные модули конфигураций не загружать. Расписание заданий отключить, сервер слушает только loopback, используемые порты предварительно проверить. Пароли передавать только через непротоколируемый локальный конфиг/окружение, не в receipts, репозитории или конечном ответе.

Нативный код создаёт только собственных пользователей/записи: известное пустое и структура НаименованиеЯзык1=own-separator-value; записывает отдельные общие настройки missing/scalar/storage с уникальными ключами. Сохраняет платформенный результат чтения. SQL-путь после нативного завершения использует read-only транзакцию, извлекает только собственные записи и байты. Пользовательские password hashes не включать в retained fixture; если удаление таких полей нарушает декодируемость, удержать только отдельные измеренные поддеревья и provenance, а весь секретный blob не публиковать.

Сравнить native property/Get и decoded snapshots до любых решений о новой форме SDK API. Дополнить запросы open-sdbl-user-data-separation-request.md и open-sdbl-common-settings-read-request.md. Запуск/остановка и экспорт имеют ограниченный timeout, сохраняют безопасные receipts и PID. Непредвиденный отказ платформы не считается измерением. Остановить только собственный сервер по проверенному PID. Не удалять базу автоматически после сбоя, чтобы сохранить артефакты; очистку выполнять отдельно по установленной принадлежности.

Открытая граница запуска: текущий публичный Unica MCP не предоставляет запуск такого автономного контура. Skill autonomous-server требует использовать публичный runtime и запрещает обход прямым runner. Прямые штатные ibsrv/ibcmd/1cv8 допустимы здесь только после явного указания пользователя, которое имеет приоритет над правилом навыка. Пока указания нет, этот контур не запускать.
