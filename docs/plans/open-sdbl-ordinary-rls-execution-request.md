# Запрос: исполнение обычного запроса при RLS

## Обнаруженное расхождение

`bsl-config-db/src/data_access.rs::require_allowed_for_restrictions`
отклоняет обычный запрос при любом ограниченном решении доступа до
исполнения SQL. Это консервативный отказ, но он не воспроизводит успешное
нативное чтение разрешённой записи. Требование уже задано в активном
OpenSpec `complete-configuration-session-runtime`, разделе
`Principal-bound data access`: обычный запрос сохраняет отдельное
платформенное поведение ошибок.

Нативные результаты 1С 8.3.27.2342 находятся в
[`accumulation-field-access`](../research/fixtures/accumulation-field-access/README.md):

- `query-rls-allowed.platform.txt`: Read=true, ограничение Read категорией
  `a`, контрольное движение `a`; обычные запросы измерения и ресурса
  успешно возвращают одну строку.
- `query-rls-queries.platform.txt`: Read=true, ограничение категорией `b`,
  то же движение `a`; обычные запросы возвращают ошибку доступа,
  `РАЗРЕШЕННЫЕ` — ноль строк.
- `query-rls-manager-filter.platform.txt`: менеджер с отбором `a`
  возвращает ошибку, с отбором `b` — ноль строк.

Это измерения конкретных запросов остатков. Из них нельзя вывести правила
произвольных соединений, агрегатов, пакетных запросов или согласованности
нескольких отдельных SQL-операций.

## Требуемая граница

SDK должен предоставлять через существующий компилятор и его результат
достаточную информацию для корректного исполнения обычного запроса
с ограничениями выбранного пользователя. Разрешённое чтение должно
успешно завершаться, запрещённое — возвращать ошибку. Для `РАЗРЕШЕННЫЕ`
сохраняется существующее применение ограничений к результату.

Адаптер open-bsl не должен самостоятельно разбирать запрос повторно,
конструировать SQL ограничений, заменять обычный запрос на
`РАЗРЕШЕННЫЕ` или считать пустую отфильтрованную выборку доказательством
отсутствия запрещённых записей. Проверка использует то же соединение,
выбранного principal и текущие параметры сеанса. Отсутствие проверенной
информации сохраняет явный отказ, который документируется как ограничение
реализации, а не как нативный результат.

## Проверка

Нужны отдельные тесты успешного обычного запроса, ошибки обычного запроса
и фильтрации `РАЗРЕШЕННЫЕ` на одном и том же наборе контрольных данных.
Положительный путь обязан доходить до исполнения, а не только до
`check_user_field_access`. Отдельно проверить явный отбор менеджера.
Более широкий контракт требует дополнительных нативных измерений.

Запрос передан агенту 0.9.10 для оценки существующего API. Этот документ
не назначает следующую версию SDK и не разрешает публикацию пакета.


## Повторная проверка доступного SDK 0.9.20, 2026-10-16

После согласованной интеграции SDK0.9.20 пробел остаётся. Публичный
`CompiledQuery` в `src/query/core/resolve.rs` содержит SQL, колонки,
логическую проекцию, отложенные представления, вложенные результаты
и служебные колонки. Контракта проверки запрещённых строк обычного
запроса в результате нет. `DatabaseDataAccess` по-прежнему вызывает
`require_allowed_for_restrictions`: любое ограниченное решение при
обычном SELECT даёт консервативный отказ до исполнения.

Требуется именно исправить измеренный положительный путь, сохранив
отрицательный и `РАЗРЕШЕННЫЕ`; снимать защитный отказ до предоставления
соответствующего контракта SDK нельзя. Сохранённые native-квитанции
достаточны только для перечисленных выше запросов остатков и отбора
менеджера. Неподдержанные формы должны оставаться явными отказами.
Новые зависимости, второй разбор запроса в open-bsl, независимый
SQL-генератор ограничений и изменение рабочих баз не требуются.

Версия следующей доработки и запуск отдельного агента ожидают
назначения пользователем. Предлагаемый номер —0.9.21; это предложение,
а не назначение версии или разрешение публикации.

## Выполнено в SDK 0.9.21, 2026-10-16

Пользователь назначил версию 0.9.21 и разрешил отдельного агента.
Изменение реализовано и интегрировано: `ordinary_row_checks(true)`
и `forbidden_row_column` позволяют проверить отказ до материализации.
Десять случаев выполняются через фактический адаптер open-bsl на собственном
PostgreSQL; отдельный контроль запрещает непроверенный SQL-захват
вложенного источника до исполнения. Отчёты и точная граница поддержки —
[`ordinary-rls-sdk21-integration-1016`](../research/fixtures/ordinary-rls-sdk21-integration-1016/README.md).
Ранние упоминания ожидания назначения версии выше описывают историю запроса.
Они не означают, что работа всё ещё ожидает назначения. Публикация SDK
и более широкая поддержка запросов этим результатом не заявляются.
