# Запрос: метаданные регистра накопления для `Остатки()`

Работать в `open-sdbl`. Текущий проверенный API — 0.9.8. Следующий
номер версии согласовать отдельно; этот запрос не разрешает менять
версию или реализовывать код внутри open-bsl.

## Зачем

Оригинальный менеджер demo
`РегистрНакопления.КоличествоЗадачПоИсполнителям.МодульМенеджера`
использует `Остатки(, Отбор, Измерения)`. ORM должен использовать
существующий запросный путь SDK, сохраняя principal, права и RLS.
Для проверки аргументов и результата нужны достоверные настройки
регистра, включая состав и порядок измерений и ресурсов.

## Что уже есть — не реализовывать повторно

- `ConfigFieldPurpose::AccumulationRegisterDimension` и
  `AccumulationRegisterResource` различают роли полей.
- Вложенные `ConfigDescriptor` имеют GUID, имя и `declared_types`.
- Виртуальная таблица `AccumulationKind::Balance` и её SQL-кодогенератор
  уже реализованы; новый SQL для этого запроса не требуется.
- `MetadataSnapshot.fields()` и физические `owner_tables` используются
  запросным кодогенератором. Они не заменяют контракт полного порядка
  коллекций конфигурации.

## Запрашиваемый API

По образцу существующих `catalog_attributes` и `characteristic_attributes`
добавить к собственному описателю регистра накопления:

```rust
pub accumulation_register_kind: Option<AccumulationRegisterKind>,
pub accumulation_register_dimensions: Option<Vec<Guid>>,
pub accumulation_register_resources: Option<Vec<Guid>>,

pub enum AccumulationRegisterKind {
    Balance,
    Turnovers,
}
```

Имена допускается согласовать со стилем SDK. Контракт важнее написания:
списки содержат GUID собственных членов в порядке конфигурации.
Типы, имена и синонимы остаются в существующих описателях членов.
Не добавлять второй набор полных описателей и не выводить вид регистра
из наличия физической таблицы итогов.

`Some([])` означает проверенную пустую коллекцию. Неизвестная форма,
повреждение, несовпадение счётчика или пропущенный член дают `None`
для соответствующей коллекции целиком. Частичный список запрещён.
Вид регистра неизвестного кода — `None`; код не угадывается.
У описателей иных видов новые поля равны `None`.
После приобретения и сборки снимка сведения должны сохраниться в
`MetadataSnapshot.descriptors`; выборочная загрузка ресурсов не должна
терять уже приобретённые коллекции.

## Измерение и проверки

Перед декодером завести и строго провалидировать OpenSpec change.
Снять нативные артефакты собственного регистра видов «Остатки» и
«Обороты», включая пустые коллекции и несколько членов с различимым
порядком. Менять исходные demo/buh/unf не требуется.
Проверить коды и расположение данных по реальной 1С, не по аналогии
с другими классами. Сохранить происхождение бинарных и XML-фикстур.

Тесты должны проверять оба вида, порядок, пустоту, отказ при повреждении,
изоляцию от реквизитов и других объектов, сохранение в итоговом снимке.
Read-only приобретение demo должно показать нужный регистр с полными
коллекциями либо явно диагностировать неизвестную форму.
Публичный API документировать по-русски с контрактом `None`.
Выполнить fmt, Clippy, workspace tests, rustdoc и strict OpenSpec.
Архивировать change отдельным коммитом после зелёных проверок.

## Уже измеренный контракт результата метода

Контроль open-bsl на 8.3.27.2342 сохранён в
`docs/research/fixtures/accumulation-register-balance/`.
Прямой метод возвращает ресурс `Количество`, а виртуальная таблица
запроса — `КоличествоОстаток`. Метод возвращает число 38,2 при
исходном ресурсе 15,2. Описания типов запроса содержат `Null`, метода —
нет. Преобразование этих результатов относится к ORM и не входит
в изменение SDK. Эти квитанции не определяют бинарный формат Config.

## Выполнено в SDK 0.9.9

Реализация `1e8af74`, архив `ab0e44a`, ветка `feat/runtime-object-metadata-0.9.9`. Запрошенные описатели доступны и подключены к существующей ORM-проекции open-bsl. Нативные проверки адаптера, границы поддержки и фактический результат оригинального compile-only demo зафиксированы в [отчёте подключения](../research/sdk-099-runtime-metadata-integration.md). Это закрывает запрос приобретения метаданных, но не реализацию всех операций ORM либо оригинальный startup.
