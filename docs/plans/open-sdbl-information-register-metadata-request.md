# Запрос: метаданные регистра сведений для `Получить()`

Работать в `open-sdbl`. Проверенный API — 0.9.9. Номер следующей
версии согласовать отдельно. Этот документ не разрешает менять версию.

## Причина

Compile-only оригинальной demo достиг менеджера
`РегистрСведений.УдалитьОтметкиВремениСсылочныхОбъектов.МодульМенеджера`.
Его экспортная функция `ОтметкаВремени` создаёт отбор по измерению
`Ссылка`, вызывает `Получить(Отбор)` и читает ресурс `Отметка`.
Сейчас компиляция останавливается на `UndefinedFunction("Получить")`.
Исходник проверен read-only; соединение закрыто до разбора, прикладной
BSL не выполнялся. Конфиденциальный модуль в репозиторий не копируется.

Справка 1С 8.3.27.2342 для `InformationRegisterManager.Get` различает
периодическую и непериодическую сигнатуры. Результат — структура ресурсов;
отбор задаёт все измерения. При отсутствии записи требуются пустые
типизированные значения ресурсов. Справка не заменяет измерение поведения
метода и бинарного формата.

Первый нативный контроль ORM сохранён в
`docs/research/fixtures/information-register-get/`: независимый
непериодический регистр, одно числовое измерение и ресурс, пустая база.
Полный отбор возвращает только ресурс со значением 0; пропущенный
отбор и пустая структура отвергаются как параметр №1. Все девять строк
сохранены с происхождением. Этот замер не определяет расположение
настроек в бинарном Config и не заменяет контроли приобретения SDK.

Дополнительный контроль Day-регистра показал: запись приводит период
к началу дня, прямой `Получить` — нет. Только точное начало дня
находит запись; другое время того же дня даёт пустой ресурс. SDK
должен отдавать настройку периодичности, а не навязывать округление
аргумента метода. Квитанция `periodic.platform.txt` содержит 11 строк.

## Уже существующие механизмы

`ConfigFieldPurpose` различает `InformationRegisterDimension`,
`InformationRegisterResource`, `InformationRegisterAttribute`.
Вложенные описатели уже содержат GUID, имена и объявленные типы.
Запросы исполняются существующим SDK-компилятором через адаптер текущего
сеанса, principal, права и RLS. Не добавлять другой SQL-компилятор.

Роли отдельных найденных полей не доказывают полноту коллекции.
В 0.9.9 у собственного `ConfigDescriptor` регистра сведений нет
контракта полных измерений/ресурсов и периодичности. Не вычислять их
из исходного BSL, имени SQL-таблицы или отсутствия найденных полей.

## Необходимый контракт приобретения

По образцу уже добавленных полей регистра накопления предоставить
на собственном описателе регистра сведений:

```rust
pub information_register_dimensions: Option<Vec<Guid>>,
pub information_register_resources: Option<Vec<Guid>>,
pub information_register_periodicity: Option<InformationRegisterPeriodicity>,
pub information_register_write_mode: Option<InformationRegisterWriteMode>,
```

Имена согласовать со стилем SDK. Состав enum определить по измеренным
значениям платформы, включая непериодический регистр; неизвестный код —
`None`. Не переносить enum периодичности нумерации документов.
Режим записи должен явно отличать независимый регистр от подчинённого
регистратору. Не выводить независимость из отсутствия разобранного поля
регистратора: начальный ORM-контракт принимает только независимые регистры.

Списки содержат собственные члены в порядке конфигурации. Имена, типы
и квалификаторы остаются в существующих описателях членов. `Some([])` —
проверенная пустота; неизвестная форма, повреждение, пропущенный член,
дубликат или неверный счётчик дают `None` для коллекции целиком.
Нельзя публиковать частичный список как полный. Реквизиты, общие
реквизиты и члены соседних объектов в списки не входят.

Сведения сохраняются в итоговом снимке и при выборочном приобретении
после освобождения исходных байтов. У других классов новые поля — `None`.
Не добавлять исполнение BSL или чтение данных регистров в приобретение.

## Проверки

Сначала OpenSpec и strict validation. Измерить на собственной тестовой
конфигурации 1С настройки периодичности, порядок коллекций и допустимую
пустоту; сохранить бинарные/XML-артефакты и происхождение. Не считать
недопустимую конфигурацию измеренным пустым случаем.

Покрыть полные/пустые/неизвестные коллекции, повреждения, неизвестный
код, изоляцию владельцев и сохранение при выборочном приобретении.
Read-only demo должна показать достоверные сведения указанного регистра
либо явно оставить неизвестные поля. Прикладной BSL не запускать.

Публичный API документировать по-русски. Выполнить fmt, Clippy,
workspace tests, rustdoc и strict OpenSpec; архивировать отдельным
коммитом после зелёных проверок. Реализация самого `Получить`, точность
периода, проверки отбора и преобразование результата остаются в ORM
и требуют собственного платформенного контроля.
