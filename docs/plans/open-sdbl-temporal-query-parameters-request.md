# Запрос: параметры момента времени и границы в существующем компиляторе

Работать в `open-sdbl`. Проверенный API — 0.9.9. Номер следующей версии
согласовать отдельно; этот документ не разрешает запускать агента,
менять версию или записывать данные рабочих баз.

## Достигнутый оригинальный вызов

Compile-only demo остановился на голом `МоментВремени()` в
`Документ.ПередачаДелВАрхив.МодульОбъекта`. Read-only извлечение
исходника показало передачу параметра запроса:

```bsl
Запрос.УстановитьПараметр("Период",
    Новый Граница(МоментВремени(), ВидГраницы.Исключая));
```

Полный прикладной модуль не копируется в репозиторий и не исполнялся.
Runtime open-bsl не должен заменять момент датой, границу — булевым
флагом без ключа ссылки, а запрос — отдельным SQL-генератором.

## Что уже есть

- `query/core/codegen/context.rs` содержит синтезированное поле
  `POINT_IN_TIME_SCHEMA_NAME`, `point_in_time_field` и разрешение
  `МоментВремени`/`PointInTime` для источника.
- `ParameterValue` содержит дату и ссылку с `ObjectId` и физическими
  RRRef-байтами. Отдельного значения момента или границы в 0.9.9 нет.
- Компилятор уже знает физическую схему и различает ссылки по объектам;
  права и RLS идут тем же путём приготовления и исполнения запроса.
- В open-bsl есть `uuid::to_1c_bytes`; не добавлять ещё одну перестановку
  UUID ради момента времени.

## Требуемый контракт

Расширить публичную модель параметров существующего QueryCompiler так,
чтобы она могла выразить:

1. Момент времени: дата и необязательная типизированная ссылка.
2. Границу по дате или моменту времени с явным включением/исключением.

Точные имена Rust-типов согласовать со стилем SDK. Тип ссылки и её
физические байты должны сохраняться раздельно. Отсутствующая ссылка
отличается от пустой ссылки конкретного вида. Не принимать строковое
представление момента, текст SQL либо произвольную структуру как
замену этому контракту.

Поддержать необходимые позиции существующих выражений и временных
аргументов виртуальных таблиц. Если какая-то позиция ещё не поддержана,
возвращать явную диагностику, а не молча терять ссылку или включение.
Новые параметры должны проходить прежнюю проверку метаданных, типов,
прав и RLS; они не открывают обход через сырой SQL.

Порядок даты, типа ссылки и UUID должен соответствовать измеренной
платформе. Не выводить порядок видов из имён или GUID метаданных.
SQL PostgreSQL и SQL Server должны выражать один логический контракт,
сохраняя существующее преобразование года и представление ссылок.

Обратное чтение синтезированного поля момента должно сохранить полную
схему результата, достаточную для восстановления даты и типизированной
ссылки адаптером open-bsl. Если текущий контракт результата уже это
обеспечивает, использовать его; не добавлять дублирующий формат.

## Нативные свидетельства

`docs/research/fixtures/document-point-in-time/` в open-bsl содержит:

- свойства нового незаписанного документа и ошибку пустой ссылки;
- Compare и равенство, запрет оператора `<`, неизменяемый снимок даты;
- различие пропущенной ссылки и пустой типизированной ссылки;
- порядок UUID внутри групп и между группами;
- три вида документов с нативными именами Document53/55/56, одинаковыми
  и переставленными UUID. Наблюдаемый порядок следует номерам хранения.

`docs/research/fixtures/accumulation-register-balance/` содержит отдельные
контроли date-boundary и moment-boundary: непосредственная дата в точке
движения исключает его; включающая граница момента включает собственное
движение, исключающая — нет. Это не доказывает общий порядок всех классов
метаданных и не заменяет контроль нескольких регистраторов одной даты.

## Процесс и проверки

Сначала OpenSpec, design, задачи и strict validation. Начать с анализа
существующего синтезированного поля и временных аргументов, расширять
их, а не писать второй компилятор.

Добавить собственные нативные контроли различимых документов одной даты,
пустой/отсутствующей ссылки, обеих границ и требуемых виртуальных таблиц.
Контроль записывает данные только в отдельную тестовую базу. Сохранить
артефакты и происхождение. Уточнить поддержку ссылок других классов
до обещания общего порядка.

Проверить оба SQL-диалекта, диагностируемые неподдержанные позиции,
параметры вместе с правами/RLS, сохранение типов результата и прежние
скалярные параметры. Комментарии и публичный Rust API — по-русски.
Выполнить fmt, Clippy, workspace tests, rustdoc и strict OpenSpec;
архивировать отдельным коммитом после зелёных проверок. Main и публикацию
не трогать. Реализация BSL-объекта и конструктора остаётся в open-bsl.

Однопараметровая Граница совпала с Включая во всех семи проверенных случаях. Выводы ограничены аргументом балансов; другие классы, turnover virtual tables и произвольные expression positions не сертифицированы.
