# Запрос: проверка прав полей регистра сведений

## Воспроизводимое расхождение

В SDK 0.9.21 `open-sdbl-db/src/access.rs::check_user_field_access`
подтверждает программное чтение полей по праву владельца для справочников
и регистров накопления. Ветка `InformationRegister` отсутствует.
В результате чтение измерения и ресурса регистра сведений отклоняется до SQL,
хотя пользователь имеет право `Read` на регистр.

В open-bsl добавлена проверка с реальным отдельным PostgreSQL:
`crates/bsl-config-db/src/local_database_read_tests.rs`.
Положительный сценарий `numeric_register_get_reads_the_actual_postgres_row`
воспроизводит отказ проверки поля. Повторный запуск на SDK 0.9.21
с выключенным флагом умолчаний сохраняет тот же отказ; оба отрицательных
контроля проходят. Журнал:
`docs/research/fixtures/local-postgres-session-adapter-1016/register-read-sdk21/`.
Структура физической таблицы в этом тесте синтетическая; она не является
измерением хранения платформы.

## Нативное свидетельство

Артефакты находятся в `docs/research/fixtures/information-register-rights-1016/`.
Замеры выполнены на 1С 8.3.27.2342 в собственной временной файловой базе,
без изменения рабочих баз. Каждый результат содержит имя пользователя
и подтверждение выключенного привилегированного режима.

Четыре профиля непериодического регистра (`profiles/*.platform.txt`):

- `ReadOwner`: `Read=true`, `setForAttributesByDefault=false`; `Получить()`
  и запрос измерения и ресурса возвращают значение `13`.
- `ReadDefaults`: `Read=true`, `setForAttributesByDefault=true`; те же чтения
  возвращают `13`.
- `NoRead`: оба флага выключены; `Получить()` и запрос завершаются отказом.
- `DefaultsOnly`: право `Read` выключено, флаг умолчаний включён; чтение
  также запрещено.

Периодический регистр проверяется отдельным скриптом `read-day.bsl`;
результаты сохраняются в `day-profiles/`. В положительном сценарии
`ReadOwner` метод `Получить(Дата(2024, 1, 2), Отбор)` возвращает `42`,
запрос периода, измерения и ресурса возвращает одну строку с периодом
`20240102000000`. Все четыре профиля проверены: `ReadDefaults` также возвращает `42`,
а `NoRead` и `DefaultsOnly` получают отказ и в методе, и в запросе.

## Требуемая граница

Поддержать измеренное программное чтение полей регистра сведений через
существующую проверку SDK. Принадлежность измерения, ресурса и стандартного
поля периода должна подтверждаться метаданными. Нельзя разрешать произвольный
GUID поля, поле другого объекта или непроверенную форму заголовка.
Право `Read` владельца остаётся обязательным; флаг умолчаний сам по себе
не заменяет его. RLS и выбранный principal сохраняются.

Не переносить SQL или разбор прав в open-bsl. Не расширять этот запрос
на запись, неизвестные стандартные поля и неизмеренные правила явных
ограничений отдельных полей.

## Приёмка

- Нативные положительные и отрицательные результаты сохранены как фикстуры.
- SDK проверяет принадлежность каждого поддержанного поля регистру.
- Положительный тест open-bsl читает существующее значение `13`,
  отсутствующая запись даёт предусмотренный контрактом результат.
- Запрещённое чтение и другой principal не получают существующую запись.
- Существующие тесты не меняются без отдельного согласования.
- OpenSpec, форматирование, Clippy, тесты и rustdoc проходят.

Пользователь согласовал отдельного SDK-агента и версию 0.9.23. Агент `open_sdbl_0923_field_rights` выполняет этот запрос вместе с запросом прав полей документов в изолированной полной копии текущего SDK. Перенос в используемый потребителем SDK выполняется отдельно после проверки патча.
