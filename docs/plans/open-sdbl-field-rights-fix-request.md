# Запрос агенту open-sdbl: сопоставление прав стандартных полей

Работай в open-sdbl, ветка open-sdbl-v9. Версию следующего выпуска согласовать с владельцем; произвольный номер не назначать. Изменения нужны существующему адаптеру open-bsl, не новой реализации языка.

## Воспроизводимый отказ

На тестовой базе PostgreSQL `buh` приобретены конфигурация, пользователи и все назначенные права допустимого пользователя. Проверка поиска по собственному реквизиту ИНН у справочника Контрагенты останавливается до SQL:

```
field access: Standard(Id) of 51b9a2d4-bd53-4f40-824e-e3b4e323279e (Projection) is denied: member rights cannot be mapped to the field
```

Стандартная ссылка проецируется также обычной выборкой и предопределёнными значениями. Поэтому дефект блокирует существующий principal-bound путь чтения.

Параметры подключения — ~/.pgpass; не выводить пароль. Стенд: `/tmp/open-bsl-find-live-095-package/src/main.rs`; лог: `/tmp/open-bsl-find-live-buh-complete-rights-095.log`. Стенд использует минимальный модуль сеанса и не доказывает полный запуск оригинальной конфигурации. Проверки разделения данных нельзя отключать для получения зелёного результата.

## Найденный участок

`crates/open-sdbl-db/src/access.rs`, `check_user_field_access`: для `FieldId::Standard` проверяется принадлежность поля объекту, затем выбирается `None`. Следующая ветка `None` выставляет `uncertain`, даже когда роль даёт Read объекту. Подтверди точную причину на ресурсах и проверь также собственные реквизиты с правами по умолчанию.

## Требуемая работа

1. Сначала OpenSpec с измеримыми требованиями и строгой валидацией.
2. Сопоставить бинарные права конкретных ролей с Rights.xml, выгруженным штатными средствами 1С. Измерить права ссылки и других реально читаемых стандартных полей; проверить настройки прав реквизитов по умолчанию. Не вывести универсальное правило из одного GUID или одной роли.
3. Исправить существующее сопоставление полей и права по умолчанию без отдельного декодера в open-bsl. Не выдавать все стандартные поля как доступные только из наличия Read владельца без измерения.
4. Сохранить отказ для действительно закрытого поля, неизвестной формы прав, отсутствующих ресурсов и несопоставимой табличной части. RLS и разделители остаются действующими.
5. Фикстуры без паролей и прикладных данных: стандартная ссылка, реально поддержанные стандартные поля, собственный реквизит; разрешающая и запрещающая роль; неизвестная форма; настройки по умолчанию. Не переписывать старые ожидания ради прохождения.
6. Повторить приобретение и проверку полей на buh. Отдельно подтвердить, что ошибка стандартного поля устранена; успешную компиляцию или последующий отказ по параметру сеанса не называть успешным SQL-чтением.
7. fmt, Clippy, workspace-тесты, rustdoc и строгая валидация; архивировать после зелёного прогона. В отчёте — измеренные правила, диагностические ограничения и фактический результат живой проверки.

## Отдельное наблюдение

У другого выбранного пользователя назначена роль `2bc105dd-b388-436d-9410-a756e3415d30`, которую SDK не приобрёл. Read-only запрос по Config подтвердил отсутствие ресурса с этим GUID. Это не доказывает удаление роли: происхождение из расширения не исследовано. Не смешивать это наблюдение с доказанным отказом сопоставления Standard(Id) у пользователя, чьи права приобретены полностью.

## Дополнительное первичное свидетельство XML

В имеющейся штатной выгрузке **UNF**, а не buh, файл `/tmp/open-bsl-unf-query-schema-xml/Roles/ПолныеПрава/Ext/Rights.xml` начинается с трёх элементов:

```xml
<setForNewObjects>true</setForNewObjects>
<setForAttributesByDefault>true</setForAttributesByDefault>
<independentRightsOfChildObjects>false</independentRightsOfChildObjects>
```

У объекта `Catalog.Контрагенты` в этом файле перечислены запрещённые интерактивные удаления; отсутствие отдельной строки Read не доказывает запрет. Это свидетельство формата декларации, а не замер выполнения и не доказательство аналогичных прав buh. Сопоставь флаги с бинарным ресурсом и проверь их действие на платформе до изменения правил.

`unica.role.info` прочитал этот XML, но вернул null для всех defaults. Поэтому для проверки флагов использован сам штатный XML; результат инструмента нельзя принимать за отсутствие настроек. Исправление инструмента не входит в задачу SDK.
