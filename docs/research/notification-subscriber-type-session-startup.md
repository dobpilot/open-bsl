# Перечисление подписчика уведомлений при компиляции buh

Исходный модуль `РегистрСведений.НастройкиОтправкиPushУведомлений.МодульМенеджера`
использует `ТипПодписчикаДоставляемыхУведомлений.GCM` и `.APNS` в функции
`ДанныеАутентификации`. Отказ возникает при компиляции, до исполнения этих
ветвей. Исходник прочитан через подготовленный SDK в изолированном режиме
только для чтения; журнал —
`target/diagnostics/readonly-startup/buh-push-enum-source-1013-startup.log`.

Нативный замер на собственной временной базе платформы 8.3.27.2342 сохранён
в `fixtures/notification-subscriber-type/`. Все 11 строк получены, включая
начальный и конечный маркеры. Представления: `GCM`, `APNs`, `FCM`; тип членов
печатается как `DeliverableNotificationSubscriberType`. Английское имя
перечисления даёт равные значения.

Реализация использует существующие таблицы `EnumKind`, `EnumValue`, `TypeId`
и сопоставление типа значения. Приоритеты резолвера не меняются. Доставка
уведомлений не реализуется этим изменением. Другие значения, перечисленные
в синтакс-помощнике, не добавлены без отдельных замеров.

Новый внешний тест воспроизводит полный сохранённый вывод, получает тип
через `BslValue::type_of` и проверяет регистронезависимость. Он прошёл,
как и 10 существующих тестов перечислений. Clippy для всех целей `bsl-rt`
и rustdoc этого крейта прошли. Справочник API перегенерирован; его генератор
не включает системные перечисления, поэтому новых строк перечисления
в справочнике нет.

Повторный запуск оригинального buh проводится отдельным неизменяемым
бинарным файлом `session-benum-startup-probe-1013`; рядом сохранена
квитанция с хешем бинарного файла, исходников и коммитом SDK. Итог следует
брать из `target/diagnostics/readonly-startup/buh-subscriber-enum-1013-startup.log`
после завершения процесса, а не из промежуточного журнала.

Повтор завершился с кодом 1 за 193,15 с. Исходный отказ перечисления
пройден; следующий отказ компиляции — `АвтономноеРабочееМесто` в модуле
объекта `ПомощникСозданияАвтономногоРабочегоМеста`. Наблюдаемый пик RSS
1 669 980 КиБ. Успешная инициализация сеанса этим запуском не подтверждена.

Дополнительный прогон существующего конвейера
`cargo test -p bsl-sema -p bsl-bytecode -p bsl-compiler -p bsl-vm`
завершился с кодом 0: 555 тестов прошли, отказов и пропусков нет.
Журнал — `target/diagnostics/notification-subscriber-pipeline-regression-1013.log`.
Это не полный прогон workspace: его текущий отказ сборки тестового
конструктора сеанса записан отдельно в
`configured-session-verification-1013.md`.

Отдельный нативный контроль `measure-bare` дал пять полных строк:
голое имя и его тип печатаются как `EnumDeliverableNotificationSubscriberType`,
псевдонимы равны. Это отличается от типа члена без префикса `Enum`.
Представление метатипа исправлено по этому замеру; новый внешний тест
проверяет весь отдельный oracle. Дельта OpenSpec дополнена и строго
провалидирована до исправления.

Оба сохранённых скрипта также исполнены через текущий CLI, то есть через
обычный резолвер, динамический компилятор и VM. Все строки представлений
значений и типов совпадают с нативными. Сравнения псевдонимов истинны,
но формат булева локализован: CLI печатает `Да`, нативный контроль — `Yes`.
Поэтому полный текст этого прогона не заявляется побайтово равным oracle.
Выводы сохранены в `target/diagnostics/notification-subscriber-cli-1013.actual`
и `notification-subscriber-bare-cli-1013.actual`.
