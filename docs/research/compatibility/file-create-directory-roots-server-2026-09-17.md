# Корневые формы и объект Файл в создании каталога

17 сентября 2026 года на серверной 1С 8.3.27.2342 `/S localhost/test`
проверены корневые и относительные формы синхронного `СоздатьКаталог`, а
также аргумент типа `Файл`. Эффективный режим совместимости —
`НеИспользовать`; Unica не использовалась.

Формы `/`, `//`, `///`, `.`, `./`, `..` и `../` завершаются успешно.
Последние четыре не создают нового элемента. Объект `Файл` успешен в трёх
измеренных состояниях: путь внутри объекта не создаётся, существующий каталог
и обычный файл сохраняются. Эта проба не проверяла каталог `Строка(Файл)` и
потому не доказывала отсутствие побочного эффекта по строковому представлению.

Финальная сессия `/tmp/open-bsl-server-measure-7f3rvap3` восстановила CF и
конфигурацию БД; XML совпал полностью. Предварительная сессия
`/tmp/open-bsl-server-measure-qyaw3b15` остановилась на синтаксической
проверке выражения `Новый Файл(...).Существует()` и также восстановила CF;
её результат не использован как oracle.

- Скрипт SHA-256: `22150b16031a9d15ec01c534ab3fa3177c935a2b7d4c6491f900bc5b725a01fe`.
- Oracle SHA-256: `f675722a8155c7ea87685c31969a79a59bf6bfff6a06b84e7ed7964fc75c98f8`.

До исправления open-bsl отвергал четыре относительные формы и объект
`Файл`. Четыре строковые формы обрабатываются как измеренные no-op до host.
Последующая изолированная серверная проба типов установила, что Файл нужно
форматировать и создавать как обычный непустой путь. Все исходные десять
наблюдений при этом сохраняются: путь внутри объекта не меняется.

`CREATEDIR.PATH_SEMANTICS` остаётся для остальных типов, иных относительных
форм и частичных отказов.

## Асинхронное продолжение

В тот же день клиентский прогон серверной базы повторил десять случаев для
`СоздатьКаталогАсинх`. Все вызовы возвращают обещание. Строковые корни
возвращаются без изменений, а объект `Файл` возвращается тем же объектом
(`same=1`) во всех трёх состояниях. Проверка наблюдала только путь внутри
объекта, поэтому её первоначальный вывод об отсутствии любых побочных
эффектов был сильнее свидетельства.

Сессия `/tmp/open-bsl-server-measure-y11125va` восстановила CF и
конфигурацию БД; XML совпал полностью.

- Async-скрипт SHA-256: `39ea26b136950b7f7630b67af02f9c4f0be84fecf0aae1248bf0f3eb7ed5a3f3`.
- Async-oracle SHA-256: `3004b7035a09824ca6c7a116974e72d0deb9ce1f605f28e28b15881cccad419a`.

Последующая изолированная проба типов 2026-09-18 проверила также каталог
`Строка(Файл)` и установила, что клиентские sync и async действительно его
создают. Поэтому готовым обещанием в VM-потоке остаются только измеренные
строковые no-op; объект Файл форматируется, передаётся worker-у и сохраняется
в VM как исходный результат. См. file-create-directory-types-client-2026-09-18.md.

`benchmarks/hot-code-diff.sh HEAD` не прошёл экран: накопленное рабочее
дерево всего плана относительно `HEAD` изменяет и `step` (8380 строк
сравнения), и `step_cold` (2850 строк). Результат не изолирует этот этап и
не используется как утверждение о производительности; для такого вывода
потребуется отдельный чередующийся A/B от подходящей промежуточной базы.
