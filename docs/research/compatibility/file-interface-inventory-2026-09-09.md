## Значимые границы для реализации

- Все пять свойств — строки только для чтения. Примеры справки не доказывают
  нормализацию относительного пути, ссылок и завершающих разделителей Linux.
- Синхронные `Существует`, `ЭтоФайл`, `ЭтоКаталог`, атрибуты,
  размер и время доступны в серверном контексте; соответствующие `Асинх`
  в таблице имеют клиентские контексты. Их обещания возвращают соответственно
  булево, число, дату; установщики возвращают обещание `Неопределено`.
- `ИнициализироватьАсинх` принимает путь и возвращает обещание объекта
  `Файл`; это не просто обещание `Неопределено`.
- `УстановитьНевидимость` и `УстановитьНевидимостьАсинх` описаны как
  неработающие в Linux. Нельзя угадывать, означает ли это исключение или
  отсутствие эффекта: требуется отдельная проба.
- Для локального времени справка описывает границу совместимости 8.2.13;
  Unix timestamp из нынешнего FileMetadata сам по себе не воспроизводит
  местное время и переходы часового пояса.
- `НачатьПолучениеНевидимости` допускает необязательное описание оповещения.
  У ряда `НачатьУстановку…` необязателен первый, но обязателен второй аргумент;
  простого диапазона числа фактически переданных значений недостаточно
  для вывода о пропусках позиционных аргументов.
- Страница мобильного `НачатьПолучениеКартинки…` показывает нулевую арность,
  тогда как обычные `Начать…` принимают описание оповещения. Не унифицировать
  сигнатуры по сходству имён.
- Методы мультимедиа используют мобильную библиотеку и схему `content:`.
  Полный перечень сохранён; включение мобильной группы и `Начать…` требует
  разрешения обнаруженного противоречия между «полным интерфейсом» и
  исходными исключениями плана. Вопрос направлен пользователю, группы
  не считаются ни реализованными, ни молча исключёнными.

настроенный измерительный workspace; свойства основной ИБ по старой выгрузке
не объявляются повторно проверенными.

Позднее 2026-09-09 по разрешению пользователя создан отдельный workspace
`/tmp/open-bsl-unica-files-wCtCU4`: `main` → `src/`, DESIGNER,
`Srvr="localhost";Ref="test";`, платформа строго 8.3.27.2342.
`unica.project.status` подтвердил `ready=true`; `repositoryReady=false`
объясняется отсутствием Git у одноразового workspace. `project.map`
подтвердил единственный source-set. `src/` пока пуст, настройки подключения
и установки находятся в локальном overlay. База не изменялась, подключение
не проверялось. Отсутствие workspace больше не является блокером;
следующий шаг — полный dump существующей базы перед измерениями.

Применённый полный dump завершился отказом до запуска платформы; `src/`
остался пустым. Receipt сохранил только последний отклонённый кандидат
`sm-searcher/bin/1cv8`, которого нет. Первоначальная гипотеза про отображение
UID в sandbox не подтвердилась для проверенных процессов Unica: их `uid_map`
тождественный, установка видна как `root:root`.

Независимая проверка дерева установки обнаружила символические ссылки
библиотек (`libatomic.so.1`, `libopenal.so` и другие). Реализация
[`capture_immutable_platform_children` в Unica v0.12.3](https://github.com/IngvarConsulting/unica/blob/v0.12.3/crates/unica-coder/src/infrastructure/platform/full_dump_publication.rs#L2571)
отвергает ссылки во всём дереве. Это подтверждённое препятствие для проверки
этой установки, но не трассировка первого отказа MCP-вызова. Изменение прав,
перенастройка sandbox или повтор неизменённого dump не устраняют это условие.
Платформенные измерения остаются невыполненными; обход проверки не применялся.

### Прямой запуск после отказа от Unica

По указанию пользователя «Не используй unica» дальнейшая работа переведена
на прямой запуск установленного `1cv8`. 2026-09-09 отдельные команды
`DESIGNER /S localhost/test /DumpCfg` и `/DumpConfigToFiles` завершились
с кодом 0. Сохранены `/tmp/open-bsl-files-platform-7xEx8x/original.cf`
(90 778 байт) и `original-xml/`. SHA-256 CF:
`d5cbf43484890723246fff6111fd4c5c245194e9b84c5172c6b6ead69d06f190`.
В текущем XML `CompatibilityMode=Version8_3_27`; это свойство выгруженной
конфигурации, а не ещё не полученный паспорт исполнения проб.

В отдельной копии `probe-xml/` подготовлена обработка с серверным модулем
формы. Команда её загрузки и запуска была отклонена автоматической проверкой
разрешений до создания процесса: требуется явное согласие на временное
изменение общей базы и последующее восстановление. `load-probe.log` и
`platform.tsv` не созданы. База этой попыткой не изменялась.

Таким образом, ограничение Unica больше не определяет следующий шаг:
прямое чтение базы проверено, но измерение ждёт согласия на мутацию.
Перед будущей загрузкой повторно проверить актуальность резервной копии:
сохранённый CF не разрешает перезаписывать более поздние изменения базы.

После явного разрешения «разрешаю изменять localhost/test» выполнена
новая сессия со свежими CF/XML: `/tmp/open-bsl-files-approved-rBiijg`.
Первые серверные пробы завершились успешно, исходная конфигурация
восстановлена с побайтным совпадением XML, кроме ConfigDumpInfo.xml.
[Результаты и границы измерения](file-object-server-2026-09-09.md).
Прежнее ожидание разрешения снято; полная матрица API остаётся незавершённой.
