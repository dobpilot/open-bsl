# Частичный отказ УдалитьФайлы на серверной 1С

18 сентября 2026 года на Linux и платформе 1С 8.3.27.2342 измерен
синхронный `УдалитьФайлы` в серверной базе `/S localhost/test`.
Эффективный режим совместимости — `НеИспользовать`; Unica не использовалась.

В отдельном временном корне последовательно созданы `a-before.txt`, непустой
каталог `b-denied` и `c-after.txt`. У каталога сняты права через
`/bin/chmod 000`, затем выполнено удаление по маске `*`. До осмотра и очистки
права обязательно возвращались; итоговая очистка использовала `/bin/rm -rf`
по точному уникальному корню.

Серверная 1С и open-bsl совпали: вызов завершился ошибкой, оба обычных файла
были удалены, закрытый каталог сохранился. Это подтверждает отсутствие отката
и выбор обычных файлов до каталога в данном Linux-порядке. Результат не
обобщается на сортировку произвольного host и гонки после выбора.

Изменение runtime не потребовалось. CLI-тест повторяет oracle в
source/bytecode × plain/optimize; детерминированные host-тесты дополнительно
проверяют остановку на первом `remove_path`, сохранение уже сделанных
изменений и отсутствие повторного I/O при втором `Ждать`.

Нативный сеанс `/tmp/open-bsl-server-measure-ewvy4477` завершился кодом 0.
CF и конфигурация БД восстановлены; XML совпал, кроме служебного корневого
`ConfigDumpInfo.xml`. SHA-256 сценария —
`e6a3d8857d8fb419b22a324ded815f32b5b8ed1f3533f18b6bcb7b9bbc08d693`,
нормализованного oracle —
`35aec3f03f52d37217b91be2c5ae70266dee96b6bebc896357b13f015b1c7e6e`.
