## Матрица

Восемь методов чтения: существование, файл/каталог, размер, невидимость,
только чтение, местное и UTC-время. Каждый проверен с корректным числом
аргументов, без аргументов и с лишним аргументом — 48 RU/EN-вызовов.
Четыре setter и инициализация дополнительно проверены с отсутствующим
вторым аргументом и массивом вместо него — 50 RU/EN-вызовов.
Всего 98; вызовы выполняются через Выполнить.

| Случай | Вызов | Доставка |
|---|---|---|
| Чтение, одно корректное описание | Возвращается | Результат и данные, 16 успехов |
| Setter, описание и корректное значение | Возвращается | Только данные, 8 успехов |
| Инициализация, описание и строка | Возвращается, путь уже изменён | Файл и данные, 2 успеха |
| Неверная арность | 62 синхронных отказа | Нет callback для этих ID |
| Setter, описание и массив | Возвращается | 8 ошибок типа, исходный флаг стандартной обработки Истина |
| Инициализация, описание и массив | Возвращается, путь уже изменён | 2 успешных результата Файл |

Итого приняты 36 операций и доставлены ровно 36 оповещений: 28 успешных,
8 ошибочных. Все обработчики увидели флаг, выставленный после возврата
Begin-вызова. 26 корректных контролей завершились успешно. Обработчик
ошибки переводит стандартную обработку в Ложь. Завершение пробы ждёт
равенства числа принятых операций и доставок и успеха всех контролей;
в oracle begin.ready=1, expected=36, delivered=36, valid=26.

Ошибки арности: Not enough actual parameters / Too many actual parameters.
Глубинная ошибка значения setter: Type mismatch (parameter number '1').
Это именно номер из глубинной ошибки операции; он не переписывается
в номер второго аргумента Begin. Точный текст нового пути при инициализации
массивом не выводился: измерены принятие, изменение пути и тип результата,
но не строковое представление массива.

## Влияние на реализацию

Арность чтения задаётся exact(1), setter/инициализации — exact(2).
Ошибка значения setter должна регистрироваться как результат операции
с последующей доставкой, не выбрасываться вместо возврата Begin.
Инициализация не должна наследовать строгую проверку типа setter.
Требования и решения внесены в активный extend-filesystem-async до реализации.

file_begin_oracle проверяет все 98 ID, разделение событий/ошибок,
отсутствие callback после отказа арности, типы результатов, RU/EN и
полноту всех строк. Это проверка нативного свидетельства, не реализации VM.
Текущий open-bsl исполняет сам измеритель, но все 98 случаев останавливаются
на получении описания с ЭтотОбъект; begin.ready=0. Это не зелёный conformance.

Не измерены этим прогоном: прямые синтаксические вызовы, неверный тип и
пустое описание оповещения, ошибки самих обработчиков, дополнительные
значения setter и точный преобразованный путь инициализации. Публичная
ссылка на BSL-модуль и сама доставка Begin в VM остаются незавершёнными.
Вопрос ЭтотОбъект/ThisObject повторно передан пользователю; отсутствие
ответа не считается согласием на новый публичный интерфейс.

Проверки завершены: fmt, Clippy workspace/all-targets с -D warnings,
полный cargo test --workspace (включая plain/optimize, round-trip и
реестры), rustdoc с -D warnings, git diff --check и все 11 строгих
проверок OpenSpec прошли. Логи этого этапа:
`/tmp/open-bsl-begin-arity-{oracle-test,clippy,workspace,doc,openspec}.log`.
Runtime-код и опубликованные API в этом этапе не менялись.
