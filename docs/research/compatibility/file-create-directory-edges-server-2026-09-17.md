# Конечные символы пути СоздатьКаталог

## Контекст и безопасность

17 сентября 2026 года выполнен прямой замер 1С 8.3.27.2342 на Linux,
серверная база `/S localhost/test`, серверный модуль управляемой формы.
Эффективный режим совместимости — `НеИспользовать`. Unica не использовалась.

Каждый из 11 случаев создавал только собственный временный корень. После
создания `leaf<символ>` измеритель удалял точный `leaf` и считал остатки:
это различает физическое снятие суффикса и отдельное имя без небезопасного
доступа вне корня. Затем весь корень удалялся.

Runner `/tmp/open-bsl-server-measure-67j6q5d2` сохранил свежие CF/XML,
выполнил пробу, восстановил CF и конфигурацию БД. Восстановленный XML совпал
полностью.

- Исходник: `tests/conformance/measure/filesystem/file-create-directory-edges.bsl`,
  SHA-256 `246e92d43d0aeb4dcf71f9a3c7e253479353f6353244a85b050eea1cb68eaf05`.
- Oracle: `tests/conformance/measure/filesystem/file-create-directory-edges.platform.txt`,
  SHA-256 `8349f51727afb52d02c24c806d0fc415272137fbbbda88f56a170c7f3a96c516`.

## Результат

NUL, TAB, LF, CR, SPACE, U+0085 и NBSP сняты до создания: последующее
удаление `leaf` оставило пустой корень. U+0001, U+007F, U+200B и U+FEFF
сохранены: после удаления базового имени оставался один элемент.

До исправления open-bsl совпадал только в шести случаях и сохранял TAB,
LF, CR, U+0085 и NBSP. `create_directory_path` теперь использует общий
`prepare_file_operation_path`, а не отдельную NUL/ASCII-space нормализацию.
Исходная строка результата асинхронного метода не меняется.

Все 11 строк совпадают в source/bytecode × plain/optimize. Виртуальный host
проверяет точные пути до `create_dir_all`. Замер не закрывает прочие типы
аргумента, корни, двоеточие и частичные отказы;
`CREATEDIR.PATH_SEMANTICS` остаётся для этого остатка.
