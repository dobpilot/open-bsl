# Ошибки metadata при `НайтиФайлы`

## Контекст и сохранность

Измерение выполнено напрямую на серверной 1С 8.3.27.2342, Linux,
`/S localhost/test`, без Unica. Код исполнялся в серверном модуле формы;
эффективный режим совместимости — `НеИспользовать`. Асинхронный и клиентский
контексты, другие ОС и остальные виды ошибок host не измерялись.

Сессия `/tmp/open-bsl-server-measure-orac3xwz` завершилась кодом 0. Исходный
CF восстановлен, повторная XML-выгрузка совпала с исходной, кроме служебного
корневого `ConfigDumpInfo.xml`.

Проба только читала дерево `/tmp/open-bsl-find-metadata-errors-N4xK8c`:
каталог с режимом `0000` и самоссылочную символическую ссылку. После фиксации
снимка права каталога восстановлены, а scratch удалён.

- Сценарий: `file-search-metadata-errors.bsl`, SHA-256
  `68089e30b4242a86bbef4695ae9debc33274b63f239f4b1dc0044abbb2f0ab07`.
- Нативный вывод: `file-search-metadata-errors.platform.txt`, SHA-256
  `ba453ae8b44add70cb6859d2b7010652f8c2808cc86d3206802c7e8287e9884c`.
- Снимок дерева: `file-search-metadata-errors.host.txt`, SHA-256
  `1f01bb465db199b0683af4b7aa9c197a180a8cc0c8720b6b528a373ecba5e701`.

## Результаты и исправление

Два дерева × три маски (`*`, `*.txt`, `error*`) × flat/recursive × RU/EN
дали 24 вызова.

Серверная 1С сохраняет результаты текущего уровня и без ошибки пропускает
вложенный каталог, чтение которого запрещено. Самоссылочная ссылка с Linux
`ELOOP` ведёт себя как ранее измеренная оборванная ссылка: для `*` останавливает
выдачу, для `*.txt` не мешает обычным файлам, а для `error*` сама попадает
в результат. RU и EN совпали.

До исправления open-bsl расходился в 16 строках: передавал `PermissionDenied`
и `ELOOP` наружу. Теперь только вложенный `PermissionDenied` пропускает один
каталог; ошибка корневого `read_dir` сохраняется. `ELOOP` признаётся правилом
оборванной ссылки только в измеренном Linux-host через errno 40. Остальные
ошибки не скрываются, другие ОС не получают выведенного по аналогии правила.

`measured_metadata_errors_match_the_native_ordered_oracle` воспроизводит
весь снимок через управляемую `FileSystem`. Отдельный системный CLI-тест
проверяет реальные права и ссылку в source/bytecode × plain/optimize.
Все 24 строки совпали с oracle во всех режимах.
