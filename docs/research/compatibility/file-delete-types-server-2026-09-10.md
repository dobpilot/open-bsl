# Типы маски удаления на серверной 1С

1С 8.3.27.2342, Linux, серверный модуль формы `/S localhost/test`.
Литеральный CompatibilityMode — Version8_3_27; effective-режим отдельно
не измерялся. Unica не использовалась. Версия 8.5 этим сеансом не проверена.

## Результат

Девять случаев используют отдельные временные деревья. В каждом есть
`data/keep.bin`; для непустого строкового представления маски дополнительно
создаётся файл с точно таким именем. Состояние проверяется после вызова,
поэтому успешный возврат не подменяет доказательство удаления.

- Маски 17, 0, Истина, Ложь, Массив и Структура удаляют файл, названный
  `Строка(маска)`. Корень `data` и сосед `keep.bin` сохраняются.
- Null, Неопределено и пустая строка удаляют весь `data` с содержимым.
- Все девять вызовов завершились без ошибки. Проверка очистки также прошла.

До исправления open-bsl отвергает число, булево, Null, массив и структуру;
совпадают только Неопределено и пустая строка. Вывод до исправления сохранён
в `/tmp/open-bsl-delete-types-WAtRue/open-bsl-before.txt`.

## Граница вывода и следующий шаг

Измерено преобразование второго аргумента, не первого. Путь во всех вызовах
был строковым. На момент отчёта даты, другие классы объектов, частичные
отказы, ссылки и гонки ещё не были измерены. Последующие серии закрыли этот
остаток; представление иных значений делегировано общему контракту `Строка`.

VM передаёт общий BSL-форматировщик в подготовку маски через
`call_builtin_delete_files_formatted`. Обход и удаление остаются общими;
форматирование из `bsl-format` в `bsl-rt` не скопировано. Прежние публичные
Rust-входы `call_builtin_files` и `call_builtin_delete_files` сохраняют
сигнатуры и строгое требование строковой маски без форматировщика.
Conformance `file_delete_types` получает ожидаемые строки из оригинального
вывода с удалением BOM и нормализацией CRLF. После изменения все девять
случаев совпали с oracle. Тест виртуальной ФС проверяет переданный
форматировщик, точный удалённый путь, отмену и ошибку форматирования без I/O.
Асинхронный вариант проверен позднее в отдельном
[клиентском замере](file-delete-async-types-client-2026-09-10.md).
Стадии ошибок форматирования остаются неизмеренными.
