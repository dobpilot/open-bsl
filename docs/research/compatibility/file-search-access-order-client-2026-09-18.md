# Порядок ошибок `НайтиФайлы`

Замер выполнен 18.09.2026 на сервной 1С 8.3.27.2342,
`/S localhost/test`, Linux, прямым `1cv8` без Unica. Сеанс
`/tmp/open-bsl-server-measure-553xxols` завершился с кодом 0.
После прогона CF/БД восстановлены, XML совпал побайтно.
Первый прогон на `/root` не дал платформенного вывода и в доказательство
не включён. Повтор использовал внешне созданный каталог
`/tmp/open-bsl-search-access-order-denied` с режимом `000`. После
замера режим восстановлен в `0700`, каталог удалён.

- [Сценарий](../../../tests/conformance/measure/filesystem/file-search-access-order.bsl),
  SHA-256 `e791c5bfe473ccf3b26b4fca743e8599fa35d9d5a9c9eea0796ec5328afdf62b`.
- [Oracle](../../../tests/conformance/measure/filesystem/file-search-access-order.platform.txt),
  SHA-256 `58a41b9ddc8b975b2e73ab3d82b89bc33066af77dc31008c6097f7ad93565945`.

Восемь RU/EN sync/async-вызовов дали одинаковую семантику.
При допустимом `Ложь` корневой `PermissionDenied` скрывается:
результатом становится пустой массив. Строка `"Да"` отвергается как
третий аргумент до обращения к ФС. В async-варианте эта ошибка
доставляется из обещания на `Ждать`, а не в момент вызова.
Точный английский текст диагностики сохранён в raw oracle, но не
включён в кросс-runtime сравнение: open-bsl использует общую
русскую диагностику приведения.

До исправления open-bsl возвращал ошибку host для допустимой
рекурсии. Общий обход теперь получает явную политику: НайтиФайлы
скрывает только корневой `PermissionDenied`, а УдалитьФайлы по маске
сохраняет ошибку. Проверка отмены после host-вызова осталась выше
преобразования ошибки. Новый conformance-тест сверяет десять структурных
строк в source/bytecode × plain/optimize.
