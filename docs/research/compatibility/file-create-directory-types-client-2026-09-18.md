# Типы аргумента СоздатьКаталог в тонком клиенте

Дата замера: 2026-09-18. Платформа: 1С 8.3.27.2342, тонкий клиент
серверной базы `localhost/test`, пустая аутентификация. Сценарий запускался
нативным runner с `--enterprise-cwd-in-io`, поэтому все относительные
побочные эффекты оставались в приватном каталоге артефактов.

Измеритель `file-create-directory-types-async.bsl` для каждого значения
отдельно вызывает sync и async, после каждого вызова проверяет существование
пути `Строка(значение)` и удаляет его перед следующей половиной. Это устраняет
неоднозначность ранней пробы объекта Файл, которая проверяла только путь,
хранимый внутри объекта.

Результат:

- строка, число, оба Boolean, дата, массив, структура, соответствие, три
  фиксированные коллекции, ТаблицаЗначений, UUID, Файл, ДвоичныеДанные,
  элемент перечисления и Тип успешно создают каталог своего строкового
  представления и в sync, и в async клиента;
- пустой СписокЗначений, Неопределено и Null имеют пустое представление и
  отвергаются без создания;
- async во всех 17 успешных случаях возвращает исходное значение с тем же
  тождеством;
- объект Файл создаёт каталог с буквальным именем `Файл`, а не каталог по
  пути `inside`, содержащемуся в объекте.

Последующая изолированная серверная проба проверила также сам каталог
`Строка(Файл)` и показала то же создание. Поэтому ранний серверный вывод о
no-op был следствием неполного наблюдения пути внутри объекта, а не отличием
контекста. Sync и async используют общий форматировщик; async дополнительно
возвращает исходное значение.

Успешный сеанс: `/tmp/open-bsl-server-measure-fy8i6jxp`. Runner восстановил
CF/БД; XML совпал, кроме ожидаемого служебного корневого `ConfigDumpInfo.xml`.
После очистки в cwd остались только пустые промежуточные каталоги `1/15` от
локализованного представления даты, конечный измеряемый путь отсутствовал.
