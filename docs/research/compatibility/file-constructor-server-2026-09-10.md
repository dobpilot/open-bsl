# Конструктор Файл и лексические свойства

1С 8.3.27.2342, Linux, серверный модуль формы базы `/S localhost/test`.
Литеральный CompatibilityMode выгрузки — Version8_3_27; effective-режим
отдельно не извлекался. Unica не использовалась. Проба не создаёт файлов
и не вызывает методы файлового I/O — только конструктор и пять свойств пути.

## Результаты 24 проб

- Новый Файл() и New File() допустимы; все пять строковых свойств пусты.
- Неопределено и Null дают пустой путь. Число, Булево, Дата, Массив и
  Структура преобразованы через Строка аргумента в том же контексте.
- `.` / `..` / `../..` дают пустой путь; `a/../../b` даёт `b`, `/../../b` — `/b`.
- `/` и `///` сохраняются и в ПолноеИмя, и в Путь, остальные поля пусты.
- `a//b///c/` даёт `a/b/c`, имя `c`, родитель `a/b/`.
- Для `.hidden` основа пустая, расширение `.hidden`; для `a.` расширение `.`,
  для `...` основа `..`, расширение `.`.
- `C:\alpha\..\b.txt` даёт `C:/b.txt`.
- NUL и TAB сохраняются в лексических свойствах. Это не доказательство
  поддержки чтения/записи файлов с такими именами.

Дата в этой сессии представлена как `1/2/2020 3:04:05 AM`, Булево — `Yes`;
сами пути совпали со Строка аргумента. Язык этих представлений не фиксируется
как отдельное правило File.

## Исправление

До изменения `fixture-before.txt` показал отказ нулевой арности и нестроковым
аргументам, сохранение лишних относительных `..` и сворачивание `///` в `/`.
Изменены дескриптор конструктора и общий разбор пути, а не отдельная копия
для инициализации. `fixture-after.txt` совпал с ожидаемыми 24 строками.
Ожидаемый файл получен из oracle; для локализуемых представлений сохранено
измеренное равенство ПолноеИмя и Строка аргумента.
Прочие корневые формы, объектные представления и операции I/O для необычных
имён остаются FILE.EDGE_BEHAVIOR; измеренные строки не используются для
автоматического снятия всего маркера.

неизмеренных вопросов. Отдельно прошли 31 тест `host_environment` и

а игнорируемый экспорт MXL не является проверкой совместимости.
