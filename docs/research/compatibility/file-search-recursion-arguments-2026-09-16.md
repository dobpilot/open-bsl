# Аргумент рекурсии НайтиФайлы

## Контур

1С 8.3.27.2342, Linux, серверная `/S localhost/test`, кластер от kan.
Синхронный поиск измерен в серверном модуле формы, асинхронный — отдельно
в тонком клиенте той же базы. Native запущен без Unica. В обоих исходных
XML CompatibilityMode=Version8_3_27; фактический режим из Метаданные —
НеИспользовать. Windows, 8.5 и файловая база в этом замере не проверялись.

Сессии `/tmp/open-bsl-server-measure-78n5swmc` и
`/tmp/open-bsl-server-measure-5p7yr208` завершились кодом 0 и RESTORED.
Перед каждой загрузкой сохранены свежие CF/XML и повторно проверена
неизменность конфигурации; после восстановлены CF и конфигурация БД.
XML совпал, кроме корневого ConfigDumpInfo.xml. Логи и резервные копии
оставлены в каталогах сессий. Это не побайтная проверка данных базы.

Каждая проба создаёт собственный уникальный временный каталог с top.txt
и branch/deep.txt, выполняет только поиск внутри него, затем удаляет
своё дерево. Рабочий каталог сервера не меняется. Маркеры setup_error
и cleanup_error отсутствуют, завершающие маркеры присутствуют.

## 112 случаев

Каждый контекст: 28 значений × RU/EN = 56 вызовов, из них 32 успешных
и 24 отказа. Маска всегда *.txt. Рекурсивный результат — top.txt,
затем branch/deep.txt; нерекурсивный — только top.txt.

| Значения флага | Результат |
|---|---|
| Истина, числа 1, -1, 2, 0.1, -0.1 | Рекурсивный поиск |
| Ложь, число 0 | Нерекурсивный поиск |
| Строки Истина, True, tRuE, Истина с ASCII-пробелами, True с NBSP | Рекурсивный поиск |
| Строки Ложь, False, False с TAB | Нерекурсивный поиск |
| Строки Да, Нет, 1, 0, пустая, пробел, True<NUL>False | Ошибка |
| Неопределено, Null, массив, структура, дата | Ошибка |

Синхронные ошибки возникают при вызове; асинхронные — при Ждать после
получения обещания. В raw для неверных значений сохранено сообщение
Type mismatch (parameter number '3'). Точная локализация и вложенность
ошибок не объявляются совпадающими с open-bsl.

## Исправление и проверка

До исправления различались четыре результата в каждом контексте:
open-bsl принимал Да/Нет через as_condition. Красный тест зафиксировал
recursion.yes.ru: рекурсивный результат вместо ошибки.

Подготовитель аргумента файловых атрибутов стал общим внутренним
file::boolean_argument с именем операции для ошибки. НайтиФайлы использует
его до обращения к host. Парсер булевых слов не дублируется; обычное
условие BSL по-прежнему принимает Да/Нет. Механизм async-обещаний не менялся.

Сравнение всех 112 результатов проходит для plain/optimize исходников
и обоих вариантов сериализованного байт-кода. Тот же тестовый помощник
повторяет прежние 448 случаев атрибутов. Пропускаются только context и
.detail, но не стадия ошибки, количество, имена или порядок файлов.
Отдельный host-тест проверяет прямые и динамические RU/EN-вызовы, оба
режима компиляции и отсутствие чтения каталога/разделителя при Да/Нет.

На момент этой серии прочие значения, сочетания нескольких неверных
аргументов и приоритет относительно файловой системы оставались открытыми.
Последующие пробы закрыли порядок до I/O; объекты используют единый отказ
условного преобразования, а путь и маска — общий `Строка`. Исходный маркер,
запись реестра и measure-строка после этого сняты вместе.

Полная проверка после исправления: cargo fmt --all -- --check,
Clippy workspace/all-targets с -D warnings, cargo test --workspace
(включая plain/optimize, round-trip, API и реестр вопросов), rustdoc
с -D warnings, git diff --check и 11 строгих проверок OpenSpec прошли.
Логи: `/tmp/open-bsl-recursion-{clippy,workspace,doc,openspec}.log`;
красные и исправленные целевые тесты сохранены рядом с префиксом
`/tmp/open-bsl-recursion-`.
