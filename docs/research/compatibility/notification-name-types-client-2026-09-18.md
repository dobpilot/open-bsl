# Типы имен в `ОписаниеОповещения`

Измерено на 1С 8.3.27.2342, Linux, в клиенте серверной
`localhost/test`, прямым `1cv8`, без Unica. Сценарий проверяет
одинаковые значения в роли имени успешного и ошибочного
обработчика. Это не измерение 8.5.

- [Сценарий](../../../tests/conformance/measure/filesystem/notification-name-types.bsl).
- [Исходный oracle](../../../tests/conformance/measure/filesystem/notification-name-types.platform.txt).

## Результат

Для Boolean, Date, Null, Type, UUID, File, Array, Structure,
пустого ValueList, пяти членов TextEncoding, SortDirection,
ByteOrder, FileOpenMode и BinaryData платформа показала
то же представление, что `Строка(Значение)`. Локализованные
Boolean, Date и Type отличаются от запуска CLI по локали, но во всех
этих случаях конструктор отклонил имя как отсутствующий метод.
Пустой ValueList и Null дали пустую строку.

Найдено узкое расхождение целого enum-типа. Каждый из
пяти членов `TextEncoding` в четвёртой позиции не вызывает отказ
отсутствующему методу. Вместо этого свойство имени ошибочного
обработчика возвращает `Добавить`. Три чужих enum-типа и
строка `"UTF8"` отвергаются. Оба модульных свойства
такого описания не читаются. Ошибочный получатель
проверяется по подменённому имени: структура без `Добавить`
отклоняется уже конструктором. Проба с двумя разными
массивами доходит до нечитаемого getter. open-bsl теперь
воспроизводит эту ветку; сохранение ссылок для будущей доставки
остаётся внутренней политикой, а не измеренным фактом.

## Проверка open-bsl

Добавлен тест source/bytecode × plain/optimize. Все 46 строк
совпадают; представления, зависящие от локали, нормализуются
до исхода конструктора. `NOTIFY.EDGE_ARGUMENTS` остаётся открытым для
непрозрачных получателей и точных диагностик.
