# Дополнительные границы индекса методов таблицы

## Среда и артефакты

Прямой запуск 1С 8.3.27.2342 на Linux в серверной базе `localhost/test`,
без Unica. Каждая проба создаёт новую локальную таблицу из двух строк и
двух колонок; прикладные данные и файловая система не изменяются. Runner
восстановил CF и конфигурацию БД; XML совпал с исходным, кроме корневого
`ConfigDumpInfo.xml`.

- измеритель: `tests/conformance/measure/filesystem/notification-table-index-edges.bsl`, SHA-256 `e92a25d29e4ace15690c933ac49efb98546c539d5962d87e4077a20d714f79ce`;
- oracle: `tests/conformance/measure/filesystem/notification-table-index-edges.platform.txt`, SHA-256 `ebd23b1ddc66500cf405f44c964c0f4dee0ceab4920648428dd7acf7f57dfb74`;
- сохранённый сеанс: `/tmp/open-bsl-server-measure-n39o2auz`.

## Результат

36 RU/EN-результатов `ТаблицаЗначений.Получить/Get` и
`СтрокаТаблицыЗначений.Установить/Set` подтвердили:

- `0.9`, `-0.0`, строка `0.9`, `+1` и `01` принимаются;
- `0,9`, строка `-0.9`, `1e0` и пустая строка отвергаются;
- при ошибке setter строка остаётся без изменений.

Это сохраняет измеренное отличие от массива: отрицательная дробь таблицы
отвергается до усечения. Текущие `table_method_index` и `parse_canonical`
совпали с oracle без изменения runtime. CLI-тест проверяет source/bytecode ×
plain/optimize.

`TABLE.METHOD_INDEX` остаётся открытым для предельных индексов и точных
локализованных сообщений. Публичный API и производительность не менялись.
