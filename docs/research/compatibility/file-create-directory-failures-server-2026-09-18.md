# Частичные отказы СоздатьКаталог на серверной 1С

18 сентября 2026 года на Linux и платформе 1С 8.3.27.2342 измерены два
частичных отказа синхронного `СоздатьКаталог` в серверной базе
`/S localhost/test`. Эффективный режим совместимости — `НеИспользовать`.
Unica не использовалась.

Оба сценария ограничены отдельным временным корнем. Первый передаёт путь с
300-байтовым компонентом после отсутствующего каталога `created`: операция
отказывает, но уже созданный `created` остаётся. Второй снимает права с
каталога внутри корня через `/bin/chmod 000`, пытается создать ребёнка и
обязательно возвращает `0700` перед осмотром и очисткой: операция отказывает,
ребёнок не появляется.

Результаты серверной 1С и open-bsl совпали:

- `long_component` — `error|prefix=1`;
- `permission` — `error|child=0`.

Изменение runtime не потребовалось: системный host делегирует
`create_dir_all`, которое сохраняет уже созданные компоненты и возвращает
первую ошибку. Добавлен CLI-тест source/bytecode × plain/optimize.

Нативный сеанс `/tmp/open-bsl-server-measure-i04_eon1` завершился кодом 0.
CF и конфигурация БД восстановлены; XML совпал, кроме служебного корневого
`ConfigDumpInfo.xml`. SHA-256 сценария —
`ea1c04ce7af0bc4d80773494ce629e8f7a9837ebb2442560e356df000d8ad0dc`,
нормализованного oracle —
`d99a68c1181ecf2c20165ca86311e6aa560d52ff199a48b5d37c4ab9dbeeff1d`.

Проба закрывает два Linux-сценария частичного отказа, но не определяет
преобразование прочих типов аргумента и не переносит Unix-права на другие ОС.
