# Точное окружение импортов динамического BSL-кода

## Расхождение и результат

Красный тест воспроизвёл отказ `переменная «Данные» читается до присваивания`
при Вычислить("Данные.Ячейка") в модуле, импортирующем Хранилище под именем
Данные. Статических обращений к импорту не было, поэтому прежняя таблица
использованных связей не содержала ни цели, ни псевдонима.

Теперь Program сохраняет отдельную таблицу объявленных импортов. Фрагмент
получает экспортную поверхность только этих целей и только под указанными
псевдонимами. Весь каталог не становится видимым. Переменные затеняют
псевдонимы по прежним правилам резолвера; неэкспортный метод отвергается
при компиляции строки. Вложенность, вызов функции другого модуля и повторное
использование кэша сохраняют исходное окружение.

Это контракт каталога open-bsl, заранее добавленный в активную delta
extend-filesystem-async, а не новый замер модели общих модулей 1С.
Нативная база этим этапом не изменялась; существующие oracle и маркеры
неизмеренных вопросов сохранены.

## Представление и границы

Формат байткода повышен 31 → 32. Секция `.imports` хранит пары
`N module=M "псевдоним"` перед `.links`. Неиспользованный импорт не теряется
при печати/разборе. Проверяются пустые и повторные без учёта регистра
псевдонимы, неизвестные цели, импорт себя и циклы, включая граф без единого
статического CallImported. Eager-init загруженного каталога использует
объявленные зависимости, а не только фактически вызванные символы.

Сема, кодоген и VM разделяют прежний алгоритм разрешения импортов.
DynamicRequest переносит нейтральные пары alias/module, а фасад снимает
сигнатуры своего каталога. Прежний compile_dynamic_snippet сохранён
для окружения без импортов; расширенный вход требует точного совпадения
предоставленных импортов с запросом. VM по-прежнему не зависит от фронтенда.

DynamicUnit содержит собственные связи. При построении исполняемого образа
они добавляются после статических; три импортные инструкции и
ByRefImportedVar собственного чанка перенумеровываются с проверкой границ
и переполнения. Копируемые статические функции не меняют свои номера связей.
Проверка связанного фрагмента использует те же проверки экспорта/арности,
что периметр конфигурации, без повторной реализации этих правил.

Прежний намеренный запрет прямого async CallImported сохранён:
`JOB.ASYNC.TARGET` этим этапом не измерялся и не переопределялся. Тест
подтверждает отказ, а также рабочий возврат BSL-обещания из синхронной
экспортной функции, вызывающей async через ЭтотОбъект. Отладочное evaluate
остаётся отдельным блокирующим исполнителем без полного общего каталога
и владельца обещаний; его задача не закрыта.

## Проверки

Два интеграционных теста проверяют plain/optimize, lazy/eager,
исходник/entry-bytecode/полный загруженный каталог, повторные запуски одного
State, псевдонимы, затенение локальной и модульной переменной, видимость,
чтение/запись, default/byref, импортированный ссылочный аргумент, исключение,
вложенные строки, обещание и смешанные статические/динамические связи.
Порядок eager-init проверяется фактическим выводом «второй, первый» при
неиспользованной зависимости, а не результатом последующего ленивого чтения.

Три теста представления проверяют round-trip импортов, отказ формату 31,
испорченные строки/цели/граф и экспортность связанного фрагмента. VM-тест
перенумерации покрывает все три инструкции, ссылки аргументов и переполнение.
Прежний компиляторный round-trip сохраняет покрытие каждого opcode;
новых opcode и изменения восьмибайтового Instr нет. Новых зависимостей нет.
Измерения производительности не выполнялись; ускорение не заявляется.

Полный `cargo test --workspace` завершился успешно, включая
`the_optimizing_passes_agree_with_the_plain_run_on_every_script` и
`checked_in_api_reference_matches_the_generator`. Также успешно завершились
`cargo clippy --workspace --all-targets -- -D warnings` и
`RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`.
Логи этапа: `/tmp/open-bsl-dynamic-imports-workspace.log`,
`/tmp/open-bsl-dynamic-imports-clippy.log`,
`/tmp/open-bsl-dynamic-imports-doc.log`.

Финальные `cargo fmt --all -- --check`, `git diff --check` и
`openspec validate --all --strict` успешны (11 проверок OpenSpec).
`cargo tree -p bsl-vm -e normal` подтверждает отсутствие зависимостей VM
от синтаксического анализатора, sema и компилятора.
