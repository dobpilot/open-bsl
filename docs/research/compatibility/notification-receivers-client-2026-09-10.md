# Обычные объекты в роли модуля оповещения

## Измерение

Клиент серверной `localhost/test`, Linux, 1С 8.3.27.2342, 2026-09-10.
Прямой `1cv8`, без Unica. Сессия `/tmp/open-bsl-notification-receivers-E3mk97`
завершилась с кодом 0 после восстановления свежего CF и побайтной сверки
XML (кроме ConfigDumpInfo.xml). Компиляция проверена до исполнения.

- [Сценарий](../../../tests/conformance/measure/filesystem/notification-receivers.bsl).
- [Исходный вывод](../../../tests/conformance/measure/filesystem/notification-receivers.platform.txt): 28 строк, BOM/CRLF сохранены.

Тринадцать получателей проверены как модуль основного обработчика и как
модуль ошибки. Описания только создаются: файловые операции не запускаются,
методы получателей не вызываются. Файл с пустым путём создан как объект
пути, не как физический файл.

## Результаты для обеих ролей

| Получатель и имя | Создание описания |
|---|---|
| Клиентская форма, экспортная процедура | Успех |
| Массив, Добавить / Add / Количество | Успех |
| Структура, Вставить | Успех |
| Соответствие, Вставить | Успех |
| Файл, Существует | Успех |
| Массив, отсутствующее имя | Экспортный метод не найден |
| Структура, имя динамического свойства | Экспортный метод не найден |
| Файл, свойство Имя | Экспортный метод не найден |
| Строка, Число, Неопределено | Несовпадение типа параметра 2 или 5 |

Во всех успешных случаях свойство модуля равно исходному объекту.
Наличие встроенного метода достаточно для конструктора; термин «экспортный
метод» в сообщении ошибки не ограничивает параметр объектом BSL-модуля.
Проверка параметра не должна требовать только специальный ModuleReference.
Также нельзя принять любое свойство или имя из общей таблицы без проверки
применимости метода к конкретному получателю.

## Следствие для архитектуры

Предыдущая проба [экспортных обработчиков](notification-handlers-client-2026-09-10.md)
описывает один класс получателей — BSL-модуль. Новое измерение расширяет
необходимую реализацию: описание удерживает объект-получатель, а проверка
имени различает встроенные методы объекта и экспортные методы BSL-модуля.
Доставка должна использовать существующий путь вызова соответствующего
класса методов, включая проверку арности, а не второй независимый диспетчер.

В текущем коде таблицы методов компонентных ObjectProtocol уже доступны.
Для методов базовых значений отдельного общего запроса применимости при
исследовании не найдено: проверка распределена в builtin-диспетчеризации.
Не следует проверять применимость пробным исполнением метода — это может
изменить объект. Нужен общий источник доступности с настоящим вызовом,
без дублирующей таблицы, способной разойтись с runtime.

Сценарий в open-bsl пока заканчивается пойманными ошибками отсутствующего
конструктора, не совпадает с oracle. Доставка встроенным получателям,
ошибки её арности, отмена и время жизни ссылок здесь не измерены.
Другие платформенные контексты и 8.5 не проверены. Rust-код не менялся.
