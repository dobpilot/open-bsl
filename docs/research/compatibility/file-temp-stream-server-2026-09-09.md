# Временный файловый поток: начальные серверные замеры

Среда: 1С 8.3.27.2342, Linux, `/S localhost/test`, серверный модуль формы,
пустые учётные данные, без Unica. XML содержит Version8_3_27; effective
compatibility в этих сеансах отдельно не измерялся. 8.5 не проверена.

## Артефакты и восстановление

В `tests/conformance/measure/filesystem/` сохранены пары:

- file-temp-stream.bsl / file-temp-stream.platform.txt;
- file-temp-storage.bsl / file-temp-storage.platform.txt.

Оба oracle — исходный BOM/CRLF-вывод платформы. Сеансы:
`/tmp/open-bsl-temp-stream-approved-VSn5w6` и
`/tmp/open-bsl-temp-storage-approved-CCuGBc`.
Каждый предварялся свежими original.cf/original-xml. После каждого CF
восстановлен, XML побайтно совпал кроме ConfigDumpInfo.xml, runner exit 0.
Маркеры begin/end присутствуют. Ошибки отдельных аргументов — результат проб,
не ошибка подготовки.

SHA-256 первого скрипта: `de333ec5d94bbb1507ec081208c4aa17575f2a6c378784b94bcad6c18afecc46`.
SHA-256 первого oracle: `16c4761df1bf64e66d3bcf20c6c859c8d1c805d836defbfbfa8ea2eb8d96f791`.
SHA-256 второго скрипта: `f1ba2869b7131b155aa1cfb491c0ea086f56069d3d4712cedd7fdb996fe8cda3`.
SHA-256 второго oracle: `f6d1df782810ba946aa23f9c74071a73c2031bd51ca4d7a81e3eaf865fbf8192`.

## Подтверждено

- Результат имеет тип File stream, начальные размер/позиция 0/0.
- Принимаются первый аргумент 0, 1, 8, Неопределено и отсутствие аргументов;
  Null, -1, 1.5 и строка 8 вызывают ошибку.
- Второй аргумент 0 и 1 принимается, -1 вызывает ошибку.
- Запись и чтение сохраняют данные на исследованных размерах, включая
  65535 и 65536. Позиция после записи равна числу записанных байтов.
- Доступно свойство ИмяФайла, но не метод ПолучитьИмяФайла.
- После Закрыть метод Размер вызывает ошибку.
- В сценариях, где имя запрошено сразу, Файл.Существует видит носитель
  с размером 0 ещё до записи; затем видит размеры записанных данных.
  После Закрыть Файл.Существует продолжает видеть носитель и его размер.

## Что пока не доказано

Оба измерителя читают ИмяФайла до записи. Получение имени может само
материализовать носитель. Поэтому эти результаты **не доказывают** отсутствие
перехода память → диск и не подтверждают порог 65535 или default буфера 8192.
Нужен независимый снимок ОС до обращения к имени, на границе и после неё.
Существование через Файл тоже не заменяет независимое наблюдение ОС.

Сроки после завершения вызова/сеанса требуют отдельной привязки наблюдений
к жизненному циклу, а не только к Закрыть. Реализация СоздатьВременныйФайл
и callback очистки этими исследовательскими пробами ещё не выполнены.

После завершения второго ENTERPRISE и проверки восстановления конфигурации
пять записанных путей уже отсутствовали в ОС; снимок сохранён в
file-temp-storage.after-session.host.txt. Это ограничивает интервал удаления,
но не определяет событие: возврат серверного вызова, окончание сеанса или
отложенная очистка внутри этого интервала пока не разделены.

Последующее независимое наблюдение описано в
[file-temp-native-server-2026-09-09.md](file-temp-native-server-2026-09-09.md):
файл в ОС обнаружен сразу после создания потока, до первого получения имени.
