# Документные ассоциации Linux-host

Это проверка реализации согласованной политики open-bsl, не новый замер 1С.
База localhost/test и пользовательские ассоциации в этом этапе не менялись.
Исходное наблюдение границы ожидания —
[gio возвращается до завершения обработчика](document-association-host-2026-09-09.md).

## Реализация

`ApplicationRequest` содержит `wait_for_exit`. Одноразовый sink принимает
`ApplicationResult`: `Started`, `Exited(ApplicationExit)`, `DocumentOpened`.
VM паркуется до запрошенного подтверждения, а не блокирует worker. Успех
без ожидания возвращает Undefined; Started/DocumentOpened при запросе
настоящего завершения отвергаются без подмены кода и изменения выходной
переменной. Системный наблюдатель после Started продолжает wait/reap.
Отдельный тест обнаружил потерю запуска при выходе CLI с не ожидаемым
обещанием RunAppAsync, если submit возвращается до spawn. Сохранён прежний
барьер попытки создания процесса: он включает подготовку/spawn, но не
ожидание приложения или результата gio. Красный прогон —
`/tmp/open-bsl-documents-unobserved-red.log`; это обнаруженная и устранённая
регрессия разработки, а не оставленное отличие.

Linux-host классифицирует одиночный существующий обычный файл без
executable-битов как документ. Это явно выбранная host-политика, не
утверждение о разборе RunApp платформой. Явный Rust Document также поддержан.
Документ передаётся gio open абсолютным локальным путём в отдельном argv.
Нет shell, подстановок, превращения начального дефиса в опцию или имени
в URI. Рабочий каталог относится к host, не к виртуальной FileSystem.
Неподдерживаемое ожидание отказывает до запуска gio. Ненулевой статус gio
и ошибка его запуска — ошибки передачи, а не коды приложения. Диагностика
gio не выводится; BSL получает класс ошибки без путей из сообщения host.

Старое обозначение NotFound зарезервировано за отсутствующим executable
(sync wait → 127, async wait и отсутствие ожидания → Undefined).
Отказы запуска gio переводятся в Other, чтобы отсутствие утилиты не было
ошибочно принято за успешный запуск без ожидания. Это также часть контракта
для внедряемого launcher. Новых внешних Rust-зависимостей нет.

## Проверки

До реализации `documents_deliver_open_errors_without_claiming_process_exit`
падал на безусловном Unsupported в submit. После реализации отсутствующий
документ даёт ошибку через sink, а не выдуманный exit status.

`crates/bsl-cli/tests/document_association.rs` создаёт собственные XDG
data/config/dirs в scratch и регистрирует только тестовый обработчик text/plain.
Обработчик — этот же Rust test executable: записывает полученный путь и
ждёт явного разрешения теста завершиться. Пользовательский редактор не
открывается. Для каждого из 32 сочетаний RU/EN × sync/async × direct/dynamic
× plain/optimize × source/bytecode проверяются:

- успешный возврат Undefined при живом обработчике;
- точный абсолютный путь относительно cwd, включая пробелы, начальный
  дефис и буквальные shell-символы;
- самостоятельное продолжение обработчика после выхода CLI.

Отдельно проверены отказ ожиданию без запуска обработчика и сохранение
выходной переменной, отказ после удаления собственной тестовой ассоциации,
отсутствие gio в изолированном PATH и прежний настоящий exit code executable.
Ещё один случай запускает документ через RunAppAsync без Ждать: обработчик
получает документ и продолжает работу после выхода CLI.
Тест не обещает работоспособность каждой desktop-среды или портала.

Facade-тесты проверяют парковку до подтверждения, динамическую глубину 3,
отказ считать Started/DocumentOpened завершением, позднюю доставку после
Drop, отмену/shutdown и работу соседнего задания при одном worker с обоими
значениями wait. Прежние реальные процессные тесты сохраняют проверки
живого ребёнка и reap после cancel/shutdown. Измеренный async RunApp oracle
продолжает проверяться с прежними явно исключёнными cwd/shell-расхождениями.

Логи этого этапа: `/tmp/open-bsl-documents-{host,facade,cli,clippy,workspace,doc,api,openspec}.log`.
После исправления гонки повторно прошли fmt, Clippy --workspace --all-targets
с запретом предупреждений, полный workspace (включая conformance,
plain/optimize, round-trip и реестр измерений), rustdoc с запретом
предупреждений, git diff --check и все 11 строгих проверок OpenSpec.
API reference регенерирована; новых BSL-имён этот этап не добавляет.
Windows-разбор, прочие ОС и оставшиеся RUNAPP-вопросы этим не закрываются.
