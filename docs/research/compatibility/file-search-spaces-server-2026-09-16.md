# Поиск пробельных имён и лексическая нормализация Файл

## Контекст и сохранность базы

Прямой запуск 8.3.27.2342 на Linux, `/S localhost/test`, кластер от kan,
без Unica. Поиск измерен на сервере, асинхронный поиск — на клиенте
серверной базы. XML содержит CompatibilityMode=Version8_3_27; обе пробы
поиска сообщают НеИспользовать. Эти свидетельства не приравниваются.
8.5 и файловая база здесь не измерялись.

Каждая сессия получила свежие CF/XML и проверку перед загрузкой, затем
восстановление CF/конфигурации БД и сверку XML с исключением только корневого
ConfigDumpInfo.xml. Все четыре запуска завершились кодом 0 и восстановлением:

| Сессия `/tmp/open-bsl-server-measure-…` | Содержание |
|---|---|
| 0gk1whtx | Первые 108 проб; исключение ЭтоКаталог скрывало состав результата |
| 2pmzxvht | Уточнённые 126 sync-проб, включая обычный файл и каталог-двойник |
| 7rsxsbdx | 140 лексических проб: 35 символов в четырёх позициях |
| uwxwjtlm | 126 async-проб по тому же дереву |

Первый вывод сохранён как file-search-spaces.initial.platform.txt, не как
итоговый oracle. Его исходный сгенерированный модуль остаётся в каталоге
первой сессии. Повторная проба ловит ошибку ЭтоКаталог отдельно и сохраняет
найденное имя, Существует и число элементов.

## Внешнее дерево и воспроизводимость

Нативная проба только читает собственное дерево
`/tmp/open-bsl-search-spaces-miRh6I`, созданное через mktemp с правами 0700.
В нём семь вариантов: одиночный каталог с конечным пробелом, тот же каталог
между соседями, два каталога padded и padded<SP>, обычный файл padded<SP>,
обычный файл padded<SP> рядом с каталогом padded, начальный пробел и конечный
TAB. Всего 13 обычных файлов. Имена и исходный порядок перечисления сохранены
в [манифесте](../../../tests/conformance/measure/filesystem/file-search-spaces.host.txt);
конечные пробелы и TAB в нём значимы. Состав проверен повторно после замеров.
Точный набор дерева воспроизводится в
[интеграционном тесте](../../../crates/bsl-cli/tests/file_search_spaces.rs).
После сверки манифеста исходное частное дерево удалено; резервные CF/XML
и результаты замеров оставлены. Дерево восстанавливается из набора теста,
но конкретный порядок ОС при новом создании не гарантирован.

[Sync-скрипт](../../../tests/conformance/measure/filesystem/file-search-spaces.bsl)
и [raw oracle](../../../tests/conformance/measure/filesystem/file-search-spaces.platform.txt),
[async-скрипт](../../../tests/conformance/measure/filesystem/file-search-spaces-async.bsl)
и [raw oracle](../../../tests/conformance/measure/filesystem/file-search-spaces-async.platform.txt)
проверяют шесть масок и три формы пути, плоско и рекурсивно.

## Измеренное поведение

- Маска сопоставляется с исходным именем: padded не выбирает padded<SP>,
  а padded<SP> выбирает. Возвращённое имя Файл обрезано, поэтому может
  указывать на отсутствующий путь: Существует=Ложь, ЭтоКаталог — ошибка.
- Конечный пробел входного пути удаляется до чтения host. Но padded<SP>/
  с конечным разделителем обращается к исходному каталогу с пробелом.
- Возможность рекурсивного спуска определяется исходным типом элемента.
  Сам спуск использует обрезанное имя. Если такого каталога нет, обход
  продолжает соседей и не теряет уже выбранные элементы.
- Два каталога padded и padded<SP> дают два объекта padded и два обхода
  содержимого padded. Содержимое исходного padded<SP> не посещается.
- Обычный файл padded<SP> рядом с каталогом padded даёт те же два имени,
  но только один обход каталога. Нормализованный путь не меняет исходный тип.
- Начальный пробел сохраняется; конечный TAB в имени каталога ведёт себя
  аналогично конечному пробелу. Клиентский async-поиск совпал с sync.

## Лексическое обрезание

[Лексическая проба](../../../tests/conformance/measure/filesystem/file-path-whitespace.bsl)
и [oracle](../../../tests/conformance/measure/filesystem/file-path-whitespace.platform.txt)
не выполняют файловый I/O. Файл.ПолноеИмя обрезает в конце и перед конечным
разделителем U+0009–000D, U+001C–0020, U+0085, U+00A0, U+1680,
U+2000–200A, U+2028, U+2029, U+202F, U+205F, U+3000. Начальная и внутренняя
позиции сохраняются. U+0000, U+0001, U+0008, U+007F, U+200B, U+FEFF
сохраняются во всех проверенных позициях.

В реализации набор совпадает с char::is_whitespace плюс U+001C–001F.
Для Файл обрезание применяется после лексической нормализации разделителей;
для входного пути поиска — до host I/O, без снятия конечного разделителя.
На момент отчёта остальные пробельные символы непосредственно на входе
поиска ещё не были измерены. Последующая матрица операционного пути закрыла
их общим правилом; `СоздатьКаталог` измерялся отдельно, удаление использует
исходные имена.

## Проверки и границы

На исходном дереве все 126 sync, 126 async и 140 лексических строк совпали
с raw oracle после удаления BOM/CRLF и исключения строк контекста. Порядок
поиска при этой сверке не сортировался. Постоянный интеграционный тест
сравнивает мультимножество в каждом результате, поскольку новые деревья
могут иметь другой host-порядок; число и дубликаты сохраняются. Он проверяет
plain, optimize, текстовый bytecode и неизменность 13 контрольных файлов.
Порядок отдельно проверяет управляемая ФС.

Host-тесты ограничивают пропуск ошибками NotFound/NotADirectory только
изменённого пути потомка: PermissionDenied и ошибка неизменённого пути
сохраняются, отмена имеет приоритет. Это защитный контракт реализации,
а не измерение всех ошибок платформы. Общие вопросы FIND.TRAVERSAL и
FILE.EDGE не закрываются. Из прежних фикстур создания восстановлен
create.spaces: теперь 26 sync и 24 async случая; async-порядок «...» остаётся
отдельным расхождением сортировки.

Итоговые проверки прошли: cargo test --workspace (включая общий
plain/optimize, bytecode round-trip и реестр вопросов), fmt --check,
Clippy --all-targets с -D warnings, rustdoc с -D warnings, регенерация
API reference, git diff --check и строгий OpenSpec — 11 элементов.
Полный файловый план этим этапом не завершён.
