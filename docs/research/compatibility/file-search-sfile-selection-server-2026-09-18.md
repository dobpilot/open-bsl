# Отбор особых имён `sfile` в файловом поиске

Измерение выполнено напрямую на серверной `localhost/test`, Linux,
1С 8.3.27.2342. Unica не использовалась. Для платформы в исходнике заменён
только placeholder корня на абсолютный путь внешнего дерева ОС. Финальная
сессия `/tmp/open-bsl-server-measure-y3_r642b` завершилась с кодом 0,
восстановила CF и БД; контрольная XML-выгрузка совпала с исходной.

- Исходник: `tests/conformance/measure/filesystem/file-search-sfile-selection.bsl`.
- Oracle: `tests/conformance/measure/filesystem/file-search-sfile-selection.platform.txt`.
- Снимок внешнего дерева: `file-search-sfile-selection.host.txt`; после запуска
  дерево не изменилось.
- SHA-256 исходника: `615c16f1692170eb81489f07d0733d128ccb47e9f7f6548f1add61060f6db38d`.
- SHA-256 oracle: `00eae9015d152dd792f6d5303f8787b87f2678b51f60b6f02b2f0474cc6484d8`.
- SHA-256 снимка: `ef1c16f26d4b30148c6fed5ffd1afeb6965bf40a3d2aa226ae79eae53753e2cb`.

Матрица содержит 13 физических имён со звёздочкой и 16 масок для каждого:
длины `?` от 1 до 8, `*`, исходное имя, экранированное имя, замену звёздочек
на `?` и четыре смеси `*`/`?`. Получено 208 результатов, а вместе с
маркерами начала и конца — 210 строк.

Платформа выделяет физическое имя со `*` в особый объект `Файл`. Прямой
конструктор сохраняет исходный каталог после двойного `sfile://`; результат
поиска теряет каталог, получает `Путь=sfile://`, а `Имя` и
`ИмяБезРасширения` содержат префикс до первой звёздочки. Без маски прямой
поиск пути со звёздочкой возвращает пустой массив.

Для выбора такого объекта действует следующая измеренная граница:

- маска с обычным литералом проходит через байтовый файловый сопоставитель;
- экранированная звёздочка является литералом;
- маска только из `?` совпадает по точной байтовой длине, но лишь начиная с
  трёх знаков;
- маски только из `*`, а также смеси `*` и `?` без литерала не совпадают.

Поэтому имена `*`, `**` и `***` не выбираются своей неэкранированной маской,
но выбираются экранированной формой. Для `**` два вопросительных знака ещё
не совпадают, а для `***` три вопросительных знака уже совпадают.

В open-bsl правило включено только для результатов `НайтиФайлы`. Удаление
по маске продолжает получать исходный физический путь и обычный файловый
сопоставитель: измерение не даёт основания менять семантику удаления.
Прямой путь со звёздочкой и без маски отсеивается до запроса metadata host.
Oracle проверяется целиком в host-тесте и в source/bytecode ×
plain/optimize. Каталоги со звёздочкой, иные формы `sfile`, дополнительные
ошибки host и циклы остаются `НЕ ИЗМЕРЕНО(FIND.TRAVERSAL)`.

Промежуточная сессия `/tmp/open-bsl-server-measure-84zdebe2` показала, что
сам BSL смог создать `a*`, но не смог построить всю матрицу физических имён;
она восстановила конфигурацию и не использовалась как oracle. Поэтому
принятый замер использует заранее подготовленное внешнее дерево ОС.
