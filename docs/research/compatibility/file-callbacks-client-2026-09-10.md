# Файловые оповещения: клиент серверной 1С

## Контур и исходные данные

Измерено 2026-09-10 прямым запуском `/opt/1cv8/x86_64/8.3.27.2342/1cv8`
на клиенте серверной `/S localhost/test`, без Unica. Это не измерение
серверного контекста, файловой базы, веб-клиента или версии 8.5.

- [Сценарий](../../../tests/conformance/measure/filesystem/file-callbacks.bsl).
- [Оригинальный вывод](../../../tests/conformance/measure/filesystem/file-callbacks.platform.txt): 28 строк, BOM и CRLF сохранены.
- SHA-256 сценария: `1d14d68093cc7574a51e348c96bebe7ef23a71b86d6d685daf7365e9464344ea`.
- SHA-256 вывода: `9f223cb3781bc1582115bb56df0963119da3d5552873dd8d19cee746c99be9b3`.

Успешная сессия — `/tmp/open-bsl-callback-flag-R2kMQP`.
Перед загрузкой сохранены свежие `original.cf` и `original-xml`.
`/CheckModules -ThinClient -Server` не обнаружил синтаксических ошибок.
После исполнения восстановлена исходная конфигурация и повторно выгружена
в `restored-xml`: XML побайтно совпал, кроме служебного `ConfigDumpInfo.xml`.
Скрипт завершился с кодом 0 после этой сверки. Проба создала и удалила
только собственный временный каталог с файлом `a`, содержащим `abc`.

## Результаты

Все восемь методов вернулись до вызова обработчиков. Во всех семи успешных
обработчиках первый аргумент — результат, второй — переданная структура
дополнительных данных. Поле этой структуры, изменённое после вызова метода,
видно обработчику (`returned=1`).

| Вызов | Вход | Результат обработчика |
|---|---|---|
| НачатьПроверкуСуществования | файл `a` | Булево, Истина |
| BeginCheckingExistence | отсутствующий путь | Булево, Ложь |
| НачатьПолучениеРазмера | файл `a` | Число, 3 |
| BeginGettingSize | отсутствующий путь | Обработчик ошибки |
| НачатьИнициализацию | `a` → `new` | Файл с путём `new` |
| BeginInitialization | `a` → `new` | Файл с путём `new` |
| НачатьПолучениеТолькоЧтения | файл `a` | Булево, Ложь |
| BeginCheckingIsDirectory | каталог пробы | Булево, Истина |

При обеих инициализациях свойство исходного объекта уже равно `new`
в строке `.return`, до обработчика. Тождество результата и исходного
объекта эта проба не сравнивает: переносить вывод предыдущего измерения
InitializeAsync на BeginInitialization без проверки нельзя.

Обработчик ошибки размера получает **три** аргумента: ИнформацияОбОшибке,
Булево, Структура. Второй приходит как Истина. В успешной пробе он объявлен
без `Знач` и изменён на Ложь; после этого остальные обработчики выполнились
и достигнут `file.end`. При предыдущей пробе с `Знач` вывод остановился после
обработчика ошибки, а клиент завершился только по тайм-ауту. Это подтверждает
необходимость исследовать изменяемый флаг стандартной обработки, а не
считать ошибочный callback обычной двухаргументной процедурой.

Сохранённый порядок — наблюдение одной сессии, не доказательство FIFO
для произвольных параллельных операций. Время готовности I/O не измерялось.
Все методы вызваны через Выполнить; ОписаниеОповещения создано через Вычислить
с именами двух экспортных обработчиков, модулем ЭтотОбъект и дополнительной
структурой. Прямые вызовы и остальные формы конструктора ещё не проверены.

## Исправление измерителя и неуспешные попытки

Первый сценарий не выдавал даже `file.begin`. Отдельная проверка компиляции
в `/tmp/open-bsl-callback-check-woxvH0` показала: клиент не видит модульные
переменные состояния. Генератор оставлял `Перем` без `&НаКлиенте`, хотя
процедуры переносил на клиент. Исправлен только генератор оболочки;
серверные объявления и локальные переменные процедур не изменены.
Тест `test_client_module_variables_have_client_context` воспроизвёл ошибку
до исправления; после него оба теста `test_gen_form_module.py` прошли.
Это исправление тестового инструмента, не изменение публичного контракта,
поэтому отдельная OpenSpec change для него не требуется.

[Документация запуска Designer](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.22_Administrator_Guide/Appendix_7._The_parameters_of_the_command_line_to_launch_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.5._Checking_configurations_and_extensions/)
использована для выбора флагов проверки; результат компиляции получен
непосредственно от установленной 8.3.27.2342.

Попытки `/tmp/open-bsl-callback-fixed-5k95Ch` и
`/tmp/open-bsl-callback-args-1RERVR` завершились по тайм-ауту 120 секунд
на обработке ошибки. Их частичные выводы не стали oracle; конфигурация
после каждой попытки восстановлена и XML сверена. В последней из них
впервые записаны типы трёх аргументов. Окончательная проба добавила проверку
булева значения и передачу этого параметра по ссылке.

## Расхождение и следующий этап

Текущий open-bsl исполняет сценарий до конца, но все восемь случаев дают
`call_error` при создании ОписаниеОповещения: тип не поддержан.
Нативный вывод не совпадает с интерпретатором и не добавлен как заведомо
зелёная conformance-фикстура. Реализация Begin-методов остаётся незавершённой.

Перед реализацией требуется уточнить контракт ОписаниеОповещения и ссылки
на модуль для CLI/embedding, измерить остальные методы, арности,
неверные обработчики, прямой вызов и тождество инициализации. Затем описать
в OpenSpec доставку callback после возврата, дополнительные данные и
изменяемый флаг ошибки; использовать существующее исполнение/планировщик,
не исполнять BSL-обработчики из фонового потока файловой системы.

На текущем дереве прошли fmt, Clippy, полный workspace, rustdoc,
два теста генератора, `git diff --check` и все 11 строгих проверок OpenSpec.
Логи Rust-проверок: `/tmp/open-bsl-callback-{clippy,workspace,doc}.log`.
Это не подтверждает отсутствующую реализацию файловых оповещений.
