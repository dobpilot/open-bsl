## Только чтение

| Исходные права | Операция | Итоговые права | Getter после |
|---|---|---|---|
| 0440 | Снять | 0640 | Ложь |
| 0660 | Установить | 0460 | Истина |
| 0550 | Снять | 0750 | Ложь |
| 0777 | Установить | 0577 | Истина |
| 0000 | Снять | 0200 | Ложь |

Меняется только бит записи владельца. Правило «снять все биты записи»
не воспроизводит платформу. На 0460 и 0577 getter возвращает Истина,
несмотря на разрешённую запись группе или остальным. Матрица не проверяет
чужого владельца и ACL и не доказывает, что атрибут заменяет access-check.
Каталог 0550 после снятия атрибута имеет 0750. Операция через симлинк
меняет цель 0440 -> 0640, сама ссылка остаётся ссылкой.

`Неопределено` отвергается. Число 1 принимается и устанавливает атрибут;
строка «Ложь» принимается, итоговый атрибут Ложь. Остальные числовые,
строковые аргументы и порядок ошибок требуют дополнительных проб.

## Невидимость

Getter возвращает Ложь и для обычного файла, и для `.hidden`.
Установка Истина обычному файлу и Ложь `.hidden` успешна, но getter
остаётся Ложь; имя не меняется. Неопределено отвергается.
Для отсутствующего пути оба getter и оба setter вызывают исключения:
Linux-no-op установки невидимости не означает игнорирование отсутствия пути.

## Запуск и сохранность

Сессия `/tmp/open-bsl-attributes-approved-JvEOqw` хранит CF, три XML-дерева,
логи и отдельный `scratch`. Подготовка создала только перечисленные файлы,
каталог и ссылку; в копии модуля placeholder заменён путём этого scratch.
GNU find записал `%f`, `%m`, `%y`, `%s` до/после, строки отсортированы.
Размер обычных файлов остался 4 байта; это не побайтная проверка содержимого.
Артефакты оставлены для повторного осмотра, общие каталоги не очищались.

Есть file.end, нет ошибки подготовки; свежий CF восстановлен. Повторная
XML-выгрузка совпала с исходной кроме ConfigDumpInfo.xml, код обёртки 0.
Это проверка конфигурации, не побайтная проверка данных всей ИБ.
Самостоятельный запуск измерителя в open-bsl был smoke-прогоном без chmod:
он проверял ловимость отсутствующих методов, а не совпадение атрибутов.

По измерению исправлен SystemFileSystem: установка меняет только 0200,
metadata.read_only отражает отсутствие этого бита. Новый тест 0660 -> 0460
сначала воспроизвёл ошибку прежнего снятия 0222, затем прошёл. BSL-методы
и невидимость этим изменением ещё не подключены.
