# Отмена при ошибке host и частичные удаления

## Область проверки

Проверяется согласованный host-контракт open-bsl: кооперативная отмена,
передача ошибок и отсутствие отката уже сделанного I/O. Новых измерений 1С
нет, localhost/test не изменялась. Детерминированные файловые host работают
только с виртуальным состоянием; системные пути не удаляются.

На момент отчёта платформенные вопросы о порядке частичных отказов и гонках
удаления оставались открытыми. Последующая серверная проба подтвердила
отсутствие отката; гонки закреплены явным контрактом одного снимка целей.
Эти тесты не меняют принятую защитную политику no-follow.

## Исправленное расхождение внутри host API

perform_file_operation проверял отмену после успешного общего результата.
Оператор ? в ветках создания и удаления, а также после всего match,
возвращал ошибку host до этой проверки. Запись атрибутов уже учитывала
отмену после отказа отдельно; у остальных глобальных операций правило
получалось непоследовательным.

Красный тест получил `Io("root: permission denied")` вместо Canceled,
когда host установил флаг отмены внутри неуспешного create_dir_all.
Лог: `/tmp/open-bsl-file-cancel-errors-red.log`.

Теперь все ветви передают Result общей завершающей проверке. Уже запрошенная
отмена имеет приоритет над результатом, в том числе ошибочным. Проверки
перед следующей операцией сохранены, выполненный I/O не откатывается.
При отсутствии отмены прежние ошибки сохраняются. Новых BSL-имён,
публичных сигнатур, формата байткода или зависимостей нет.

## Детерминированные проверки

В `bsl-rt/tests/file_async.rs` добавлены 16 сочетаний: восемь мест отказа
с отменой и без неё. Проверяются создание каталога, прямое удаление,
удаление по маске, получение временного каталога, получение разделителя,
отказ перечисления при поиске и удалении. История изменений подтверждает
отсутствие отката и следующего удаления. Все семь тестов файла прошли:
`/tmp/open-bsl-file-cancel-errors-focused.log`.

`open-bsl/tests/file_partial_failure.rs` проверяет 128 сочетаний:
четыре сценария × sync/async × RU/EN × direct/dynamic × plain/optimize ×
source/bytecode. Один и тот же виртуальный host сохраняется для фона.

| Отказ | Сохранённый результат |
| --- | --- |
| Ошибка третьего элемента read_dir | Ни одного удаления: выбор не завершён |
| Ошибка перед удалением b.txt | a.txt удалён, b.txt и c.txt сохранены |
| Ошибка после удаления b.txt | a.txt и b.txt удалены, c.txt сохранён |
| Ошибка внутри удаления дерева | Изменённая host часть дерева не восстанавливается |

BSL получает исходную причину отказа. Для всех 64 async-сочетаний второе
Ждать возвращает ту же ошибку без повторного I/O. Вызовы записи/создания,
которые могли бы означать откат, запрещены самим тестовым host.
Лог: `/tmp/open-bsl-file-partial-failure-focused.log`.

## Общие проверки

Полный `cargo test --workspace`, Clippy всех targets с `-D warnings`,
rustdoc с `-D warnings`, fmt, `git diff --check` и строгий OpenSpec
(11/11) завершились успешно. В workspace прошли сравнение обычного и
оптимизированного исполнения, API reference и реестр измерений.
Логи: `/tmp/open-bsl-file-operation-failures-{workspace,clippy,doc}.log`.
Игнорируемый MXL dump и закрытые table_compare2-случаи без отдельной
переменной окружения не объявляются проверенными этой приёмкой.

Полный файловый план остаётся открытым; нативные границы удаления и
согласование системного владения временными файлами этим не закрываются.
