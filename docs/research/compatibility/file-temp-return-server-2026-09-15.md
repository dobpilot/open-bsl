# Временные файлы: возврат серверного вызова и окончание клиента

## Контекст и сохранность

Linux, localhost/test, сервер 8.3.27.2342 запущен пользователем напрямую
от kan; клиент использует ту же установленную версию. Default-служба
systemd при этом не активна — её статус не отражает прямой запуск кластера.
Unica не использовалась. Код создания — серверные функции без контекста формы;
первый снимок после возврата выполняется на клиенте до следующего RPC.
Клиент и сервер находятся на одной машине, файловое пространство проверяется
отдельным обычным контрольным файлом.

XML содержит CompatibilityMode=Version8_3_27; серверное
Метаданные.РежимСовместимости вернуло НеИспользовать. Оба значения сохранены
без попытки объявить их эквивалентными. 8.5 и файловая база этим прогоном
не проверялись.

Сначала новый run-on-server-1c.py проверен прежним file-globals.bsl:
`/tmp/open-bsl-server-measure-wnx0x4w8`. Результат совпал с замером 09-09
после замены только случайной части имён `/tmp/v8_*` (включая порядок поиска).
Исходный повторный вывод —
[file-globals.platform-2026-09-15.txt](../../../tests/conformance/measure/filesystem/file-globals.platform-2026-09-15.txt).

Проба срока жизни выполнена дважды. Первая сессия
`/tmp/open-bsl-server-measure-iqf28ksm` подтвердила существование до выхода;
внешняя проверка пришлась уже на восстановление. Повторная сессия
`/tmp/open-bsl-server-measure-awb93m8l` добавила отдельный снимок сразу после
возврата ENTERPRISE, **до первого LoadCfg**. Во всех трёх сессиях сохранены
свежие CF/XML, восстановлен CF и подтверждено побайтное совпадение XML,
кроме корневого ConfigDumpInfo.xml. Каждый runner завершился с кодом 0.
Это подтверждает конфигурацию, не побайтную сохранность всех данных ИБ.

## Метод и результаты

[Скрипт](../../../tests/conformance/measure/filesystem/file-temp-return.bsl),
[исходный вывод](../../../tests/conformance/measure/filesystem/file-temp-return.platform.txt),
[внешний снимок](../../../tests/conformance/measure/filesystem/file-temp-return.host.txt).

Создаются четыре независимых серверных временных файла:

- `closed` — пустой временный поток, явно вызван Закрыть.
- `released` — пустой временный поток, переменной присвоено Неопределено без явного Закрыть.
- `open` — пустой временный поток без явного Закрыть или сброса переменной.
- `name` — имя от ПолучитьИмяВременногоФайла, затем отдельная запись трёх байтов ABC.

Роль open описывает действия BSL, а не измеренный набор открытых OS-дескрипторов:
в этой пробе `/proc/*/fd` не исследовался.

| Наблюдение | closed | released | open | name |
|---|---|---|---|---|
| После явного Закрыть/сброса переменной | существует | существует | — | — |
| До возврата серверной функции | существует, 0 байтов | существует, 0 байтов | существует, 0 байтов | существует, 3 байта |
| На клиенте после возврата, до следующего RPC | существует, 0 байтов | существует, 0 байтов | существует, 0 байтов | существует, 3 байта |
| В следующем серверном вызове | существует, 0 байтов | существует, 0 байтов | существует, 0 байтов | существует, 3 байта |
| На клиенте перед завершением | существует, 0 байтов | существует, 0 байтов | существует, 0 байтов | существует, 3 байта |
| OS lstat после завершения ENTERPRISE, до LoadCfg | отсутствует | отсутствует | отсутствует | отсутствует |

BSL-снимки содержат пять позиций: сначала контрольный файл, затем эти четыре
роли. Во всех снимках контрольный файл существует и имеет размер 3. Он создан
сервером внутри отдельного каталога, подготовленного клиентом, и явно удалён
клиентом после наблюдений. Четыре исследуемых файла не удаляются кодом пробы.
Внешний наблюдатель читает metadata только четырёх явно выведенных путей;
не сканирует temp и не удаляет ничего.

## Вывод и границы

Для этих случаев Закрыть, сброс переменной и возврат серверного вызова
не означают удаления файла. Наблюдаемая граница удаления находится между
последним клиентским снимком и возвратом процесса ENTERPRISE. Проверка
до LoadCfg исключает восстановление конфигурации как причину исчезновения.
Это не устанавливает точную внутреннюю точку очистки, задержку во всех
сеансах, поведение при ошибке/отмене или принудительном убийстве процесса.

Политика open-bsl «сеансовый учёт, callback host и очистка CLI при штатном
выходе» не противоречит этим наблюдениям, но её системная реализация ещё
не завершена. Создание имени и последующая запись тоже участвуют в измеренной
очистке 1С; нельзя считать реестр только временных потоков полным интерфейсом.
Безопасное владение текущим объектом по выданному имени остаётся обязательным.

На open-bsl скрипт компилируется и заканчивает работу с диагностикой отсутствия
СоздатьВременныйФайл; это **не** совпадение с oracle. Результат интерпретатора
не использован для создания `.platform.txt` или изменения общего platform.tsv.

Для смешанного контекста исправлен генератор: явная директива
@onec-server-without-context теперь действует и при наличии async-объявления.
Воспроизводящий unit-тест был красным и стал зелёным; нативная проверка модулей
обеих сессий не обнаружила синтаксических ошибок.
