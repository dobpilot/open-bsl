## Конструкторы и проверка обработчиков

Английское имя — **NotifyDescription**. Попытка `NotificationDescription`
отвергнута как неизвестный тип; не следует регистрировать выдуманный alias.
Из количества аргументов 0–6 приняты 0, 2, 3 и 5. Для 1, 4 и 6 получена
ошибка компиляции динамического выражения «Constructor not found».
Четыре аргумента с пропусками не стали допустимой формой.

Пустой конструктор создаёт описание с пустыми строками двух имён процедур
и Неопределено в модуле, дополнительных параметрах и модуле ошибки.
Форма из двух аргументов сохраняет имя и модуль; третий добавляет данные;
пять добавляют имя и модуль обработчика ошибки.

Непустые формы проверяют экспортный обработчик уже при создании.
Несуществующее имя отвергнуто с точной причиной `The export method is not found`.
Пустая строка и Неопределено вместо имени дают несовпадение типа параметра 1.
Число 123 дошло до поиска экспортного метода с именем `123`: это свидетельство
преобразования именно этого числа, не универсальная проверка всех типов.
Неопределено и число вместо модуля дают несовпадение типа параметра 2;
структура дошла до поиска экспортного метода, но метод в ней не найден.
Число вместо модуля ошибки даёт несовпадение типа параметра 5.

Случай `ctor.error.number` имеет четыре аргумента и отвергнут по форме
конструктора; он **не** измеряет преобразование числового имени ошибки.
Текст вложенной причины сохранён отдельно от внешней ошибки Вычислить.

## Свойства и тождество

| Русское свойство | Английское имя | Содержимое полной формы |
|---|---|---|
| ИмяПроцедуры | ProcedureName | Имя экспортного обработчика |
| Модуль | Module | Исходная клиентская форма |
| ДополнительныеПараметры | AdditionalParameters | Переданное значение |
| ИмяПроцедурыОбработкиОшибки | ErrorHandlerProcedureName | Имя обработчика ошибки |
| МодульОбработкиОшибки | ErrorHandlerModule | Переданная клиентская форма |

Для каждого имени выполнено чтение и присваивание Неопределено.
Все десять записей отвергнуты именно как `Object field is not writable`,
а не из-за несовместимого значения. Имена свойств в сообщении нормализованы
к русскому варианту.

Псевдоним описания равен ему; два независимо созданных описания с одинаковыми
аргументами не равны. Структура дополнительных данных сохраняется по ссылке:
изменение исходного Счетчик с 1 на 2 видно через свойство. Модуль равен
переданному ЭтотОбъект. Это не измерение времени жизни ссылок после завершения
исполнения или сборки циклов.

## Качество пробы и расхождение

Первая сессия `/tmp/open-bsl-notification-description-Mmmx23` показала,
что несуществующие обработчики мешают исследовать свойства. Во второй,
`/tmp/open-bsl-notification-description-valid-KZr3fp`, использованы реальные
экспортные процедуры, но отдельная функция запрашивала ИнформацияОбОшибке
вне непосредственного блока Исключение и получала пустое описание.
Окончательная версия передаёт объект ошибки из самого обработчика исключения.
Все три сессии закончились восстановлением CF и сверкой XML.
Промежуточные выводы не заменяют опубликованный окончательный oracle.

В open-bsl конструктор пока отсутствует; сценарий выполняется до конца
с пойманными отказами, а не совпадает с платформой. Runtime на этом этапе
не изменён. Отдельно нужны измерения прямого вызова, регистронезависимости,
неэкспортного/серверного/функционального обработчика и его арности,
других объектов-модулей и ошибок пятой формы.

Следствие для реализации: текущий `Arity` хранит один непрерывный диапазон.
Диапазон 0–5 ошибочно разрешил бы 1 и 4; перед регистрацией конструктора
нужно выбрать совместимое представление набора арностей и проверить sema,
runtime и генерацию API reference. Проверка экспортного метода при создании
также требует реального контракта ссылки на модуль, а не хранения любого
значения с обещанием проверить его только при доставке callback.
