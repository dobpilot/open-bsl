# Маски в обычном дереве и каталогах с одним файлом

Серверная localhost/test, Linux, 1С 8.3.27.2342. Прямой разрешённый запуск
без Unica. Вопрос effective compatibility из предыдущих замеров не закрыт.
Выполнены 300 запросов: 20 масок в обычном дереве и в 14 singleton-каталогах.

- [Исходник](../../../tests/conformance/measure/filesystem/file-masks-single.bsl).
- [Сырой результат](../../../tests/conformance/measure/filesystem/file-masks-single.platform.txt).
- [Подготовленные пути](../../../tests/conformance/measure/filesystem/file-masks-single.host.txt).

Сопоставление singleton-каталогов с именами:
`s00=a`, `s01=Z`, `s02=1`, `s03=я`, `s04=漢`, `s05=😀`, `s06=.hidden`,
`s07=a*`, `s08=a?`, `s09=a\b`, `s10=[`, `s11=[x]`, `s12=-`, `s13=]`.
Обычное дерево содержит все эти имена, кроме s07–s09.
Номера масок одни и те же в каждом блоке, записаны в исходнике.

## Подтверждённые обычные случаи

Один `?` сопоставляется с одним байтом UTF-8, не Unicode-скаляром:
`я` найден через `??`, `漢` через `???`, `😀` через `????`.
Это проверено как совместным деревом, так и одиночными файлами.
В обычном дереве `*` возвращает все 11 файлов, включая `.hidden`;
`*.*` — только `.hidden`. `a*` находит `a`.

`[a-z]` находит `a`, не `Z`. Обе формы отрицания `[!a-z]` и `[^a-z]`
находят пять остальных однобайтных имён. `[[:alpha:]]` находит только
`a` и `Z`; `[а-я]` не находит ни одного файла. Незакрытая `[` трактуется
буквально, `[[]x]` находит `[x]`, `[a-]` — `a` и `-`, обратный диапазон
`[z-a]` не находит файлов. `[[]` и `[]]` находят соответствующие скобки.
Полный набор POSIX-классов, экранирование и локали пока не измерены.

## Особые имена — отдельный слой поведения

В каталоге с единственным `a*` маски `*` и `??` возвращают пустой массив,
но `a*` и `a\*` дают один объект с Имя=`a` и остатком ПолноеИмя
`sfile://sfile://a*` после удаления scratch-префикса. Это не обычный
буквальный файловый объект; нельзя приписать эффект чистому glob-сопоставителю.
В каталоге с `a?` маски `??`, `a*`, `*` возвращают этот файл как `a?`.
Для `a\b` маски `???`, `a*`, `*` возвращают Имя=`b`, остаток ПолноеИмя=`a/b`.

Таким образом, предыдущий смешанный замер не опровергал побайтовое
сопоставление обычных имён. Но взаимодействие специальных имён в одном
массиве остаётся необъяснённым. Оно должно остаться отдельным вопросом
совместимости поиска/объектов пути, не исчезнуть при реализации простых случаев.

## Воспроизводимость

Сессия `/tmp/open-bsl-single-masks-approved-FF2FSI`: свежий CF, три XML-дерева,
логи и scratch. Дерево подготовлено средствами ОС, чтобы запись 1С не
преобразовала исходные имена. В сгенерированном модуле заменён только
placeholder scratch; результаты не сортировались, сокращён только его префикс.
Manifest ОС отсортирован отдельно. Файлы сохранены как артефакты.

Все 300 строк есть, есть file.end, ошибок подготовки нет. CF восстановлен,
XML до/после идентичен кроме ConfigDumpInfo.xml; код обёртки 0. Это не
побайтная проверка данных всей ИБ. Smoke-прогон open-bsl проверяет только
исполнимость оболочки с ловимым отсутствием FindFiles, не результат поиска.
