# Удаление по маске и read-only на серверной 1С

Источник: `tests/conformance/measure/filesystem/file-delete-masks.bsl`;
oracle: соседний `file-delete-masks.platform.txt`, исходные BOM/CRLF сохранены.
1С 8.3.27.2342, Linux, `/S localhost/test`, серверный модуль формы,
пустые учётные данные, без Unica. XML содержит Version8_3_27; effective
compatibility отдельно не проверялся. Это не замер 8.5 или файловой базы.

Сеанс `/tmp/open-bsl-delete-masks-approved-ztdzM1`. Свежие original.cf и
original-xml получены перед загрузкой. После выполнения восстановлен CF,
XML совпал побайтно кроме ConfigDumpInfo.xml, runner exit 0. Оба маркера
begin/end присутствуют, ошибок setup/cleanup нет. Каждый случай использовал
своё временное дерево; очистка снимала read-only у оставшегося файла.

SHA-256 скрипта: `82d702c491d6c757971cfe8e28fc65241dad154f5d2f88a0c0937ab2e066df39`.
SHA-256 вывода: `d0d09a8ba7dcd932c4123e40f0139d202e3278801e4a29ecc321ec83be4a1398`.

## Результаты

В каждой строке семь признаков существования: data, data/a.txt, data/b.bin,
data/ro.txt, data/branch.txt, data/branch.txt/deep.bin, data/stay/deep.txt.

- `*.txt` удаляет подходящие файлы и branch.txt с содержимым; сохраняет
  data, b.bin и stay/deep.txt. Это не рекурсивное удаление всех txt в дереве.
- `*` удаляет непосредственных детей с содержимым, но сохраняет data.
- Пустая и Неопределено-маска удаляют сам data с содержимым.
- Маска для отсутствующего пути или обычного файла ничего не удаляет.
- Read-only файл удаляется напрямую, по маске и внутри дерева. Дополнительный
  запрет по атрибуту на этой Linux-платформе не подтверждён. Это не обещание
  удаления при любых правах родителя, ACL, владельце или на других ОС.

## Реализация и границы

Выбор путей общий с НайтиФайлы, без повторной нормализации через объект Файл.
Непустая маска выбирает только непосредственных детей; remove_path принадлежит
host и сохраняет прежнее намеренное удаление самой ссылки, а не её цели.
Отмена проверяется при выборе и перед каждым удалением. Прямой вызов не требует
новых возможностей metadata/read_dir/path_separator от старого host.

Порядок частичных отказов, гонки, нестроковые маски и полный набор ошибок
этим ранним замером не проверены; они закрыты последующими oracle и явным
host-контрактом. Поведение ссылок платформы здесь также не проверено. Старый
байт-код с одним аргументом сохраняется; новый компилятор
дополняет отсутствующую маску Неопределено.
