# Особые имена `sfile` в файловом поиске

Измерение выполнено напрямую на серверной `localhost/test`, Linux,
1С 8.3.27.2342. Unica не использовалась. Конфигурация и БД восстановлены,
контрольная XML-выгрузка совпала с исходной.

- Исходник: `tests/conformance/measure/filesystem/file-search-sfile.bsl`.
- Oracle: `tests/conformance/measure/filesystem/file-search-sfile.platform.txt`.
- Дерево до и после запуска: `file-search-sfile.host.txt`; оно не изменилось.
- Артефакты сессии: `/tmp/open-bsl-server-measure-7j3gc_et`.
- SHA-256 исходника: `ccc091a27e5b53329e6d25b7c7452dffe6a0b8d01ec53d4e5520dbe758e41b09`.
- SHA-256 oracle: `9c44e0bb1e8c6cef231d54bc56286ae10da53a6759ff95f5ae705a2f1b424424`.

Файлы со знаком вопроса остаются обычными: прямой объект и результаты
`НайтиФайлы` сохраняют имя, путь, существование и размер. Обратная косая
черта разбирается как разделитель: физический `a\b` выдаётся как
несуществующий объект пути `a/b`. Это подтверждает ранее принятое защитное
отличие open-bsl: host-имя с разделителем отвергается до выхода из каталога.

Любое из измеренных имён со звёздочкой (`*`, `*a`, `a*`, `a*b`, `a**`,
`a*.txt`) превращается в особый объект. Прямой `Новый Файл` получает
`ПолноеИмя=sfile://sfile://<исходный путь>`, а результат поиска теряет
каталог и получает `ПолноеИмя=sfile://sfile://<имя>`, `Путь=sfile://`.
`Имя` и `ИмяБезРасширения` равны части до первой звёздочки, расширение
пусто. `Существует()` возвращает `Ложь`; чтение вида и размера ошибочно.

Включение такого имени не сводится к уже измеренному чистому glob. Маска
`*` не возвращает ни одно из шести звёздочных имён. Маска, повторяющая имя,
и вариант с экранированной звёздочкой возвращают объект. Эта первая матрица
не позволяла вывести правило вопросительных масок. Последующий замер 208
сочетаний установил измеренную границу отбора; см.
`file-search-sfile-selection-server-2026-09-18.md`. Неизмеренные формы
по-прежнему относятся к `FIND.TRAVERSAL`.
