# Файлы, каталоги, запуск приложений и временные файлы

Сопоставление от 2026-09-09. open-bsl: `1335406`; прежние незакоммиченные
изменения benchmark не относятся к этому анализу. Runtime не изменялся,
новые пробы на 1С в рамках этого сопоставления не запускались.

## Источники и границы доказательства

Справка прочитана через публичные `unica.documentation.search` с фильтром
`sourceKinds=[platform-help]` и `unica.documentation.get`. Основание выводов —
полный `text` страниц, не поисковые фрагменты. Поставщик `platform-syntax-help`,
корпус `syntax-context`, `authority=vendor`, версия установки и
`applicableVersion=8.3.27.2342`, фактический язык `ru`.
Поиск также возвращал английское руководство семейства 8.3.27; оно не
использовано для установления сигнатур. Подстановки локали у использованных
страниц синтакс-помощника нет.

| Контекст | Режим совместимости | Что подтверждено |
|---|---|---|
| Установленная справка 8.3.27.2342 | Не определяет режим конкретной ИБ | Документированные сигнатуры, доступность, ограничения |
| Планируемый замер серверной Linux 1С | Прочитать фактический literal перед запуском; предполагаемый `Version8_3_27` требует подтверждения | В этом анализе НЕ ИЗМЕРЕНО |
| Клиентская 1С для запуска приложения | Указать отдельно в протоколе | В этом анализе НЕ ИЗМЕРЕНО |
| Другие ОС, 8.5, веб- и мобильный клиенты | Не проверены | Совместимость не заявляется |

Справка не заменяет платформенный oracle. Действующие измерения
[`measure-temp-files.bsl`](../../../tests/conformance/measure/measure-temp-files.bsl)
и [результат](../../../tests/conformance/measure/measure-temp-files.platform.txt)
проверяют суффикс `.bin`, отсутствие заранее созданного файла, запись,
перезапись, удаление файла/дерева и повторное удаление отсутствующего пути.
Они не проверяют расширение без точки, расширение по умолчанию, маски,
сроки очистки или процессы. Точный режим ИБ не записан в самом этом TSV;
для новых сравнений нужно сохранить отдельный паспорт запуска.

## Сопоставление

| Возможность | Справка 1С | open-bsl | Что делать |
|---|---|---|---|
| `УдалитьФайлы / DeleteFiles` | Процедура, 1–2 аргумента; второй — маска [D1] | Есть только один аргумент; файл, дерево, отсутствующий путь | Дополнить маской, сохранить измеренные случаи |
| `НайтиФайлы / FindFiles` | 1–3 аргумента; возвращает `Массив` объектов `Файл`; файлы и каталоги [D2] | Нет BSL-функции; `FileSystem::read_dir` есть | Добавить тип результата, сопоставление масок и обход |
| `Новый Файл`, `ПолноеИмя`, `Существует`, `ЭтоКаталог` | Объект пути и доступ к состоянию [D8–D11] | Нет BSL-типа `Файл`; host-метаданные есть | Обязательная зависимость поиска, не замена массивом строк |
| `СоздатьКаталог / CreateDirectory` | Процедура, один аргумент; существующий каталог не ошибка [D3] | Нет BSL-функции; `create_dir_all` есть | Добавить обёртку после проверки граничных случаев |
| `ЗапуститьПриложение / RunApp` | Процедура, 1–4 аргумента, код завершения — выходной параметр; без командного интерпретатора [D4] | Нет функции и host-возможности запуска | Отдельный этап с выбором контекста и обработкой выходного аргумента |
| `КомандаСистемы / System` | Командный интерпретатор; только тонкий/толстый клиент [D5] | Нет | Не использовать как реализацию `RunApp`; отдельный возможный объём работ |
| `ПолучитьИмяВременногоФайла / GetTempFileName` | 0–1 аргумент; по умолчанию `.tmp`; `xml` и `.xml` эквивалентны; файл не создаётся [D6] | Есть; суффикс дописывается дословно, по умолчанию пустой | Проверить и исправить нормализацию, сохранить отсутствие файла |
| `КаталогВременныхФайлов / TempFilesDir` | Строка каталога временных файлов пользователя процесса [D7] | Нет BSL-функции и отдельного host-метода; `std::env::temp_dir` используется внутри системного `temporary_path` | Расширить host-контракт без обхода виртуальной ФС |
| Очистка временных имён/файлов | Описаны очистка при следующем запуске и серверные сроки жизни [D6] | Нет учёта выданных путей и соответствующей автоматической очистки | Отдельно измерить и спроектировать владение и жизненный цикл |
| `ФайловыеПотоки.СоздатьВременныйФайл / CreateTempFile` | 0–2 аргумента; `ФайловыйПоток`, память до лимита, затем диск [D12] | Менеджер и обычные потоки есть; этого метода нет | Дополнить существующий `bsl-stream`, не создавать второй стек потоков |
| Асинхронные варианты | Возвращают `Обещание`; доступность и тип результата различаются [D13–D18] | Перечисленных файловых вариантов нет | Самостоятельный этап после синхронного контракта |

Чтение/запись содержимого уже представлены `ДвоичныеДанные`, файловыми
и текстовыми потоками, `ТекстовыйДокумент`, `ЗначениеВФайл/ЗначениеИзФайла`
и компонентами форматов. Их полная совместимость не проверялась здесь.
Копирование/перемещение, FTP/HTTP-адресация и клиентские диалоги не входят
в первую реализацию запрошенных операций; это не заявление об их отсутствии в 1С.

## Детали, влияющие на план

1. **Маски зависят от ОС.** D1/D2 документируют для Linux/macOS учёт регистра,
   `*`, `?`, классы `[abc]`, диапазоны и отрицание `[!...]`. Одного текущего
   ZIP-сопоставителя `*`/`?` недостаточно. Не переносить в общий файловый API
   специфическое ZIP-правило обратного слеша и выборки каталогов.
   Пример с `|` и `;` в D2 выглядит как фильтр диалога; его применимость
   к этому методу НЕ ИЗМЕРЕНО и не должна угадываться по примеру.
2. **Без маски поиск не равен перечислению каталога.** D2 допускает полный
   путь и говорит, что флаг рекурсии без маски игнорируется. Отсутствующий
   аргумент, пустая строка и `Неопределено` требуют отдельных проб.
3. **Удаление ссылок — намеренная граница open-bsl.** `remove_path` использует
   `symlink_metadata` и удаляет саму ссылку, не её целевое дерево. Комментарий
   прямо связывает это с безопасностью host. Не исправлять это вслепую
   «под платформу». Доступ через ссылки в родительских компонентах пути
   требует отдельного аудита: данный код сам по себе не является sandbox.
4. **Запуск не равен shell.** D4 одновременно перечисляет сервер в доступности
   и предупреждает об исключении при серверном и пакетном вызове. D5 не
   предлагает серверной альтернативы. Успешный CLI-запуск через host нельзя
   выдавать за воспроизведение серверной 1С. Открытие документа по ассоциации
   и запуск исполняемого файла — разные сценарии. Возможность открыть URL
   в D4 прямо не гарантируется.
5. **Временное имя не есть открытый временный файл.** Текущее
   `temporary_path` кратко создаёт путь с `create_new` и удаляет его до
   возврата. Это проверяет коллизию в момент резервирования, но не сохраняет
   владение именем до будущего открытия. Для временного потока нельзя
   построить безопасную реализацию из раздельных «получить имя → открыть».
6. **Очистка зависит от контекста.** D6 описывает удаление файлов сеанса
   в течение 20 минут после его завершения и файлов серверного вызова
   через 20 минут после окончания вызова; второй режим недоступен при
   совместимости 8.3.16 и ниже. Отождествление `State::drop` с серверным
   вызовом или немедленная очистка были бы новым решением, не фактом 1С.
   `TempStorageSession` — временное хранилище значений, не реестр файлов ОС.
7. **Временный поток — не просто `ПотокВПамяти`.** D12 задаёт результат
   типа `ФайловыйПоток`, монопольное чтение/запись, порог 65535 байт и
   буфер 8192 байта по умолчанию. Закрытие, удаление backing-файла и
   точный момент перехода на диск требуют платформенных проб.
8. **Асинхронность не унифицирует доступность.** D13 (`НайтиФайлыАсинх`)
   перечисляет сервер, D14–D18 его не перечисляют. Результат создания
   каталога — строка, удаления — `Неопределено`, запуска — число либо
   `Неопределено`, создания временного потока — `ФайловыйПоток`.

Последующая [прямая серверная проба](file-async-server-2026-09-09.md)
уточнила пункт 8: перечисление сервера в D13 не подтверждается успешным вызовом
в измеренном контексте 8.3.27.2342 — метод отказывает с причиной «только на клиенте».
[Клиентская проба](file-async-client-2026-09-09.md) подтверждает обещание массива
Файл и ошибку явно неопределённой рекурсии при Ждать, а не при создании обещания.

## Опорные места реализации

- [`builtin.rs`](../../../crates/bsl-rt/src/builtin.rs): `BuiltinFn`, арности,
  `host_effect`, `call_builtin_files`, `call_builtin_temp_file`.
- [`env.rs`](../../../crates/bsl-rt/src/env.rs): `FileSystem`, `FileMetadata`,
  `DirEntry`, `SystemFileSystem::temporary_path/remove_path`.
- [`stream.rs`](../../../crates/bsl-stream/src/stream.rs): `StreamData`,
  `FileStreamsManager`; типы памяти и файла уже различаются.
- [`writer.rs`](../../../crates/bsl-zip/src/archive/writer.rs):
  `mask_matches`, `split_pattern`; не копировать второй алгоритм.
- [`compiler.rs`](../../../crates/bsl-compiler/src/compiler.rs): глобальные
  builtin-аргументы компилируются в временные регистры значений, тогда как
  вызовы BSL-процедур уже используют `ArgMode` для ссылок. Выходной
  `КодВозврата` нельзя реализовать изменением локальной копии аргумента.
- [`host_environment.rs`](../../../crates/open-bsl/tests/host_environment.rs):
  тест `temporary_binary_file_stays_in_the_session_file_system`.
