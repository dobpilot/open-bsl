# Контрольные деревья поиска по ссылкам

1С 8.3.27.2342, Linux, серверный модуль формы `/S localhost/test`.
Литеральный CompatibilityMode — Version8_3_27; effective-режим и 8.5
отдельно не проверялись. Unica не использовалась.

## Подготовка

Каталог сессии `/tmp/open-bsl-find-link-controls-NhS1hY/tree` содержит
шесть независимых деревьев. В каждом есть `plain.txt` и `actual/direct.txt`
с байтами `direct\n`. Общая цель `outside` содержит `remote.txt` (`remote\n`)
и `nested/leaf.txt` (`leaf\n`). Все ссылки относительные и остаются внутри
этого scratch-каталога; ни одна проба не изменяет файлы.

| Дерево | Дополнительные элементы |
|---|---|
| plain | Нет |
| file | linked-file.txt → ../outside/remote.txt |
| dir | linked-dir → ../outside |
| broken | broken.txt → ../absent |
| valid | Обе существующие ссылки |
| mixed | Все три ссылки |

Измеритель содержит абсолютный путь подготовленной сессии. Перенос на
другую машину требует нового изолированного дерева и изменения КореньСсылок;
это не автономный conformance fixture. Дерево оставлено для следующих проб.

## 24 результата

Числа в ячейках — 1С / open-bsl до исправления.

| Дерево | `*` | `*`, рекурсия | `*.txt` | `*.txt`, рекурсия |
|---|---:|---:|---:|---:|
| plain | 2 / 2 | 3 / 3 | 1 / 1 | 2 / 2 |
| file | 3 / 3 | 4 / 4 | 2 / 2 | 3 / 3 |
| dir | 3 / 3 | 7 / 4 | 1 / 1 | 4 / 2 |
| broken | 0 / 3 | 0 / 4 | 2 / 2 | 2 / 3 |
| valid | 4 / 4 | 8 / 5 | 2 / 2 | 5 / 3 |
| mixed | 0 / 5 | 0 / 6 | 3 / 3 | 3 / 4 |

Исходные строки сохраняют не только количества, но все пути в порядке
возврата. Без оборванной ссылки платформа проходит `linked-dir`, включая
вложенный каталог, даже когда имя ссылки не совпадает с `*.txt`. Путь
результата остаётся через имя ссылки, а не заменяется каноническим путём цели.

Для дерева dir сначала выданы linked-dir, plain.txt, actual; затем содержимое
linked-dir и его nested; затем actual/direct.txt. Следовательно, измеренный
порядок — совпадения текущего каталога перед рекурсивными результатами,
а не немедленный спуск при встрече каталога. Это не доказательство сортировки
или стабильности порядка ОС для других наборов.

Оборванная ссылка воспроизводит прежнюю аномалию отдельно от существующих
ссылок: `*` даёт ноль, а `*.txt` сохраняет совпадения текущего уровня и
не даёт обычного actual/direct.txt. Механизм этого поведения, зависимость
от имени/позиции оборванной ссылки и другие маски пока не установлены.
Нельзя заменить все ошибки metadata пустым массивом по этим четырём случаям.

## Следствия для реализации

Последующий [замер масок и порядка](file-search-broken-masks-server-2026-09-10.md)
подтвердил зависимость аномалии от позиции оборванной ссылки: результаты
первой и последней позиции различаются. Ниже сохранены ограничения этого этапа.

Нужны отдельные изменения: следование по существующей ссылке на каталог,
выдача текущего уровня до рекурсивного спуска и уточнение обработки оборванных
ссылок. Пределы глубины/числа элементов и отмена остаются обязательными;
поведение циклических ссылок платформы этим деревом не измерено.

`DirEntry::is_dir` нельзя просто переключить на следование по ссылкам:
его действующий контракт означает вид самого элемента и используется ZIP.
Файловый поиск должен отдельно получать сведения о цели через host metadata
или иной явно описанный host-контракт, не меняя смысл общего поля для ZIP.
FIND.TRAVERSAL остаётся открытым; в измерительном шаге runtime не менялся.

## Исправление подтверждённой части

Позднее общий обход переведён на стек ожидающих каталогов: сначала все
совпадения уровня, затем его поддеревья в порядке host. В DirEntry добавлен
отдельный признак ссылки; прежний is_dir не изменён. Только при рекурсии
по сообщённой ссылке поиск читает metadata цели через тот же host.
Все 16 строк plain/file/dir/valid совпали с исходным выводом 1С, включая пути
и порядок. На этом этапе NotFound цели запрещал только спуск. Позднее
[замер средней позиции](file-search-broken-middle-server-2026-09-10.md)
привёл к исправлению измеренных случаев оборванной ссылки; неизмеренные
сочетания остаются в FIND.TRAVERSAL.

Тест виртуального host воспроизвёл прежний порядок до исправления. Реальный
Unix-тест сверяет измеренные множества valid для двух масок, локальные
результаты перед вложенными и сохранение no-follow is_dir. Цикл завершается
ошибкой host или защитным пределом, не частичным успехом; это правило
open-bsl, не замер циклов 1С. Отдельный тест отменяет поиск после metadata
ссылки и подтверждает, что дочерний каталог не открывается.

Прошли 11 тестов поиска и полный `cargo test --workspace`, включая ZIP,
асинхронные операции, конформанс plain/optimize/round-trip и реестр вопросов.
Также прошли fmt, Clippy и rustdoc с `-D warnings`, регенерация API reference
и строгая проверка OpenSpec. Полный журнал —
`/tmp/open-bsl-search-recursion-workspace.log`. Конфиденциальный корпус без
OPEN_BSL_TABLE_COMPARE2_CASES и игнорируемая выгрузка MXL сохраняют обычные
ограничения полного набора и не считаются выполненным платформенным замером.
