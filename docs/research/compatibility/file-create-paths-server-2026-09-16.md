# Создание каталогов: пути и фактические имена

## Контекст и сохранность базы

После активации лицензии пользователем прямые запуски 1С снова доступны.
Linux, 8.3.27.2342, `/S localhost/test`, кластер от kan, без Unica.
Обычная проба выполняется на сервере, async — на клиенте серверной базы.
Выгрузки содержат CompatibilityMode=Version8_3_27; обе пробы вернули
Метаданные.РежимСовместимости=НеИспользовать. Эти значения сохранены
раздельно, без предположения об их эквивалентности. 8.5 и файловая база
здесь не измерялись.

Каждый запуск получил свежие CF/XML, повторную проверку перед загрузкой,
затем восстановление CF/конфигурации БД и побайтную сверку XML, кроме
корневого ConfigDumpInfo.xml. Во всех пяти сессиях восстановление подтверждено:

[исходный вывод первой пробы](../../../tests/conformance/measure/filesystem/file-create-paths.initial.platform.txt)

даже контрольный block, а УдалитьФайлы отказал. Проверка ОС обнаружила
оба объекта. Это не основание объявить само создание неуспешным.

## Подтверждённые правила

[Серверный скрипт](../../../tests/conformance/measure/filesystem/file-create-paths.bsl),
[исходный серверный вывод](../../../tests/conformance/measure/filesystem/file-create-paths.platform.txt),
[клиентский скрипт](../../../tests/conformance/measure/filesystem/file-create-paths-async.bsl),
[исходный клиентский вывод](../../../tests/conformance/measure/filesystem/file-create-paths-async.platform.txt).

- `missing/../leaf` создаёт leaf, не создавая missing.
- `block/../leaf` создаёт leaf даже при обычном файле block; его данные сохраняются.
- `/` и `\` разделяют компоненты; повторные разделители и `.` сворачиваются.
- Пустая строка, Неопределено и Null отвергаются. Процедура в выражении и лишний аргумент не создают каталог.
- NUL завершает путь операции: `nul<NUL>tail` и `nul<NUL>/tail` создают только nul.
- star* отвергается; question?, конечная точка, три точки, кириллица и TAB допустимы в измеренных именах.
- Асинхронный метод возвращает обещание исходной строки, включая исходные разделители и NUL. Измеренные ошибки создания приходят при Ждать; лишний аргумент — при вызове.

Произвольные числа/коллекции не проверялись: возможное преобразование в
относительное имя вывело бы запись за пределы частного дерева.

## Зачем понадобился внешний снимок

[Скрипт снимка](../../../tests/conformance/measure/filesystem/file-create-layout.bsl),
[вывод 1С](../../../tests/conformance/measure/filesystem/file-create-layout.platform.txt),
[дерево ОС до выхода](../../../tests/conformance/measure/filesystem/file-create-layout.host.txt).

Вывод НайтиФайлы для ` spaced /leaf ` недостаточен для вывода о созданном
дереве: он показывает только имя ` spaced` и не показывает leaf. В первой
внешней попытке после ENTERPRISE уже остался лишь проблемный каталог colon;
прочие каталоги исчезли. Поэтому повторная проба ждёт observer.release
до 60 секунд через `/usr/bin/sleep 1`. После file.observe=ready наблюдатель
проверил точный выведенный корень `/tmp/v8_H03f8U_5.create-layout-tree`, снял
дерево `find … -printf '%y\t%P\n' | LC_ALL=C sort` и только затем создал
observer.release. Конечные пробелы в исходном снимке значимы и сохранены.

Снимок подтверждает, что конечный ASCII-пробел всего пути удаляется:
фактическое имя leaf, не `leaf `. Начальные и внутренние пробелы сохраняются:
каталог действительно называется ` spaced `, а вложенный — leaf.
Лексические свойства Файл также удаляют конечный пробел, но сохраняют NUL
в строке. Проба отдельно обнаружила sfile-представление путей со звёздочкой;
оно пока не реализовано и не подменяет отказ создания.

Остатки трёх собственных деревьев с C:leaf после проверки удалены точными
командами rm/rmdir: только трёхбайтовые контрольные файлы и пустые каталоги.
Это воспроизводимые данные пробы, пользовательские файлы не удалялись.
Ни общий temp, ни каталоги резервных копий не очищались.

## Исправление и проверяемая граница

create_directory_path использует существующий file::normalize_path и
разделитель своего host. Устранённые компоненты не проверяются через metadata;
системный FileSystem::create_dir_all остаётся прежним. Общий разбор удаляет
только измеренный конечный ASCII-пробел, без обобщения на другие пробельные
символы. NUL ограничивает путь операции, не исходный асинхронный результат
и не свойства Файл. Отмена после получения разделителя останавливает
следующее обращение к host.

Воспроизводящие host-тесты сначала упали на передаче ненормализованного пути,
затем прошли. Дополнительный тест реальной ФС сверяет физические имена с
внешним снимком, не используя НайтиФайлы. Три oracle-derived фикстуры:
file_create_paths — 25 случаев; file_create_paths_async — 23;
file_path_trailing_spaces — четыре лексические строки.

Из обеих фикстур создания исключён поиск по конечному пробелу, который остаётся
отдельным расхождением FIND.TRAVERSAL/FILE.EDGE_BEHAVIOR. Пробельный случай
создания при этом проверяется реальной ФС и отдельной лексической фикстурой.
Из async-фикстуры исключён порядок имён block/…: клиентское сравнение строк
и серверная сортировка ТаблицаЗначений дают разный порядок, а создание
каталога … уже подтверждено серверной фикстурой и сохранённым async-выводом.
Локализованные Promise/String в expected приведены к Обещание/Строка CLI;
прочие строки взяты из 1С. Полные измерители не объявляются полностью
совпавшими с open-bsl. Исходные oracle сохранены без таких преобразований.

CREATEDIR.PATH_SEMANTICS не снят: остаются прочие типы, корни, частичные
отказы и дополнительные специальные имена. Полный файловый план не закрыт.
Общий platform.tsv не перезаписывался, ingest не запускался.
