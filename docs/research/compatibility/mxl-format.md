# Формат MXL (табличный документ 1С:Предприятие)

| | |
|---|---|
| **Название** | MXL, табличный документ 1С:Предприятие |
| **Расширение** | `.mxl` |
| **Сигнатура** | `4D 4F 58 43 45 4C` (`MOXCEL`) |
| **Версия** | 8.1.11 и 8.1.12 (наблюдались обе; см. «Заголовок») |
| **Порядок байтов** | Little-Endian — с оговоркой, см. ниже |
| **Кодировка тела** | UTF-8 с BOM, переводы строк `CR LF` |
| **Источник сведений** | Замеры на платформе 1С:Предприятие 8.3.27.2130 |

## Важно: формат только НАЧИНАЕТСЯ как двоичный

Вопреки расширению и сигнатуре, MXL — **не двоичный формат** в обычном
смысле. Двоичны только первые 13 байт. Всё остальное — **текст** в скобочной
нотации 1С, где данные записаны десятичными числами и строками в кавычках.

Практическое следствие: таблицы со смещениями осмысленны только для
заголовка. Для тела вместо смещения указан **порядковый номер элемента**
внутри группы — по нему и ведётся разбор, потому что разделов в теле нет ни
меток, ни длин, и читаются они строго подряд.

### Об оговорке про порядок байтов

Все наблюдавшиеся многобайтовые значения меньше 256, поэтому байтовая
последовательность заголовка допускает **два одинаковых по результату
прочтения**:

* один байт-заполнитель, затем три `u16` little-endian — `08 00`, `01 00`, `0C 00`;
* три `u16` big-endian — `00 08`, `00 01`, `00 0C`, — и байт-заполнитель в конце.

Здесь документируется первое: платформа работает на x86, а значения
совпадают с первой тройкой чисел тела (`{8,1,12,`). **Различить их можно
только файлом, где компонент версии ≥ 256**; такого среди замеренных не
встретилось. Для чтения это безразлично — по сигнатуре и одному байту версии
файл опознаётся одинаково при любом прочтении.

## Блок 1. Заголовок

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| `0x00`          | 6              | `char[6]`  | `signature`   | Всегда `MOXCEL`. По ней опознаётся файл |
| `0x06`          | 1              | `u8`       | `pad`         | Всегда `0x00`. См. оговорку о порядке байтов |
| `0x07`          | 2              | `u16` LE   | `version_major` | Наблюдалось `8` |
| `0x09`          | 2              | `u16` LE   | `version_minor` | Наблюдалось `1` |
| `0x0B`          | 2              | `u16` LE   | `version_build` | Наблюдалось `11` и `12` |

Тройка версии **дублируется** первыми тремя числами тела. В замеренных
файлах значения совпадали всегда; расхождение считать признаком повреждения.

```rust
#[repr(C)]
struct MxlHeader {
    signature: [u8; 6],   // b"MOXCEL"
    pad: u8,              // 0x00
    version_major: u16,   // 8
    version_minor: u16,   // 1
    version_build: u16,   // 11 | 12
}
// size_of::<MxlHeader>() == 13 при #[repr(C, packed)]
```

## Нотация тела

Тело — это дерево из трёх видов узлов:

| Узел | Запись | Примечание |
|:-----|:-------|:-----------|
| Группа | `{элемент,элемент,…}` | Может вкладываться |
| Строка | `"текст"` | Внутренняя кавычка **удваивается** |
| Атом | `123`, `-1`, `00000000-0000-0000-0000-000000000000` | Число, GUID или голое слово |

Правила, каждое из которых проверено на выводе платформы:

* экранируется **только кавычка**; запятые, скобки и переводы строк внутри
  кавычек пишутся как есть — многострочный текст ячейки физически разрывает
  строку файла;
* переводы строк **не несут смысла** для разбора, но при побайтном
  воспроизведении важны: платформа ставит их в строго определённых местах;
* разделов в теле не размечено — они идут подряд, и каждый следующий
  находится только тем, что предыдущий прочитан до конца.

## Блок 3.2. Строки и ячейки

Сразу за прологом идёт число строк, затем сами строки. **Заголовок строки
приписан к последней ячейке предыдущей строки**, а не начинает новую —
физические переводы строк расставлены не по логическим границам.

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| элемент 15 | атом | `u32` | `row_count` | Число описанных строк |
| +размер прошлого поля | атом | `u32` | `row_index` | Номер строки, 0-based |
| +1 | атом | `u32` | `row_format` | Индекс в палитре форматов; `0` — не задан |
| +1 | атом | `u32` | `cell_count` | Число ячеек в строке |
| +1 | атом | `u32` | `first_column` | Номер первой колонки, 0-based. **Поля нет, если `cell_count == 0`** |
| +1 | группа | `Cell` | `cells[0]` | Первая ячейка |
| +1 | атом | `u32` | `column` | Номер колонки следующей ячейки — между ячейками |
| … | | | | Повторяется `cell_count` раз |

```rust
struct Row {
    index: u32,
    format: u32,          // 0 — формат не задан
    cells: Vec<(u32, Cell)>,  // (номер колонки, ячейка)
}
```

### Запись ячейки

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| элемент 0 | атом | `u32` | `mask` | Битовая маска состава, см. ниже |
| элемент 1 | атом | `u32` | `format` | Индекс в палитре форматов; `0` — не задан |
| +размер прошлого поля | группа | `{"S",строка}` | `value` | Только при бите 1. **Представление** значения |
| +размер прошлого поля | группа | `{"S",строка}` | `detail` | Только при бите 2. Значение расшифровки |
| +размер прошлого поля | строка | `"текст"` | `detail_param` | Только при бите 3. Имя параметра расшифровки |
| +размер прошлого поля | группа | `LocalizedString` | `text` | Только при бите 4 |
| +размер прошлого поля | атом | `u32` | `tail` | Только при бите 4; всегда `0` |

Маска состава:

| Бит | Значение | Название | Описание |
|:----|:---------|:---------|:---------|
| 1 | `0x02` | `HAS_VALUE` | Ячейка со значением. **Тип не сохраняется**: и число, и дата, и булево пишутся как `{"S","<как печатается>"}` |
| 2 | `0x04` | `HAS_DETAIL` | Значение расшифровки |
| 3 | `0x08` | `HAS_DETAIL_PARAM` | Имя параметра расшифровки |
| 4 | `0x10` | `HAS_TEXT` | Текст либо имя параметра макета |

Локализованная строка — `{1,1,{<код языка>,<текст>}}`, а у пустой строки
вырождается в `{1,0}`. **Код языка различает текст и параметр**: `"#"` —
текст ячейки, пустая строка `""` — имя параметра макета.

```rust
struct Cell {
    mask: u32,
    format: u32,
    value: Option<String>,        // бит 1 — представление
    detail: Option<String>,       // бит 2
    detail_param: String,         // бит 3
    text: String,                 // бит 4, код языка "#"
    parameter: String,            // бит 4, код языка ""
}
```

## Блок 3.5. Рисунки

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| +размер прошлого поля | атом | `u32` | `issued_ids` | Сколько номеров выдано за всё время |
| +1 | атом | `u32` | `drawing_count` | Сколько рисунков сейчас. **Отличается от предыдущего, если рисунок удаляли** |
| +1 | группа × N | `Drawing` | `drawings` | По одной группе на рисунок |

Запись рисунка — `{{0,<формат>},2,<кол1>,<стр1>,<смещК1>,<смещС1>,<кол2>,<стр2>,<смещК2>,<смещС2>,<номер>,0}`:

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| элемент 0 | группа | `{0,u32}` | `format` | Индекс в палитре форматов |
| элемент 1 | атом | `u32` | `kind` | Всегда `2` у прямоугольника |
| элементы 2–3 | атомы | `u32,u32` | `begin_col`, `begin_row` | Ячейка левого верхнего угла |
| элементы 4–5 | атомы | `i64,i64` | `begin_col_off`, `begin_row_off` | Смещение внутри неё |
| элементы 6–9 | атомы | | `end_*` | То же для правого нижнего угла |
| элемент 10 | атом | `u32` | `id` | Номер рисунка |
| элемент 11 | атом | `u32` | `tail` | Всегда `0` |

**Координата — не пиксели и не миллиметры**, а четверти пункта (1/288
дюйма), разложенные на «номер ячейки плюс смещение внутри неё»:

```
абсолютная координата по X = Σ(ширина колонок 0..k) + смещение
абсолютная координата по Y = Σ(высота строк   0..k) + смещение
```

Ширина колонки в этой сетке — `ШиринаКолонки × 21`, высота строки —
`ВысотаСтроки × 4`; умолчания 189 и 45 соответственно.

## Блок 3.6. Группы строк

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| +размер прошлого поля | атом | `u32` | `group_count` | Число групп |
| +1 | группа | `RowGroup` | `groups[i]` | Тело группы |
| +1 | атом | `i32` | `terminator` | Всегда `-1` после каждой группы |
| +размер прошлого поля | атом ×3 | `u32` | `reserved` | Три нуля |

Тело группы — `{<строка1>,<строка2>,<уровень>,<имя>,<свёрнута>,0}`. Уровень
вложенности хранится **числом**: `0` — внешняя, `1` — вложенная в неё.

Свёрнутость записана **дважды**: флагом в группе и битом `0x20000` в формате
каждой её строки («строка скрыта»).

```rust
struct RowGroup {
    first_row: u32,
    last_row: u32,
    level: u32,
    name: String,      // {1,0} у безымянной
    collapsed: bool,
}
```

## Блок 3.7. Объединения

Три списка подряд, каждый — `{0}` если пуст либо `{<число>,<запись>,…}`.

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| +размер прошлого поля | группа | `Merge[]` | `cell_merges` | Прямоугольники ячеек |
| +1 | группа | `RowMerge[]` | `row_merges` | Объединения целых строк |
| +1 | группа | `ColMerge[]` | `column_merges` | Объединения целых колонок |

| Список | Запись | Поля |
|:-------|:-------|:-----|
| ячеек | `{c1,r1,c2,r2,флаг}` | **Колонка первой**, координаты АБСОЛЮТНЫЕ |
| строк | `{-1,r1,-1,r2,0}` | Колонки заменены на `-1` |
| колонок | `{c1,-1,c2,-1,0,GUID}` | Строки на `-1`, плюс GUID набора колонок |

Флаг: `0` — объединение, `2` — **отмена** объединения в этих ячейках; она
нужна, чтобы разорвать объединение целых колонок в отдельной строке.

Записи **отсортированы** по строке, затем по колонке, а не идут в порядке
создания.

```rust
struct Merge {
    c1: u32, r1: u32, c2: u32, r2: u32,
    unmerge: bool,   // флаг == 2
}
```

## Блок 3.8. Именованные области и имя документа

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |

Запись — пара «имя, тело», записи разделены запятой; **отсортированы по

| Тело | Вид | Поля |
|:-----|:----|:-----|
| `{1,{<тип>,c1,r1,c2,r2,GUID},0}` | Область ячеек | Тип: `1` — строки, `2` — колонки, `3` — прямоугольник |
| `{2,<номер рисунка>,0}` | Именованный рисунок | |

У области-строк колонки заменены на `-1`, у области-колонок — строки.

## Блок 3.9. Палитры

Палитра линий стоит в **начале** тела, остальные — в хвосте. Все палитры
дедуплицируются: одинаковое оформление занимает один элемент.

| Палитра | Индексация | Элемент |
|:--------|:-----------|:--------|
| Линии | 0-based | `{4,0,{0},<стиль>,<толщина>,7,GUID,0}`; стиль `1` сплошная, `2` точечная, `3` двойная |
| Форматы | **1-based**, `0` = «не задан» | `{<маска>,<значения по возрастанию бита>}` |
| Шрифты | 0-based | `{7,0,703,<кегль×10>,0,0,0,<насыщенность>,<курсив>,<подчёркивание>,<зачёркивание>,0,0,0,0,34,"<гарнитура>",1,100}` |
| Цвета | 0-based, первые два заняты | `{3,0,{<цвет>}}` — заданный, `{3,3,{<код>}}` — цвет стиля |

Порядок хвоста строго такой:

```
<число форматов>,<форматы…>,
<число шрифтов>,<шрифты…>,
<число форматных строк>,<форматные строки…>,
<число описаний типов>,<описания…>,
<число GUID>,<GUID…>,
<число цветов>,<цвета…>
```

### Биты формата

Формат — **не запись с полями, а набор «бит + значение»**; значения идут по
возрастанию бита. Маска **шире 32 бит**: встречалось `8589954623`.

| Бит | Значение | Название | Смысл значения |
|:----|:---------|:---------|:---------------|
| 0 | `0x0001` | `FONT` | Индекс в палитре шрифтов |
| 1 | `0x0002` | `BORDER_LEFT` | Индекс в палитре линий |
| 2 | `0x0004` | `BORDER_TOP` | То же |
| 3 | `0x0008` | `BORDER_RIGHT` | То же |
| 4 | `0x0010` | `BORDER_BOTTOM` | То же |
| 6 | `0x0040` | `ROW_HEIGHT` | Высота строки × 4 |
| 7 | `0x0080` | `COL_WIDTH` | Ширина колонки × 8 |
| 8 | `0x0100` | `H_ALIGN` | `0` влево, `2` вправо, `5` авто, `6` по центру |
| 9 | `0x0200` | `V_ALIGN` | `0` верх, `8` низ, `24` по центру |
| 10 | `0x0400` | `TEXT_COLOR` | Индекс в палитре цветов |
| 11 | `0x0800` | `BACK_COLOR` | То же |
| 14 | `0x4000` | `TEXT_PLACEMENT` | `3` — переносить по словам |
| 17 | `0x20000` | `ROW_HIDDEN` | Строка скрыта свёрнутой группой |
| 24 | `0x1000000` | `NUMBER_FORMAT` | У ячейки числовой формат |
| 22,23,25 | `0x2C00000` | `VALUE_*` | Тройка бит ячейки со значением |

Цвет упакован как `B<<16 | G<<8 | R` — **синий в старшем байте**: красный
это `255`, синий `16711680`.

## Блок 3.10. Настройки и хвост

| Смещение (Byte) | Размер (Bytes) | Тип данных | Название поля | Описание |
|:----------------|:---------------|:-----------|:--------------|:---------|
| +размер прошлого поля | группа | `PrintSettings` | `settings` | 29 полей |
| +1 | группа | `{0}` | `tail_a` | |
| +1 | атомы ×7 | `u32` | `tail_b` | `0,0,0,1,0,0,0` |

Значащие поля настроек (нумерация с 1):

| Поле | Название | Описание |
|:-----|:---------|:---------|
| 5 | `show_grid` | `1` показывать сетку, `0` нет |
| 12 | `fixed_left` | Число зафиксированных слева колонок |
| 13 | `fixed_top` | Число зафиксированных сверху строк |
| 27 | `has_fixed_top` | Признак, что фиксация сверху задана |

Параметры страницы — **сортированный список пар** «идентификатор, значение»,
а не запись с полями: `1` — ориентация (`2` ландшафт), `2` — масштаб печати,
`6`…`11` — поля, всегда `1000`.

Область печати — `{0,-1,-1,-1,-1,GUID}` когда не задана, иначе
`{3,c1,r1,c2,r2,GUID}`.

## Пример Hex Dump и разбор

Документ из одной ячейки `R1C1` с текстом `A`. Первые 48 байт:

```
Смещение  Байты                                            ASCII
--------  -----------------------------------------------  ----------------
00000000  4D 4F 58 43 45 4C 00 08  00 01 00 0C 00 EF BB BF  MOXCEL.........·
00000010  7B 38 2C 31 2C 31 32 2C  0D 0A 7B 22 23 22 2C 22  {8,1,12,..{"#","
00000020  22 2C 31 2C 31 2C 22 23  22 2C 22 D0 AF D0 B7 D1  ",1,1,"#","·····
```

### Пошаговый разбор

**Шаг 1. Сигнатура, `0x00`…`0x05`**

```
4D 4F 58 43 45 4C  →  "MOXCEL"
```
Файл опознан как MXL.

**Шаг 2. Версия, `0x06`…`0x0C`**

```
00                 →  pad
08 00              →  version_major = 8
01 00              →  version_minor = 1
0C 00              →  version_build = 12
```
Версия формата 8.1.12. (О втором возможном прочтении — см. оговорку выше.)

**Шаг 3. BOM, `0x0D`…`0x0F`**

```
EF BB BF           →  UTF-8 BOM
```
Дальше начинается текст. Заголовок кончился, смещения больше не значимы.

**Шаг 4. Начало тела, `0x10`…**

```
7B                 →  '{'   открывающая скобка корневой группы
38 2C              →  "8,"  version_major = 8
31 2C              →  "1,"  version_minor = 1
31 32 2C           →  "12," version_build = 12
0D 0A              →  CR LF (разделитель, смысла не несёт)
```
Тройка версии тела совпала с заголовком — файл цел.

**Шаг 5. Языковые настройки, `0x1A`…**

```
7B 22 23 22 2C 22 22 2C 31 2C 31 2C 22 23 22 2C 22 …
{  "  #  "  ,  "  "  ,  1  ,  1  ,  "  #  "  ,  " …
```
Читается как группа `{"#", "", 1, 1, "#", "Язык по умолчанию", "Язык по
умолчанию", 0}`. Байты `D0 AF D0 B7 D1 …` — UTF-8 для «Язы…».

**Шаг 6. Что дальше**

За языками идут `{128,72}` (умолчания размеров), палитра линий `{0},0`,
шесть служебных `{0,0}`, затем `0,2,` и число строк. Для этого документа
раздел строк выглядит так:

```
{0,0},0,2,1,0,0,1,0,
              │ │ │ │
              │ │ │ └─ first_column = 0
              │ │ └─── cell_count = 1
              │ └───── row_format = 0
              └─────── row_index = 0
{16,0,           маска 0x10 — только текст; формат не задан
{1,1,
{"#","A"}        код языка "#" → это текст, а не параметр
},0},
```

## Что НЕ измерено

Ниже перечислено то, что в замерах не встретилось или не различалось. Это не
описание формата, а честная граница знания.

* **Порядок байтов заголовка** — оба прочтения дают одинаковые байты на всех
  доступных файлах; нужен файл с компонентом версии ≥ 256.
* **Шесть служебных групп `{0,0}`** пролога и одиночные поля, помеченные
  «назначение не измерено»: во всех замерах они постоянны.
* **Содержимое непрямоугольных рисунков** — текстовой надписи, картинки,
  диаграммы. Известно только, что типы `Текст`, `Картинка`, `Диаграмма`,
  `ДиаграммаГанта`, `СводнаяДиаграмма` и `Объект` существуют.
* **Раскладка дополнительных наборов колонок на общую сетку.** Известно, что
  платформа сводит наборы по объединению границ; на строках, привязанных к
  двухколоночному набору, наблюдалось расхождение в одну физическую колонку,
  причина которого не установлена.
* **Постоянные поля записи линии** `{4,0,{0},<стиль>,<толщина>,7,GUID,0}` —
  ведущие `4,0,{0}`, число `7` и сам GUID: во всех файлах они одинаковы,
  то есть GUID здесь тег вида записи, а не идентификатор конкретной линии.
