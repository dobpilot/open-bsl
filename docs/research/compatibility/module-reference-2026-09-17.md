# ЭтотОбъект: значение ссылки и проверка экспортов

Реализован первый этап согласованного пользователем контекста текущего
BSL-модуля open-bsl. Это не эмуляция объекта управляемой формы и не новый
замер 1С; localhost/test в этом этапе не менялась.

## Реализованная часть

ЭтотОбъект/ThisObject разрешается через общую таблицу встроенных функций
с нулевой арностью; голое имя поддерживается тем же резолвером, что другие
глобальные свойства. Переменные сохраняют приоритет. Тип МодульBSL/BSLModule
зарегистрирован в базовом runtime, без публичного конструктора. Таблица API
регенерирована, списки имён вручную не дублируются.

VM хранит ленивый кэш значения в ModuleState. Вложенный исполнитель
Вычислить/Выполнить и компонентный обратный вызов разделяют этот кэш с
владельцем, но новый запуск его не наследует. В каталоге каждый экземпляр
модуля имеет отдельный кэш. Перестановка текущего состояния на время шага
теперь переносит весь ModuleState: перенос только slots оставлял бы
самоссылку у пустого scratch. Временное пустое состояние не создаёт Rc
при каждой инструкции. Сама ссылка хранит только имена экспортов, снятые
с Program.function_names/exported_functions; модульных переменных в ней нет.

ОписаниеОповещения использует существующий ObjectProtocol::has_method,
чтобы проверить экспорт без его исполнения. Независимой вручную заданной
таблицы имён модульных методов нет. Ссылка пригодна для сравнений, хранения
в коллекциях и использования как ключ соответствия.

## Проверки

До реализации фасадный тест падал при компиляции с UndefinedVariable
для ЭтотОбъект. Проба каталога отдельно обнаружила перенос одних slots
без идентичности; после переноса полного состояния она проходит.

`crates/open-bsl/tests/module_reference.rs` проверяет source/bytecode ×
plain/optimize, первое чтение из динамического фрагмента, функции и async-
процедуру, вложенную динамику и восстановление после исключения, сравнение
и ключ соответствия, тип, арность, отсутствие конструктора, перекрытие
параметром/модульной переменной, приём экспортных процедуры/функции и отказ
неэкспортному получателю. Обработчики при создании описания не вызываются.
Каталог отдельно проверяется с обоими наборами оптимизаций: два общих
модуля, их тела/функции/динамические фрагменты, entry и повторный запуск.

Unit-тест VM сохраняет самоссылку в модульной переменной, переносит состояние
во вложенный исполнитель и проверяет через Weak, что после Drop кэш
освобождён. Сохранённое значение не удерживает экземпляр модуля.

Логи этапа: `/tmp/open-bsl-module-reference-{red,test,ownership,api,clippy,workspace,doc,openspec}.log`.

После реализации прошли fmt, Clippy --workspace --all-targets с запретом
предупреждений, полный workspace, rustdoc с запретом предупреждений,
git diff --check и все 11 строгих проверок OpenSpec. Проверены актуальность
API reference, реестр измерений, общий conformance и plain/optimize/round-trip.
Формат байт-кода на этом этапе не менялся: новая встроенная функция
передаётся существующим форматом имени. Прямые модульные вызовы этими
зелёными проверками не объявляются поддержанными.

## Незавершённая часть

Прямые вызовы экспортных методов через ссылку и доставка Begin пока не
реализованы. CallObjectMethod несёт только готовые значения аргументов,
теряя ссылочные цели и отличия пропуска от явного Undefined. Следующий
этап должен сохранить эти сведения общим механизмом ArgMode и проверить
образ, эффекты и round-trip; блокирующий FunctionCaller не является заменой
планируемой доставки в VM. Этот этап не закрывает родительский пункт плана.
