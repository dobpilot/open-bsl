# Асинхронные маски удаления на клиенте серверной базы

1С 8.3.27.2342, Linux, клиентский модуль формы `/S localhost/test`.
Литеральный CompatibilityMode — Version8_3_27, effective-режим отдельно
не проверялся. Это не серверный вызов асинхронных методов и не замер 8.5.
Unica не использовалась.

## Измерено

18 случаев: УдалитьФайлыАсинх и DeleteFilesAsync для масок 17, 0, Истина,
Ложь, Null, Неопределено, пустой строки, массива и структуры. Каждый случай
использует отдельное временное дерево с файлом `Строка(маска)` и соседом
`keep.bin`. Для пустого представления отдельный целевой файл не создаётся.

Все вызовы вернули обещание, ТипЗнч которого равен Тип("Обещание").
После Ждать результат равен Неопределено. Непустые маски удалили целевой
файл, сохранив корень и соседа; Null, Неопределено и пустая строка удалили
сам каталог. Подготовка и очистка завершились без ошибок.

Даты, прочие типы, ошибки форматирования и их стадия не измерены: успешные
пробы не доказывают порядок ошибок. Первый аргумент всегда строковый.

## Реализация и найденные сопутствующие дефекты

Подготовка DeleteFilesAsync теперь передаёт общий форматировщик в тот же
разбор маски, что синхронный вызов. В поток по-прежнему передаются только
нейтральные строки, а не BSL-значения и не форматировщик.

Исходный измеритель выявил два дефекта, мешавших сравнению:

- При Вычислить копировались статические функции, но терялись их формы
  структур. Проверка образа правильно отвергала такой Program. Теперь
  статические формы сохранены, формы фрагмента добавлены с проверяемой
  перенумерацией его NewStructure. Отдельный тест воспроизвёл прежний отказ
  и проверил статическую, динамическую и вложенную динамическую структуры.
- Дескриптор Обещание существовал, но отсутствовал в каталоге типов.
  Зарегистрирован существующий дескриптор без конструктора; русское имя
  проверяется исходной пробой. Английский псевдоним этим замером не проверен.

После исправлений весь вывод совпал с 18 строками oracle без ослабления
проверки типа. Conformance `file_delete_types_async` использует исходный BSL
и ожидаемый вывод 1С только с нормализацией BOM/CRLF.

## Проверки

Полный `cargo test --workspace` завершился с кодом 0, включая конформанс,
plain/optimize, текстовый round-trip и проверку реестра вопросов. Прошли
fmt, Clippy workspace с `-D warnings`, rustdoc workspace с `-D warnings`
и строгая проверка 11 объектов OpenSpec. Логи находятся в каталоге сессии:
`workspace.log`, `clippy.log`, `doc.log`, `openspec.log`; воспроизведение
дефекта форм — `shapes-red.log`, исправление — `shapes-green.log`.
Стандартные ограничения полного набора сохраняются: конфиденциальный
корпус без OPEN_BSL_TABLE_COMPARE2_CASES не запускается, а игнорируемая
выгрузка MXL не является сравнением с oracle.

Дополнительная проверка защитных границ VM (не новая семантика 1С):
`dynamic_structure_indices_are_checked_before_and_after_relocation`
подставляет фрагмент без собственной таблицы форм и проверяет отказ,
несмотря на наличие статической формы. При сохранной таблице итоговый
индекс 65535 исполняется, 65536 отвергается без переполнения u16.
Полный workspace, Clippy и fmt прошли; журнал повторного полного запуска —
`/tmp/open-bsl-dynamic-shape-boundary-workspace.log`.
