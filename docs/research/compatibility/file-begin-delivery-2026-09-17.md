# Доставка Begin-оповещений Файл

Реализован измеренный набор из 13 Begin-методов с RU/EN-именами. Это этап
`extend-filesystem-async`, а не завершение всего файлового плана.

## Свидетельство платформы

Новая клиентская проба выполнена напрямую на серверной базе `localhost/test`,
1С 8.3.27.2342, без Unica. Каталог сессии:
`/tmp/open-bsl-server-measure-5busosqg`. Runner завершился кодом 0 и RESTORED:
восстановлены свежий CF и конфигурация БД; XML совпал, кроме корневого
ConfigDumpInfo.xml. Резервные копии и исходный вывод сохранены в каталоге.

- [Сценарий](../../../tests/conformance/measure/filesystem/file-begin-delivery.bsl).
- [Девять строк результата](../../../tests/conformance/measure/filesystem/file-begin-delivery.platform.txt).
- [Conformance-фикстура](../../../tests/conformance/fixtures/file_begin_delivery.bsl)
  и [oracle](../../../tests/conformance/fixtures/file_begin_delivery.expected).

Oracle скопирован из platform.txt runner, не получен из open-bsl; обе копии
проверены `cmp`. Вывод open-bsl побайтно совпал с ним. Две инициализации
возвращают исходный объект с последним путём `second`; при возврате основного
тела ещё нет доставленных событий. Все четыре setter с массивом вместо
значения доставляют ошибку после возврата, с ИнформациейОбОшибке и исходным
стандартным флагом Истина. Присваивание Ложь позволяет завершить все доставки.
Новая проба не создаёт и не изменяет файлов: инициализация меняет объект пути,
setter отвергает значение до I/O.

Арности, остальные результаты и коллекционные получатели основаны на ранее
сохранённых file-begin-arity, file-callback-methods, file-callback-object-delivery
и file-begin-description. Нового измерения на 8.5 этим этапом не заявляется.

## Реализация

`bsl-rt` проверяет описание до операции, переиспользует подготовку запросов
Async и передаёт нейтральную регистрацию через HostPromiseSpawner. Default
старого host отказывает до I/O и мутации пути. Ready-инициализация не требует
фонового доступа; она сохраняет тождество объекта и меняет путь после успешной
регистрации, но до возврата метода.

`bsl-vm` подготавливает проверенный служебный образ до регистрации I/O.
Он использует обычные Await и CallObjectProcedure, исходный каталог и общий
AsyncState. В файловом потоке нет BSL-обработчиков. Задача доставки остаётся
живой после возврата основного тела, может уступить worker и отменяется вместе
с execution. Уже выполненный I/O при отмене не откатывается.

Ошибка операции перехватывается только вокруг Await. Изменяемый стандартный
флаг передаётся отдельной ссылочной ячейкой. Для стандартной обработки
сохраняется исходный RtError: пойманное внутри обработчика другое исключение
его не заменяет. Возврат ошибки host/CLI вместо модального окна — явная
политика open-bsl, не имитация UI 1С.

Образ владеет копией статических чанков, таблиц и ссылок своего модуля, как
динамический фрагмент; отдельного интерпретатора callbacks и нового формата
байткода нет. При повторном имени используется существующая запись таблицы.
Тест вложенной регистрации сначала воспроизвёл ошибку дубликата, затем прошёл
после исправления. Стоимость копирования не измерялась; выигрыша скорости
не заявляется.

## Проверки и границы

- Начальная красная проверка: UnknownMethod для НачатьИнициализацию.
- 208 сочетаний: 13 методов × RU/EN × прямой/динамический вызов × plain/optimize
  × source/bytecode. Проверяются результат, данные, отложенность, запись host
  и отказ Begin в позиции выражения до мутации.
- Пять отдельных интеграционных тестов: описание/пустая форма, тождество,
  изменяемый флаг, исходная ошибка, вложенная регистрация одного имени.
- Проверка reduced и прежнего HTTP-only host без изменения пути.
- Single-worker matrix расширена до 40 сочетаний, из них 16 для Begin:
  чтение/запись, прямой/динамический вход, модульная ссылка, успех/отмена.
  Проверяются исполнение соседнего задания, сообщения callback, отсутствие
  доставки после отмены и отсутствие отката записи.

Итоговые проверки прошли: `cargo test --workspace` (включая conformance,
plain/optimize, текстовый round-trip, API reference и реестр измерений),
`cargo fmt --all -- --check`, Clippy workspace/all-targets с `-D warnings`,
rustdoc с `-D warnings`, `git diff --check`, строгий OpenSpec — 11/11.
Логи этапа: `/tmp/open-bsl-file-notifications-{workspace,clippy-final,doc,openspec}.log`.

Полная семантика функций/async в роли обработчика, ошибок самих обработчиков
и небулевого стандартного флага остаётся `NOTIFY.DELIVERY_EDGES`: код,
реестр и строка measure-all связаны. Эта строка явно сообщает о незавершённом
клиентском замере и не является oracle. Нужен отдельный сценарий наблюдения
ошибочного callback; конструктор не доказывает семантику его исполнения.
Отладочное evaluate и непосредственные импорты динамического текста также
остаются отдельными задачами. Изменения OpenSpec не архивированы.
