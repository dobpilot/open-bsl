# Индексы ТаблицыЗначений как получатели оповещения

17 сентября 2026 года на 1С 8.3.27.2342 в тонком клиенте серверной базы
`localhost/test` измерена коллекция Индексы и отдельный индекс таблицы.
Unica не использовалась. Итоговый сеанс
`/tmp/open-bsl-server-measure-zrtv0wtc` восстановил исходную CF и
конфигурацию БД; XML совпал, кроме корневого `ConfigDumpInfo.xml`.

Свойство Индексы возвращает равную ссылку на общую коллекцию. Add принимает
0 или 1 аргумент и возвращает тот же индекс, который доступен по позиции;
пустая строка, `А, Б` и `А,А` допустимы, неизвестная колонка отвергается.
Delete принимает один индекс, Clear — ни одного аргумента; обе процедуры
при вызове как функции отказывают до мутации.

`Скопировать()` и `Скопировать(Неопределено, "")` переносят все
описания индексов в новые, независимые объекты. Явный непустой
список колонок очищает индексы даже когда он перечисляет все колонки.
`СкопироватьКолонки` не переносит индексы ни без аргумента, ни с
явным списком колонок.

ОписаниеОповещения принимает коллекцию для Count, Add, Delete и Clear в
обоих языках. Отдельный индекс отвергается как тип второго параметра для
Count и заведомо неизвестного имени одинаково. Это отличается от обычной
ошибки поиска метода и должно сохраняться реализацией.

Две предварительные сессии обнаружили ошибки контекста самого измерителя:
серверный CheckModules не знает ОписаниеОповещения, а тонкий клиент не
компилирует прямой `Новый ТаблицаЗначений`. Обе базы восстановлены; итоговый
скрипт использует клиентский режим и динамический конструктор таблицы.
