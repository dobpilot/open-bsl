# Клиентские глобальные файловые обещания

Платформа 8.3.27.2342, клиент серверной базы `/S localhost/test`, пустые
учётные данные. Асинхронные методы формы размещены на клиенте; выражения
вызываются через `Вычислить`, затем результат ожидается через `Ждать`.
Изменялось только собственное временное дерево, удалённое в конце пробы.
В выводе его префикс заменён на `<root>`.

## Измеренные результаты

Все вызовы сначала вернули Promise.

| Проба | Результат Ждать |
| --- | --- |
| СоздатьКаталогАсинх, новый путь | String, исходная строка пути |
| CreateDirectoryAsync, уже существующий путь | Та же строка |
| Путь с завершающим `/` | Разделитель сохранён в результате |
| Путь с `new/../dot` | Компоненты сохранены в результате |
| Создание внутри файла / путь Неопределено | Ошибка при Ждать, причина Error creating directory |
| УдалитьФайлыАсинх с маской *.txt | Undefined; a.txt и дерево nest.txt удалены, b.bin сохранён |
| DeleteFilesAsync без маски | Undefined; каталог удалён |
| Удаление отсутствующего пути | Undefined, без исключения |
| Удаление пути Неопределено | Ошибка при Ждать, причина Error deleting files |
| КаталогВременныхФайловАсинх / TempFilesDirAsync | String, `/tmp/` |

Общее описание ошибки для Неопределено не доказывает, какое преобразование
аргумента выполнялось внутри платформы. Граничные типы, локализованные
описания ошибок и точный порядок проверок остаются отдельными вопросами.

## Реализация и найденная регрессия

Прямые вызовы open-bsl подключены к общей фоновой файловой операции и
проверяются в `file_globals_async.bsl`. Однако исходный динамический
измеритель выявил проблему: `Вычислить` исполняет фрагмент через отдельный
ProgramExecution; полученное файловое обещание принадлежит его токену,
и внешний Ждать отвергает его как чужое. Это дефект open-bsl, не поведение 1С.

Воспроизведение: `bsl-cli tests/conformance/measure/filesystem/file-async-globals.bsl`.
Ожидаемые результаты сохранены в платформенном выводе ниже; прежний отказ
`обещание принадлежит другому запуску` не принимается как oracle и не скрывается
заменой динамических проб на прямые. Простая замена токена после полного внутреннего
ожидания также недостаточна: она сохранила бы блокировку вызывающего worker.

### Исправление 2026-09-10

Вложенный HostIo теперь заимствует владельца файловых обещаний внешнего
AsyncState. Новый запрос регистрируется сразу у него; внутренний drive
не ждёт файлового I/O и не уничтожает чужой handle. Исходный измеритель
повторён в open-bsl: результаты, сохранение строки пути и стадия ошибок
совпали; локализованные имена типов и подробные тексты ошибок различаются.

Регрессии проверяют Вычислить, вложенный Вычислить, copy-back через Выполнить,
отложенный read_dir, внешнее и повторное Ждать. В реальном пуле с одним worker
проверены пробуждение и отмена динамического поиска. Конформанс-пример
`file_promises_dynamic.bsl` использует результаты приведённых платформенных проб.
Произвольные пользовательские async-задачи и HTTP-обещания этим исправлением
не перепривязываются; их динамический путь не был предметом данной проверки.
