# Пути `Добавить` и `ИзвлечьВсе` ZIP-архива

Измерение выполнено напрямую на серверной `localhost/test`, Linux,
1С 8.3.27.2342. Unica не использовалась. Сессия
`/tmp/open-bsl-server-measure-ovkvdkbn` завершилась с кодом 0,
восстановила CF и БД; контрольная XML-выгрузка совпала с исходной.

- Исходник `file-archive-content-io-edges.bsl`: SHA-256
  `b7914be0badc7194f4bf30736745d11c443d879bcb4fa801facd57cac27f3d87`.
- Oracle `file-archive-content-io-edges.platform.txt`: SHA-256
  `31b6a0d81d77bd7b7cef76a1c5416266ebd63de592e7b94b87ee70beab795fbe`.

Десять суффиксов проверены отдельно для источника `Добавить` и
каталога `ИзвлечьВсе`. NUL, TAB, LF, CR, SPACE, U+0085 и NBSP
снимаются; U+007F, U+200B и U+FEFF сохраняются. В первой группе архив
содержит один файл; во второй файл появляется либо в базовом, либо в
физически отдельном каталоге.

`Добавить` нормализует измеренный путь до обхода. Прежний случай
завершающего разделителя не пропускается через helper: для ZIP это
уже измеренный сигнал маски `*`. Его сочетания с краевыми пробелами этот
замер не обобщает. `Извлечь` и `ИзвлечьВсе` используют общую
нормализованную `destination`; потом к ней добавляются безопасные имена записей.
Сквозной тест сверяет все 22 строки в source/bytecode × plain/optimize.
