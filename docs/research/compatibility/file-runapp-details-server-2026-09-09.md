# RunApp: выходной параметр и командная строка

Серверная 1С 8.3.27.2342, `/S localhost/test`, пустые учётные данные,
управляемая форма, `&НаСервере`, вызов через `Выполнить` внутри `Попытка`.
Перед каждой пробой выходная локальная переменная равна числу 12345.
Это продолжение [проверки доступности](file-runapp-server-2026-09-09.md).

## Выходной параметр и проверка типов

| Проба | Результат | Выходной параметр |
| --- | --- | --- |
| `/usr/bin/true`, ожидание Истина | Без исключения | Число 0 |
| `/usr/bin/false`, ожидание Истина | Без исключения | Число 1 |
| Ожидание Ложь | Без исключения | Неопределено |
| Пропущенный третий аргумент при переданном четвёртом | Без исключения | Неопределено |
| Ожидание Неопределено / 0 / 1 / Null | Ошибка вызова | Число 12345, без изменения |
| Рабочий каталог Неопределено | Ошибка вызова | Число 12345, без изменения |
| Несуществующий рабочий каталог, команда true | Без исключения | Число 0 |
| Пустая команда, ожидание Истина | Без исключения | Число 0 |
| Команда Неопределено | Ошибка вызова | Число 12345, без изменения |
| Четвёртый аргумент — литерал 42, команда false | Без исключения | Локальная переменная не передавалась, осталась 12345 |

Успех `true` с несуществующим cwd не устанавливает фактический рабочий каталог
дочернего процесса. Нужна отдельная проба `pwd`, прежде чем описывать fallback.
Подробная причина ошибок типов не извлекалась: сохранено исходное описание
ошибки вызова. В выводе типы названы Number/Undefined из-за языка сеанса.

## Командная строка

| Команда | Код |
| --- | --- |
| `/usr/bin/true ; /usr/bin/false` | 1 |
| `/usr/bin/true && /usr/bin/false` | 1 |
| `/usr/bin/false || /usr/bin/true` | 0 |
| `exit 17` | 17 |
| `"/usr/bin/false"` | 1 |

Операторы и встроенная команда `exit` исполняются, а не передаются как обычные
аргументы `true`/`false`. Это измеренная shell-семантика в данном контексте;
имя конкретного shell и его реализация этой пробой не установлены.
Пробы не изменяли файлы и не запускали пользовательские приложения.

Согласованный план open-bsl требует отсутствия неявного shell. Результат
передан пользователю для решения: сохранить это как осознанное отличие либо
изменить контракт. До решения нельзя ни внедрять shell, ни объявлять текущий
прямой Rust-запуск полностью совместимым с серверной платформой.

## Дополнение 2026-09-17: составные выходные цели

завершения записывается в поле структуры и элемент массива. Объект и индекс
вычисляются один раз, после вычисления команды; измеренный порядок — `CT`.

`/tmp/open-bsl-server-measure-0tzxizvg`; каждый runner завершился с кодом 0,
восстановил CF/БД и подтвердил совпадение XML. SHA-256 финального измерителя —
`db178d152c9237120defed67cfd35aecd5f600c9a0ee581dc1f40a77fc504ca1`,
oracle — `f77893e7505e808344ad20838c8b899579ac66c0c2aaee8db660b8e65d45f4f0`.
Oracle совпадает в source/bytecode × plain/optimize; `RUNAPP.OUTPUT_TARGETS`
снят из реестра. Формат байткода не менялся.
