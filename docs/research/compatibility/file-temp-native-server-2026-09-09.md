# Независимое наблюдение временного носителя серверной 1С

## Контекст и сохранность базы

Linux, 1С 8.3.27.2342, `/S localhost/test`, серверный модуль управляемой
формы, пустые учётные данные, без Unica. XML Version8_3_27; effective
compatibility отдельно не проверялся. Вывод не переносится на 8.5 или
файловую базу без нового замера.

Сеанс `/tmp/open-bsl-temp-native-approved-8vaLq3`. Свежие original.cf и
original-xml сохранены перед загрузкой. После измерения CF восстановлен,
XML побайтно совпал кроме ConfigDumpInfo.xml. Runner завершился с кодом 0.
Все 18 фаз подтверждены наблюдателем; присутствуют file.begin/file.end и
observer.complete, нет file.setup_error.

## Метод

Артефакты находятся в `tests/conformance/measure/filesystem/`:
file-temp-native.bsl, file-temp-native.platform.txt, file-temp-native.host.txt
и точная использованная копия file-temp-native.observer.sh.

Наблюдатель читал symlink-цели и stat метаданные `/proc/1416828/fd`, только
для `/tmp/v8_*.tmp`. Содержимое файлов не читалось. До ack-файла BSL стоял
на границе фазы; ожидание ограничено 5 секундами. Шаблон каталога наблюдения
заменён только в сгенерированном модуле, не в сохранённом BSL-источнике.
При повторении нужно выбрать актуальные PID/рабочий каталог и свежую копию
базы; сохранённый observer — артефакт конкретного сеанса, не готовый runner.

Фазы: 0 — до создания потока; 1 — сразу после; 2 — запись ровно до границы;
3 — запись ещё одного байта; 4 — после первого чтения ИмяФайла; 5 — после
Закрыть. Префикс a — default и граница 65535, b — лимит 8, c — (8, 0).

## Результат

| Поток | Новый файл, фаза 1 | Фаза 2 | Фаза 3 | После ИмяФайла | После Закрыть |
|---|---|---|---|---|---|
| default | inode 828132, размер 0 | 65535 | 65536 | тот же inode/размер | дескрипторы отсутствуют |
| лимит 8 | inode 828139, размер 0 | 8 | 9 | тот же inode/размер | дескрипторы отсутствуют |
| (8, 0) | inode 828146, размер 0 | 8 | 9 | тот же inode/размер | дескрипторы отсутствуют |

Пути сопоставлены по native.name, полученному только после фазы 3:
`/tmp/v8_wtsHqO_5.tmp`, `_6.tmp`, `_7.tmp`. Каждый новый inode появляется
на двух дескрипторах 57/58; это не два разных файла. Остальные строки fd
принадлежат исходному состоянию процесса и не используются как результат.

Это подтверждает раннее создание файла и изменение его размера в ОС до
чтения ИмяФайла. Предыдущая гипотеза о материализации исключительно из-за
получения имени для этих трёх случаев исключена. Внутреннее буферизование,
содержимое файла на каждой фазе и фактический default размера буфера 8192
этим наблюдением не определяются. Закрытие дескриптора не означает удаления
пути: предыдущее file-temp-storage измерение видело файл после Закрыть.

## Влияние на план

Требование «только память до лимита, затем создание host-файла» нельзя
считать измеренным серверным контрактом. Пользователю предложено выбрать
измеренное серверное поведение либо сохранить исходную модель как намеренное
отличие. До выбора соответствующее требование OpenSpec не переписано и
СоздатьВременныйФайл не объявлен реализованным.
