## Результаты

Метод и английский RunAppAsync возвращают обещание, арность — 1–3.
Второй аргумент по умолчанию пустая строка, третий — Ложь; пропуск позиции
через запятую сохраняет default. Четвёртого выходного аргумента нет.

| Случай | Результат |
|---|---|
| true/false, флаг пропущен или Ложь | Обещание Неопределено |
| true, Истина | Число 0 |
| false, Истина, включая кавычки и RU/EN | Число 1 |
| Пустая команда, Истина | Число 0 |
| Отсутствующая программа, в том числе Истина | Неопределено |
| Неопределено/Null/число вместо команды или cwd | Ошибка при Ждать |
| Неопределено/Null/0/1 вместо флага | Ошибка при Ждать |
| Ноль/четыре аргумента через Вычислить | Ошибка при вызове, обещание не получено |
| true, несуществующий cwd, Истина | Число 0 |
| true<NUL>ignored, Истина | Число 0 |
| `exit 17`, Истина | Неопределено |
| `true ; false` с абсолютными путями, Истина | Число 1 |

Все успешные обещания ожидались дважды и дали одинаковые результаты.
Без ожидания пробы не устанавливают момент завершения процесса относительно
Ждать. Успех при отсутствующем cwd не устанавливает фактический каталог.
Два разных случая операторов не доказывают универсального разбора через
конкретную оболочку. Исходная последовательность и тексты причин сохранены.

Отсутствующая программа отличается от ранее измеренного серверного RunApp,
где с ожиданием получался 127. Это различие методов **и контекстов**;
синхронный клиентский RunApp этой серией отдельно не сравнивался.

## Реализация и проверяемые ограничения

Builtin RU/EN и defaults включены в общие таблицы и sema. Async использует
прежний launcher, но переводит NotFound в Undefined, а не 127; настоящий
код процесса 127 сохраняется. Команда обрезается до NUL только в async-входе.
Готовый результат и ошибки подготовки становятся обещаниями; ожидаемый
процесс использует общий sink без SyncWait. Динамическое обещание принадлежит
внешнему execution. Новый публичный Rust-вход — bsl_rt::call_run_app_async;
он подготавливает CallOutcome, а создание обещания остаётся задачей VM.

Согласованный запрет неявного shell сохранён. Строгий cwd также сохранён:
host получает исходный каталог без fallback. Поэтому два дополнительных
случая, cwd_missing и shell_sequence, **не совпадают** с 1С и явно исключены
из утверждения о совместимости. Их oracle не переписан. RUNAPP.EDGE_ARGUMENTS
сохраняет эти ограничения и остальные неизмеренные границы.
Прямая сверка всех 35 строк после реализации показала ровно эти различия:
cwd_missing — Undefined вместо 0; shell_sequence — 0 вместо 1.

CLI-тест сравнивает 33 остальных случая в plain/optimize и обоих текстовых
байткодах. Нормализация касается только BOM/CRLF, строки контекста, языка
типов и текста ошибок; наличие обещания, стадия ошибки, значение, повторное
ожидание остаются проверяемыми. Два известных расхождения названы в фильтре.
Отдельные host-тесты проверяют отказ submit, отсутствие launcher, отложенные
результаты 17/127/NotFound/PermissionDenied/без кода, отсутствие утечки текста
host, соседнюю async-задачу и повторное ожидание. Реальный дочерний процесс
проверяется в пуле одного worker, прямо и через три вложенных Выполнить:
complete/cancel/shutdown, продолжение процесса после отмены и независимый reap.
Отдельная CLI-проба проверяет продолжение процесса после выхода без ожидания.

Итоговые проверки прошли: cargo test --workspace (включая общие
plain/optimize и bytecode round-trip, реестр вопросов и генератор API),
fmt --check, Clippy --all-targets с -D warnings, rustdoc с -D warnings,
git diff --check и строгий OpenSpec — 11 элементов. API reference
регенерирован. Прочие задачи файлового плана остаются открытыми.
