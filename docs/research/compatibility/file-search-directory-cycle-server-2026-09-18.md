# Циклическая ссылка каталога в НайтиФайлы

18 сентября 2026 года на Linux и платформе 1С 8.3.27.2342 измерен
рекурсивный `НайтиФайлы` в серверной базе `/S localhost/test`.
Эффективный режим совместимости — `НеИспользовать`; Unica не использовалась.

В отдельном временном дереве находились `top.txt`, `branch/deep.txt` и
символическая ссылка из `branch` обратно в сам `branch`. Имя ссылки содержит
80 ASCII-байтов: системный предел разрешения ссылок завершает обход до
защитного предела open-bsl. Дерево удалялось `/bin/rm -rf` по точному
уникальному корню, поэтому очистка не следовала по циклу.

Серверная 1С и open-bsl вернули успешный массив из 42 элементов: исходный
`top.txt` и 41 представление `deep.txt` до Linux `ELOOP`. Уже найденные
элементы сохраняются; возникающий на следующей ссылке `ELOOP` трактуется тем
же измеренным правилом оборванной ссылки, а не ошибкой всего вызова.

Изменение runtime не потребовалось. CLI-тест повторяет oracle в
source/bytecode × plain/optimize.

Нативный сеанс `/tmp/open-bsl-server-measure-7kp6r_y1` завершился кодом 0.
CF и конфигурация БД восстановлены; XML совпал, кроме служебного корневого
`ConfigDumpInfo.xml`. SHA-256 сценария —
`cf1323e18161705fee4772676ede461ed060037331d0a3807f3dd75da48a21f8`,
нормализованного oracle —
`9b8a090a538768a925c774e2362c5a6dd749042380229ed3e6c6ce7ca36390b0`.

Проба характеризует Linux-цикл через одну ссылку. Она не переносит предел 42
на другие длины пути или ОС и не закрывает остальные классы ошибок host.
