# Виды обработчиков Begin и наблюдение их ошибок

## Подтверждённое измерение видов

Клиентская проба на серверной localhost/test, 1С 8.3.27.2342, выполнена
напрямую без Unica. Сеанс `/tmp/open-bsl-server-measure-zrl4ja2z` завершился
кодом 0; восстановлены CF и конфигурация БД, XML совпал кроме корневого
ConfigDumpInfo.xml. Исходный вывод и резервные копии сохранены.

[file-begin-handler-kinds.bsl](../../../tests/conformance/measure/filesystem/file-begin-handler-kinds.bsl)
и [девять строк oracle](../../../tests/conformance/measure/filesystem/file-begin-handler-kinds.platform.txt)
проверяют синхронную функцию успеха, async-функцию и async-процедуру успеха,
синхронную функцию ошибки. Первое наблюдение после Begin показывает ноль
доставок; каждый обработчик видит завершение вызывавшего тела. Async-варианты
выполняют участок после Ждать ExistsAsync. Результат инициализации — исходный
Файл. Синхронная функция ошибки получает начальный флаг Истина, изменяет его
на Ложь и возвращает 99 без стандартной ошибки.

Тот же исходник и oracle добавлены в conformance как file_begin_handler_kinds.
Обе копии oracle сверены cmp с platform.txt успешного native-сеанса;
вывод прежнего open-bsl совпал побайтно. Фокусный conformance-тест прошёл.
Новой реализации для этих случаев не потребовалось. Измерение не описывает
async-обработчик ошибки, ошибки самих callback или небулевые флаги.

## Исправление измерительного наблюдателя

Для следующих проб runner получил явный --observe-client-errors, который
добавляет во временный модуль приложения ОбработкаОтображенияОшибки.
Он пишет client.error и отключает стандартное отображение, не меняя
требование завершить сеанс. Прежний режим не устанавливает обработчик.

Первый вариант ошибочно содержал два параметра вместо трёх. В сеансах
`/tmp/open-bsl-server-measure-83ckzh2h` и
`/tmp/open-bsl-server-measure-9vjze5l8` записана только начальная часть пробы,
затем появилось модальное окно и native достиг таймаута. Оба сеанса
восстановили CF/БД и подтвердили XML, но oracle из них не принимался.
Попытка WM_DELETE тестового окна не дала продолжения; это не измерение
семантики остальных callback. Снимок второго окна сохранён как
`/tmp/open-bsl-standard-flags-window.png`.

Причина сверена с [документацией 1C](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_32._Debugging_and_testing_applications/32.3._Runtime_errors/32.3.4._Error_display_processing/):
порядок — информация об ошибке, требование завершения сеанса, стандартная
обработка. Добавлена красная проверка точной трёхпараметровой сигнатуры и
запрета присваивания признаку завершения; после исправления все 22 теста
измерителя прошли с реальной проверкой ACL вне песочницы.
Логи `/tmp/open-bsl-client-error-observer-arity-red.log` и
`/tmp/open-bsl-client-error-observer-tests.log`.

## Подтверждённое расхождение стандартного флага

Исправленный наблюдатель проверен native-сеансом
`/tmp/open-bsl-server-measure-c78t4utw`: код 0, RESTORED, сверка XML успешна.
[Сценарий](../../../tests/conformance/measure/filesystem/file-begin-standard-flags.bsl)
передаёт одиннадцать значений через ссылочный параметр синхронного обработчика.
[Исходный результат](../../../tests/conformance/measure/filesystem/file-begin-standard-flags.platform.txt)
сохранён без вывода open-bsl или подмены диагностик.

| Итог стандартной обработки | Присвоенные значения |
| --- | --- |
| Ошибка подавлена | Ложь, 0, строка "False" |
| Сохранена исходная ошибка операции | Истина, 1, -1, Неопределено, Null, пустая строка, массив, структура |

Изначальный open-bsl подавлял только Boolean(false). Тест воспроизвёл
расхождение на нуле, затем прошёл после замены этой проверки на успешное
as_condition(false). Алгоритм преобразования не дублируется. Неприводимое
значение не возвращает собственную ошибку преобразования вместо исходной.
Отдельный VM-тест проверяет сохранение отличимого IoError для Undefined,
Null, массива и пустой строки.

Сохранение исходной ошибки дополнительно измерено отдельным сеансом
`/tmp/open-bsl-server-measure-j4qk2gte` с ошибкой доступа при чтении размера
отсутствующего файла, вместо ошибки типа аргумента setter. Все одиннадцать
флагов дали ту же классификацию; восемь ошибок содержат именно Error accessing
file с исходным путём, а не ошибку преобразования. Сеанс завершился кодом 0,
восстановил CF/БД и подтвердил XML. Сохранены
[сценарий](../../../tests/conformance/measure/filesystem/file-begin-size-flags.bsl)
и [34 строки oracle](../../../tests/conformance/measure/filesystem/file-begin-size-flags.platform.txt).
Интеграционный тест проверяет согласованность обоих независимых oracle.

Интеграционный тест читает итог из native-oracle и проверяет 176 сочетаний:
11 значений × RU/EN × прямой/динамический вызов × plain/optimize ×
source/bytecode. Логи `/tmp/open-bsl-standard-flags-red.log`,
`/tmp/open-bsl-standard-flags-focused.log`, `/tmp/open-bsl-standard-flags-vm.log`.

## Подтверждённые ошибки обработчиков успеха

Повторный сеанс `/tmp/open-bsl-server-measure-ps1h90mc` завершился кодом 0
с RESTORED и совпадением XML. Все шесть callback вошли в свои тела;
оба варианта с Ждать выполнили участок после ожидания.
[Сценарий](../../../tests/conformance/measure/filesystem/file-begin-handler-errors.bsl)
и [исходный вывод](../../../tests/conformance/measure/filesystem/file-begin-handler-errors.platform.txt)
сохранены и сверены cmp с platform.txt успешного сеанса.

Исключения синхронной процедуры, синхронной функции и async-процедуры
до/после Ждать попали в обработчик приложения: четыре client.error.
Исключения async-функции до/после Ждать отдельно приложению не сообщались.
Перенаправления в обработчик ошибки исходного ОписаниеОповещения не было.

Open-bsl совпал во всех 48 сочетаниях шести видов × прямой/динамический
вызов × plain/optimize × source/bytecode. Проверяются фактический вход,
участок после Ждать, точное исключение и отсутствие перенаправления.
Ошибку, которую 1С доставляет обработчику приложения, фасад возвращает
host как ошибку исполнения. В CLI это завершает запуск, а не продолжает
другие callbacks после UI-обработчика. Неиспользуемое обещание async-функции
сохраняет свою ошибку без отдельного отказа запуска. Изменений runtime
для этих шести случаев не потребовалось.

## Закрытие границ доставки

Последующая матрица `file-begin-error-handlers` измерила двенадцать вариантов
sync/async-функций и процедур обработки ошибки, включая исключения до и после
`Ждать`. Отдельная проба стандартного флага дополнила прежние одиннадцать
значений датой, типом, перечислением, соответствием, `Файл`, двоичными
данными, буфером, UUID, описанием типов, описанием оповещения и ссылкой на
BSL-модуль. Все одиннадцать новых значений сохранили исходную ошибку операции.

[Исходник](../../../tests/conformance/measure/filesystem/file-begin-standard-flag-kinds.bsl)
имеет SHA-256 `27a7f874ee89076ee03ec4e7e527a83edb41ba03bde52670b5ddaea69974f818`,
[oracle](../../../tests/conformance/measure/filesystem/file-begin-standard-flag-kinds.platform.txt)
— `b2190b16ba04d4f3f2882fff8d16d390ae70ce6befe9fa1807c105ed7fb98b54`.
Сессия `/tmp/open-bsl-server-measure-us2rya16` завершилась кодом 0,
восстановила CF/БД и подтвердила совпадение XML. Интеграционный тест проверяет
все 22 вида флага в RU/EN, direct/dynamic, plain/optimize и source/bytecode.

Таким образом, `NOTIFY.DELIVERY_EDGES` снят комплектом с registry,
measure-all и кодового комментария. Полнота методов конкретных объектных
получателей остаётся отдельной задачей. Новых зависимостей и изменений формата
байткода нет; ускорение не заявляется.
