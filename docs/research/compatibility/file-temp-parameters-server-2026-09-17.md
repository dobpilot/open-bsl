# Параметры и доступ к временному потоку серверной 1С

Измерены аргументы, сохранение имени, видимость длины и независимое чтение.
Результаты уточняют реализационный контракт CreateTempFile; сам метод и
системная автоочистка этим исследованием не реализованы.

## Сеансы и сохранность базы

Обе пробы выполнены напрямую, без Unica, на серверной `localhost/test`,
Linux, 1С 8.3.27.2342, с пустыми учётными данными. Использован серверный
модуль формы; на 8.5 и файловую базу результаты автоматически не переносятся.

| Проба | Каталог артефактов | Проверенный результат |
|---|---|---|
| file-temp-parameters | /tmp/open-bsl-server-measure-hrgifgur | 70 вызовов и 6 первоначальных отказов независимого чтения |
| file-temp-visibility | /tmp/open-bsl-server-measure-z2zfz0hk | 30 наблюдений записи/чтения и 6 наблюдений после закрытия |

Оба runner завершились кодом 0 и RESTORED: свежий CF восстановлен,
конфигурация БД обновлена, XML совпал, кроме корневого ConfigDumpInfo.xml.
Каталоги содержат резервные копии, исходный BOM/CRLF-вывод и restoration.txt.
Нормализованные platform.txt скопированы в репозиторий и проверены `cmp`:

- [Параметры](../../../tests/conformance/measure/filesystem/file-temp-parameters.bsl)
  и [результат](../../../tests/conformance/measure/filesystem/file-temp-parameters.platform.txt).
- [Видимость](../../../tests/conformance/measure/filesystem/file-temp-visibility.bsl)
  и [результат](../../../tests/conformance/measure/filesystem/file-temp-visibility.platform.txt).

Общий platform.tsv не менялся. Oracle не генерировались из open-bsl.

## Параметры и имя

32 успешных вызова, 38 отказов. RU/EN ведут себя одинаково:

- Принимаются отсутствие аргументов и явные `(65535,8192)`.
- В каждой позиции принимаются 0, 1, 8, 8192, 65535, 65536 и Неопределено.
- В каждой позиции отвергаются Null, -1, 1.5, строка "8", Ложь, Истина,
  дата, массив и структура. Третий аргумент также отвергается при вызове.
- Успешный результат — File stream с длиной/позицией 0 и признаками r/w/seek.
  Файл существует. После Закрыть имя остаётся тем же, файл ещё существует.

`File stream` — представление типа в контексте этих сеансов. Его нельзя
механически подставлять вместо прежнего русского oracle «Файловый поток»:
имена типов и локализованное представление — разные проверки.

## Видимость не равна возможности независимого чтения

Первая редакция после записи открывала Новый ДвоичныеДанные по имени потока.
Все шесть случаев остановились на отказе конструктора. Эти результаты
сохранены, а не заменены предполагаемыми байтами.

Уточняющая проба перехватывает отказ отдельно и продолжает измерение. Во всех
30 наблюдениях причина — `File shared access error '<temp>'`. До независимого
открытия измеряется Файл.Размер; до этого не вызываются Размер, Перейти или
Закрыть исходного потока. Затем размер и данные проверяются через сам поток.

Для default, (65535,8192), (0,0), (1,1), (8,8192) и (65536,16384):

- После записи 1, 8, 8191, 8192, 8193 байт длина файла сразу равна записанной.
- Размер исходного потока и число прочитанных им байтов равны той же длине.
- Первый/последний байты — 65/90; для однобайтовой записи оба равны 90.
- Независимое чтение открытого файла отвергается совместным доступом.
- После Закрыть независимое чтение успешно возвращает 8193 байта во всех
  шести случаях, файл не удаляется.

Это не доказательство внутреннего размера буфера 8192 и не измерение
производительности. Не проверены внешние процессы, rename/unlink открытого
файла, все варианты повторного открытия и общие правила блокировок 1С.

## Влияние на реализацию и план

В delta добавлены проверяемые требования к аргументам, имени после закрытия,
наблюдаемой длине и независимому BSL-чтению стандартного host. Простой поток
над std::fs::File без учёта совместного доступа недостаточен для последнего
сценария. Произвольный embedding-host сохраняет ответственность за свой I/O;
подменять его файловую систему процессной нельзя.

Отдельно остаётся системное право очистки. Проверка inode и следующий unlink
не защищают атомарно от конкурентной подмены. Пользователю задан вопрос о
границе доверия процессов с тем же UID; ни ослабление гарантии, ни новый
приватный каталог этим исследованием не реализованы. Эта развилка не мешала
снять текущие измерения и не закрывает остальной объём файлового плана.

Два теста `temporary_file_oracle` проверяют полный состав и значения
сохранённых наблюдений; это целостность свидетельства, не conformance ещё
отсутствующей реализации CreateTempFile. Активное изменение не архивировано.

Контрольный запуск того же file-temp-parameters на текущем open-bsl вернул
ошибку вызова во всех 70 случаях: метод ещё отсутствует. Вывод сохранён в
`/tmp/open-bsl-temp-parameters-before.txt`; он не используется как oracle.
32 успешных нативных случая тем самым задают конкретную красную проверку
для предстоящей реализации, а не закрытый пункт функциональности.

Проверки этапа прошли: полный workspace (включая conformance, plain/optimize,
round-trip, API reference и реестр измерений), fmt, Clippy all-targets с
`-D warnings`, rustdoc с `-D warnings`, `git diff --check` и строгий OpenSpec
11/11. Логи: `/tmp/open-bsl-temp-parameters-{workspace,clippy,doc,openspec}.log`.
