# Расширения файловых масок на серверной 1С

17 сентября 2026 года на Linux, платформе 1С 8.3.27.2342 и серверной базе
`/S localhost/test` измерен чистый диалект файловых масок. Конфигурация имеет
`CompatibilityMode=Version8_3_27`. Unica не использовалась.

Каждая из 40 проб создавала один файл в отдельном временном каталоге. Имя и
маска обрамлялись обычными символами `x`/`y`, чтобы точка, пробелы и
управляющие символы не стали конечным компонентом пути. Проверены двенадцать
реализованных POSIX-классов, отрицание класса, экранирование `?`, `[`,
обычного символа, `]` и `-`, а также четыре повреждённые формы.

Все 40 результатов open-bsl побайтно совпали с серверным oracle. Изменение
runtime не потребовалось; добавлена прямая проверка чистого сопоставителя.
Предварительная строка с именем `*` удалена из окончательного измерителя:
платформа представляет такой результат через особый `sfile://`, поэтому он
не доказывает семантику чистой маски.

Последующий `file-search-sfile` 18 сентября измерил эти два недостающих
физических имени отдельно: звёздочка переводит объект в слой `sfile://`, а
обратная косая черта разбирается как разделитель пути. Они не являются
обычными именами в области `file_mask_matches`. Поэтому вопрос
`FILE.MASK_EXTENSIONS` закрыт разделением областей без изменения алгоритма;
неизвестные правила отбора специальных объектов остаются в
`FIND.TRAVERSAL`.

Финальная сессия `/tmp/open-bsl-server-measure-_rpddd9q` восстановила CF и
конфигурацию БД; XML совпал полностью, кроме служебного корневого
`ConfigDumpInfo.xml`. Предварительная сессия
`/tmp/open-bsl-server-measure-qdm2nq_5` также восстановлена, но её результат
не принят как oracle из-за строки со специальным именем.

- Скрипт SHA-256: `51580ffa307895cb0bdbf513248f593c6de189c03edf5e3bc8a20c39aa74a1ba`.
- Oracle SHA-256: `4ec71dd9abf42f5eb2f9eafbe00af28fc06a42ec2abbed3a3b6feab8be73157c`.

Проверки: локальный запуск полного BSL-измерителя, побайтный `diff` с oracle,
`cargo test -p bsl-rt --test file_masks` и проверка реестра открытых вопросов.
