# Асинхронный временный поток и совместный доступ на Linux

## Измерения

Две пробы выполнены напрямую на 1С 8.3.27.2342, серверная база localhost/test,
без Unica. file-temp-async исполнялся на клиенте этой базы, file-temp-sharing —
на сервере. Свежие CF/XML сохранены перед каждой загрузкой; оба runner
завершились RESTORED после восстановления CF, обновления конфигурации БД
и сверки XML, исключая только корневой ConfigDumpInfo.xml.

Артефакты первого сеанса — `/tmp/open-bsl-server-measure-vn9r62a1`,
второго — `/tmp/open-bsl-server-measure-ionitpe7`. Raw, backup и подтверждения
восстановления сохранены. Нормализованные `platform.txt` побайтно перенесены
в `tests/conformance/measure/filesystem/file-temp-{async,sharing}.platform.txt`.
Общий measure-all/platform.tsv не менялся.

## CreateTempFileAsync: результат и стадия ошибки

70 RU/EN-вызовов используют тот же набор параметров, что прежняя синхронная
проба: default, явные 65535/8192, три аргумента и по 16 значений в каждой
из двух позиций. Получены:

- 32 успеха: возвращается обещание файлового потока; носитель существует,
  размер/позиция равны нулю, чтение/запись/позиционирование доступны;
- 36 ошибок параметров: вызов возвращает обещание, ошибка возникает при
  первом и повторном Ждать;
- два отказа лишнему третьему аргументу: ошибка при вызове, обещания нет.

При успехе повторное Ждать возвращает тот же объект. После Закрыть повторное
ожидание также возвращает его, с прежним именем; файл ещё существует.
Эта проба не определяет момент создания до Ждать и поведение отмены.

На момент измерения Async ещё не был реализован в open-bsl: контрольный прогон сохранён в
`/tmp/open-bsl-temp-async-before.txt`, все 70 вызовов получили отказ при вызове.
Тест oracle проверяет полноту измерения, а не выдаёт её за приёмку реализации.
Delta записана до кода. Нельзя заменить неблокирующее создание синхронным
I/O с готовым обещанием: FileHandle и TemporaryFileResource существующего
host не обязаны быть Send. Кроме переноса результата потребуется сохранить
право очистки при отмене и при позднем завершении после закрытия сеанса.

Обновление 2026-09-18: CreateTempFileAsync реализован через
`background_access` и `create_transferable_temporary_file`. Worker передаёт
открытый дескриптор вместе с исходным правом очистки; VM регистрирует
его в локальном сеансе и создаёт поток без повторного открытия. Все 70
измеренных RU/EN-случаев проходят в plain/optimize и source/bytecode;
дополнительная проба подтверждает, что задержанное создание не блокирует
соседнюю async-задачу. Поздний результат при закрытии State остаётся открытым
продуктовым вопросом, а не скрытой политикой этого этапа.

## Совместный доступ: носитель, а не строка пути

Серверная проба создаёт собственный временный поток и записывает два байта.
Затем явные `/usr/bin/ln` и `/usr/bin/mv` создают hard link и переименовывают
его файл в собственный временный каталог. Семь наблюдений:

- независимое ДвоичныеДанные по первоначальному пути отвергается;
- чтение через hard link и новое имя также отвергается;
- новый пустой файл, созданный и закрытый по старому пути, читается: 0 байтов;
- ИмяФайла исходного потока сохраняет первоначальную строку;
- после Закрыть hard link и новое имя читаются: по 2 байта.

Проба сама удаляет только свои файлы и каталог. Наблюдение не подтверждает
правила автоочистки переименованных файлов и не используется для такого вывода.

## Реализация системного host

Внутренний модуль bsl-rt `temporary_file_access` на Linux учитывает device/inode
открытых носителей, возвращённых SystemFileSystem::create_temporary_file.
FileSystem::read проверяет идентичность своего открытого дескриптора до чтения,
а не повторно открывает проверенный путь. Пока жив исходный дескриптор,
независимое чтение отвергается; metadata и исходное чтение/запись работают.
Освобождение одного носителя снимает только его запись. Никакого удаления
файлов этот механизм не делает и права очистки не предоставляет.

Учёт общий для экземпляров SystemFileSystem и его фонового адаптера в одном
процессе. Это не межпроцессная OS-блокировка и не запрет std::fs::read;
произвольный embedding-host не заменяется системным. Другие open/write API
и другие ОС не получают не измеренной здесь общей модели совместного доступа.

Красный тест сначала воспроизвёл успешное независимое чтение вместо отказа.
После реализации Linux-тест проверяет размеры 1/8/8191/8192/8193, чтение
исходным дескриптором, отказ в другом потоке через background_access,
отдельные файлы, hard link/rename/подмену и отсутствие удаления при Drop.
ДвоичныеДанные проверены до и после освобождения в восьми сочетаниях
plain/optimize × direct/dynamic × source/bytecode. TEMP задаётся только
изолированному дочернему процессу, окружение параллельных тестов не меняется.

Это проверка системного носителя через низкоуровневое создание, а не полный
BSL CreateTempFile стандартного CLI: системное право автоочистки ещё отсутствует,
поэтому последний продолжает отказывать до создания. Виртуальные host-тесты
синхронного компонента проходят отдельно. Async, безопасная системная очистка,
обработка её поздних ошибок и сквозная системная приёмка остаются открытыми.
Новых внешних зависимостей, публичных API и изменений формата байткода нет.
Производительность этим этапом не измерялась.

Полный `cargo test --workspace` прошёл, включая сравнение plain/optimize,
conformance, реестр измерений, API reference, Connector, ZIP, потоки и задания.
Также прошли fmt, Clippy всех целей с `-D warnings`, rustdoc с запретом
предупреждений, `git diff --check` и все 11 строгих проверок OpenSpec.
Логи: `/tmp/open-bsl-temp-access-{red,focused,host,workspace,clippy,doc,openspec}.log`.

переменной окружения этим прогоном не подтверждён, служебный ignored
MXL-dump не запускался. Четыре изменения плана остаются активными.
