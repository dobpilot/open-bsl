# Операционный путь `СоздатьФабрикуXDTO`

Измерение выполнено напрямую на серверной `localhost/test`, Linux,
1С 8.3.27.2342. Unica не использовалась.

Первый успешный сеанс `/tmp/open-bsl-server-measure-ynbdygua` показал
файловое правило, но включал английское локализованное имя типа
`XDTO factory`. Исходник изменён так, чтобы фиксировать только успех разбора,
и выполнен повторно. Финальный сеанс
`/tmp/open-bsl-server-measure-16nrefik` завершился с кодом 0. Оба запуска
восстановили CF и БД; контрольные XML-выгрузки совпали с исходной.

- Финальный исходник `file-xdto-factory-io-edges.bsl`: SHA-256
  `afb7f11cc6669525547dd889ee5321c5ea96b51d6fbcf74b86247375a153d212`.
- Oracle `file-xdto-factory-io-edges.platform.txt`: SHA-256
  `54342abae46a2289e25a26a6bee8c12546e5bebfa7fada49c4fc6c1c1bc5b43d`.

Каждая проба записывает минимальную корректную XSD в базовый файл и вызывает
`СоздатьФабрикуXDTO` по имени с одним суффиксом. NUL, TAB, LF, CR, SPACE,
U+0085 и NBSP снимаются до host, поэтому фабрика строится. U+007F, U+200B и
U+FEFF сохраняются в имени отсутствующего файла и дают ошибку.

До исправления фабрика напрямую вызывала `FileSystem::read` с исходным
путём. Теперь она переиспользует `prepare_file_operation_path`, сохраняя
ошибки компонента XDTO и файловую систему сеанса. Сквозной тест сверяет все
12 строк в source/bytecode × plain/optimize.
