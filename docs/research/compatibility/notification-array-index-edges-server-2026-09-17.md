# Дополнительные границы индекса методов массива

## Среда и артефакты

Прямой запуск 1С 8.3.27.2342 на Linux в серверной базе `localhost/test`,
без Unica. Измеритель не создаёт файлов и не меняет прикладные данные:
каждая операция работает с новым локальным массивом из двух элементов.
Runner временно загрузил измерительную конфигурацию, затем восстановил CF
и конфигурацию БД; XML совпал с исходным, кроме корневого
`ConfigDumpInfo.xml`.

- измеритель: `tests/conformance/measure/filesystem/notification-array-index-edges.bsl`, SHA-256 `e27bd9af9c47f95e0c32aedc7a27fe84b9c4f0de30131c45384dda356b5556a5`;
- oracle: `tests/conformance/measure/filesystem/notification-array-index-edges.platform.txt`, SHA-256 `3fc8199df63e6e289ff5a65372e64401925101dbeeb1faef7bcbb7bf9288c238`;
- сохранённый сеанс: `/tmp/open-bsl-server-measure-uy1qt9l5`.

## Результат

Для RU/EN `Получить/Get` и `Установить/Set` получены 48 результатов:

- числа `-0.9`, `0.9` и `-0.0` усекаются к нулю; `-1.9` отвергается;
- строки с пробелами, `+1`, `01`, `0.9` и `-0.9` принимаются;
- `0,9`, `1e0` и пустая строка отвергаются;
- ошибочный setter не изменяет массив.

Текущий общий `parse_canonical` уже совпал со всеми строками, поэтому
runtime не менялся. Новый CLI-тест проверяет точный oracle в четырёх
режимах: source/bytecode × plain/optimize.

`ARRAY.METHOD_INDEX` не снят: безопасная проба намеренно не измеряет
платформенный предел расширения `Вставить` и точные локализованные тексты
ошибок. Производительность и публичный API этим этапом не менялись.
