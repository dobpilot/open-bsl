# Проверка защитных границ файловой реализации

Это промежуточная проверка реализованной части, не приёмка всего файлового
плана. Она выявила и исправила обход no-follow конечным разделителем.
Новые нативные замеры 1С в этом этапе не выполнялись; localhost/test
не изменялась. Проверки используют только собственные временные деревья.

## Удаление каталога-ссылки с завершающим разделителем

До исправления SystemFileSystem::remove_path сначала передавал исходный
путь symlink_metadata. Для selected результат был ссылкой, для selected/
на этой Linux-машине — каталогом цели. Следующий remove_dir_all затрагивал
содержимое цели. Красный тест потерял свой target/sentinel, тогда как
контроль без разделителя сохранил файл. Это дефект защитной политики
open-bsl, а не новое свидетельство поведения 1С.

Исправление в [env.rs](../../../crates/bsl-rt/src/env.rs) на Unix отделяет
конечные / до metadata и сохраняет признак исходного окончания. Конечная
ссылка удаляется сама; обычный файл с таким окончанием даёт NotADirectory
без удаления; настоящий каталог удаляется как прежде. Путь только из /
не превращается в пустую строку. Пробелы и внутренние компоненты не
нормализуются. Windows-префиксы не обрабатываются этим Unix-правилом.

[Документация Rust remove_dir_all](https://doc.rust-lang.org/std/fs/fn.remove_dir_all.html)
описывает удаление самой ссылки и защиту от symlink TOCTOU на большинстве
платформ, с перечисленными исключениями. Это не гарантия, что исходный путь
с последним / обозначает ссылку при его разрешении ОС, и не условное
удаление только объекта с заранее сохранённой идентичностью. Исправление
не подменяет нерешённую задачу системного временного ресурса таким обещанием.

## Проверки

[system_file_removal.rs](../../../crates/bsl-rt/tests/system_file_removal.rs):

- Каталог-ссылка: selected, selected/ и selected/// удаляют ссылку,
  сохраняя содержимое цели.
- Ссылка на файл и оборванная ссылка с теми же окончаниями: цель сохраняется
  либо остаётся отсутствующей, удаляется только ссылка.
- Обычный файл с / или /// сохраняется, ошибка — NotADirectory.
- Настоящий каталог с конечным пробелом и окончаниями / удаляется;
  пробел имени не обрезается.
- Удаление дерева не удаляет цели ссылок внутри него.
- Ссылка в родительском компоненте разрешается и при чтении, и при удалении
  собственного контрольного файла. Это явно показывает отсутствие sandbox.

Тест deleting_a_link_with_trailing_separators_never_deletes_its_target
в [file_async.rs](../../../crates/open-bsl/tests/file_async.rs) проверяет
96 комбинаций: три окончания × RU/EN × sync/async × прямой/динамический
вызов × plain/optimize × исходник/байт-код. После каждого запуска проверены
точные байты цели и отсутствие самой ссылки. Это host-политика open-bsl;
данные этих тестов не становятся платформенным oracle.

## Согласованные политики не являются новыми разрешениями

Общий design прямо исключает sandbox разрешённых корней и возлагает
ограничение доступа на host. Комментарий remove_path, обещавший защиту
sandbox-скрипта, был неверен и исправлен. Нельзя рекомендовать стандартный
host для изоляции недоверенного скрипта на основании no-follow последней ссылки.

Действующий контракт запуска требует отсутствия неявного shell. Код
SystemApplicationLauncher использует Command::new с отдельными argv;
разборщик не выполняет подстановки. Измеренное использование shell серверной
1С не отменяет этот контракт. Аналогично сохраняется защитное удаление
самой ссылки, а не измеренное удаление её цели серверной 1С. Нового согласия
пользователя на изменение этих политик нет; оно не требуется для исправления
дефекта уже выбранного no-follow. Запросы о возможном изменении совместимости
не должны блокировать реализацию действующих защитных правил.

## Что эта проверка не закрывает

| Область | Подтверждённое состояние | Незавершённый объём |
|---|---|---|
| Удаление | Исправлена конечная ссылка с /, parent-ссылки разрешаются | Остальные края удаления и частичные отказы; это не root confinement |
| Запуск | Прямой executable/argv, ожидание отдельно от жизни VM | Document остаётся Unsupported; это не успешная приёмка ассоциаций |
| Временная очистка | CLI передаёт зарегистрированные ресурсы в host.remove, не удаляет по их описательному path | SystemFileSystem создаёт OpenedTemporaryFile без права очистки; CreateTempFile и сквозная очистка ещё отсутствуют |
| Begin | Сохранены измерения результатов, арностей и ошибок | Доставка в VM и представление BSL-модуля не реализованы |

Отдельного автоматического восстановления/удаления аварийных остатков нет;
добавлять его нельзя по согласованному решению пользователя. Устранение
данного дефекта не доказывает безопасность владения ещё не реализованным
системным временным ресурсом. Финальный security review всех четырёх
изменений и их архивирование остаются открытыми.
