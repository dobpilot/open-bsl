## Матрица и вывод

Четыре дерева × восемь масок × два режима рекурсии × RU/EN дают 128 вызовов.
Маски: `*`, `*.*`, `*.txt`, `*.bin`, `b*`, `a*`, `*dir`, `broken.*`.
Ошибок вызова нет, все строки содержат полный упорядоченный список путей.

Для late порядок верхнего уровня: after.txt, latedir, middle.txt,
broken.bin, earlydir, before.txt. Оба каталога содержат по txt-файлу.
С *.txt плоский результат — after.txt, middle.txt, before.txt; рекурсивный
добавляет только latedir/late.txt. Несовпавшая broken.bin не прервала выдачу
совпадений, но поздний earlydir уже не выбран для спуска. При маске *dir
оба имени каталогов остаются в результате, без их не совпадающего содержимого.

В between совпавшая broken.txt после after.txt обрывает совпадения;
при рекурсии уже выбранный latedir всё ещё обходится. В double с *.bin
первая совпавшая оборванная last.bin включается, а последующая broken.bin
уже не включается. В first с *.txt первая broken0.txt включается, после
неё включаются обычные after.txt и middle.txt; оборванная first.txt
останавливает выдачу до before.txt. Рекурсивных результатов нет: первая
оборванная запись встретилась раньше любого кандидата спуска.

Все 128 результатов совпали с существующим алгоритмом open-bsl без
изменения runtime. Это подтверждение правил отдельного прерывания
совпадений и выбора каталогов, а не основание скрывать любые ошибки host.
PermissionDenied, циклы ссылок, иные маски и сочетания с пробельными
именами не измерялись. Маркер, ID FIND.TRAVERSAL и его единственная строка
в measure-all сохранены; в реестре уточнён уже проверенный объём.

## Регрессионные проверки

Тест multiple_and_nonmatching_broken_links_match_the_native_ordered_oracle
в crates/bsl-rt/tests/find_files.rs воспроизводит снимок как управляемую
FileSystem и сверяет все 128 строк нативного oracle, включая порядок
и число результатов. Ссылки этого снимка дают NotFound; другие ошибки
не подменяются им. Тест не требует исходного scratch или запуска 1С.

До изменений тестов CLI на том же физическом дереве уже совпал с native;
сравнение исключало только строку эффективного режима, недоступного
open-bsl. Дополнительно совпали plain, optimize и исполнение обоих
текстовых листингов байткода. Runtime-алгоритм и публичный API не менялись;
новые сценарии уточняют существующую активную delta поиска.

После добавления теста прошли fmt, Clippy --workspace --all-targets с
запретом предупреждений, полный cargo test --workspace, rustdoc с запретом
предупреждений, git diff --check и все 11 строгих проверок OpenSpec.
Логи — /tmp/open-bsl-search-late-links-{clippy,workspace,doc,openspec}.log.
Scratch сохранён; перед завершением его порядок/типы/цели ссылок повторно
совпали со снимком, все обычные файлы остались пустыми. Непроверенные
части файлового плана этими успешными проверками не закрываются.
