# Временный поток поддерживающего host и имя файлового потока

## Результат и границы

Синхронное создание временного потока реализовано в `bsl-stream` поверх
прежних контрактов `bsl-rt`. VM передаёт сеансовый реестр через CallContext;
структура InterpreterServices и прежние конструкторы сохранены. Менеджер
запоминает исходные FileSystem, RandomHandle и TemporaryFileRegistry.
Новый State или контекст вызова не заменяет владельца сохранённого менеджера.

До создания проверяются параметры, открытый реестр, поддержка права очистки
и источник имени. Поток получает дескриптор атомарно созданного host-файла
после регистрации его собственного ресурса, без повторного открытия пути.
Закрытие сохраняет имя и не удаляет файл; конец отдельного вызова также
не запускает очистку. При завершении State применяется выбранный callback.
Без callback удаления нет.

SystemFileSystem не объявляет поддержку права очистки и потому новый BSL-метод
отклоняет до создания файла. Прежнее низкоуровневое атомарное создание
сохранено. Системный ресурс удаления, защита от подмены, измеренные правила
совместного доступа, CreateTempFileAsync и учёт файла, записанного по ранее
выданному временному имени, не реализованы этим этапом. Вопрос о границе
доверия процессов с тем же UID остаётся открытым; контракт не ослаблен.

Поддерживающий host обязан возвращать `new_owned`. Если он нарушил это
обещание или реентерабельно закрыл учёт во время создания, вызов завершается
ошибкой, дескриптор освобождается, но путь не превращается в право удаления.
В таком ошибочном host файл может остаться; это явно проверенный отказ,
а не гарантия уборки после нарушения контракта.

## Нативное имя файлового потока

Проба `tests/conformance/measure/filesystem/file-stream-name.bsl` выполнена
на серверной 1С 8.3.27.2342, localhost/test, напрямую без Unica.
Маркер `stream-name-1`; восемь строк сохранены в соседнем `.platform.txt`.
Пять обычных абсолютных путей — plain, `./`, `nested/../`, двойной разделитель
и конечный ASCII-пробел — возвращаются через ИмяФайла без нормализации.
Запись английского FileName отвергается; после Закрыть имя то же.
У ПотокВПамяти получение этого свойства завершается ошибкой.

Сеанс `/tmp/open-bsl-server-measure-tjrtkzbi` завершён с RESTORED.
Исходная CF и конфигурация БД восстановлены; XML совпали, кроме корневого
ConfigDumpInfo.xml. Backup, исходный вывод и restoration.txt сохранены.
Платформенный результат побайтно сверён с checked-in oracle и
`tests/conformance/fixtures/file_stream_name.expected`; BSL-источники также
совпадают. `measure-all/platform.tsv` этим замером не изменялся.

Это новое измерение только свойства имени. Параметры и немедленное создание
временного потока опираются на прежние [70 вызовов и пробы видимости](file-temp-parameters-server-2026-09-17.md).
Другие формы пути, предельные параметры и точные ошибки сохраняют маркер
`STREAM.TEMP_EDGES`, запись реестра и одну строку measure-all.
Внутренние размеры буферов 1С из наблюдений не выводятся; компонент не
удерживает записанные байты в отдельном буфере, I/O выполняет host.

## Проверка компонента

`crates/open-bsl/tests/temporary_stream.rs` содержит семь тестов:
создание/чтение/запись/close/очистка в восьми сочетаниях plain/optimize,
direct/dynamic и source/bytecode; исходный сеанс и источник имени;
закрытый сеанс; прежний менеджер без контекста; неподдерживающий host;
ошибка BSL с callback и без него; два нарушения host-контракта;
70 измеренных аргументных вызовов на обоих языках.
Отказы до I/O проверены счётчиком создания, повторное открытие пути
запрещено самим тестовым host. Создание сначала воспроизводило UnknownMethod,
после реализации все семь тестов прошли.

Формат байткода не менялся (31), новых зависимостей нет. BSL-справочник
регенерирован из дескрипторов, а не отредактирован вручную. Измерений
производительности и заявлений об ускорении этот этап не содержит.

Пройдены полный `cargo test --workspace` (включая plain/optimize,
conformance, реестр измерений, Connector, ZIP, потоки и задания), fmt,
Clippy для всех целей и rustdoc с запретом предупреждений, `git diff --check`
и все 11 строгих проверок OpenSpec. Логи этапа сохранены в
`/tmp/open-bsl-temporary-stream-{focused,workspace,clippy,doc,api,openspec-final}.log`.
Обычные условия suite сохраняются: конфиденциальные table_compare2 без
переменной окружения не подтверждаются этим прогоном; служебный ignored
MXL-dump не исполнялся. Четыре изменения OpenSpec остаются активными.
