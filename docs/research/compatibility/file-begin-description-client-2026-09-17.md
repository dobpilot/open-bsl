# Описание для НачатьИнициализацию

Измерено 2026-09-17 напрямую на клиенте 8.3.27.2342 серверной localhost/test,
без Unica. [Скрипт](../../../tests/conformance/measure/filesystem/file-begin-description.bsl)
и [вывод](../../../tests/conformance/measure/filesystem/file-begin-description.platform.txt).
Файлы по передаваемым путям не создаются: инициализация меняет объект Файл.

Сессия `/tmp/open-bsl-server-measure-v48sqmyg` сохранила свежие original.cf
и original-xml, восстановила CF/БД и сверила restored-xml с original-xml.
Игнорировался только корневой ConfigDumpInfo.xml. restoration.txt подтверждает
восстановление; platform.txt перенесён побайтно и проверен cmp. Общий oracle
platform.tsv не менялся.

Девять вызовов с Неопределено/Undefined, Null, Ложь, 0, пустой/непустой
строкой, массивом и структурой вместо описания отказали при вызове.
ПолноеИмя исходного объекта не изменилось. В отличие от этих значений,
пустое ОписаниеОповещения/NotifyDescription принято обеими языковыми
формами метода: путь изменён до возврата, ошибка не возникла.

Положительный контроль с Вставить соответствия после возврата метода
показывает ещё пустое соответствие, а последующее наблюдение — одну запись.
Её ключ равен исходному Файл, значение равно переданным данным same.
Это подтверждает доставку и тождество, но не общий FIFO параллельных I/O.

Пустое описание не означает неверный тип или обязательность успешного
обработчика. Для реализации это отдельная принятая форма; проверка типа
описания должна предшествовать мутации пути. Правило не переносится без
замера на ошибки операции с пустым описанием и остальные Begin-методы.

В open-bsl BeginInitialization ещё отсутствует: все вызовы дают ошибку
неизвестного метода, в том числе положительные контроли. Лог:
`/tmp/open-bsl-begin-description-before.log`. Скрипт компилируется и завершается
в обоих runtime, но не объявлен зелёной conformance-фикстурой. Реализация
доставки, ошибки самих обработчиков и стандартная обработка остаются открытыми.
