# Табличные Get/Set для обработчиков оповещения

## Контекст и восстановление

1С 8.3.27.2342, Linux, серверная `/S localhost/test`, кластер от kan,
серверный код управляемой формы. Native-запуск без Unica. В XML
CompatibilityMode=Version8_3_27, эффективный режим из Метаданные —
НеИспользовать; значения не отождествляются. Клиентская доступность,
версия 8.5 и файловая база этой серией не измерялись.

Сессия `/tmp/open-bsl-server-measure-ui0hf1zv`: свежие CF/XML, повторная
проверка неизменности перед загрузкой, восстановление CF/конфигурации БД
и побайтная сверка XML, кроме корневого ConfigDumpInfo.xml. Runner завершился
кодом 0, подтверждение и резервные копии сохранены. Скрипт изменяет только
таблицы в памяти; пользовательские файлы и данные ИБ не обрабатывает.

## Матрица из 155 проб

Три getter: таблица → строка, колонки → колонка, строка → ячейка.
Один setter: строка.Установить/Set. Восемнадцать индексов × четыре
получателя/операции × RU/EN дают 144 пробы. Ещё девять проверяют арность,
две — setter как выражение. Исходная таблица имеет две колонки, строки
`[10, 20]` и `[30, 40]`. После каждого вызова проверены обе строки и
число строк/колонок. Вызовы идут через Выполнить/Вычислить.

| Индекс | Все четыре операции |
|---|---|
| 0, Ложь | Первая позиция |
| 1, 1.9, "1", " 1 ", "1.9", Истина | Вторая позиция |
| 2, -0.9, -1, -1.9 | Ошибка без изменения |
| Имя колонки "Левая", "x" | Ошибка, не доступ по имени |
| Неопределено, Null, массив, дата | Ошибка без изменения |

Getter принимает ровно один аргумент, setter — два. Setter не функция:
выражение отвергается до записи. RU/EN совпали. Особенно важен -0.9:
табличные методы отвергают его, тогда как измеренная вставка массива
выбирает индекс 0. Копирование подготовки индекса массива целиком было
бы ошибкой совместимости.

## Реализация и проверки

В существующую диспетчеризацию Get добавлены таблица/колонки/строка,
в BufSet — только строка. Таблица и коллекция колонок setter не получили.
Общий разбор числа выделен из подготовки массива; таблица отдельно
отвергает отрицательное значение до усечения. Семантика [] не менялась.
Getter переиспользует индексатор, setter — выбор имени по индексу и
set_field_by_name/set_cell с существующим приведением к типу колонки.
Новые таблицы имён, формат байткода и публичные Rust-методы не добавлялись.
Проверка result_required дополнена для Set строки до вызова обработчика.

До реализации положительные native-пробы давали ошибки в open-bsl.
После реализации все 155 строк совпали. В fixture удалены только BOM,
CRLF и строка контекста вместе с её запросом; значения не получены из
open-bsl. Runtime-тесты отдельно проверяют ошибки индексов/арности без
записи, неизменность именованного [], живой доступ к исходной таблице
через полученную строку и сохранение прежнего отказа удалённой строке.
Последний тест — регрессия реализации, не новое измерение платформы.

Прямые/параметрические вызовы и запрет выражения проверены с оптимизацией
и без неё. Запись значения неподходящего типа через Set сверяется с
существующим присваиванием свойству той же типизированной колонки.
Это проверка переиспользования прежнего приведения, не отдельный oracle
всех типов столбцов. Общее тождество/хэш табличных обёрток не менялось.

TABLE.METHOD_INDEX оставляет открытыми прочие строки, диапазоны, точные
ошибки и удалённые объекты; добавлены маркер, реестр и одна строка
измерителя measure-all. ARRAY.METHOD_INDEX не закрыт и не переименован.
Доставка Begin-оповещений и другие отсутствующие обработчики остаются
отдельной работой, а не следствием появления этих четырёх операций.

Полный cargo test --workspace прошёл, включая plain/optimize, текстовый
round-trip и проверку реестра вопросов. Также прошли fmt --check,
Clippy --all-targets и rustdoc с -D warnings, регенерация API reference,
git diff --check и строгий OpenSpec — 11 элементов. Файловый план в целом
остаётся открытым; этот этап не является его архивированием.
