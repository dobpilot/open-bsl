## Наблюдения

Для 15 января и 15 июля 2020 года установка местных `12:34:56` даёт
UTC `09:34:56`; установка UTC `12:34:56` даёт местные `15:34:56`.
Каталог допускает UTC-setter и оба getter с таким же результатом.
У отсутствующего пути setter и оба getter вызывают исключения.

| Установленное UTC-время | Прочитанное UTC-представление | Местное представление |
|---|---|---|
| 1960-01-15 12:34:56 | 1960-01-15 12:34:55 | Пустое |
| 1900-01-15 12:34:56 | 1900-01-15 12:34:55 | Пустое |
| 0001-01-01 00:00:00 | 0002-11-30 00:00:00 | Пустое |
| 9999-12-31 23:59:59 | 9999-12-31 23:59:59 | Пустое |

Во всех четырёх случаях setter завершился без исключения. Результаты нельзя
пока приписать отдельному слою: нужны внешнее чтение фактического mtime
и вывод типа/полей BSL-даты. Пустое представление само по себе не доказывает
ни пустую дату, ни Неопределено. Маска `ДФ` в этом сеансе не дала ISO-вид:
результат локализован на английский. Следующая проба должна выводить поля
независимо от Формат.

`Неопределено` и число 17 отвергаются UTC-setter; последующее чтение
сохраняет прежнюю дату. Строка `20200115123456` принимается без исключения;
она совпадает с прежним значением, поэтому это ещё не доказывает запись
преобразованной строки. Вызов setter как функции вызывает
`Object procedure called as function`. Сохранено только верхнее описание
ошибок, без утверждения о совпадении полного текста с open-bsl.

## Проверки и последствия

Есть `file.begin`, `file.end` и успешная очистка, нет ошибки подготовки.
Scratch `/tmp/v8_cBCfXV_5.times` после прогона отсутствует. Восстановление
свежего CF прошло; повторный XML идентичен исходному кроме
`ConfigDumpInfo.xml`, код обёртки 0. Это проверка конфигурации, не побайтное
сравнение данных всей ИБ.

В open-bsl тот же исходник дошёл до конца, фиксируя отсутствующие методы
как ошибки. Совпадения поведения времени пока нет. Rust-host `set_modified`
хранит целые секунды UTC; его round-trip не является oracle для BSL.
Нельзя переносить обнаруженные искажения даты внутрь host без установления
их причины и границ.

Следующие пробы: поля и тип пустого местного результата, фактический mtime
через ОС, epoch ±1 секунда, изменяющая значение строка, местные даты на
переходах зоны, объяснение контекста совместимости. Реестр и `.expected`
этим исследованием не меняются.

Продолжение: [поля дат и внешний mtime](file-time-edges-server-2026-09-09.md).
Пустое местное представление подтверждено как дата 0001-01-01. Для
минимальной UTC-даты getter отдаёт поля 0-0-0; прежнее форматированное
`0002-11-30` нельзя трактовать как действительное календарное значение.
