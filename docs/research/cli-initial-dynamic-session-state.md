# Начальный динамический признак сеанса CLI

Configured CLI передаёт `false` через существующий
`SessionResources::with_database_configuration_changed_dynamically` при
открытии своего нового логического сеанса. Это измеренное начальное
состояние сеанса, а не признак, вычисленный по текущим метаданным базы.
Другие хосты без ресурса продолжают получать прежний явный отказ.
Наблюдение внешних динамических обновлений во время исполнения этим
изменением не реализовано и не заявлено.

OpenSpec `initialize-cli-session-dynamic-status` строго провалидирован
до кода. Два новых внешних теста `session_dynamic_configuration_status`
проверяют обработчик инициализации, обе языковые функции, разделение
состояния разных сеансов и отсутствие ресурса. Тесты, Clippy новых тестов
и обычной цели CLI, форматирование прошли. Старые тесты не изменялись.

Повторный исходный demo в режиме только для чтения завершился с кодом 1
за 149,25 с; компиляция заняла 124,46 с. Прежний отказ отсутствующего
динамического ресурса пройден. Следующий отказ —
`Runtime(UnknownProperty("НеИспользовать"))`. На этом пути создан образ
фонового выполнения 4 624 168 225 байт, буфер передан без копирования;
наблюдаемый пик RSS 7 100 884 КиБ. Эти числа не являются сравнительным
замером производительности.

Лог: `target/diagnostics/readonly-startup/demo-dynamic-initial-1013-startup.log`.
Неизменяемый бинарный файл `session-dyninit-startup-probe-1013` и его
квитанция сохранены рядом. SDK в контуре — `86683e1`.
Полная инициализация demo и повторный исходный UNF пока не подтверждены.
