# Поверхность платформы для модулей сеанса `demo`, `buh` и `unf`

Дата разведки: 2026-09-21.

## Цель и границы

Документ фиксирует минимальную объектную поверхность платформы, которую должен
предоставить хост, чтобы начать исполнять обработчик
`УстановкаПараметровСеанса` в трех используемых информационных базах:

| База | Конфигурация | Ресурс модуля сеанса | Корневой обработчик |
|---|---|---|---|
| `demo` | `МинДок`, «1С:МинДок, редакция 1.0» | `172561c5-c3bf-4b95-850c-618fd89e947a.7` | собственный модуль сеанса и БСП |
| `buh` | `БухгалтерияПредприятияКОРП` | `f0ba0954-a66b-4085-9df1-b8a4283bdbd3.7` | только делегирование в БСП |
| `unf` | `УправлениеНебольшойФирмой` | `dc6d7646-10e5-41e7-9723-e450f206df84.7` | только делегирование в БСП |

Разведка выполнена по ресурсам `Config` живых баз. Исходники распакованы только
во временный каталог, изменения в базы не вносились. Карта API ниже получена
статическим обходом прямых вызовов модуля сеанса, реализации
`СтандартныеПодсистемыСервер.УстановкаПараметровСеанса`, двух вызываемых ею
менеджеров справочников и процедуры `ПередЗапускомПрограммы`.
Семантика ленивой инициализации отдельно измерена на реальной платформе;
протокол приведен в разделе «Измерение ленивой инициализации».

Это не полный граф произвольной выборочной инициализации. БСП строит реестр
обработчиков динамически, а затем вызывает имя модуля и метода из строк. Точный
граф такой ветки зависит от переданного списка параметров, состава подсистем,
расширений и данных базы. Для него ниже зафиксирована граница и механизм, а не
ложно точный список всех транзитивных запросов.

Нужно различать поверхность компиляции и поверхность исполнения. Resolver
open-bsl разбирает целый модуль, поэтому каждое голое глобальное имя во всех
его процедурах должно быть объявлено, даже если процедура не будет вызвана в
этом сеансе. Это касается прежде всего имен общих модулей и платформенных
менеджеров. Свойства и методы значений проверяются при фактическом обращении;
их минимальный исполнимый набор и приведен ниже. Практический хост поэтому
должен регистрировать глобальные имена из метаданных конфигурации целиком, а
реальные объекты и данные может поднимать лениво по мере вызова.

## Два разных профиля исполнения

`УстановкаПараметровСеанса(Неопределено)` является полным стартом сеанса. БСП:

1. создает массив установленных параметров;
2. инициализирует `ПараметрыКлиентаНаСервере`;
3. при наличии подсистемы вызывает модуль мультиязычности;
4. вызывает менеджер `Справочники.ВерсииРасширений`;
5. выполняет `ПередЗапускомПрограммы()`;
6. возвращается до построения реестра параметрических обработчиков.

При переданном массиве имен БСП работает иначе. Она обслуживает несколько
параметров сама, вызывает менеджеры `ИдентификаторыОбъектовМетаданных` и
`ВерсииРасширений`, а для остальных строит соответствие обработчиков через
`ИнтеграцияПодсистемБСП` и `ОбщегоНазначенияПереопределяемый`. Поэтому хосту
нужен отдельный контракт для динамической диспетчеризации общих модулей.

Сводная матрица выглядит так:

| Группа API | `demo` | `buh` | `unf` | Профиль |
|---|:---:|:---:|:---:|---|
| параметры сеанса и модульное состояние | + | + | + | оба |
| метаданные конфигурации, язык и роли | + | + | + | полный старт |
| версия платформы и режим запуска | + | + | + | полный старт |
| пользователь информационной базы | + | + | + | полный старт |
| текущий сеанс ИБ, фоновое задание и профиль безопасности | + | + | + | полный старт |
| расширения конфигурации | + | + | + | оба |
| менеджеры `ВерсииРасширений` и `ИдентификаторыОбъектовМетаданных` | + | + | + | второй менеджер только при выборочном вызове |
| поиск и динамический вызов общих модулей | + | + | + | оба |
| константы, прикладной пользователь и соединения ИБ | + |  |  | полный старт `demo` |
| журнал регистрации | + |  |  | ветка проверки веб-доступа `demo` |
| хранилища настроек и начальная страница | + | + | + | только клиентский режим |
| запросы и предметные менеджеры данных | + | + | + | обработчики выбранных параметров |

## Сверка с синтакс-помощником 1С

Сведения этого раздела взяты из локального синтакс-помощника платформы
`8.3.27.2342`, корпус `platform-syntax-help:syntax-context`, язык ответа —
русский, источник — поставщик платформы. Минимальная версия, проверяемая кодом
БСП в обследованных конфигурациях, начинается с `8.3.24`; справка более новой
установки подтверждает текущий контракт, но сама по себе не доказывает
поведение промежуточных выпусков. Для каждого вывода указан стабильный
`documentId`; реестр полных идентификаторов находится в конце документа.

### Жизненный цикл параметров сеанса

Справка подтверждает, что `ПараметрыСеанса` — доступное только для чтения
свойство глобального контекста, значением которого является изменяемый объект
`ПараметрыСеанса` [SP-01]. Его именованные свойства можно читать и записывать,
коллекцию можно обходить, а метод `Очистить()` переводит параметры в состояние
«Не установлено» [SP-03]. Это состояние отличается от значения
`Неопределено`.

Событие `УстановкаПараметровСеанса(ТребуемыеПараметры)` имеет два режима
[SP-02]:

- при установке соединения оно вызывается до всех остальных обработчиков, а
  аргумент равен `Неопределено`;
- перед первым фактическим использованием неинициализированного параметра
  аргумент содержит массив идентификаторов требуемых параметров;
- если после обработчика хотя бы один запрошенный параметр остается в
  состоянии «Не установлено», платформа генерирует исключение.

Следовательно, хосту недостаточно один раз вызвать модуль сеанса вручную. Для
совместимости нужны автоматический вызов при создании сеанса, перехват первого
чтения неустановленного свойства и повторная инициализация после `Очистить()`.
Права на чтение, установку и очистку параметров также являются частью модели:
синтакс-помощник отдельно указывает проверку права установки при `Очистить()`
[SP-03].

### Измерение ленивой инициализации

Поведение измерено 2026-09-21 на платформе `8.3.27.2342` в двух
независимых чистых файловых базах. Оба прогона дали побайтно
одинаковый вывод. В конфигурацию были добавлены строковые параметры
`ПробаА`, `ПробаБ`, `ПробаУправление` и `ПробаТрасса`. Прогон выполнен
штатным `tests/conformance/measure/1c/run-on-1c.sh` в изолированной
копии конфигурации.

Измерение показало:

1. При старте сеанса обработчик получает `Неопределено`; записанные им
   значения видны стартовому коду формы.
2. После `Очистить()` первое чтение `ПробаА` синхронно вызывает
   `УстановкаПараметровСеанса` с массивом, содержащим `ПробаА`.
3. Во время установки `ПробаА` можно прочитать другой неустановленный
   параметр `ПробаБ`. Платформа синхронно и вложенно вызывает тот же
   обработчик с массивом `[ПробаБ]`, после чего продолжает внешний вызов.
4. Чтение параметра, который уже находится в стеке инициализации, не
   вызывает обработчик повторно. И прямое самочтение `ПробаА → ПробаА`, и цикл
   `ПробаА → ПробаБ → ПробаА` дают исключение `Error getting value of context
   attribute (ПробаА)` в точке повторного чтения.
5. Если обработчик вернулся, не установив запрошенную `ПробаА`, исходное
   чтение дает то же исключение.
6. После неудачной инициализации запрошенный, но не установленный параметр
   снова становится `Unset`: следующее чтение повторно вызывает обработчик.
7. Записи не откатываются при исключении. Если обработчик успел записать
   `ПробаА`, а затем вызвал исключение, после перехвата ошибки значение доступно.
8. Успешная вложенная инициализация `ПробаБ` также сохраняется, если внешний
   обработчик `ПробаА` после этого вызывает исключение.

Трасса вложенного цикла равна `required:ПробаА|required:ПробаБ`: нового
входа для второго чтения `ПробаА` нет. Это поведение требует от `Session`
стека активных инициализаций: новое имя может вложенно запустить обработчик,
а имя, уже находящееся в стеке, должно немедленно завершить чтение ошибкой.

### Безопасный и привилегированный режимы

`УстановитьБезопасныйРежим()` принимает `Булево` или строковое имя профиля
[SP-16]. Безопасный режим запрещает внешние действия, включая файловую систему,
Интернет, запуск приложений, COM и внешние компоненты, а привилегированный
режим внутри него игнорируется. `БезопасныйРежим()` возвращает `Ложь`,
`Истина` либо имя профиля [SP-17].

`УстановитьПривилегированныйРежим()` принимает `Булево`, а
`ПривилегированныйРежим()` возвращает `Булево` [SP-18], [SP-19]. В этом режиме
платформа не выполняет проверки прав.

Оба режима имеют область процедуры или функции. Включения учитываются
счетчиком; явных выключений должно быть не больше включений, а оставшееся
состояние автоматически снимается при возврате из вызова [SP-16], [SP-18]. Это
требует стека режимов, привязанного к кадрам VM. Один булев флаг в `State` не
воспроизводит контракт платформы и может оставить повышенные права после
исключения.

### Хранилища настроек

Синтакс-помощник уточняет сигнатуры условной клиентской поверхности:

- `Загрузить(КлючОбъекта, КлючНастроек = "", ОписаниеНастроек,
  ИмяПользователя)` возвращает произвольное значение либо `Неопределено`
  [SP-20];
- `Сохранить(КлючОбъекта, КлючНастроек = "", Настройки,
  ОписаниеНастроек, ИмяПользователя)` требует право
  `СохранениеДанныхПользователя` [SP-21];
- обращение к настройкам другого пользователя требует право
  `АдминистрированиеДанных` [SP-20], [SP-21].

Оба метода доступны на сервере, в толстом клиенте и во внешнем соединении.
Таким образом, их нельзя считать чисто интерфейсным локальным хранилищем:
серверная реализация должна сохранять разделение данных по пользователям и
проверять права.

## Обязательная поверхность полного старта

### Глобальные объекты и функции

| Объект или функция | Нужные члены | Причина |
|---|---|---|
| `ПараметрыСеанса` | чтение и запись именованных свойств | хранение состояния строго одного сеанса |
| `Метаданные` | свойства и коллекции из следующего раздела | проверки БСП перед запуском |
| `Справочники` | менеджеры `ВерсииРасширений`, а для выборочного профиля также `ИдентификаторыОбъектовМетаданных`; вызов их экспортных методов | БСП вызывает код менеджеров напрямую |
| `ПользователиИнформационнойБазы` | `ТекущийПользователь()` | проверка первого запуска; у результата нужно свойство `Имя` |
| `РасширенияКонфигурации` | `Получить()`, `Получить(, Источник)` и `ПолучитьИнформациюОПроблемахПримененияВСеансе()` | построение параметров об установленных и подключенных расширениях |
| `ТекущийРежимЗапуска()` | возвращаемое значение либо `Неопределено` | выбор серверного/клиентского пути запуска |
| `Новый СистемнаяИнформация` | свойство `ВерсияПриложения` | проверка минимальной версии платформы |
| `Base64Строка()` | двоичные данные в строку | контрольная сумма расширения; это имя отличается от имеющегося в open-bsl `ПолучитьBase64СтрокуИзДвоичныхДанных` |
| `Символы` | свойство `ПС` | сборка контрольных сумм и диагностик БСП |

Потребуются уже существующие в базовом runtime функции `НСтр`,
`ПустаяСтрока`, `ЗначениеЗаполнено`, `ТипЗнч`, `Тип`, `Строка`,
`СтрРазделить`, `СтрНачинаетсяС`, `СокрЛ` и условный оператор `?()`.

### Контекст сеанса и режимы безопасности

Первый вызов БСП проверяет, не выполняется ли он внутри фонового задания. Для
этого нужны:

- `ПолучитьТекущийСеансИнформационнойБазы()`;
- метод `ПолучитьФоновоеЗадание()` результата;
- свойство `ИмяМетода` фонового задания;
- `Метаданные.РегламентныеЗадания` с обходом коллекции и свойством
  `ИмяМетода` элемента.

Далее БСП проверяет возможность исполнения обработчиков. Для серверных баз
это не факультативная ветка: нужны
`СтрокаСоединенияИнформационнойБазы()`,
`ОбщегоНазначения.ИнформационнаяБазаФайловая()`,
`УстановитьБезопасныйРежим()`, `БезопасныйРежим()`,
`УстановитьПривилегированныйРежим()`, `ПривилегированныйРежим()` и
`Вычислить()`. При наличии подсистемы профилей безопасности дополнительно
вызывается динамически полученный модуль
`РаботаВБезопасномРежиме.ПрофильБезопасностиИнформационнойБазы()`. Для
диагностики исключения используется
`ОбработкаОшибок.КраткоеПредставлениеОшибки(ИнформацияОбОшибке())`.

`СтрокаСоединенияИнформационнойБазы()` возвращает строку регистрации базы из
клиентского приложения, а в фоновом или регламентном задании — строку
регистрации базы на сервере [SP-25]. Следовательно, значение зависит от вида
сеанса и не должно быть одной глобальной строкой движка.

Хосту не требуется воспроизводить кластер 1С как отдельную подсистему, но он
должен дать этим операциям согласованную семантику своего контекста запуска.
Безопасное безусловное возвращение фиктивных значений здесь способно скрыть
реальный запрет выполнения обработчиков.

### `Метаданные`

Заглушки с одними `ОбщиеМодули` и `Найти` для запуска недостаточно. На
безусловном пути БСП читает:

- `Метаданные.Имя` и `Метаданные.Версия`;
- `Метаданные.ВариантВстроенногоЯзыка`;
- `Метаданные.СвойстваОбъектов.ВариантВстроенногоЯзыка["Русский"]`;
- `Метаданные.ОсновныеРоли.Содержит(Роль)`;
- `Метаданные.Роли.АдминистраторСистемы` и
  `Метаданные.Роли.ПолныеПрава`;
- свойство `Имя` у объекта роли.

Синтакс-помощник подтверждает, что `ВариантВстроенногоЯзыка` имеет тип
одноименного системного перечисления, а русские и английские конструкции
остаются допустимыми при любом выбранном варианте [SP-22]. `ОсновныеРоли` —
коллекция ролей, определяющая права при пустом списке пользователей ИБ
[SP-23].

Дальнейшие обработчики БСП также обращаются к коллекциям `Справочники`,
`Константы`, `ФункциональныеОпции` и `ЭлементыСтиля`, к свойствам элементов
этих коллекций и к сравнению объектов метаданных. Они относятся к условным
веткам после `ПередЗапускомПрограммы`, поэтому их нельзя считать обязательными
для первого вертикального среза с `ТекущийРежимЗапуска() = Неопределено`.

### Расширения конфигурации

Элемент коллекции `РасширенияКонфигурации.Получить()` должен предоставлять:

- `Имя`;
- `Версия`;
- `ХешСумма`;
- `БезопасныйРежим`;
- `ИспользуетсяВРаспределеннойИнформационнойБазе`;
- `Активно`;
- `ОбластьДействия`.

Элемент результата `ПолучитьИнформациюОПроблемахПримененияВСеансе()` должен
иметь свойство `Расширение`. Нужны системные перечисления:

- `ИсточникРасширенийКонфигурации.СеансАктивные`;
- `ИсточникРасширенийКонфигурации.СеансОтключенные`;
- `ОбластьДействияРасширенияКонфигурации.РазделениеДанных`.

Это не пустая совместимость «на будущее»: в обследованных снимках у `demo`
зарегистрировано одно расширение, у `buh` — два, у `unf` — ни одного.

### Параметры сеанса, которые устанавливает ядро БСП

На полном старте:

- `ПараметрыКлиентаНаСервере` — `ФиксированноеСоответствие`;
- `УстановленныеРасширения`;
- `ПодключенныеРасширения`.

На выборочном вызове дополнительно могут устанавливаться:

- `КлючДанныхПовторногоИспользования` — новый `УникальныйИдентификатор`;
- `БуферОбмена` — `ФиксированнаяСтруктура`;
- `ОбновлениеСправочниковИдентификаторов` — `ФиксированнаяСтруктура`;
- `ВерсияРасширений`.

Сам контейнер параметров должен быть экземпляром, принадлежащим конкретному
`State`: два сеанса не разделяют значения, а повторный вызов внутри одного
сеанса видит ранее записанные свойства.

### Коллекции и значения

Код стартового пути использует следующие конструкторы и члены:

- `Массив`: `Добавить`, `Найти`, `Количество`, `ВГраница`, индексирование и
  обход `Для каждого`;
- `Соответствие`: `Вставить`, `Получить`, `Количество` и обход; элемент обхода
  имеет `Ключ` и `Значение`;
- `ФиксированноеСоответствие(Соответствие)`;
- `Структура`: `Вставить`, `Свойство` и свойства по именам;
- `ФиксированнаяСтруктура(Структура)`;
- `СписокЗначений`: `Добавить`, `Количество`, `НайтиПоЗначению` и обход;
  элемент списка имеет `Значение`;
- `УникальныйИдентификатор` без аргументов.

Большая часть этой поверхности уже есть в базовом runtime open-bsl. Для ORM
важно не создать вторую реализацию тех же типов.

## Вызовы модулей конфигурации

Исполнение требует не только объектов данных, но и загрузчика модулей
конфигурации. Минимальный контракт: получить общий модуль или менеджер объекта
по имени, сохранить его модульные переменные в пределах сеанса и вызвать
экспортную процедуру/функцию без учета регистра с передачей параметров по
ссылке.

Общий для трех баз прямой граф содержит:

- `СтандартныеПодсистемыСервер.УстановкаПараметровСеанса`;
- `ДлительныеОперации.ПропуститьОбработчикПередЗапускомПрограммы`;
- `ОбщегоНазначенияКлиентСервер.ВерсияКонфигурацииБезНомераСборки`;
- `ОбщегоНазначенияКлиентСервер.СравнитьВерсии`;
- `ОбщегоНазначения.ВерсияРежимаСовместимости`;
- `ОбщегоНазначения.РазделениеВключено`;
- `ОбщегоНазначения.ДоступноИспользованиеРазделенныхДанных`;
- `ОбщегоНазначения.ПодсистемаСуществует` и
  `ОбщегоНазначения.ОбщийМодуль`;
- `ОбновлениеИнформационнойБазыСлужебный.ВерсияИБ`;
- `ПользователиСлужебный.УстановитьНачальныеНастройки`;
- `ИнтеграцияПодсистемБСП.ПередЗапускомПрограммы`;
- `ОбщегоНазначенияПереопределяемый.ПередЗапускомПрограммы`;
- `Справочники.ВерсииРасширений.УстановкаПараметровСеанса`.

Внутри `ИнтеграцияПодсистемБСП.ПередЗапускомПрограммы` есть еще один
условный слой. По данным повторно используемого модуля и наличию подсистем он
может вызвать `ПередЗапускомПрограммы()` у модулей
`ПользователиСлужебныйВМоделиСервиса`, `ИнтеграцияПодсистемБТС`,
`ИнтеграцияПодсистемБИП` и `ИнтеграцияПодсистемПлюс`. Эти вызовы требуют того
же общего механизма загрузки модулей; конкретный набор определяется составом
каждой конфигурации.

Собственное переопределение `ПередЗапускомПрограммы` различается:

- в `demo` процедура пуста;
- в `buh` вызываются `ЭлектронноеВзаимодействие.ПередЗапускомПрограммы()` и
  `Маг1ССервер.ПередЗапускомПрограммы()`; первое при наличии подсистемы
  динамически вызывает
  `ОбменСКонтрагентамиИнтеграцияСобытия.ПередЗапускомПрограммы()`;
- в `unf` вызываются
  `НачалоРаботыСПрограммойСервер.ПередЗапускомПрограммы()`,
  `Маг1ССервер.ПередЗапускомПрограммы()` и
  `ТелефонияСервер.ПередЗапускомПрограммы()`. Все три сразу выходят при
  `ТекущийРежимЗапуска() = Неопределено`; в клиентском режиме они добавляют
  интерфейс начальной работы, функциональные опции, константы и запуск фоновой
  проверки телефонии.

`ОбщегоНазначения.ОбщийМодуль(Имя)` возвращает объект, на котором код вызывает
экспортный метод с динамически известным именем. В выборочном профиле дополнительно
нужны `ОбщегоНазначения.ВыполнитьМетодКонфигурации` и регистрация обработчиков
через:

- `ИнтеграцияПодсистемБСП.ПриДобавленииОбработчиковУстановкиПараметровСеанса`;
- `ОбщегоНазначенияПереопределяемый.ПриДобавленииОбработчиковУстановкиПараметровСеанса`;
- `ИнтеграцияПодсистемБСП.ПриУстановкеПараметровСеанса`;
- `Справочники.ИдентификаторыОбъектовМетаданных.УстановкаПараметровСеанса`.

Статический поиск зарегистрированных ключей дал 44 обработчика у `demo`, 68 у
`buh` и 75 у `unf`. Это верхняя граница доступного реестра, а не число вызовов
за один старт: исполняются только обработчики запрошенных имен.

## Дополнительная поверхность `demo`

Модуль сеанса `buh` и `unf` только делегирует в БСП. `demo` после этого всегда
вызывает собственные модули:

- `ТехнологияСервиса.ВыполнитьДействияПриУстановкеПараметровСеанса`;
- `СотрудникиСобытия.УстановкаПараметровСеанса`;
- `ФизическиеЛицаСобытия.УстановкаПараметровСеанса`;
- `ОбработкаЗапросовXDTO.УстановкаПараметровСеанса`;
- `ШаблоныДокументов.ПриУстановкеПараметровСеанса`;
- `РабочиеСтолыСервер.ПриУстановкеПараметровСеанса`.

Непосредственно в модуле сеанса используются:

- `ОбщегоНазначения.РазделениеВыключено()`;
- `Константы.ДокументооборотИспользоватьОграничениеПравДоступа.Получить()`;
- `Константы.ДокументооборотВключитьПраваДоступа.Получить()`;
- `Константы.ОграничиватьДоступЧерезВебСерверы.Получить()`;
- `Справочники.Пользователи.ПустаяСсылка()`;
- `Пользователи.ТекущийПользователь()` и свойство
  `РазрешенныеВебСерверы` результата;
- `ПользователиИнформационнойБазы.ТекущийПользователь()` и свойство
  `ПарольУстановлен` результата;
- `НомерСоединенияИнформационнойБазы()`;
- `ПолучитьСоединенияИнформационнойБазы()`;
- свойства соединения `НомерСоединения`, `ИмяПриложения`, `ИмяКомпьютера`;
- `ЗаписьЖурналаРегистрации(...)` и
  `УровеньЖурналаРегистрации.Ошибка`;
- строковые функции `Найти` и `НРег`.

`ПарольУстановлен` — доступное только для чтения булево свойство на сервере, в
толстом клиенте и во внешнем соединении [SP-24]. Получение списка соединений
требует права `АктивныеПользователи`; при его отсутствии платформа вызывает
исключение [SP-12]. Поэтому API соединений хоста должен получать контекст прав,
а не возвращать общий список без проверки.

Последовательность проверки веб-доступа условна: она выполняется только в
разделенном режиме, при включенной константе ограничения и полном старте.
Однако подмена результата константы ради обхода ветки изменила бы семантику
конфигурации; честный хост должен реализовать перечисленную поверхность.

Сам модуль сеанса `demo` записывает параметры:

- `ДокументооборотИспользоватьОграниченияПравДоступа`;
- `ОлицетворяемыйПользователь`;
- `ЗагрузкаОбработанныхДанныхИзДругойСистемы`;
- `МиграцияДанныхРазрешеноПрерываниеПроцессов`;
- `ПроисходитАвтозаполнениеФайлаПоВладельцу`;
- `ОтключитьОбновлениеЗадач`;
- `ЭтоНагрузочноеТестирование`.

Транзитивные прикладные обработчики добавляют как минимум
`ВерсияБИД`, `УзелИнтегрированнойСистемы`, `ОсновнойСотрудник`,
`СотрудникиПользователя`, `РолиТекущегоПользователя` и
`ФизическоеЛицоПользователя`; их вычисление уже требует предметных каталогов,
регистров и запросов.

## Условная клиентская поверхность

В `ПередЗапускомПрограммы` есть две ветки, которые возвращаются сразу, если
`ТекущийРежимЗапуска() = Неопределено`. Для выделенного серверного сеанса
gateway разумно и правдиво возвращать `Неопределено`, если именно таков
контекст запуска. Имитировать клиентский режим только ради прохождения кода не
следует.

Для настоящего клиентского режима потребуются дополнительно:

- `ХранилищеОбщихНастроек.Загрузить/Сохранить`;
- `ХранилищеСистемныхНастроек.Загрузить/Сохранить/Выбрать`;
- `НастройкиНачальнойСтраницы.ПолучитьСоставФорм/УстановитьСоставФорм`;
- конструктор `СоставФормНачальнойСтраницы`;
- `ХранилищеЗначения.Получить()` и конструктор с параметрами сжатия;
- `СжатиеДанных`;
- коллекции и свойства состава форм начальной страницы.

Эта поверхность не нужна первому серверному вертикальному срезу, но нужна для
обещания совместимости с клиентским стартом.

## Что это меняет в плане конфигурационного runtime

Первый исполнимый вертикальный срез должен включать больше, чем доступ к
таблицам данных:

1. реестр и загрузку исходников общих модулей, модуля сеанса и менеджеров
   объектов конфигурации;
2. один экземпляр `ПараметрыСеанса` и состояние модулей на один `State`, а
   также состояние «Не установлено» и автоматический вызов обработчика перед
   первым чтением;
3. богатую модель `Метаданные` с версией, языком и ролями;
4. менеджеры каталогов с вызовом экспортных методов, а не только CRUD;
5. API расширений конфигурации;
6. пользователя ИБ, версию платформы, режим запуска и сведения о режиме
   совместимости;
7. динамический вызов общего модуля по строковому имени;
8. для `demo` — константы, текущего прикладного пользователя, соединения ИБ и
   журнал регистрации;
9. стек безопасного и привилегированного режимов с автоматическим снятием на
   границе вызова;
10. права `АктивныеПользователи`, `СохранениеДанныхПользователя`,
    `АдминистрированиеДанных` и права чтения/установки параметров сеанса в
    контексте пользователя.

`Запрос`, каталоги, регистры и константы становятся обязательными на следующем
слое, когда выполняются зарегистрированные обработчики конкретных параметров.
Поэтому полезно принять два критерия готовности: сначала полный старт с
`Неопределено`, затем выборочная установка заданного набора параметров. Попытка
сразу объявить поддержкой весь реестр скрыла бы динамические зависимости и не
дала бы воспроизводимого теста.

## Ограничения результата

- Карта API статическая: значения констант, наличие подсистем и реальные ветки
  в каждом сеансе не исполнялись. Это ограничение не относится к отдельному
  измерению ленивой инициализации.
- Вызовы через строки и возвращаемые объекты общих модулей перечислены в точке
  диспетчеризации; полный граф раскрывается только для выбранного набора имен.
- Список описывает API, встреченный в обследованных версиях трех баз. После
  обновления конфигурации его следует получать повторно.
- Семантика, не покрытая приведенными страницами синтакс-помощника, здесь не
  устанавливается. Каждое такое решение о поведении реализации должно быть
  измерено на 1С либо оформлено по дисциплине `НЕ ИЗМЕРЕНО` при внесении кода.
