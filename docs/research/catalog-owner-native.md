# Владелец нового объекта справочника

1С 8.3.27.2342 выполнила две пробы в отдельных файловых базах: `measure-catalog-owner.bsl` (17 наблюдений) и `measure-catalog-owner-multiple.bsl` (20 наблюдений). XML справочников и тело модуля сохранены рядом с эталонами в `tests/conformance/measure/1c/`.

При одном владельце тело модуля уже читает пустую ссылку соответствующего справочника; запись в теле отклоняется до выбора нового объекта. После создания присваивание непустой ссылки сохраняется. Неподходящая строка приводится к пустой ссылке владельца. При двух владельцах начальное значение — `Неопределено`; неподходящая строка тоже даёт `Неопределено`. Ссылки каждого из двух владельцев принимаются. У справочника без владельцев свойство читается как `Неопределено`, но присваивание отклоняется. Дополнительные восемь проб в каждом варианте подтвердили приведение числа, булева значения, `Неопределено`, `Null`, массива, структуры, ссылки неподходящего справочника и объекта справочника к начальному значению.

Эти наблюдения подтверждают новое состояние объекта, а не чтение существующей записи или запись в информационную базу. Пробы создают только значения в памяти. В исходной buh список владельцев `РегистрацииВНалоговомОргане` уже приобретён SDK через `ConfigDescriptor::catalog_owners`: единственный владелец — `Организации`. Повторный декодер Config не нужен. Список сохранён в ORM; измеренное свойство реализовано в существующем объекте справочника. Тест проекции адаптера проверяет настоящий сжатый описатель из Config buh и независимо подтверждённый XML идентификатор владельца.

Все четыре новых теста объекта прошли, включая неизвестные владельцы и изоляцию. Полный workspace-прогон прошёл без изменения старых ожиданий: форматирование, Clippy, тесты (363,9 с), rustdoc, потребитель фасада, деревья зависимостей runtime/VM и strict OpenSpec. Лог — `/tmp/open-bsl-catalog-owner-096-gates.log`.

Повторный исходный запуск buh завершился через 210,9 с с кодом 1: следующий модуль `Справочник.СтраныМира.МодульОбъекта` не разрешает `ПроверитьЗаполнение`. Прежняя ошибка `Владелец` больше не возникает. Маркер пользовательского скрипта не достигнут; успешная инициализация исходного сеанса этим результатом не доказана. Лог — `/tmp/open-bsl-buh-096-owner.log`.
