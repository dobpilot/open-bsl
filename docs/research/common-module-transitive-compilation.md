# Компиляция дочернего общего модуля

Замер 2026-10-02: 1С 8.3.27.2342, русская локаль, отдельная файловая база
`/tmp/open-bsl-transitive-unused-096-ib`. Рабочие информационные базы не менялись.

Родительский общий модуль содержит исправный экспорт с результатом `42` и
соседний экспорт, вызывающий дочерний модуль. В дочернем есть исправный
экспорт с результатом `24` и соседний экспорт с неизвестной переменной.

Проба `measure-module-transitive-unused.bsl` вызвала только исправный экспорт
родителя. Платформа завершилась штатно; сохранённый вывод содержит три строки,
в том числе `module.transitive.good` со значением `42`. Ошибка дочернего модуля
этому вызову не мешает.

Проба `measure-module-transitive-called.bsl` затем вызвала дочерний экспорт
через родителя внутри `Попытка/Исключение`. Платформа не завершилась за 90 с;
раннер остановил принадлежащий ему процесс. Журнал той же базы записал:

```text
{CommonModule.ЗамерыТранзитивногоДочернего.Module(6,10)}: Переменная не определена (СовсемНеизвестноеИмя)
```

Это отказ компиляции, не успешный результат замера. Не создавать для второй
пробы пустой эталон и не выдавать тайм-аут за значение выражения. Данные не
определяют повторную попытку компиляции после отказа.

Диагностика из журнала сохранена отдельно в
[`measure-module-transitive-called.compiler.platform.txt`](../../tests/conformance/measure/1c/measure-module-transitive-called.compiler.platform.txt).
Успешный вывод первой пробы находится в
[`measure-module-transitive-unused.platform.txt`](../../tests/conformance/measure/1c/measure-module-transitive-unused.platform.txt).

Для повторения используйте штатный `run-on-1c.sh` с соответствующим скриптом
и отдельной `ONEC_IB`. Намеренно ошибочные модули подмешиваются только этим
двум пробам и не входят в общий каталог серверных замеров.

Для buh это объясняет, почему семантическая ошибка в консервативном замыкании
может не мешать ещё не обращавшемуся к модулю коду. Достижимость ошибочного
модуля при реальной инициализации buh этим минимальным примером не доказана.
Текущий механизм отложенного голого имени модуля использует ловимый `Raise`;
применять его без изменений к ошибке компиляции нельзя.

Добавлен независимый runtime-вариант `RtError::ModuleCompilation(String)`.
Интеграционная проба через компонент и инициализатор общего модуля проверяет,
что существующая VM пропускает внутренний и внешний обработчики исключения,
сохраняет тип ошибки для хоста и позволяет другому `State` работать независимо.
Это ещё не отложенная компиляция исходника: резолвер и формат образа остаются
прежними, версия формата — `41`.

После этого изменения прошли форматирование, Clippy, все workspace-тесты,
rustdoc с запретом предупреждений, сборка `open-bsl-consumer` и проверка
нормальных зависимостей ядра/VM. Полный журнал:
`/tmp/open-bsl-module-compilation-error-workspace.log`. Строгая проверка
OpenSpec для предлагаемого продолжения также проходит.

## Тело вызывающего метода и аргумент

Дополнительная проба `measure-module-transitive-arguments.bsl` выполнена в
новой базе `/tmp/open-bsl-transitive-args-096-ib`. Родитель перед обращением
к дочернему записывает и закрывает файл-маркер; отдельная функция вычисления
аргумента делает то же со вторым файлом. Оба файла отсутствовали до прогона.

После модального отказа компиляции и остановки платформы по 90-секундному
ограничению оба файла содержали `executed`. Журнал указывает на неизвестную
переменную в дочернем модуле на строке 6. Нативные значения маркеров и эта
диагностика сохранены в
[`measure-module-transitive-arguments.compiler.platform.txt`](../../tests/conformance/measure/1c/measure-module-transitive-arguments.compiler.platform.txt).

Следовательно, в этом статическом вызове родительский метод начинает
исполняться и вычисляет аргумент до отказа компиляции дочернего модуля.
Раннер не завершился успешно, и эталон полного вывода скрипта не создавался.
При повторении пробы старые маркеры нужно сначала проверить и удалить;
раннер отказывается запускаться, если они уже существуют.

Отдельный тест фасада
`caller_and_argument_run_before_fatal_child_initialization` закрепляет тот же
порядок через существующую инициализацию модулей и компонент, возвращающий
`RtError::ModuleCompilation`: записаны только `caller` и `argument`, тело
дочернего метода и обработчик исключения не выполняются. Это проверка
механизма VM, а не реализация отложенной диагностики неизвестных имён.

После добавления теста полный прогон 2 октября 2026 года прошёл:
форматирование, Clippy, workspace-тесты (включая сравнение оптимизаций),
rustdoc с запретом предупреждений, сборка потребителя фасада и деревья
нормальных зависимостей. Журнал:
`/tmp/open-bsl-module-argument-order-workspace-unrestricted.log`.
Первый запуск в песочнице остановился на запрете локального HTTP-сокета;
повторный запуск с разрешением локальных сокетов завершился успешно.
