# Повторный оригинальный запуск UNF после внедрения состояния сеанса

Read-only запуск с точной зарегистрированной строкой соединения, SDK 3ff9202 и текущими изменениями root получил 7881 модуль, завершился отказом за 444.88 с. Время подготовки factory 380.64 с; наблюдаемый пиковый RSS процесса 7391428 КиБ. Квитанция: `target/diagnostics/readonly-startup/unf-dynamic-host-1013-startup.log`, память: `unf-dynamic-host-1013-memory.tsv` в том же каталоге.

Прежняя ошибка отсутствия host-признака динамического обновления пройдена. Новая ошибка: SDK проверка Read поля ХранилищеПараметра (10336352-f3a1-4bc3-bdec-1a2eef15f176) регистра ПараметрыРаботыВерсийРасширений (bf070420-9eb7-4372-96a6-b0d00ac3ce8c) для пользователя Администратор.

Не считать отказ доказательством недостаточных нативных прав. Проверить исходный вызывающий модуль, наличие привилегированного режима и соответствие приобретённых прав. Адаптер сейчас получает ctx, но ветка CurrentUser вызывает user_decisions без проверки ctx.privileged_mode; это кандидат на причину, пока не доказанный контекстом оригинального вызова. Проверки прав не обходились.

Read-only извлечение оригинального исходника подтвердило контекст: РегистрСведений.ПараметрыРаботыВерсийРасширений.МодульМенеджера, строка 32 включает привилегированный режим, строка 33 исполняет этот запрос, строка 34 выключает режим. Квитанция `target/diagnostics/readonly-startup/unf-extension-storage-source-1013.log`. Отказ текущего адаптера нельзя исправлять выдачей дополнительных ролей пользователю: требуется учитывать действующий режим текущего кадра. Нативный контроль самой границы доступа и OpenSpec должны предшествовать реализации.

Адаптер изменён после strict validation `honor-effective-session-query-privilege` и нативного контроля `fixtures/query-effective-privilege`: обычный отказ no-Read, привилегированное чтение и возврат к отказу после выключения. Active SafeMode в собственном контроле был NO; suppression activeSafe подтверждён отдельным сохранённым замером режимов ядра. Новый публичный тест `query_effective_privilege` проверяет effective mode в callback Query.Execute, reset, безопасный режим и новый сеанс. Он не является интеграционным тестом настоящего DatabaseDataAccess/БД. Обычный Clippy config-db/session и целевой Clippy нового теста проходят. Повторный оригинальный UNF с адаптером сейчас выполняется; успех пока не заявлен.

Проверка закрытости фасада режимов: `cargo test -p open-bsl-consumer security_mode` действительно выполнила один тест `a_component_controls_the_current_frame_through_facade_names_only`, он прошёл. Остальные строки с нулём тестов в этой квитанции являются отфильтрованными целями, не отдельными прогонами.

Повторный read-only прогон с effective-frame policy завершился отказом за 436.4 с, peak RSS 7440576 КиБ. Ошибка FieldRead пройдена; запрос реально выполнен и вернул Binary длиной 410 байтов, после чего преобразование `ХранилищеПараметра` отказало как неподдерживаемое. Квитанция `target/diagnostics/readonly-startup/unf-effective-privilege-1013-startup.log`. Этот результат подтверждает достигнутый привилегированный путь адаптера, но не весь набор RLS/разделения данных. 19 существующих data_access::tests прошли без изменений.

Попытка короткого технического SELECT без исходного контекста остановилась ещё при компиляции: отсутствует константа условия разделения данных cc906f05-5ea6-43cb-a084-c4ee51ca4bd5 (`unf-storage-shape-1013.log`). SQL не выполнен, содержимое не прочитано; фиктивное значение условия не задано. Это подтверждает независимую проверку разделителей в компиляторе, но не полный тест всех сценариев разделения данных.

Технический runtime-прогон завершился за 439.35 с, peak RSS7456116КиБ: Binary410, header01 01, external_reference=false; существующий SDK decode_stored_value возвращает List(3), first_kind=String. Это подтверждение framing/decompression, не доказательство полного BSL преобразования содержимого. Квитанция unf-storage-runtime-1013-startup.log.

В изолированной копии адаптера подключён SDK-черновик `decode_stored_value_text` без изменения версии SDK/main. Release-сборка прошла (`storage-text-integration-build-1013.log`). Колонка допускается только при Binary, подтверждённом FieldId::Metadata, отсутствии composite_member и единственной декларации типа ХранилищеЗначения; проверка выполняется один раз для каждой колонки результата, а не для каждой строки. Преобразование использует существующий декодер open-bsl и снимок ORM. Отдельный оригинальный прогон `unf-storage-text-1013-startup.log` выполняется; исход этого прогона пока не известен. Portable proposal root-адаптера сохранён в `target/diagnostics/inline-storage-adapter-proposal-1013.patch`; он не применён в основную рабочую копию, поскольку SDK main пока не содержит этого API. Новые тесты ORM подтверждают отказ повреждённого/неподдерживаемого текста и detached snapshot (2 passed); новый тест декларации отклоняет неизвестный тип, неверный тег и иной GUID (1 passed). Целевой Clippy и fmt проходят.

Независимый собственный нативный PG-контроль SDK завершён с `own.rows=2`, `completed=YES`, но записал иной формат: `02 01` и 16-байтовый GUID перед содержимым. Он не подтверждает десятибайтовую оболочку достигнутого UNF `01 01`. Новая форма не добавлена в декодер по предполагаемому смещению. Точные собственные байты и provenance находятся в `/tmp/sdbl-stored-value-text-native-1013`; положительное независимое подтверждение старой оболочки остаётся открытой задачей.

Оригинальный прогон с текстовым декодером завершился отказом за 478.8 с (factory410.95с, peakRSS7441176КиБ). Достигнуто преобразование текста; существующий снимок отказал: «объект типа НепрозрачноеЗначение не переносится между сеансами». Квитанция `unf-storage-text-1013-startup.log`. Успешное чтение ХранилищеЗначения не подтверждено; следующий шаг — определить UUID сериализованного непрозрачного вида без вывода содержимого, затем измерить необходимое преобразование. Для следующего технического прогона подготовлена диагностическая печать только UUID видов объектов; новый прогон ещё не запущен.

SDK-черновик зафиксирован `05a24e5e5e420d9e55483cbf643eb736c1bf65c0` (base3ff9202, отдельная ветка draft/stored-value-text). По квитанциям агента: полный набор944passed/13ignored, fmt/Clippy/rustdoc/12strict прошли. Версия0.9.15 и main не менялись; positive native0101 остаётся неподтверждённым. Диагностический оригинальный повтор для UUID запущен как `unf-storage-type-1013-startup.log`, процесс ещё активен; предыдущий478.8с прогон terminal1 и не перезапускается повторно.

Проверка источника отказа: `value_graph::check_portable` допускает примитивы, UUID, Array/Structure/Map/ValueTable и зарегистрированные immutable Extension, но не VstrOpaque. Текст ResourceLimit относится к общей проверке переносимости, а не к реально обнаруженному смешению пользователей. Разрешение переноса самого opaque не материализует значение и не исправляет исполнение оригинального кода; проверка не изменена. UUID-диагностика использует существующее SDK-дерево и печатает только второй Atom узлов с тегом #, валидный GUID; полезная нагрузка и имена полей не выводятся.

Декодер runtime получил явный резолвер скалярных объектов через фасад. Без резолвера прошли 29 прежних тестов VSTR; три новых теста фасада тоже прошли. Общий декодер физического UUID из hex выделен из `extension_identity` без второго кодека. Изолированный адаптер сопоставляет уникальный `object_reference_type` только для справочника; неизвестные виды остаются неподдерживаемыми. Смысл числового префикса не определён этим замером: проверяется только наблюдённая скалярная грамматика. Адаптер ещё не перенесён в root до интеграции SDK API.
