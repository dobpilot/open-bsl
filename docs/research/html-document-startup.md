# Документ HTML в исходном demo

После подключения `Остатки` read-only compile-only demo останавливается
на `Новый ДокументHTML` в `Таймлист`. Исходник приобретён из базы без
исполнения. В строках 1388 и 1408 конструктор используется без аргументов;
затем создаются `body`, текстовый узел, дочерняя связь и выполняется
`ЗаписьDOM.Записать(ДокументHTML, ЗаписьHTML)` с выводом в строку.
Это не доказывает вызов этих функций при старте сеанса.

Открыты полные страницы установленной справки 8.3.27.2342:
`platform-syntax-help:syntax-context:objects/catalog63/catalog1781/HTMLDocument/ctors/ctor127.html`
и `platform-syntax-help:syntax-context:objects/catalog63/catalog1781/HTMLDocument/properties/DocumentElement7815.html`.
Первая описывает создание с заголовком; доступность второго свойства
включает сервер и тонкий клиент. По этой странице нельзя запрещать
нулевой конструктор, который использует оригинальный код.

Нативный [контроль](fixtures/html-document/constructor.bsl) исполнен
репозиторным раннером на собственной файловой базе
`/tmp/open-bsl-accumulation-balance-1006-ib`, код завершения 0.
[Четыре строки результата](fixtures/html-document/constructor.platform.txt)
подтверждают оба конструктора, запись `Тело`, создание текстового узла
и его добавление: тело имеет одного ребёнка. Представления типов в
основном языке контрольной базы — `HTML document` и `DOM text`.
Исходные базы не изменялись, новые записи данных не создавались.

В `bsl-xml` уже реализованы `ДокументDOM` и `ЗаписьDOM`.
До реализации необходимо проверить возможность повторного использования
дерева узлов и записи. Создавать второй DOM или XML-сериализатор не следует.
HTML-разбор и HTML-сериализация не считаются эквивалентными XML автоматически;
точный вывод исходного сценария ещё требуется измерить.

## Запись исходного сценария

Следующий [контроль](fixtures/html-document/write.bsl) воспроизвёл
последовательность `ЗаписьDOM` → `ЗаписьHTML.УстановитьСтроку()` →
`Записать` → `Закрыть` на реальной платформе. Код завершения 0,
сохранены [две строки](fixtures/html-document/write.platform.txt).
Длина — 111; строка начинается doctype HTML 4.0 Transitional и
содержит `<html><body>TimelistRecognizeResult</body></html>` без CR/LF.
Следовательно, обычное объявление XML и его форматирование использовать
для HTML без отдельного режима нельзя.

Перед реализацией создано изменение
`openspec/changes/add-html-document-dom-output`, прошедшее строгую
валидацию. Оно сохраняет общий DOM и прежний XML-контракт; начальная
структура документа, заголовок, замена тела и дополнительные правила
HTML-вывода ещё требуют нативных контролей.

## Структура, заголовок и пустые элементы

Исправленный [контроль структуры](fixtures/html-document/structure.bsl)
завершился с кодом 0; сохранены
[девять строк](fixtures/html-document/structure.platform.txt).
Первый вариант скрипта содержал неверный вызов писателя и завершился
по таймауту; его запуск измерением не считается.

Нулевой конструктор создаёт корень `html` без детей, а `Тело` равно
`Неопределено`. Назначение собственного `body` сохраняет его тождество.
Повторное назначение заменяет тело и отсоединяет старое: его родитель
становится неопределённым. Имя узла тела — `body`; представление типа
в этом контроле — `HTML body element`.

Конструктор с заголовком создаёт `head/title` перед телом. В заголовке
и текстовом узле символы `<`, `&`, `>` экранируются, двойная кавычка
текстового узла остаётся буквальной. Пустой `br` пишется `<br>`,
пустой `div` — `<div></div>`. Результат сохраняет doctype и не имеет
переводов строк. Нативное поведение прочих пустых элементов и атрибутов
пока не измерено; оно не выводится из XML-режима.

[Контроль типов](fixtures/html-document/node-types.bsl) завершился с кодом 0;
[семь строк результата](fixtures/html-document/node-types.platform.txt)

не имеет детей, а запись содержит только doctype и `<html></html>`.
Пустая строка не создаёт `head/title`.

Четыре focused-теста конструкции и владения узлами прошли после
исправления проверки пустоты `BslString` через `len_utf16()`.
Строковая HTML-запись добавлена; ещё два профильных теста сравнивают
её с сохранёнными нативными результатами. Все шесть тестов прошли.
[Контроль типа писателя](fixtures/html-document/writer-type.bsl)
завершился с кодом 0; [результат](fixtures/html-document/writer-type.platform.txt)

Проверка через CLI обнаружила конфликт с ранее зарегистрированной
в `bsl-rt` заглушкой `ЗаписьHTML`: движок отвергает двойную регистрацию.
Подготовлена миграция этой регистрации в `bsl-xml`, но она ожидает
согласования вместе с существующими тестами. Тест плотности кодов
ожидает диапазон 1–18 вместо новых 1–20; другой тест закрепляет
отказ конструктора-заглушки. Их ожидания не изменены.
Это не зелёный прогон всего `bsl-xml` или CLI.

## Жизненный цикл строкового писателя

[Контроль](fixtures/html-document/writer-lifecycle.bsl) завершился с
кодом 0; сохранены [восемь строк](fixtures/html-document/writer-lifecycle.platform.txt).
Закрытие до открытия и повторное закрытие возвращают `Неопределено`.
Закрытие открытого пустого получателя возвращает пустую строку.
Повторная запись документа в один получатель даёт ошибку, сохраняя
первый результат. Повторное `УстановитьСтроку()` допустимо и очищает
накопленный вывод. Отказ закрытия без получателя в прототипе заменён
на измеренный результат; OpenSpec дополнен сценариями перед исправлением.

## Дочерние узлы документа и определение типа

[Контроль связей](fixtures/html-document/node-links.bsl) завершился с
кодом 0 и дал [семь строк](fixtures/html-document/node-links.platform.txt).
Он обнаружил отличие от первой реализации: документ имеет двух детей,
хотя сам корень `html` по-прежнему пуст. Отдельный
[контроль детей](fixtures/html-document/document-children.bsl) дал
[восемь строк](fixtures/html-document/document-children.platform.txt):
сначала `ОпределениеТипаДокументаDOM` с именем `html`, затем корень `html`.
У обоих родитель — документ. У текста родитель — тело, владелец — документ.

Перед исправлением добавлен и строго провалидирован сценарий OpenSpec.
В общий DOM введён вид определения типа; XML-разбор его не создаёт.
HTML-конструктор создаёт этот узел до корня, сериализация записывает
doctype из него. Получение тела ищет элемент документа вместо первого
ребёнка. Имя `DOMDocumentType` подтверждено страницей установленной
справки `DOMDocumentType/properties/PublicId5299.html`; XPath и произвольная
мутация нового вида пока отклоняются явно.

После исправления прошли 190 unit-тестов `bsl-xml`, включая прежний XML,
XPath, XSD и XDTO, с явным исключением конфликтующего теста диапазона
конструкторов. Этот исключённый тест не изменён; прогон не заменяет
полный обязательный набор.

## Числовая квитанция и временная регистрация

Проверка через CLI дошла до сравнения и выявила различие локали
булевых представлений (`Да`/`Yes`). Исходные квитанции не правились.
Снят отдельный [числовой контроль](fixtures/html-document/tree-contract.bsl):
[22 строки](fixtures/html-document/tree-contract.platform.txt) получены
на 1С с кодом 0 и точно воспроизведены CLI. Для логических результатов
используются 1/0, а виды узлов проверяются сравнением с существующим
перечислением. Это не нормализация вывода интерпретатора под эталон.

До согласования миграции конструктора удалена только новая дублирующая
регистрация `ЗаписьHTML`; реализация и девять профильных тестов сохранены.
Прежний тест отказа заглушки через фасад снова проходит без правки.
Полная HTML-запись через фасад остаётся неподключённой. Обновлённый патч
миграции находится в `/tmp/open-bsl-html-registration-proposed.patch`.
