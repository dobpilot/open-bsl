# demo: ФизическиеЛица как собственный получатель

На 2026-10-02 прочитан один ресурс Config demo
`79f32f3d-a78d-45da-b795-4839105f1fa2.0` (6792 распакованных байта).
В модуле объекта ДескрипторыДоступаОбъектов имеется вызов
`ФизическиеЛица.Сортировать("ГруппаДоступа Возр", Сравнение)`
на строке 32 сырого ресурса. Описатель того же объекта в сохранённой
фикстуре Config содержит собственное имя ФизическиеЛица.

`Resolver::import_alias` исключает локальные и модульные переменные,
но не проверяет `receiver_property`. Поэтому необходимо проверить
коллизию свойства собственного получателя и псевдонима общего модуля.
Это подтверждённый пробел проверки, но приоритет платформы ещё не измерен.
Не следует изменять порядок разрешения общих глобальных имён или
подменять неизвестную функцию методом без проверки собственного имени.

Следующий замер: в изолированной конфигурации создать собственную
табличную часть с именем общего модуля и сравнить голый вызов её метода
с явно квалифицированным `ЭтотОбъект`, отдельно с локальным и модульным
затенением. Затем добавить воспроизводящий тест резолвера по результату.
Рабочая demo не изменялась; выполнен только SELECT одного ресурса.

## Нативный результат

Проба `measure-receiver-alias-collision.bsl` на 1С 8.3.27.2342
в отдельной файловой базе завершилась успешно. Общий модуль
`ДополнительныеСвойства` экспортирует `Количество`, возвращающий 999.
Модуль объекта справочника проверяет стандартное свойство с тем же именем.
Голый вызов и явный `ЭтотОбъект` дают 0, параметр-структура с одним
элементом даёт 1. Эталон сохранён в одноимённом `.platform.txt`.
Это измерение подтверждает приоритет свойства получателя над псевдонимом
общего модуля, сохраняя приоритет параметра. Общая лестница библиотечных
глобальных имён этим измерением не меняется.
