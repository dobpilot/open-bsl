# Проверка заполнения справочника: нативные наблюдения

Измерение выполнено на 1С 8.3.27.2342 в изолированной файловой базе.
Объект создавался только в памяти, запись в рабочие базы не выполнялась.
Исходники и семь строк результата находятся в
`tests/conformance/measure/1c/measure-catalog-check-filling.bsl`
и соответствующем `.platform.txt`; тело объекта — в
`catalog-check-filling-module.bsl`.

| Состояние объекта | Результат |
| --- | --- |
| Вызов из тела модуля при создании | Ошибка |
| Код и наименование пустые | Ложь |
| Заполнен только код | Ложь |
| Заполнено только наименование | Истина |
| Заполнены код и наименование | Истина |
| Английский метод, оба поля заполнены | Истина |
| Передан один аргумент | Ошибка |

Таким образом, проверка непустого кода не является обязательной в этой
конкретной конфигурации. Эти результаты нельзя распространять на другие
справочники без приобретённых настроек проверки заполнения.

Сигнатура сверена с полным Синтакс-помощником установки 8.3.27.2342:
`platform-syntax-help:syntax-context:objects/catalog125/catalog126/object130/methods/CheckFilling3495.html`.
Метод не принимает аргументов и возвращает Булево; описание связывает
проверку с настройками реквизитов и событием проверки заполнения.

Следующие измерения должны установить список проверяемых реквизитов,
эффекты параметров обработчика и порядок события относительно стандартной
проверки. Текущий SDK не публикует эти настройки; успешный результат по
умолчанию не заменяет их приобретение.

Дополнительная проба `measure-catalog-check-filling-handler.bsl` дала двадцать семь
строк. В первых двенадцати вызовах вход обработчика — `FALSE:1:Description`:
отказ выключен, один путь имеет английское стандартное имя. Наблюдение
без изменений возвращает Ложь; очистка массива — Истина; очистка с отказом —
Ложь. Язык пути имеет значение: пустые `Code` и `Description` возвращают
Ложь, а `Код`, `Наименование` и неизвестный `НесуществующийРеквизитПробы` —
Истина. Для измеренных стандартных полей система использует английские
пути, а проверенные русские и неизвестный пути не приводят к отказу.
Варианты `description` и `DESCRIPTION` также дают Ложь: эти английские
пути принимаются в разном регистре. Присваивание параметру нового пустого
массива возвращает Ложь, как и присваивание нового массива с `Code`.
В отличие от очистки исходного массива, замена значения параметра не
отменяет исходную проверку `Description`. Чтобы различить исходный и новый
список окончательно, добавлена проба с заполненным Description и пустым Code:
мутация исходного списка до единственного `Code` даёт Ложь; присваивание
нового пустого массива или нового массива с `Code` даёт Истина. Проверка
продолжает использовать исходный массив, а не новое значение параметра.
Правила собственных реквизитов и табличных частей пока не измерены.

Полный текст события прочитан в Синтакс-помощнике той же установки:
`platform-syntax-help:syntax-context:objects/catalog125/catalog126/object130/events/FillCheckProcessing339.html`.
Нативные исходники обработчика сохранены отдельно в
`catalog-check-filling-handler-module.bsl`.

Проба `measure-catalog-check-filling-messages.bsl` сняла сообщение до его
вывода, через `ПолучитьСообщенияПользователю(Истина)`. Пустой объект
возвращает Ложь и одно сообщение: `"Description" is a required field.`;
поле сообщения — `Description`, путь к данным пустой. Язык установленной
платформы в этом замере английский; русский текст этим результатом не
установлен. Артефакт содержит пять строк.

Русский текст независимо измерен повтором с `/Lru`, через временную
обёртку `ONEC_ENTERPRISE_PLATFORM`. Его отдельный артефакт —
`measure-catalog-check-filling-messages-ru.platform.txt`: сообщение
`Поле "Наименование" не заполнено`; поле по-прежнему `Description`, путь
пустой. Первый запуск остановился до выполнения BSL из-за нехватки места
для временного файла базы. После удаления завершённых временных баз
повтор завершился и дал пять строк; неудачный запуск не является замером.

Отдельные пробы кода с изменением исходного массива обработчика дали
`"Code" is a required field.` в английском запуске и `Поле "Код" не заполнено`
в русском. Поле сообщения — `Code`, путь пустой; оба вызова возвращают Ложь
и одно сообщение. Результаты сохранены в
`measure-catalog-check-filling-messages-code{,-ru}.platform.txt`.

Проба `measure-catalog-check-filling-own-attribute.bsl` использует отдельный
XML справочника с собственным строковым реквизитом длины 30 и режимом
`ShowError`. Наименование заранее заполнено. Пустой собственный реквизит
даёт Ложь; список обработчика — `FALSE:2:Description:ПроверяемаяСтрока`.
Сообщение — `"ПроверяемаяСтрока" is a required field.`, поле —
`ПроверяемаяСтрока`. После присваивания `test` результат — Истина.
XML и шесть строк результата сохранены рядом с пробой; данные не записывались.
Повтор текущего скрипта также подтвердил `catalog.own.body=EMPTY:ERROR`.

При добавлении английского синонима `Own attribute title` английское
сообщение использует этот синоним, а поле остаётся `ПроверяемаяСтрока`.
Первый повтор с этим XML аварийно завершился внутри платформы; после
освобождения квоты повтор дал пять строк. Прежний результат не использован
как доказательство для изменённой XML. Финальный повтор текущего скрипта
дал шесть строк, включая `catalog.own.body=EMPTY:ERROR`.

Отдельная русская проба дополнительно подтвердила чтение собственного
реквизита при инициализации как пустой строки и отказ при записи:
`catalog.own.body=EMPTY:ERROR`. Сообщение при `/Lru` —
`Поле "Own attribute title" не заполнено`: язык шаблона и выбранного
синонима различаются. Дополнительный замер подтвердил
`catalog.own.language=en` и `catalog.own.system_language=ru`.
Синоним выбирается существующим текущим языком конфигурации, шаблон —
явно переданным языком системы. Итоговая русская проба содержит восемь строк.

полную `catalog_standard_fill_checking`: коммиты `d00668e`, `7bfadc2`.
Его собственный нативный корпус подтверждает 728 стандартных таблиц и
31 334 настройки полей. Оригинальный СтраныМира проверяет оба стандартных
поля; настройки этого объекта не заменяются настройками минимальной пробы.

Скалярная проба `measure-catalog-check-filling-scalars.bsl` дала шесть строк.
Все четыре собственных реквизита настроены на `ShowError`; строка и
наименование предварительно заполнены. Обработчик получает список
`Description:ПроверяемаяСтрока:ПроверяемоеЧисло:ПроверяемоеБулево:ПроверяемаяДата`.
При начальных значениях отказ дают число и дата, сообщения приходят в этом
порядке. После присваивания числа 1 и даты 2026-10-02 результат — Истина
как для Ложь, так и для Истина в булевом реквизите. Проверка заполнения
булевого реквизита не равнозначна отдельному замеру глобального
`ЗначениеЗаполнено`: существующий маркер этого открытого вопроса не снят.
XML и результат сохранены рядом с пробой; записи объектов не выполнялись.

Проба `measure-catalog-check-filling-common.bsl` дала семь строк.
Общий НаименованиеЯзык1 явно применён к справочнику и настроен на ShowError.
При заполненном наименовании обработчик получает пути Description,
ПроверяемаяСтрока, НаименованиеЯзык1 именно в этом порядке. Сообщения
незаполненных собственных и общих строк идут в таком же порядке.
Заполнение только собственной строки сохраняет Ложь и сообщение
`"НаименованиеЯзык1" is a required field.`; заполнение обеих строк даёт
Истина. Применённые общие поля следуют за собственными, а не перед ними.
