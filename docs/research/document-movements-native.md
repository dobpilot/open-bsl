# Коллекция движений документа: нативные наблюдения

Измерено 2026-10-02 на 1С 8.3.27.2342, русская локаль. Отдельные файловые базы `/tmp/open-bsl-document-movements-096` и `/tmp/open-bsl-document-movements-register-096`. Прикладные данные demo/buh/unf не менялись. Скрипты не вызывают `Записать` или проведение.

`measure-document-movements.bsl` сохраняет восемь наблюдений документа без связанных регистров. Коллекция доступна в теле модуля и после него имеет то же тождество; её тип отображается как `Коллекция движений`. `Количество / Count` равно нулю, обход пуст, `RegisterRecords` возвращает тот же объект. Коллекции разных документов различаются; замена свойства отвергается.

`measure-document-movements-register.bsl` сохраняет тринадцать наблюдений. Нативный XML регистра `РасписаниеЗагрузкиРесурсов` взят из выгрузки УНФ; для минимальной базы сохранены ресурс `Мощность` и числовое измерение `НомерСтрокиТаблицыРесурсов`, без ссылок на остальные прикладные объекты. Документ пробы связан с этим регистром через `RegisterRecords`. Его коллекция имеет один элемент; доступ по имени регистра и индексу даёт тот же набор записей. Тип — `Регистр сведений набор записей: РасписаниеЗагрузкиРесурсов`. Новый набор пуст, `Записывать` ложно; изменение флага видно через индекс и не меняет флаг второго документа. Обход даёт один элемент.

Это не модель пустой коллекции для любой конфигурации. В исходной XML УНФ `Событие` связано с одним регистром, `ЗаказПокупателя` — с 51. Состав и порядок требуется приобрести из Config через SDK. Нативные наблюдения не доказывают запись или чтение наборов из базы, состав их строк, отборы, правила преобразования флага или поведение коллекции других классов регистров.

Дополнительные пробы довели корпус до 29 наблюдений: русский `КоллекцияДвижений` и английский `RegisterRecordsCollection` обозначают фактический тип коллекции; у набора доступны `Count` и `Write`. `measure-document-movements-flags.bsl` подтверждает ещё пять строк: флаг разрешено установить в теле модуля, он сохраняется у того же набора после создания, а присваивание через `Write` меняет `Записывать`.

Первая проба флага не дала результата и завершилась по тайм-ауту. В подготовленном модуле дополнительные объявления функций стояли после исполняемого тела. После переноса объявлений перед телом повторный нативный запуск дал все пять строк; результат не восстанавливался выводом интерпретатора.

Реализация ORM сохраняет полный приобретённый список идентификаторов и отдельные изменяемые наборы каждого документа; неизменяемые описания типов кешируются в каталоге. Неизвестный список связей остаётся неизвестным, ошибочные или неподдержанные элементы не пропускаются. Реплей 29 строк проходит через фасад в независимых сеансах. Получение связей из SDK и исходный запуск УНФ пока не завершены. Запись строк и чтение данных регистра здесь не реализовывались.

`bsl-config-db`: нативный ресурс Config `Событие` сохраняет одну связь,
а `ЗаказПокупателя` — все 51 в исходном порядке. Для второго документа
ожидания получены из `RegisterRecords` штатной выгрузки
`/tmp/open-bsl-unf-query-schema-xml/Documents/ЗаказПокупателя.xml`;
UUID каждого регистра прочитан из его собственного XML. Описатель
документа взят из соответствующего сохранённого SDK `unf/config.pack`.
Корень тестового каталога ограничен одним документом; это проверка
проекции приобретённых связей, а не запуск полного УНФ.

сохранены в `crates/bsl-config-db/tests/fixtures/document-owned-attributes/`.
