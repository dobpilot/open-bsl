# Глобальный менеджер шаблонов второго фактора

Read-only compile-only demo после добавления HTML-документа остановилась
в `Справочник.ШаблоныДвухфакторнойАутентификации.МодульМенеджера` на
`ШаблоныНастроекВторогоФактораАутентификации`.
Извлечённый исходник обращается к имени в строках 267 и 270 экспортной
процедуры создания/обновления шаблона. Исходник хранится только в `/tmp`;
исходная процедура не исполнялась. Одноимённого общего модуля в снимке нет.

Полностью прочитаны страницы установленной справки 8.3.27.2342:

- `objects/Global context/properties/SecondAuthenticationFactorSettingsTemplates12079.html`:
  свойство только для чтения глобального контекста, начиная с 8.3.14; доступно на сервере.
- `objects/catalog63/catalog732/SecondAuthenticationFactorSettingsTemplatesManager.html`:
  менеджер с методами `НайтиПоИмени`, `ПолучитьШаблоны`, `СоздатьШаблон`.

[Нативный контроль](fixtures/second-factor-template-global/global.bsl)
исполнен репозиторным раннером на собственной файловой базе
`/tmp/open-bsl-accumulation-balance-1006-ib`, код завершения 0.
[Две строки](fixtures/second-factor-template-global/global.platform.txt)
подтверждают имя типа менеджера и английский псевдоним глобального имени.
Методы шаблонов не вызывались, данные баз не изменялись.

Активное изменение `complete-configuration-session-runtime` дополнено
и строго провалидировано до кода. Объявление использует прежнюю пару
`GlobalDescriptor`/`FunctionDescriptor` ORM, без изменений резолвера.
Локальная и модульная переменная имеют прежний приоритет.

Реальная служба шаблонов не подключена. Выполнение доступа возвращает
явную перехватываемую ошибку вместо пустого менеджера или успешной записи.
Это позволяет компилировать неисполняемые процедуры, но не является
реализацией чтения или изменения шаблонов. Если исходная инициализация
достигнет службы, потребуется адаптер текущего principal и отдельные
нативные контроли до завершения полного запуска.

123 unit-теста ORM прошли, включая новые проверки обоих псевдонимов,
регистра, перехвата ошибки и приоритета переменных. Первый прогон выявил
коллизию нового кода функции с существующим 66; новый код заменён на 70,
старые коды и тесты не менялись. Clippy для ORM/XML прошёл, справочник API
перегенерирован. Это не полный зелёный workspace и не успешный старт demo.

## Локальный объект настройки

Конструктор `НастройкаВторогоФактораАутентификации` / `SecondAuthenticationFactorSetting`
возвращает отдельное значение с пустым именем и пустым `Соответствие`.
[Контроль соответствия](fixtures/second-factor-template-global/setting-map.bsl)
дал [десять строк](fixtures/second-factor-template-global/setting-map.platform.txt).
Присвоенное соответствие не копируется; изменения видны через обе ссылки.
Новые экземпляры не разделяют коллекцию по умолчанию.

Первый контроль ошибочно использовал `Структура` и остановился в своей
перехватывающей ветке; его частичная квитанция сохранена в `setting.platform.txt`.
Она не считается полным воспроизведением всех последующих проверок.
Контроль преобразования имени подтвердил строковое преобразование числа,
но затем также обнаружил отличие от предполагаемой атомарности setter:
после ошибки параметры уже недоступны как соответствие.

[Отдельный контроль отказа](fixtures/second-factor-template-global/setting-rejection.bsl)
с [шестью строками](fixtures/second-factor-template-global/setting-rejection.platform.txt)
подтвердил очистку свойства до `Неопределено`; прежнее соответствие сохраняет
значение 43. Спека исправлена по измерению до реализации этого поведения.
Нативный [контроль арности](fixtures/second-factor-template-global/setting-arity.bsl)
отклонил один числовой, один строковый и два аргумента;
[три строки](fixtures/second-factor-template-global/setting-arity.platform.txt) сохранены.

В `bsl-orm` реализованы этот конструктор и два свойства без сохранения
пользователя. Имя принимает строку и измеренное обычное преобразование числа;
неизмеренные формы явно отклоняются. Служба шаблонов остаётся отдельной и
неподключённой. Полные числовые контроли соответствия и отказа воспроизведены
через фасад; все 125 unit-тестов ORM прошли без правки прежних ожиданий.

После конструктора read-only compile-only demo завершилась за 67,36 с,
приобретение 4,58 с, 3953 модуля. Следующий отказ в том же менеджере —
`UndefinedVariable("ТипОбработкиНастроекВторогоФактораАутентификации")`.
Журнал `/tmp/open-bsl-demo-second-factor-setting-1006.log`.
Настройки пользователей и исходный BSL не исполнялись.

## Перечисление обработки настроек

Нативный контроль `fixtures/second-factor-template-global/processing-type.bsl` на 1С 8.3.27.2342 завершился шестью строками. Подтверждены оба значения, английские псевдонимы, различие значений и русские представления. Состав независимо подтверждён синтакс-помощником: `objects/catalog2/catalog2690/SecondAuthenticationFactorSettingsProcessingType.html` и страницы свойств `DontUse12085.html`, `UseNextIfFailed12084.html`. Перечисление добавлено в существующие таблицы runtime; сохранение настроек пользователей не реализовано этим изменением. Интеграционный тест `second_factor_processing_matches_the_native_platform_receipt` воспроизвёл все шесть строк без расхождений. Повторная compile-only проверка demo ещё требуется.

Compile-only demo после перечисления 2ФА: загрузка 4.70 с, 3953 модуля, общий прогон 73.82 с. Следующая ошибка — `UndefinedFunction("СоздатьБизнесПроцесс")` в `БизнесПроцесс.Ознакомление.МодульМенеджера`. Соединение закрыто перед компиляцией; код модулей не исполнялся. Перечисление проверено нативным контролем, 307 unit-тестами runtime, Clippy runtime/CLI и rustdoc runtime; полный workspace этим прогоном не подтверждён.
