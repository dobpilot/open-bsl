# Статический разбор локальных обработок декомпилятора

2026-10-10 исследованы `Декомпилятор1Сv8.epf` и `Декомпилятор1Сv83.epf`
из `/run/media/kan/Green storage/SOFT/1С/полезные обработки/`.
Исходные EPF не изменялись. Обработки и встроенная DLL не запускались.
Это исследование существующих артефактов, без изменения публичного API,
производственного декодера или семантики BSL; новый OpenSpec не требуется.

Навык `unica:code-search` использован для выбора порядка исследования.
Канонический `unica.view {}` ранее сообщил, что workspace не содержит
настроенного набора исходников. Эти EPF разобраны непосредственно
существующим читателем контейнера v8unpack, без нового парсера.

## Состав

У обеих обработок доступен BSL-модуль формы (1403 байта): кнопка вызывает
`ДекомпилироватьФайл`, диалог выбирает CF/EPF/ERF. Основной модуль обработки
защищён: в контейнере есть `image`, но нет его исходного `text`.

Защищённый образ обеих версий побайтово одинаков:

- 189007 байт, UTF-8 с BOM;
- SHA-256 `5ca15c02a0656e76a3c58e89d19eb6913dc20b6a2ec1d6657e814ffbe2694d88`;
- 15778 команд, точка входа модуля 2940;
- 75 констант, 466 глобальных переменных, 32 записи процедур;
- обфусцированные имена и нелинейный поток команд.

Экспортная `ДекомпилироватьФайл` имеет вход 11103. По сравнению EPF
нельзя заключать, что v83 содержит более новый алгоритм: основной образ
совпадает. Оболочка контейнера различается.

## Уточнение чтения контейнера

Автоопределение формата v8unpack отказало для v83, потому что первый
указатель свободного блока не равен `ff ff ff 7f`. Прямое чтение обычным
`Container` успешно извлекло те же 11 ресурсов. Ненулевой указатель
свободного блока не означает 64-битный контейнер. Полный файл v83 длиннее
размера прочитанного контейнера; оставшиеся байты в этой проверке не
интерпретировались. Это не утверждение о полном разборе всех свободных блоков.

## Раскрытая инициализация

В строковой константе 5 находится скрытый текст инициализации.
Следующие участки команд подтверждают алгоритм конкретного образа:

| Команды | Действие |
| --- | --- |
| 2940–2948 | Позиция = 1, граница = длина константы 5, результат = пустая строка. |
| 12133–12137, 11243–11247 | КодСимвола константы по позиции; вычитание позиции и константы 288. |
| 3241–3244 | Второе вычитание, Символ, добавление к строке результата. |
| 3245–3248, 3960–3965 | Увеличение позиции и сравнение с длиной. |
| 8185–8188 | Выполнить собранную строку, затем очистить её. |

Статическое преобразование:
`decoded[i] = chr(ord(encoded[i]) - (i + 1) - 288)`.
Раскрыты 10823 символа BSL-инициализации. Результаты для обеих EPF
совпали побайтово. Этот текст при исследовании не исполнялся.

Это раскрытие строковой константы, а не декомпиляция всех 32 процедур.
Алгоритм подтверждён структурой команд этого артефакта, но не является
новым измерением семантики платформы или основанием менять runtime.

## Найденные сведения о декомпиляции

В раскрытом тексте присутствуют:

- имена таблиц `Cmd`, `Const`, `Var`, `Lbl`, `Proc`, `DefPrm`;
- таблица опкодов на 152 строки, коды 0–151;
- количества снимаемых/добавляемых значений, текст BSL-операции,
  категории генерации, приоритеты выражений и специальные категории;
- шаблоны объявлений, умолчаний, `Знач`, `Экспорт`, условных операторов,
  циклов, исключений и меток;
- сообщения о недостатке значений стека, неизвестном опкоде и
  несовпадении ожидаемого перехода при определении тернарного выражения.

Эти сведения показывают табличный генератор выражений с отдельными
обработчиками конструкций. Тела обработчиков ещё защищены; точные
алгоритмы восстановления границ цикла или `Если` из одной таблицы
не устанавливаются. Полный граф вызовов и достижимости не построен.

Категория 99 назначена кодам `11`, `32`, `41` и `129–151`.
В инициализации категория связана с диагностикой неизвестного опкода.
Статически найден фрагмент 15400–15410: сравнение категории с 99;
при совпадении начинается сборка сообщения. Переход 13652–13657 вызывает
внешнюю `Сообщить` с уровнем `ОченьВажное`, затем переходит по метке.
Из этого нельзя без полного контекста заключать, что отвергается весь модуль.

Особенно важно для нашей задачи: старый декомпилятор не имеет нормальной
строки генерации для `JmpTrue` (41), а наш оригинальный образ содержит
70 таких команд во всём массиве. Это не 70 достижимых команд; для оценки
пригодности нужны графы конкретных кадров.

## Внешние компоненты

Найдены строки `VBScript.RegExp`, `AddIn.Cv8cf`, `Cv8cf.dll`.
Встроенный макет содержит DLL размером 547840 байт: PE32, Intel i386.
По командам обработки есть вызовы загрузки внешней компоненты и операции
с файловой структурой. DLL извлечена только во временный каталог и
проверена `file`/`objdump`/`strings`; она не загружалась.

По одним именам нельзя доказать, что DLL отвечает только за контейнер,
а вся декомпиляция выполняется в BSL. Однако таблица генерации BSL,
диагностика стека и работа с описаниями команд находятся в защищённом
модуле самой обработки. Полный машинный код DLL не разобран.

## Повторный разбор тел после расширения генератора BSL

Полный исходник обработки пока не восстановлен: существующий сборщик
отвергает перемежающиеся границы инициализации (entry2940 находится
между телами обычных методов). В образе23 обычных объявления и девять
внешних. Проверка по каждому обычному кадру выявила, что почти все
переходят к командам перед своим входом. Физическая нижняя граница
кадра отвергала их ещё до разбора выражений. Отдельный нативный
контроль `ordinary-backward-shared` подтверждает допустимость такого
направления перехода; он не доказывает правильность всех тел EPF.

Без этой границы диагностически восстановлено одно короткое тело
(67 байт, два вызова и Возврат);22 тела остаются неподдержанными.
Основные первые отказы: остаток стека на границе блока, неизвестное
глобальное имя, условие с незавершённым выражением, неподдержанный
индекс/операция и метки в foreach. Это результаты генератора исходника,
не платформенные ошибки и не доказательство неправильности EPF.
Числа и адреса сохранены в [frame-audit.json](fixtures/local-decompiler-epf/frame-audit.json).

У глобальных дескрипторов441 допустимое частное имя flags0,19 частных
имён начинаются с цифры, пять имён flags2 и одно имя flags16. Все
external_slot равны-1. Невалидные для BSL-текста имена — не только
известная форма временного итератора0+имя: ни у одного из19 нет такого
партнёра. Нельзя молча применять к ним прежнюю нормализацию итератора.

Во временной диагностической копии частные имена заменены уникальными
идентификаторами, flags16 заменён на0 только для продолжения разбора
выражений. Это не продукционная поддержка и не измеренная семантика
флага16; такая копия не исполнялась. По-прежнему восстановлено только
одно тело; остальные переходят к следующему ограничению генератора.
Таблица опкодов/шаблонов из раскрытой инициализации остаётся полезным
свидетельством, полного алгоритма обработчиков этим разбором не извлечено.

## Повторный разбор текущим генератором

После измеренного снятия нижней границы обратного перехода повторён
статический разбор неизменённого образа текущими `native_image.rs` и
`native_scoped_functions.rs`. Журнал `epf-current-scoped-audit-1010.log`:
по-прежнему восстановлено одно из23обычных тел (67байт),22отвергнуты.
Отказы теперь указывают на реальные неподдержанные границы выражений,
стек, глобальные имена, foreach и локальные индексы. Новых полных тел
алгоритма декомпиляции не получено. Изменение границы перехода само по себе
не снимает эти ограничения; EPF и DLL не исполнялись, имена и флаги
не нормализовались, исходный образ не менялся.
