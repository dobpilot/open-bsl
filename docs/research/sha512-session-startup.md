# SHA512 в оригинальном запуске demo

Диагностический повтор 2026-10-13 подтвердил фактический аргумент
`Enum(HashSha512)` у конструктора `ХешированиеДанных`.
Лог: `/tmp/open-bsl-demo-session-hash-1013-startup.log`.
Перечисление корректно; отказ происходил в неподдержанном алгоритме
`bsl-crypto`, где ранее реализованы MD5, SHA1 и SHA256.

Контроль `tests/conformance/measure/1c/measure-sha512.bsl` выполнен
на 1С 8.3.27.2342 в собственной `/tmp/open-bsl-sha512-1013-ib`.
Окончательный эталон `.platform.txt` содержит шесть строк без ошибки:
пустые данные, повторный снимок, поэтапное a/bc и целое abc.
Вывод интерпретатора совпал побайтово. Центральный `platform.tsv`
не перезаписывался. Исходные информационные базы не изменялись.

Реализация использует `sha2::Sha512` из существующей зависимости.
Преобразование входных данных и свойства объекта не изменяются;
новые алгоритмы CRC32 и PBKDF2 этим изменением не реализуются.
Существующие тесты криптографии сохранены, добавлен внешний тест
с нативными суммами и проверкой продолжения после снимка.

Повтор с поддержкой SHA512 завершился следующим отказом в
`ХешированиеДанных.Добавить`: текущая реализация принимает только
двоичные данные. Лог `/tmp/open-bsl-demo-session-sha512-1013-startup.log`.
Фактический тип аргумента снимается отдельным диагностическим повтором.

Нативный контроль `measure-hash-string-input.bsl` подтвердил принятие
строк: abc совпадает с двоичным abc; «Привет» совпадает с его UTF-8
байтами. Эталон содержит пять строк без ошибки. Это измерение ещё не
означает реализацию строки в интерпретаторе.

Строковый вход оригинального demo подтверждён диагностикой:
`diagnostic.hash_add_type=Строка` в
`/tmp/open-bsl-demo-session-hash-input-1013-startup.log`.
Реализация использует существующее UTF-8-представление `BslString`.
Оба измеренных сценария теперь воспроизводятся побайтово.

Окончательный workspace-прогон после обоих изменений завершился:
3582 теста прошли, 0 упало, 1 игнорируется. Лог:
`/tmp/open-bsl-hash-string-workspace-tests-1013.log`.
Workspace Clippy, rustdoc и fmt прошли. Предыдущий прогон с потерянным
crypto-артефактом не используется как доказательство.
