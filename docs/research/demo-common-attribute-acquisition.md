# Общий реквизит, остановивший demo

Последний запуск исходной demo отказал при компиляции `Справочник.ГруппировкиЗадач.МодульОбъекта`: `НаименованиеЯзык1` читается до присваивания. Данные свойств получателя сейчас включают стандартные и собственные реквизиты, но не применимые общие реквизиты. Добавлять глобальное имя или угадывать локальную переменную здесь нельзя.

Из `open-sdbl/tests/fixtures/demo/config.pack` извлечён ресурс `03f9d2d0-eae4-4098-a70e-4eb569b11fd9`. Он содержит описание `НаименованиеЯзык1`, строковую квалификацию `S,150,1` и UUID справочника `9e9e2a57-8536-4983-a5c0-7841ead585e8` в составе применимости. Сам ресурс справочника этого имени не содержит.

Для независимой проверки 1С 8.3.27.2342 выполнила `ibcmd infobase config export` для demo в `/tmp/open-bsl-demo-common-attributes-096-native`. Операция завершилась кодом 255 через 8,4 с с `Stream format error`; вся выгрузка не считается успешной. Сохранены 23323 файла. Именно два нужных файла — `CommonAttributes/НаименованиеЯзык1.xml` и `Catalogs/ГруппировкиЗадач.xml` — целы, прошли разбор XML и несут те же UUID. XML общего реквизита сохранён в `tests/conformance/measure/1c/common-attribute-demo-native/НаименованиеЯзык1.xml`.

Нативные свойства общего реквизита: `xs:string`, Length 150, AllowedLength Variable, AutoUse DontUse. Content содержит 51 запись; для Catalog.ГруппировкиЗадач указано Use. Это доказательство применимости конкретного реквизита к конкретному объекту, а не универсальный вывод о неизвестных кодах Config или всех режимах AutoUse.

Следующий шаг — приобрести тип и измеренную применимость через SDK. Не требуется второй декодер в open-bsl. Затем нужны собственное хранение значения в объекте и нативные проверки чтения, присваивания, квалификаторов и изоляции экземпляров. Причина общей ошибки всей XML-выгрузки отдельно не диагностирована и не подменяет доказательства целых файлов.
