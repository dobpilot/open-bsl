# Тип идентификатора обсуждения при запуске UNF

Read-only повтор исходного UNF после регистрации измеренного имени типа метаданных завершился UnknownType("ИдентификаторОбсужденияСистемыВзаимодействия"). Это регистрация типа, отличная от уже объявленного конструктора: конструктор без реализации хоста продолжает явно отказывать.

Собственная одноразовая файловая база `/tmp/open-bsl-conversation-type-native-1013-ib` подтвердила оба имени типа и представление CollaborationSystemConversationID без настройки системы взаимодействия. Скрипт и пять строк результата: `tests/conformance/measure/1c/measure-collaboration-conversation-type.{bsl,platform.txt}`. Поиск исходников сохранил вызовы Тип и конструктора в `target/diagnostics/readonly-startup/unf-collaboration-type-source-1013.log`; поиск не устанавливает достигнутый стек.

После строгой проверки OpenSpec support-reached-conversation-type зарегистрирован один существующим механизмом описанный тип и связь с прежним конструктором17. Реализация конструктора не менялась. Новый тест проверяет равенство имён, представление, отличие от Неопределено и прежний явный отказ конструкции. Clippy библиотеки и нового теста, rustdoc и генерация справочника прошли. Общий workspace-прогон не заменён этими целевыми проверками.

Отдельный read-only повтор оригинального UNF запущен через `conversation-unf-probe-1013`; результат ещё ожидается.
