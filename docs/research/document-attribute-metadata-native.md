# Метаданные реквизитов документа

На платформе 1С 8.3.27.2342 в изолированной файловой базе выполнен `tests/conformance/measure/1c/measure-document-attribute-metadata.bsl`. Его сохранённый эталон содержит 21 наблюдение: порядок двух реквизитов, поиск по имени без учёта регистра, индексацию, `Получить`, идентичность полученного значения и отказ записи свойства. `Получить` преобразует числовую строку и булево значение в индекс; индексирование булевым значением отклоняется. Дробный числовой индекс усекается. Тип реквизита совпадает с типом метаданных документа и имеет измеренное представление `Metadata object`; отдельный тип `ОбъектМетаданныхРеквизит` платформа не находит.

Представление использует уже приобретённый неизменяемый массив реквизитов. `ЗаполнятьИзДанныхЗаполнения` и `ЗначениеЗаполнения` читаются из приобретённых данных, без подстановки неизвестных значений. Граф значения заполнения восстанавливается материализаторами текущего State. Неизвестная коллекция отличается от известной пустой; отсутствующий граф и неправильное число корней отклоняются явно.

Тест `crates/bsl-session/tests/document_attribute_metadata.rs` воспроизводит все семь строк отдельного нативного сценария исчезнувшей ссылки перечисления на двух измеренных языках интерфейса и все 21 наблюдение коллекции. В последнем сравнении нормализуется только ранее существующее представление булева результата `Да` к нативному `Yes`. Старые ожидания тестов для этого изменения не менялись.

Проверки рабочего дерева прошли: форматирование, Clippy всей workspace, все workspace-тесты, rustdoc с запретом предупреждений, потребитель фасада, деревья зависимостей runtime/VM и strict OpenSpec. Лог — `/tmp/open-bsl-document-attribute-metadata-096-gates.log`. Это подтверждает данный набор свойств, но не полный API метаданных или успешную инициализацию исходных demo/buh/unf.
