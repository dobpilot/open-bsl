# Общий реквизит в новом объекте справочника

На 1С 8.3.27.2342 выполнены `measure-common-attribute-runtime.bsl` и `measure-common-attribute-runtime-auto.bsl` в двух изолированных файловых базах. Каждый сохранённый эталон содержит восемь наблюдений. Общий реквизит скопирован из нативной XML demo с сохранением имени и строкового типа длиной 150; состав заменён минимальным проверяемым набором объектов.

Первый вариант использует `AutoUse=DontUse` и явно включает `ЗамерВременныхТаблиц`. Второй использует `AutoUse=Use`, а `ВладелецПробы` явно исключает через `Content/DontUse`. В обоих вариантах новый включённый объект читает пустую строку уже в теле модуля, но запись в теле отклоняется. После создания присваивание работает без учёта регистра имени, число 42 становится строкой, строка длиной 151 обрезается до 150. Другой экземпляр сохраняет пустое значение. Чтение у исключённого справочника завершается ошибкой.

Пробы не записывают объекты в базу. Они подтверждают доступность и память конкретного строкового реквизита нового объекта справочника; проверки разделителей данных, существующих записей и остальных типов не проведены. При подключении необходимо отдельно сохранить полный состав общих реквизитов, включая неизвестные формы. Фильтрация только описателей с известным `common_attribute_usage` не доказывает полноту состава.

Полнота корневого списка дополнительно проверена read-only чтением `Config` в текущих demo/buh/unf через разрешённые подключения. Измеренная коллекция `15794563-ccec-41f6-a83c-ec5f7b9a5bc1` содержит соответственно 13, 7 и 7 идентификаторов. Все 13 UUID demo совпали с целыми XML общего реквизита из частичной выгрузки; все семь UUID каждого из buh/unf совпали с независимым нативным XML-корпусом SDK. Полная demo-выгрузка от этого не стала успешной. Сжатые `root`, ресурс его конфигурации и списки UUID сохранены в `crates/bsl-config-db/tests/fixtures/common-attributes/`. Принадлежность коллекции также независимо подтверждена старой нативной separator-фикстурой SDK, происхождение которой описано в `tests/fixtures/separators/README.md`.

Реализация сохраняет корневой список и отдельно проецирует применимые общие реквизиты из снимка SDK; для строковых значений используется существующая конверсия собственного реквизита. Восемь новых тестов проверяют нативные сценарии, изоляцию сеансов одного движка, все 13 описателей demo, квалификаторы, явные включения/исключения и ошибки неполных или неизвестных данных. Неподдержанные типы отклоняются при обращении. Полные fmt/Clippy/workspace-тесты (353,6 с)/rustdoc, потребитель фасада, деревья зависимостей и strict OpenSpec прошли без изменения старых ожиданий. Лог — `/tmp/open-bsl-common-attributes-096-gates.log`.
