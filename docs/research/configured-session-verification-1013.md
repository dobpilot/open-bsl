# Проверки текущего рабочего дерева: 2026-10-13

После добавления перечисления подписчиков выполнены:

- `cargo test -p open-bsl-consumer`: 38 тестов прошли, отказов нет;
  это проверка замкнутости фасада, а не запуск оригинальных сеансов.
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`: успешно.
- `cargo clippy --workspace -- -D warnings`: успешно для обычных целей.
  В этом прогоне отсутствует `--all-targets`; он не подтверждает сборку тестов.
- `cargo tree -p bsl-rt -e normal` и `cargo tree -p bsl-vm -e normal`:
  SDK и СУБД отсутствуют; у ядра сохраняется зависимость на `bsl-number`,
  у VM — на bytecode, format, number и rt.
- Целевой тест `open_questions_registry_matches_source_markers` из
  `bsl-rt/tests/open_questions_registry.rs`: прошёл. Наличие маркеров,
  записей реестра и строк замеров согласовано. Это проверка учёта
  неизмеренных вопросов, а не подтверждение их семантики платформой.

Полные квитанции лежат в `target/diagnostics/session-current-*`.
Проверки выполнялись последовательно в `target/cleanup-build`, с GCC,
отключённой инкрементальной компиляцией и без отладочной информации.

Полный набор тестов текущего дерева и Clippy для всех целей пока не зелёные:
патч `target/diagnostics/host-session-existing-tests.patch` не применён.
`git apply --check` подтверждает его применимость. Три строки приводят
старую фикстуру HashSum к измеренному бинарному контракту; одна строка
добавляет отсутствующее поле `session_started: None` в старый тестовый
конструктор. Требование пользователя о согласовании изменений существующих
тестов сохраняется; автоматическое продолжение задачи не является согласием.

Ни эта проверка, ни предыдущий зелёный прогон до изменения хеша и даты
не подтверждают успешную инициализацию оригинальных demo/buh/unf.
Текущие отказы указаны в плане
`docs/plans/configured-session-startup-current-failures.md`.

с кодом 101 до исполнения тестов: E0063 в `bsl-session/src/tests.rs:14`,
