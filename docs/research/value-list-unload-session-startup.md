# Выгрузка значений списка при запуске demo

После измеренной сортировки исходный demo достигает отсутствовавшего
метода `СписокЗначений.ВыгрузитьЗначения`. В существующую таблицу
компонента добавлены этот метод и английское имя `UnloadValues`,
с нулевой арностью, без изменений других методов или зависимостей.

Нативный контроль 1С 8.3.27.2342 сохранён в
`tests/conformance/measure/1c/measure-value-list-unload.bsl` и соседнем
`.platform.txt`. Девять строк воспроизводятся побайтно в обычном и
оптимизированном исполнении. Пустой список возвращает пустой массив;
выгружаются значения, а не представления. Замена ячейки массива не
изменяет значение элемента списка. Изменение свойства вложенной структуры
видно из списка: изменяемое значение сохраняет идентичность.

Проверка типа использует сравнение с `Тип("Массив")`, потому что текущий
нативный контур отображает тип как `Array`, а интерпретатор — как
`Массив`. Это различие локализации не меняет измеряемый контракт.
Первый вариант контроля без явной инициализации переменной, используемой
в `Выполнить`, завершился тайм-аутом; он не является эталоном.

Прочитана полная страница синтакс-помощника версии 8.3.27.2342:
`platform-syntax-help:syntax-context:objects/catalog234/catalog235/ValueList/methods/UnloadValues206.html`.
Два новых внешних юнит-теста проходят. Clippy и rustdoc всего workspace
прошли без предупреждений. API-справочник перегенерирован; полный набор
тестов ещё выполняется. Исходный demo прошёл выгрузку и завершился
объектной ошибкой `ИнформацияОбОшибке`, подробности которой исходный
диагностический лог не раскрывает. Лог сохранён в
`/tmp/open-bsl-demo-session-vunload-1013-startup.log`; наблюдавшийся пик RSS
составил 11 536 800 КиБ. Подготовлен повтор с чтением подробного
представления через существующий фасад. Повтор
`/tmp/open-bsl-demo-session-vdetail-1013-startup.log` подтвердил пустое
подробное представление; нужно исследовать цепочку причин или место
возбуждения, а не угадывать содержание ошибки.

Полный прогон `/tmp/open-bsl-value-list-unload-workspace-tests-1013.log`
остановился на существующем тесте
`single_worker_pool_runs_other_jobs_and_wakes_or_cancels_file_waiters`:
после отмены он увидел два вызова вместо нуля. Изолированный повтор
без тяжёлого demo прошёл; ожидания теста не менялись. Это не доказывает
причину отказа. Полный повтор без параллельного demo завершился без ошибок,
включая этот тест; лог
`/tmp/open-bsl-value-list-unload-workspace-recheck-1013.log`.
