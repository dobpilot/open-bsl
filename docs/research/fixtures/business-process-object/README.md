## Трёхпараметрический обработчик заполнения

Первая проба `fill-handler.bsl` с `fill-handler-object.bsl` завершилась единственной строкой ошибки при вставке в данные обработчика. Это сохранённое отрицательное свидетельство, не полный результат параметров. Отдельная `fill-handler-empty.bsl` с тем же защищённым модулем дала ещё 12 строк для пустой структуры.

Нативный обработчик получает непустую структуру с общей памятью, но пустую — как Неопределено. Текст заполнения — Неопределено; стандартная обработка первоначально включена. Мутация непустой структуры видна вызывающему коду; замена параметра данных не заменяет его переменную. Присвоенная обработчиком дата сохраняется. Повторный вызов изменяет прежний счётчик экземпляра; другой экземпляр сохраняет ноль.

ORM вызывает обработчик через существующий `call_configuration_instance_handler`, нормализует пустую структуру и передаёт три измеренных параметра. Пока поддержан измеренный путь с отключением стандартной обработки в обработчике; стандартное заполнение после обработчика и другие сигнатуры явно отклоняются. Обе полные квитанции совпали в replay, который теперь покрывает 57 строк шести контролей. Первую ошибочную пробу в этот итог не включали.
