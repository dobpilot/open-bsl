# Контекст ОписаниеОшибки

Измерено 2026-10-07 на 1С:Предприятие 8.3.27.2342, серверный модуль
управляемой формы собственной файловой ИБ
`/tmp/open-bsl-html-dom-ru-1007-ib`, язык интерфейса ru.
Команда — `tests/conformance/measure/1c/run-on-1c.sh measure.bsl`
с указанной ИБ и обёрткой `/tmp/open-bsl-1cv8-ru-1007.sh`.
Рабочие demo, buh и unf не изменялись и прикладной код не исполнялся.

Восемь строк нативной квитанции показывают:

- До ошибки и после завершения обработчика описание пусто.
- Внешний обработчик видит собственную ошибку `outer-probe`.
- Вызванная из него отдельная функция получает пустое описание: контекст
  обработчика вызывающей функции не наследуется.
- Вложенный обработчик видит `inner-probe`; после него восстановлено
  `outer-probe`, а не последняя ошибка всей задачи.

Внешний перехват сообщает `probe.unsupported`, если хост ещё не реализует
контракт. Эта строка отсутствует в нативной квитанции. Она позволяет
исполнить тот же контроль в текущем open-bsl без необработанного исключения;
совпадение с платформой пока не достигнуто. Динамическое выполнение,
асинхронные продолжения и конфигурационные обратные вызовы отдельно этим
контролем не измерены. Полный текст описания с координатами не фиксируется:
проверены пустота и наличие заданных сообщений.

На этапе первоначального замера runtime не менялся. Измерение требует состояния активного обработчика
конкретного вызова с восстановлением внешнего обработчика; единственное
поле последней ошибки задачи само по себе не обеспечивает этот контракт.
До реализации требуется отдельное изменение OpenSpec и проверка границ
обработчика в существующем байткоде. Не следует исправлять это простым
возвратом `current_exception` из заглушки компонента.

## Дополнительные контроли

`nonlocal-exits.bsl` / `.platform.txt` — восемь наблюдений: описание
не сохраняется после возврата из обработчика, выхода из цикла через
`Продолжить`/`Прервать` и перехода за обработчик; переход из вложенного
обработчика во внешний восстанавливает внешнюю ошибку.

`dynamic.bsl` / `.platform.txt` — восемь наблюдений: `Выполнить` и
`Вычислить` получают пустое описание как вне обработчика, так и при вызове
из него; после динамического фрагмента внешняя ошибка остаётся доступна.
Эти контроли исполнены тем же runner на той же собственной ИБ. В текущем
интерпретаторе оба безопасно завершаются строкой `probe.unsupported`.
Поведение конфигурационного callback и асинхронного продолжения из этого
не следует.

`presentation.bsl` / `.platform.txt` — четыре наблюдения: нативное
`ОписаниеОшибки()` содержит заданное сообщение, но не равно свойству
`Описание`, краткому или подробному представлению того же снимка. Поэтому
ни одно из этих представлений нельзя выдать за измеренный эквивалент
ОписаниеОшибки. Это отдельный контроль формата, а не доказательство
поддержки полного нативного стека в open-bsl. У текущего `current_error_info`
уже явно записано сознательное ограничение диагностической модели: без
платформенных координат и стека. Реализация новой функции обязана явно
сохранить эту границу либо отдельно реализовать и проверить полный формат;
молчаливое заявление полного совпадения недопустимо.

`async.bsl` / `.platform.txt` — восемь наблюдений **на клиенте** той же
изолированной ИБ: генератор переносит async-декларации в клиентский модуль,
поскольку сервер платформы их не разрешает. Дочерняя функция не наследует
ошибку родителя; её собственное описание сохраняется через `Ждать`,
родительское — после ожидания дочернего результата. Ожидается только
проверка существования собственного отсутствующего пути, записи нет.
Контроль проходит путь ожидания файловой операции, но отдельно не
доказывает, что конкретное обещание оставалось незавершённым в момент
`Ждать`; длительность приостановки не измерялась.

Новый тест `crates/bsl-cli/tests/error_description_handler_scope.rs`
сравнивает точные байты первых четырёх контролей (32 строки) и отдельно
проверяет aliases, арность и отсутствие ошибки другого State. На текущей
реализации оба теста падают из-за существующей заглушки; журнал
`/tmp/open-bsl-error-description-red-1007.log`. Это ожидаемый красный этап,
не зелёный регрессионный прогон. Контроль `presentation` в точный replay
не включён: он сохраняет отдельно известное различие форматирования.

## Реализация и проверки 2026-10-07

Функция перенесена в существующий builtin-путь VM. `ExceptionRange`
получил явный `handler_end_pc`; текстовый формат повышен до 43. Конец
учитывается при разборе, проверке образа, разбиении блоков и перемещении
инструкций. Кадр хранит пойманные значения с областями обработчиков;
описание выбирается по текущему `pc`, без проверки на каждом обычном шаге.
Перед установкой новой ошибки удаляются завершённые области.

Два новых CLI-теста теперь проходят: 32 строки первых четырёх нативных
контролей совпадают. Async-драйвер исправлен: основной блок вынесен в
явную async-процедуру, поскольку runner оборачивает тело автоматически,
а CLI не допускает Ждать на верхнем уровне. После правки повторён нативный
замер; окончательные вход и выход включены в provenance.

Новый `open-bsl/tests/error_description_pending.rs` удерживает две файловые
операции каналами хоста и проверяет `ExecutionPoll::Waiting` до разрешения
каждой. После продолжения совпадают все восемь нативных async-строк.
Три теста `bsl-vm/tests/handler_extents.rs` проверяют round-trip, вложенную
ошибку, неверный конец и пустой обработчик. Ещё 26 прежних проверок
повреждённых программ и 7 прежних compiler round-trip проходят без правок.

Clippy библиотек workspace и rustdoc workspace с `-D warnings` прошли.
Нормальные деревья зависимостей bsl-rt/bsl-vm совпадают с предыдущими.
Справочник перегенерирован, сравнение с генератором прошло.
Полный workspace не подтверждён: ожидается согласование пяти старых
тестовых литералов нового публичного поля и ожидания прежней заглушки.
Полный формат диагностических координат и стека не реализован; для него
сохраняется прежнее явное ограничение диагностической модели.
Проверка release-кода горячего цикла ещё не выполнена; выводов о скорости нет.

Проверка `the_optimizing_passes_agree_with_the_plain_run_on_every_script`
завершилась успешно за 155.53 с, реестр открытых вопросов также прошёл.
`cargo test -p bsl-bytecode --lib --no-run` ожидаемо остановлен компилятором
на старом литерале `analysis.rs`: отсутствует `handler_end_pc`.
Это зафиксированная причина необходимости согласованной механической
правки, а не изменение прежнего ожидаемого поведения. Тест не исправлялся.

## Контекст экземпляра конфигурации

`instance.bsl`, `ObjectModule.bsl` и девять строк `instance.platform.txt`
измерены серверным runner на той же собственной файловой ИБ. Runner
накладывает собственный модуль на обработку Замеры; рабочие базы не меняются.
Инициализация объекта, созданного даже внутри внешнего обработчика, и
экспортный вызов без собственного обработчика получают пустое описание.
Собственный обработчик объекта видит свою ошибку, а после возврата
вызывающий сохраняет внешнюю. Ошибка, брошенная экспортной процедурой,
попадает во вложенный обработчик вызывающего; после него восстанавливается
внешняя ошибка.

`bsl-session/tests/error_description_instance.rs` повторяет все девять
наблюдений через SessionFactory и существующий объект ORM. Только
приёмник сообщений заменён массивом результатов, как в остальных replay
сеанса. Метаданные контрольной обработки явно имеют пустые реквизиты и
части; это не подмена неизвестного состава производственной конфигурации.
Тест прошёл без дополнительных runtime-правок. Вместе с четырьмя прежними
scope-контролями воспроизводятся 41 нативная строка. Отдельные четыре строки
контроля presentation сохраняют доказательство различия полного формата.

Release-экран `hot-code-diff.sh HEAD` выполнен через временную копию,
добавляющую только ссылку на соседний open-sdbl для path-зависимостей
изолированного worktree. Исходный benchmark-скрипт не изменялся. Журнал —
`/tmp/open-bsl-handler-scope-hot-code-1007.log`, код выхода 1:

- `step`: 0xe86c → 0xd59c, 9257 различающихся строк дизассемблирования;
- `step_cold`: 0x8c22 → 0x8b68, 4392 различающихся строки.

Сравнение относится ко всему накопленному рабочему дереву против HEAD
`2b9a739`, а не изолированной правке ОписаниеОшибки. Экран обнаружил
изменение кода и не снимает риск раскладки; эти размеры не доказывают
ускорение или замедление. Чередующийся A/B не проводился, численного
вывода о производительности нет. Временные target и worktree удалены.

Четыре прежних теста `bsl-session/tests/data_processor_objects.rs` и
прежний тест `open-bsl/tests/brief_error_description.rs` прошли без правок.
Новый тест экземпляра прошёл Clippy с `-D warnings`. Синтаксис runner
проверен `bash -n`; три прежних теста генератора форм прошли.
