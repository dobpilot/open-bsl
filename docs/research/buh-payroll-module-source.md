# Исходник модуля расчёта зарплаты в buh

2026-10-02, тестовая buh, платформа 8.3.27.2342.

После реализации `ПроверитьЗаполнение` исходная инициализация останавливается
при связывании `УчетЗарплаты`: вызов
`РасчетЗарплатыДляНебольшихОрганизаций.ДатаСобытияСУчетомНерабочихДней`
не имеет объявления в снимке. Пользовательский скрипт не достигнут.

Проверка не меняла базу. Выполнены ограниченные `SELECT` к `Config` и
выборочная выгрузка двух общих модулей штатным `ibcmd config export objects`.
Пароль передан через стандартный ввод, а не в аргументах команды.

Общий модуль имеет GUID `aab59d30-8535-4c41-9461-f127db41da91`.
Его ресурс `.0` существует: 42 475 сжатых байт, 343 524 после распаковки.
Контейнер содержит записи `image` и `info`; записи `text` нет.
Загрузчик возвращает отсутствие текста из `container_text`, а вызывающий
`load_base_graph` подставляет пустую строку через `unwrap_or_default`.
Это объясняет отсутствие объявления; ошибка не связана с препроцессором.

Нативная XML-выгрузка общего модуля содержит `Ext/Module.bin`, а не
`Ext/Module.bsl`. Для `УчетЗарплаты` выгружен BSL-текст; вызов находится
на строке 13 382. Таким образом, обычная нативная выгрузка не восстанавливает
текст проблемного модуля.

У двух других описателей с тем же именем GUID
`e3e83675-e363-40c2-b7a4-a44169bffff4` и
`e4374694-0fc0-4b0e-9666-a02d0b51a7d3`. Совпадение имени само по себе не
доказывает, что это общие модули; использовать их текст как замену нельзя.

Артефакты исследования находятся в
`/tmp/open-bsl-payroll-native-export-096`,
`/tmp/open-bsl-buh-payroll-resources-096.log` и
`/tmp/open-bsl-payroll-<GUID>.decoded`.
Полные прикладные исходники и скомпилированный модуль в репозиторий не добавлены.

Пользователь подтвердил отсутствие исходника и потребовал декомпилятор.
Восстановленный BSL должен поступать в существующий компилятор open-bsl;
пустая строка и подмена функции успешной заглушкой не решают задачу.

## Разбор образа

Указанные пользователем источники:
[v8unpack](https://github.com/saby-integration/v8unpack) и
[описание стековой машины](https://habr.com/ru/articles/489392/).
Из статьи получена ссылка на авторский
[v8asm](https://github.com/EvilBeaver/v8asm).
Для воспроизводимости исследованы коммиты
`51473807dc8f874e9b06d84f466fff0861f3c4ac` и
`c7b203d4b6cf8565188c6fd1d512a7d345f61711` соответственно.
Оба проекта распространяются под MIT; сторонний код в workspace не добавлен.

Оригинальный читатель контейнера `v8unpack` выделил `image` длиной
342 751 байт и `info` длиной 15 байт. Его читатель сериализованных значений
успешно разобрал образ: версия корня `1`, секции `Cmd`, `Const`, `Var`,
`Proc`. В образе 11 913 инструкций, 648 констант, 38 внешних переменных
и 119 процедур и функций. Адрес тела модуля — `4294967295`.
Значение этого адреса пока не подтверждено контрольной компиляцией.

В секции `Proc` присутствует
`ДатаСобытияСУчетомНерабочихДней`: флаги `17`, три параметра,
начальный адрес `5641`, восемь записей локальных переменных.
Третий параметр имеет запись значения по умолчанию `B,1`.
Толкование флагов и значений предстоит проверить на собственном модуле
с известным исходником и нативным результатом исполнения.

В XML-макете `Описание` проекта `v8asm` найдено 129 строк инструкций.
Каждый числовой код, использованный в этом образе, имеет строку в таблице;
в частности, встречается код `128`. Это проверка покрытия числовых кодов,
а не доказательство их семантики на платформе 8.3.27.2342.
Таблица содержит операции со стеком, ссылки на переменные и свойства,
вызовы, переходы, итераторы и обработчики исключений. Декомпилятор должен
сохранять порядок вычислений и передачу параметров по ссылке; простая
подстановка строк по мнемоникам этого не гарантирует.

Разобранный образ сохранён только в
`/tmp/open-bsl-payroll-image-096`. Для продуктового разбора необходимо
переиспользовать `parse_serialized` и имеющийся читатель контейнера
`bsl-config-db`, а не переносить Python-зависимости.
