# Имена типа вложенных метаданных при запуске UNF

Read-only исходный запуск UNF с диагностическим приёмником журнала завершился UnknownType("ОбъектМетаданных"). Лог: `target/diagnostics/readonly-startup/unf-event-log-host-1013-startup.log`. Поиск оригинальных исходников подтвердил сравнения ТипЗнч с Тип("ОбъектМетаданных") в нескольких модулях; сам поиск не устанавливает достигнутый стек.

Отдельный нативный замер на собственной файловой базе `/tmp/open-bsl-metadata-object-type-native-1013-ib` завершился успешно. Скрипт и шесть строк результата сохранены в `tests/conformance/measure/1c/measure-metadata-object-type.{bsl,platform.txt}`. Вложенная обработка имеет представление Metadata object и совпадает с русским ОбъектМетаданных и английским MetadataObject. Корень конфигурации имеет отдельное представление Metadata object Configuration.

После строгой валидации OpenSpec support-reached-metadata-type-names оба имени добавлены как синонимы существующего дескриптора ORM. Старое имя ОбъектМетаданныхКонфигурации сохранено. Новый отдельный тест проверяет все три имени на существующем объекте документа и отличие корня. Тест и целевой Clippy прошли; справочник перегенерирован. Успешная инициализация оригинального UNF этим ещё не подтверждена.

Дополнительно прошли `checked_in_api_reference_matches_the_generator` и все три проверки `open_questions_registry`. Общий workspace-прогон этим не заменён.
