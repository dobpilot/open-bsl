# Условное разделение, остановившее demo

Проверка относится к 1С 8.3.27.2342 и оригинальному тонкому сеансу demo.
Исходники конфигурации не менялись; соединение диагностического запуска
работало только для чтения, новые сетевые соединения были запрещены.

## Достигнутый вызов

После измеренной инициализации связанных параметров разделения оригинальный
сеанс прошёл прежнюю ошибку чтения `ОбластьДанныхЗначение`. Трассировка адаптера
установила следующий отказ:

`Константы.ОграничиватьДоступЧерезВебСерверы.Получить()`.

Запуск завершился кодом 1 за 508,92 с, компиляция — 328,15 с. Лог:
`target/diagnostics/separation-traced-original-startup-run.log`.

В `МодульСеанса`, строки 43–44, этот вызов выполняется после проверки
`Не ОбщегоНазначения.РазделениеВыключено()`. Проверка делегируется через
`СтандартныеПодсистемыПовтИсп` и `РаботаВМоделиСервиса` в
`РаботаВМоделиСервисаПовтИсп.РазделениеВключено()`. Там после проверки
метаданных читается функциональная опция `РаботаВМоделиСервиса`.

## Физическая и логическая привязка

Read-only SDK-диагностика установила:

- Independent: `ОбластьДанныхОсновныеДанные`, GUID
  `6df2bb92-558c-4453-9de4-e4176e8f93dc`, столбец `_Fld731`, AutoUse Use.
- IndependentAndShared: `ОбластьДанныхВспомогательныеДанные`, GUID
  `530a3164-4ef1-4b3b-8269-13764ef4bf15`, столбец `_Fld1269`, AutoUse DontUse.
- Константа: GUID `ddb5654b-0dba-4966-984a-320b6542c809`, таблица
  `_Const2106`, столбцы `_fld2107`, `_fld731`, `_recordkey`.

Поэтому отказ нельзя исправлять исключением этой константы из разделителя:
Independent действительно применим к её таблице. Первоначальная гипотеза
об обратном возникла из-за перепутанных GUID и опровергнута этой диагностикой.
Лог: `target/diagnostics/separation-web-constant-diagnostics-run.log`.

В сохранённом ресурсе Config `6df2bb92-558c-4453-9de4-e4176e8f93dc.deflate`
после ссылок на параметр значения и параметр использования есть третья ссылка:
`cc906f05-5ea6-43cb-a084-c4ee51ca4bd5`. Приобретённый каталог сопоставляет её
константе `ИспользоватьРазделениеПоОбластямДанных`, таблица `_Const1835`.
Это наблюдение об артефакте, а не самостоятельная реализация декодера.
SDK 0.9.13 передаёт только первые две ссылки в `DataSeparationSettings`;
условие не доходит до компилятора запроса.

## Справка и нативный контроль

Полностью прочитана страница Синтакс-помощника 8.3.27.2342:
`platform-syntax-help:syntax-context:objects/catalog63/catalog272/catalog1506/object1954/properties/ConditionalSeparation9012.html`.
Источник — vendor, язык ru. Она определяет `ОбщийРеквизит.УсловноеРазделение`
как ссылку на булеву константу, которая не входит в этот общий реквизит
и задаёт использование разделителя в сеансе.

Собственный нативный контроль:
`tests/conformance/measure/1c/measure-common-attribute-conditional-separation.bsl`.
XML: `common-attribute-conditional-separation.xml`, булева константа из
существующего `functional-option-constant.xml`. Исходные demo/buh/unf
не изменяются; каждая попытка выполняется в новой файловой базе `/tmp`.

Первая попытка доказала: при false условии и false use запрос разрешён;
после записи true условия в том же сеансе запрос запрещён; true use
разрешает его, возврат к false use вновь запрещает. Метаданные указывают
именно контрольную константу. Значение условия нельзя фиксировать навсегда
на первом чтении, игнорируя запись той же константы в этом сеансе.

Вторая попытка дополнительно обнаружила, что при начальном false условии
объект не предоставляет свойство разделителя по имени. Это не помешало
исследованию запроса; для следующей попытки строка разделителя не присваивается
через свойство объекта, значение задаётся параметром сеанса.
Финальный строковый контроль, метка `common-attribute-conditional-separation-5`,
создал три строки: empty в пустой области, A и B в соответствующих областях.
При true условии/B получено `B;`; при false условии/C получено `empty;`.
Количество при false условии остаётся 1 и с false use. Следовательно,
выключенное условие выбирает пустую область, а не все области и не последнее
активное значение параметра.

Числовой контроль `measure-common-attribute-conditional-separation-number.bsl`
и соседний `.platform.txt`, метка `common-attribute-conditional-separation-number-1`,
подтвердил то же поведение для пустого 0 и областей 1/2/3. Обе финальные
попытки завершились кодом 0, по 21 строке, без `conditional.control_error`.
Переключение постоянного условия в том же сеансе действует на последующий
запрос; это не основание заявлять измеренным поведение изменения из другого
сеанса или Shared-режима с условием.

Запрос на SDK подготовлен в
`docs/plans/open-sdbl-conditional-separation-request.md`. До его реализации
нет исправления в компиляторе запросов open-bsl и нет успешного старта demo.

## Shared: отдельный строковый контроль

`measure-common-attribute-conditional-separation-shared.bsl` и соседний
`.platform.txt`, метка `common-attribute-conditional-separation-shared-1`,
получены в новой файловой базе `/tmp/open-bsl-conditional-separation-shared-1009-v2-ib`.
XML отличается режимом `IndependentlyAndSimultaneously`; глобальное условие —
та же булева константа. Финальный процесс завершился кодом 0, удержано
20 строк, есть обе метки, `conditional.control_error` отсутствует.

При true условии/B получено `B;`. При false условии/C получено `empty;`,
count=1 также при false use. После возврата true условия при false use
запрос успешен и возвращает `A;B;empty;`, count=3. Таким образом, измеренный
String Shared при выключенном условии выбирает пустую область, а при включённом
условии и выключенном use допускает все три области. Последнее отличается
от измеренного отказа Independent, не является переносом вывода между режимами.
Числовой Shared и другие типы этим контролем не измерены.

Первый запуск в песочнице не создал базу из-за IPC lock process 0 и завершился
кодом 1. Повтор вне песочницы прошёл на другом новом пути. В журнале повторного
запуска есть предупреждение `"НаименованиеЯзык1" is a required field`;
оно не стало исключением тела контроля: все три записи подтверждены итоговым
запросом, обе метки и все 20 ожидаемых строк получены. Причина предупреждения
не установлена и не используется как доказательство семантики заполнения.

## Shared: отдельный числовой контроль

`measure-common-attribute-conditional-separation-number-shared.bsl` и его
`.platform.txt` сняты в новой файловой базе
`/tmp/open-bsl-conditional-separation-number-shared-1009-v1-ib`. Метка
`common-attribute-conditional-separation-number-shared-1`, 20 строк, обе метки,
нет control_error, процесс завершился кодом 0.

При true условии/2 возвращается `B;`, count=1. При false условии/3
возвращается `empty;`, count=1, включая false use. После возврата true
условия при false use возвращается `A;B;empty;`, count=3. Тем самым Numeric
Shared измерен отдельно; ограничение предыдущего строкового контроля
остаётся верным для него самого, но этот числовой контроль дополняет корпус.
Дополнительных типов и иных контекстов исполнения он не доказывает.
