# Динамический признак зависит от истории сеанса

Контроль на собственной PostgreSQL-базе и платформе 8.3.27.2342 завершён.
Исходные demo/buh/unf не изменялись. Динамическое обновление выполнено
нативным `ibcmd config apply --dynamic=force --session-terminate=disable`;
операция завершилась с кодом 0.

Один клиент A PID 1881901, сеанс 24, сохранялся живым:

| Фаза | Ревизия исполняемого модуля | Русский/английский признак |
| --- | --- | --- |
| До обновления | 1 | No / No |
| После обновления | 1 | Yes / Yes |
| Повтор после обновления | 1 | Yes / Yes |

Новый клиент B, сеанс 30, исполнял ревизию 2 и получил No / No;
завершился с кодом 0. После B тот же A снова получил Yes / Yes.
Тип результата во всех случаях — Boolean. Root независимо прочитал
результаты и подтвердил живой PID A. Артефакты сохранены в
`fixtures/dynamic-configuration-session-history/`; агент дополнительно
собирает полную квитанцию нативных команд и снимков базы.

Следствие: значение нельзя восстановить как один общий признак текущей
конфигурации базы. Одновременно существующие сеансы одной базы имеют
разные значения после одного обновления. SDK не должен придумывать
состояние платформенного сеанса по fingerprint или наличию ConfigSave.

Для CLI остаётся отдельное решение о контракте собственного нового
сеанса с фиксированным снимком кода. Оно должно быть явно описано и
проверено до подключения значения к `SessionResources`; библиотечное
отсутствие ресурса пока сохраняет явную ошибку.
