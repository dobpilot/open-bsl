# Копия буфера образа worker при запуске demo

После измеренных исправлений `СтрНайти` и `СтрЗаменить` оригинальный
demo достиг создания менеджера фоновых заданий. Выполнение отказало
при выделении 4 622 258 960 байт под прежним лимитом адресного пространства
12 ГиБ. Пик RSS повтора — 6 852 548 КиБ.
Лог: `/tmp/open-bsl-demo-session-replace-1013-startup.log`.

Повтор под gdb с выключенной печатью аргументов кадров поймал SIGABRT:
`runtime_for_engine` → `Engine::job_runtime` →
`EngineJobService::is_ready` → `construct_manager`.
Лог: `/tmp/open-bsl-demo-session-memstack-1013-startup.log`.
Нулевой код gdb означает завершение диагностического инструмента,
а не успех инициализации: inferior завершился сигналом SIGABRT.
Core dump не создавался, исходная база оставалась read-only.

Исходник установленной стандартной библиотеки подтверждает:
`From<String> for Arc<str>` копирует буфер через `Arc::from(&v[..])`.
Приватное поле WorkerRecipe заменено на `Arc<String>`; конструктор
использует `Arc::new(text)`. Готовый буфер переносится, текстовый
формат, парсер, содержимое и публичные API не меняются.
Это внутренний рефакторинг без нового OpenSpec-контракта.

Существующие тесты публичных путей и жизненного цикла фоновых заданий
прошли. Workspace Clippy, rustdoc и fmt прошли. Оригинальный повтор
`/tmp/open-bsl-demo-session-imgmove-1013-startup.log` дополнительно
записывает размер текста и равенство указателя буфера до/после переноса.
Полный прогон: `/tmp/open-bsl-worker-image-move-workspace-tests-1013.log`.
До окончания повторов отсутствие последующих ошибок не утверждается.

Повтор подтвердил: образ содержит 4 622 258 942 байта, ёмкость
готового String — 5 576 327 168 байт, `buffer_moved=true`.
Старое место отказа пройдено. Следующее выделение 128 МиБ отказало
в reader образа; gdb зафиксировал worker-потоки в
`reader_after_header` → `parse_image` → `build_worker_engine`.
Лог: `/tmp/open-bsl-demo-session-readmem-1013-startup.log`.

Внутренний reader заменён на заимствованные строки и одну строку
вперёд. Предварительный проход считает точное количество значимых
строк без хранения текста; защиты счётчиков и номера ошибок сохранены.
Формат 44 и публичный API не меняются, новый OpenSpec не требуется.
Существующие bytecode-тесты, compiler round trip и разделение имён
прошли без изменения ожиданий. Workspace fmt, Clippy и rustdoc прошли.
Полный прогон `/tmp/open-bsl-streaming-reader-workspace-tests-1013.log`
завершился успешно.

Оригинальный demo с reader прошёл прежний отказ и выполнил дополнительные
запросы. Следующий отказ — отсутствует `СписокЗначений.СортироватьПоПредставлению`.
Лог: `/tmp/open-bsl-demo-session-stream-1013-startup.log`.
Пик RSS — 11 548 764 КиБ. Полный текстовый образ всё ещё велик;
исправление не является доказательством малой памяти во всех конфигурациях.
