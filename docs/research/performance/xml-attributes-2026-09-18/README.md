# XML: резервирование значений атрибутов

Продолжение [оптимизации текстовых участков](../xml-text-2026-09-18/README.md).
База — рабочее дерево после той правки, не `main`. Сохранённые release-
бинарники: `/tmp/open-bsl-xml-attributes-before` и
`/tmp/open-bsl-xml-attributes-after`. Эти временные файлы не являются
постоянными артефактами. Счётчики и результаты A/B сохранены рядом.

## Изменение

Значения атрибутов собирались через посимвольный `String::push`, который
повторно увеличивал ёмкость. Теперь обычный участок до кавычки или `&`
сканируется с подсчётом длины UTF-8, резервируется и дописывается целиком.
Общий код с текстовыми узлами вынесен в закрытый `append_plain_run`;
для текста разделитель — `<`, для атрибута — его открывающая кавычка.
Обработка сущностей, ошибки и наблюдаемое поведение не изменены.
Новый OpenSpec change не требуется: это внутренний рефакторинг без
изменения API и архитектурных границ. Аллокатор и владение BSL-объектами
остаются прежними.

Новый тест проверяет обе кавычки, ASCII, кириллицу, трёх- и четырёхбайтовые
символы, смешение с `&amp;` и ошибку незакрытого значения. Он прошёл на
реализации до правки и после неё. Полный набор bsl-xml: 178 тестов прошли.

## Аллокации

Счётчики получены через пример `alloc-profile`; подготовка отделена от
основного цикла. Измерительный аллокатор не использовался для замера скорости.

| Основной цикл xml_parse | До | После |
|---|---:|---:|
| Запросы памяти | 5 847 067 | 5 640 064 |
| Realloc | 207 019 | 16 |
| Суммарно запрошено байт | 546 594 760 | 543 126 400 |
| Пик живых запрошенных байт | 77 074 836 | 77 074 836 |

Удалено 207 003 realloc, то есть более 99,99% оставшихся перевыделений.
Это не устранение аллокаций вообще: остаётся около 5,64 млн запросов
памяти. Пик памяти не уменьшился. Подготовка и счётчики json_write/xml_write
не изменились. Контрольный вывод совпал.

## A/B

Обычная release-сборка без переопределения `RUSTFLAGS` и без `--optimize`.
Пять пар на сценарий, порядок before/after меняется через пару.
Команда запуска: `perf stat -x ';' -e instructions:u,cycles:u -- <binary>
benchmarks/<scenario>.bsl`. Счётчики относятся ко всему процессу, время —
к штатному таймеру benchmark, без подготовки. В каждой паре проверен вывод
без последней строки времени. Все 30 запусков записаны в `ab.csv`.
Изменение каждой пары: `(after / before - 1) * 100`; таблица даёт среднее
и диапазон этих изменений.

| Сценарий | Инструкции, среднее (диапазон), % | Такты, среднее (диапазон), % | Внутреннее время, среднее (диапазон), % |
|---|---:|---:|---:|
| json_write | −0,001 (−0,001…0,000) | −1,32 (−2,04…−0,59) | −1,40 (−2,33…−0,39) |
| xml_parse | −0,22 (−0,22…−0,21) | −1,91 (−3,70…−0,96) | −1,68 (−3,80…−0,78) |
| xml_write | +0,007 (−0,018…+0,036) | −3,68 (−5,38…−2,55) | −3,41 (−4,61…−2,61) |

Контрольные writers не выполняют изменённый код, но их время тоже
изменилось. Поэтому весь выигрыш времени xml_parse нельзя приписывать
удалению realloc: шум и размещение кода не исключены. Устойчиво измерены
сокращение аллокаций и числа инструкций. Результат ограничен этим benchmark;
плотные ссылки на сущности и короткие одиночные значения отдельно не
профилировались.
