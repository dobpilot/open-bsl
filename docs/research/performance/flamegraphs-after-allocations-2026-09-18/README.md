# A/B flamegraph: текущее дерево и main после оптимизаций аллокаций

Замер от 18 сентября 2026 года. `main` — локальный коммит
`22fa7c07a48b018e030252fac22bc374d22a8618`. Текущая сторона — снимок
рабочего дерева ветки `bsl-rt-v4.3` над
`1335406cba2d957999fd4a254b819da976ce66f4`, **включая незакоммиченные
изменения**, в том числе прямой UTF-16-вход XML-парсера. Это сравнение
всего дерева с main, а не изолированная цена последней правки.

## A/B-счётчики

Пять чередующихся пар на сценарий, без `--optimize`. Дельта каждой пары:
`current / main - 1`; показаны среднее и полный диапазон. Такты и
инструкции относятся ко всему CLI-процессу. Время — штатный таймер BSL
benchmark; у xml_parse он исключает подготовку документа.

| Сценарий | Инструкции, % | Такты, % | Внутреннее время, % | Медиана времени main → current, мс |
|---|---:|---:|---:|---:|
| json_write | +2,58 (+2,58…+2,59) | +4,65 (+1,22…+8,11) | +4,05 (+1,57…+8,40) | 252 → 261 |
| xml_parse | −7,58 (−7,59…−7,58) | −7,81 (−8,57…−6,92) | −8,77 (−9,82…−7,80) | 897 → 818 |
| xml_write | −17,46 (−17,51…−17,40) | −18,92 (−19,58…−17,81) | −17,84 (−18,59…−16,91) | 352 → 289 |

Исходные пары — [ab.csv](ab.csv). Контрольный вывод main/current совпал
во всех A/B-запусках и во всех запусках под профилировщиком. Во всех
трёх сценариях диапазоны этого замера не пересекают ноль. Машина рабочая,
частота CPU и нагрузка не фиксировались; это не гарантия тех же процентов
на другой машине или в другое время.

## Что показывают стеки

Доли ниже взвешены периодами cycles:u; inclusive учитывает стек целиком,
leaf — только верхний исполняемый кадр. Исходные доли —
[profile-summary.csv](profile-summary.csv).

| Сценарий | step_cold inclusive, main → current | step leaf, main → current |
|---|---:|---:|
| json_write | 60,85% → 59,12% | 10,45% → 13,19% |
| xml_parse | 44,08% → 36,74% | 11,67% → 16,60% |
| xml_write | 67,26% → 60,07% | 8,57% → 11,42% |

- XML-чтение и запись быстрее main в этом A/B; доля путей под step_cold
  сократилась. В текущем чтении видны новые пути `from_utf16`,
  `read_name_range`, `append_plain_run`; их появление само по себе не
  означает регрессии — это результат изменения реализации.
- JSON-запись остаётся регрессией: +2,58% инструкций и +4,05% времени.
  Рост доли step указывает направление дальнейшего исследования, но
  не устанавливает причину. Профиль не изолирует отдельную правку VM.
- Рост относительной доли step в XML нельзя выдавать за доказательство
  замедления самого диспетчера: после сокращения другой работы доля
  оставшейся закономерно может вырасти. Инлайнинг также влияет на
  распределение сэмплов между именами кадров.

## Методика и качество

Обе стороны собраны отдельно из снимков исходников. Сценарии
json_write/xml_parse/xml_write между снимками побайтно одинаковы; на обеих
сторонах исполнялась одна и та же копия из текущего снимка.

```sh
env -u CARGO_ENCODED_RUSTFLAGS CCACHE_DISABLE=1 \
  RUSTFLAGS='-C force-frame-pointers=yes -C llvm-args=-align-all-functions=5' \
  cargo build --offline --locked --profile profiling -p bsl-cli
```

Сборки завершены до измерений. Профиль profiling наследует release и
сохраняет debug-информацию. В отличие от некоторых прежних замеров,
выравнивание на 32 байта здесь явно сохранено вместе с frame pointers;
числа из старых отчётов напрямую с этой серией не смешиваются.

Каждый flamegraph объединяет восемь последовательных запусков:

```sh
perf record -F 997 -e cycles:u --call-graph fp -o profile.data -- \
  bash -c 'for i in {1..8}; do "$1" "$2" || exit; done' profile BIN SCRIPT
perf script -i profile.data
```

Профили охватывают весь процесс, включая подготовку xml_parse, компиляцию
и завершение. Для A/B отдельно используется `perf stat -x ';' -e
instructions:u,cycles:u -- BIN SCRIPT`. SVG и нормализованные diff
построены через уже используемую в workspace библиотеку inferno 0.11.21.

| Сценарий | Сэмплы main | Сэмплы current |
|---|---:|---:|
| json_write | 2 242 | 2 353 |
| xml_parse | 8 383 | 7 717 |
| xml_write | 3 048 | 2 601 |

Потерянных сэмплов: **0** во всех шести профилях. Неопознанные leaf-кадры
занимают 2,05–6,34% веса; раскрытие стеков через системные библиотеки
не идеально. Доля процессов кроме bsl-cli меньше 0,02%. Все SVG проверены
на корректный XML и наличие кадров. Из-за конечного числа сэмплов
мелкие различия flamegraph не следует считать точными измерениями.

Машина: AMD Ryzen 9 5900X, Linux 7.1.10-100.fc43.x86_64. В начале записи
load average составлял 8,42 / 7,64 / 5,84. Версия компилятора —
[rustc.txt](rustc.txt). Хэши бинарников — [binaries.sha256](binaries.sha256),
исходников текущего снимка — [current-source.sha256](current-source.sha256),
состояние рабочего дерева — [worktree-status.txt](worktree-status.txt).

Сырые perf.data, снимки исходников, сборки и вспомогательный renderer
оставлены в `target/flamegraphs/after-allocations-2026-09-18/`.
В этом каталоге отчёта сохранены SVG, folded-стеки, perf report,
логи записи и контрольный вывод. Продуктовый код в ходе этого замера
не изменялся; проверки — сборка обеих сторон, совпадение результатов
benchmark и валидация профилей, не новый прогон workspace-тестов.
