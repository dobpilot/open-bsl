# Сериализация чисел без отдельной строки результата

`BslNumber::append_canonical` дописывает число в существующий `String`.
`to_canonical` и новый метод используют один алгоритм, при этом прежнее
точное резервирование `to_canonical` сохранено. В `vstr` числовая лексема
пишется непосредственно в буфер Writer. Ветка очень малых дробей сохраняет
старую вспомогательную строку префикса; обещания полного отсутствия
аллокаций для любого числа нет. BigInt тоже может выделять рабочую память.

## Аллокации

Полный масштаб table_save_load, пример `alloc-profile`, отдельно от
временных измерений. Подготовка и проверки не входят в строки фаз ниже.
Измерительные копии — `target/table-allocation-study/`, выходные файлы
перенаправлены из `/tmp` в этот каталог.

| Фаза / показатель | До | После |
|---|---:|---:|

| Сохранение: realloc | 28 | 28 |
| Сохранение: суммарно запрошено байт | 806 253 461 | 801 978 473 |
| Сохранение: пик живых байтов | 830 406 653 | 830 406 653 |

Пики включают исходную таблицу и не являются RSS. Устранены 1 129 128
временных строк чисел, суммарно 4 274 988 байт. Крупные буферы прежние,
поэтому пик памяти не уменьшился. Подготовительные счётчики совпали.
Результат повторной сериализации загруженного значения — «тождественно».
Логи: `before-save.log`, `alloc-save.log`, `before-save-load.log`, `alloc.log`.

## Методика A/B

База — release после разделения пустой строки:
`target/table-empty-string-after/bsl-cli`. Кандидат —
`target/table-number-write-after/bsl-cli`. Это сравнение текущей ветки
до/после одной правки, не с main. Штатные release-флаги и выравнивание
из `.cargo/config.toml`. По три чередующиеся пары на сценарий и режим:
table_compare, table_compare2, table_save_load, plain/optimize.

`ab.py` проверяет код завершения, счётчик perf, контрольный stdout
и SHA-256 выходного файла. Сценарии не уменьшены; в копиях для измерения
изменён только путь выходного файла. Таймер — основная фаза BSL,
инструкции — весь процесс, включая подготовку и проверку.
Сборки и тесты агента во время A/B не выполняются. Внешняя нагрузка
не закреплена. Диапазоны пар не являются доверительными интервалами.

## Результаты A/B

36 успешных запусков, контрольный вывод совпал между сторонами и режимами,
SHA-256 всех сохранённых таблиц одинаков. [ab.csv](ab.csv) содержит сырые
счётчики, [ab.log](ab.log) — дельты, [binaries.sha256](binaries.sha256) —
идентификаторы бинарников. Дельты — среднее попарное после/до − 1.

| Сценарий | Режим | Время, % | Диапазон пар, % | Инструкции, % |
|---|---|---:|---:|---:|
| table_compare | plain | +1,49 | +0,26…+2,23 | +0,050 |
| table_compare | optimize | +1,56 | +0,36…+2,64 | +0,014 |
| table_compare2 | plain | −0,00 | −1,03…+1,78 | +0,090 |
| table_compare2 | optimize | +0,17 | −1,03…+0,89 | +0,077 |
| table_save_load | plain | −0,30 | −1,05…+0,52 | −2,059 |
| table_save_load | optimize | −0,54 | −1,25…+0,07 | −2,097 |

Отдельные таймеры из сырых stdout table_save_load:

| Фаза | plain, % (диапазон) | optimize, % (диапазон) |
|---|---:|---:|
| Сохранение | +0,77 (−2,49…+3,02) | −1,80 (−1,87…−1,67) |
| Загрузка | −0,82 (−2,49…+0,83) | +0,16 (−0,92…+1,17) |
| Проверка повторной сериализацией | −2,67 (−4,76…−0,92) | −1,93 (−2,66…−0,92) |

Сокращение числа запросов и инструкций подтверждено. Уверенное ускорение
суммарной фазы сохранения/загрузки не установлено: диапазон пересекает
ноль в обоих режимах. Инструкции включают повторную сериализацию при
проверке, которая также использует новый путь. Наблюдаемое замедление
table_compare около 1,5% сохраняется во всех трёх парах каждого режима;
причина не установлена, отсутствие побочной регрессии не заявляется.

Правка оставлена как устранение промежуточных строк при неизменном формате.
Она не заменяет следующего исследования крупных буферов сериализации.
