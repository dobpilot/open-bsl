# XML: точное резервирование исходного буфера

Продолжение [преобразования ключа атрибута](../xml-attribute-key-2026-09-18/README.md).
База — рабочее дерево после той правки, не `main`. До изменения сохранён
release-бинарник `/tmp/open-bsl-xml-source-before`, после —
`/tmp/open-bsl-xml-source-after`. Бинарники временные, результаты измерений
сохранены рядом.

## Выбор изменения

Сначала проверено разделение пустого `Rc<Vec<XmlAttr>>` между элементами.
Оно не реализовано: `core::XmlEvent.attrs` публичен, и дополнительный
владелец меняет доступность `Rc::get_mut`/`try_unwrap`. Такое изменение
требует отдельного решения о публичном контракте владения, а не молчаливого
введения под видом внутренней оптимизации.

Выбрано резервирование закрытого буфера `XmlParser::src`. Раньше
`text.chars().collect()` использовал нижнюю оценку размера итератора,
затем доращивал большой Vec<char>. Теперь `chars().count()` определяет
точное количество символов; `with_capacity` и `extend` заполняют один
буфер без его роста. Это дополнительный проход по входу.

Представление, API, владение выдаваемыми событиями и поведение парсера не
меняются. Внутренний рефакторинг не требует нового OpenSpec change.
Новый тест сохранности исходных символов прошёл до и после правки:
ASCII, кириллица, трёх- и четырёхбайтовые символы, пустая строка, NUL и
перевод строки. Все 182 теста bsl-xml прошли.

## Аллокации основного цикла xml_parse

Измеритель — пример alloc-profile, отдельно от замеров скорости.

| Метрика | До | После |
|---|---:|---:|
| Запросы памяти | 5 010 061 | 5 010 055 |
| Realloc | 16 | 10 |
| Суммарно запрошено байт | 534 966 334 | 386 444 722 |
| Живые запрошенные байты в конце | 22 129 226 | 22 129 226 |
| Пик живых запрошенных байт | 77 074 836 | 60 534 728 |

Всего шесть устранённых realloc, но это крупные буферы: суммарно
запрошено на 148 521 612 байт меньше, пик уменьшился на 16 540 108 байт
(около 21,46%). Это запрошенные у аллокатора байты, **не RSS** процесса.
Завершённый цикл удерживает столько же памяти, сколько до правки.
Подготовка и счётчики json_write/xml_write не изменились. Контрольный
вывод до/после совпал.

## Чередующийся A/B

Пять пар на каждый сценарий, порядок before/after чередуется. Обычная
release-сборка без переопределения RUSTFLAGS, без `--optimize` и без
измерительного аллокатора. Запуск: `perf stat -x ';' -e
instructions:u,cycles:u -- <binary> benchmarks/<scenario>.bsl`.
Счётчики — весь процесс, время — штатный таймер основного цикла. Вывод
без строки времени сверялся во всех запусках. Все 30 результатов —
в ab.csv; процент вычислен попарно как `(after / before - 1) * 100`.

| Сценарий | Инструкции, среднее (диапазон), % | Такты, среднее (диапазон), % | Внутреннее время, среднее (диапазон), % |
|---|---:|---:|---:|
| json_write | −0,000 (−0,003…+0,001) | +0,82 (−0,65…+1,89) | +1,16 (0,00…+2,31) |
| xml_parse | +0,57 (+0,51…+0,58) | −2,66 (−6,33…+2,36) | −4,48 (−8,63…+1,09) |
| xml_write | −0,000 (−0,037…+0,036) | +0,17 (−5,30…+6,77) | +0,34 (−5,23…+6,25) |

Результат принят как сокращение пика памяти ценой небольшого роста
числа инструкций. Устойчивое ускорение по времени не доказано: диапазон
xml_parse пересекает ноль. Writers не исполняют изменённый код; изменение
их времени не приписывается этой правке. Документы другого размера и
другого соотношения ASCII/Unicode отдельно не профилировались.
