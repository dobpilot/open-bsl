# XML: резервирование текстовых участков

Продолжение [резервирования имён](../xml-name-2026-09-18/README.md).
База — рабочее дерево после той правки, не `main`. До изменения сохранён
release-бинарник `/tmp/open-bsl-xml-text-before`, после —
`/tmp/open-bsl-xml-text-after`. В обоих случаях обычная release-сборка,
без переопределения `RUSTFLAGS`. Временные бинарники не являются постоянными
артефактами; исходные счётчики и результаты сохранены рядом с отчётом.

## Изменение

`XmlParser::read_text_run` сканирует обычный участок до `<` или `&`,
подсчитывая длину UTF-8. Затем резервирует место и дописывает участок
целиком вместо повторного роста `String` при посимвольном `push`.
Обработка сущностей, CDATA, пробельных узлов и ошибок не изменена.
Добавлен тест смешанного текста с ASCII, кириллицей, трёх- и
четырёхбайтовыми символами, сущностью, CDATA и вложенным элементом.
Он прошёл как до, так и после изменения реализации.

Это внутренний рефакторинг без изменения API, архитектурных границ и
наблюдаемой семантики; новый OpenSpec change не требуется. Аллокатор
остаётся прежним, arena и CoW не вводятся.

benchmarks/xml_parse.bsl`. Подготовка отделена от основного цикла; полные
значения — в `*.before.csv` и `*.after.csv`. Измерительный аллокатор
используется только для счётчиков, не для замера скорости.

## Чередующийся A/B

Пять пар на каждый сценарий, порядок before/after меняется через пару.
Каждый запуск: `perf stat -x ';' -e instructions:u,cycles:u -- <binary>
benchmarks/<scenario>.bsl`. Оптимизации компилятора (`--optimize`) не
включены. Инструкции и такты — весь процесс; последняя строка вывода —
штатный внутренний таймер benchmark. Остальной вывод сравнивается во всех
запусках. `ab.csv` содержит все 30 результатов; проценты считаются по
каждой паре как `(after / before - 1) * 100`, затем усредняются.

| Сценарий | Инструкции, среднее (диапазон), % | Такты, среднее (диапазон), % | Внутреннее время, среднее (диапазон), % |
|---|---:|---:|---:|
| json_write | −0,000 (−0,002…+0,002) | −1,34 (−2,29…−0,80) | −1,59 (−2,27…0,00) |
| xml_parse | −0,83 (−0,83…−0,82) | −3,42 (−5,09…−2,52) | −3,82 (−5,74…−2,37) |
| xml_write | +0,014 (−0,020…+0,056) | −1,75 (−3,41…+0,49) | −1,95 (−3,34…−0,34) |

Writers не выполняют изменённый код: изменения их времени не считаются
выигрышем от этой правки. На рабочей машине шум времени и влияние
размещения кода не исключены; уменьшение числа инструкций xml_parse
устойчиво во всех парах. Вывод ограничен этим сценарием: строки из
одиночных символов и плотных ссылок на сущности отдельно не профилировались.
