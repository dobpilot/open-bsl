# Разделяемая пустая строка по умолчанию в таблицах

## Область правки

Только `table::default_of(TypeId::String)`: значение пустой строки
удерживается в thread-local и клонируется через существующий `Rc`.
Момент приведения типов и начальные `Неопределено` в новых строках
таблицы не меняются. Остальные конструкторы строк, сериализация, VM и
allocator не изменены. Кэш удерживает одно строковое значение на поток,
а не растёт с количеством таблиц или ячеек. Дописывание в полученную
строку отделяет её существующим механизмом `BslString::append`.

Классификация OpenSpec: внутренний рефакторинг без изменения публичного
API и поведения, в рамках `rust-module-boundaries`. Новых решений о
семантике 1С не принято, существующие маркеры не изменены.

## Аллокации

Существующий пример `alloc-profile`, полный масштаб, фаза сравнения
отделена от генерации. Измерительные BSL-копии лежат в
`target/table-allocation-study/`: добавлены маркеры начала/конца,
выходной файл перенаправлен в этот каталог. До — профиль из предыдущего
исследования, после — `alloc.log` в этом каталоге.

| table_compare, сравнение | До | После |
|---|---:|---:|
| Запросы памяти, включая realloc | 18 401 278 | 3 101 279 |
| Realloc | 177 | 177 |
| Суммарно запрошено байт | 5 109 075 605 | 3 640 275 701 |
| Пик живых запрошенных байтов | 4 453 555 759 | 2 984 755 855 |

Удалено 15 299 999 выделений: вместо 15,3 млн отдельных пустых строк
создаётся одна. Суммарный объём и пик уменьшились на 1 468 799 904 байта.
Пик включает исходные таблицы и не является RSS. В подготовительной
фазе счётчики не изменились. Инструментированное время не используется
для заявления об ускорении.

У `table_compare2` и `table_save_load` все счётчики фаз совпали с базой.
Сохранены `before-compare.log`, `before-compare2.log`,
`before-save-load.log`, `alloc-compare2.log` и `alloc-save-load.log`.

## Методика A/B

База — сохранённый release-бинарник после удаления внутреннего Rc буфера
`target/bmp-buffer-window-after/bsl-cli`, не main. Кандидат —
`target/table-empty-string-after/bsl-cli`. Сборка использует штатное
выравнивание `.cargo/config.toml`. По три чередующиеся пары для каждого
из трёх сценариев в plain/optimize: всего 36 запусков.

`ab.py` проверяет код завершения, счётчик perf и контрольный вывод между
всеми запусками сценария. Из вывода убираются только таймеры. Для
table_save_load дополнительно сравнивается SHA-256 сохранённого файла.
Время — последний таймер benchmark, инструкции — весь процесс, включая
генерацию и проверку; это разные области измерения. Диапазон попарных
дельт не является доверительным интервалом. Нагрузка машины не закреплена.

Исходные сценарии не изменены; копии для A/B лежат в
`target/table-empty-string-after/`, единственное отличие — путь выходного
файла. Посторонние файлы в `/tmp` не затрагиваются.

## Результаты A/B

Все 36 запусков прошли. Контрольный вывод между сторонами и режимами
совпал; файлы table_save_load совпали по SHA-256. Сырые числа —
[ab.csv](ab.csv), дельты — [ab.log](ab.log), бинарники —
[binaries.sha256](binaries.sha256). Минус означает уменьшение стоимости.

| Сценарий | Режим | Время, среднее % | Диапазон пар, % | Инструкции, среднее % |
|---|---|---:|---:|---:|
| table_compare | plain | −31,39 | −31,45…−31,30 | −13,265 |
| table_compare | optimize | −30,91 | −32,18…−29,47 | −13,385 |
| table_compare2 | plain | +3,09 | +0,88…+6,09 | +0,008 |
| table_compare2 | optimize | −2,72 | −4,12…−1,89 | +0,014 |
| table_save_load | plain | +2,21 | +0,15…+4,89 | −0,001 |
| table_save_load | optimize | −0,85 | −1,09…−0,44 | +0,008 |

Во время A/B тесты и сборки этого агента не выполнялись. Пример состояния
машины в ходе прогона: load average 6,61 / 8,52 / 6,92. Время малых
изменений остальных сценариев нельзя приписать определённой причине:
в plain есть наблюдаемое замедление на 2–3%, в optimize — снижение,
а аллокации не изменились и инструкции почти неизменны. Эти результаты
не скрываются и не объявляются отсутствием регрессий. Выигрыш
table_compare подтверждается временем всех пар, инструкциями и памятью.

Правка оставлена. Следующий независимый кандидат — устранение временной
строки при канонической сериализации числа; в этой серии он не реализован.
