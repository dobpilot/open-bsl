# XML: имя закрывающего тега без второй строки

Продолжение [резервирования атрибутов](../xml-attributes-2026-09-18/README.md).
База — рабочее дерево после той правки, не `main`. До изменения сохранён
release-бинарник `/tmp/open-bsl-xml-end-name-before`, после —
`/tmp/open-bsl-xml-end-name-after`. Временные бинарники не являются
постоянными артефактами; исходные счётчики и A/B сохранены рядом.

## Изменение и проверки поведения

Раньше закрывающий тег создавал новую String, сравнивал её с именем
открытого элемента и освобождал строку из стека. Теперь границы имени
сканируются общим `read_name_range`, символы сравниваются напрямую с
сохранённым именем, а в событие конца перемещается строка из стека.
При ошибке строка для диагностики по-прежнему собирается из входа.
Порядок проверки `>`, извлечения элемента из стека и сравнения сохранён.

Новый тест прошёл до изменения и после него: ASCII, кириллица,
трёх- и четырёхбайтовые символы, пробелы перед `>`, пустое имя,
незакрытый тег, отсутствие открывающего, несовпадающие имена и обе
стороны совпадения по префиксу. Сообщения об ошибках проверяются точно.
Все 179 тестов bsl-xml прошли.

Внутренний рефакторинг не меняет API, наблюдаемое поведение и
архитектурные границы; новый OpenSpec change не требуется. CoW и arena
не вводятся, используется прежнее владение String.

## A/B

Обычная release-сборка без переопределения RUSTFLAGS и без `--optimize`.
Пять пар на сценарий, порядок before/after чередуется. Запуск:
`perf stat -x ';' -e instructions:u,cycles:u -- <binary>
benchmarks/<scenario>.bsl`. Счётчики — весь процесс, время — штатный
внутренний таймер benchmark. Остальной вывод сверяется во всех запусках.
Все 30 результатов в `ab.csv`. Процент считается для каждой пары как
`(after / before - 1) * 100`, затем приводятся среднее и диапазон.

| Сценарий | Инструкции, среднее (диапазон), % | Такты, среднее (диапазон), % | Внутреннее время, среднее (диапазон), % |
|---|---:|---:|---:|
| json_write | −0,001 (−0,003…−0,000) | +0,12 (−1,78…+1,46) | −0,44 (−2,95…+1,52) |
| xml_parse | −0,85 (−0,86…−0,85) | −2,64 (−4,75…+0,49) | −2,89 (−5,07…+1,22) |
| xml_write | −0,001 (−0,036…+0,016) | −0,66 (−2,36…+0,55) | −0,38 (−3,63…+2,08) |

Снижение инструкций устойчиво во всех парах xml_parse. Диапазоны тактов
и времени пересекают ноль, поэтому среднее не доказывает устойчивого
ускорения по времени. Writers не исполняют изменённый код и не считаются
ускоренными этой правкой. Длинные имена и преимущественно ASCII-документы
отдельно не профилировались.
