# XML: преобразование ключа поиска атрибута

Продолжение [оптимизации свойств имени](../xml-properties-2026-09-18/README.md).
База — рабочее дерево после той правки, не `main`. Исходный release-
бинарник сохранён как `/tmp/open-bsl-xml-attribute-key-before`, итоговый —
`/tmp/open-bsl-xml-attribute-key-after`. Бинарники временные, результаты
измерений сохранены рядом.

## Два варианта

`ЗначениеАтрибута(Имя)` каждый раз преобразовывал ключ через Display,
создавая промежуточную String и копируя её в итоговую String.

1. Проверен существующий кэш `BslString::shared_utf8`. Он убрал 59 998
   аллокаций на benchmark, но добавил 24 байта удерживаемой памяти и дал
   замедление во всех пяти A/B-парах. Вариант **отклонён**, его данные
   сохранены как `cached-ab.csv` и `*.cached.csv/out`.
2. Итоговая правка использует существующий `to_utf8_string()`:
   один буфер точной ёмкости, без кэша и удержания дополнительной памяти.

Новых API, зависимостей, кэшей или алгоритмов нет. Это внутренний
рефакторинг без изменения поведения; новый OpenSpec change не нужен.
Новый тест прошёл на исходной реализации: повторный поиск, Unicode,
замена непарного суррогата как прежде, изменение ключа конкатенацией и
отсутствующий атрибут. Вариант с кэшем также прошёл все 181 тест bsl-xml,
но это не отменяет отрицательный результат A/B.

## Аллокации основного цикла xml_parse

Итог: минус 30 000 аллокаций и 360 000 суммарно запрошенных байт,

Контрольный вывод до/после совпал.

## Чередующийся A/B

Для каждого варианта пять пар на каждый из трёх сценариев, порядок сторон
чередуется. Release без переопределения RUSTFLAGS и без `--optimize`.
Команда: `perf stat -x ';' -e instructions:u,cycles:u -- <binary>
benchmarks/<scenario>.bsl`. Счётчики — весь процесс, время — штатный
таймер основного цикла. Во всех запусках сверяется вывод без строки времени.
`ab.csv` — 30 запусков итогового варианта, `cached-ab.csv` — 30 запусков
отклонённого. Проценты вычислены попарно как `(after / before - 1) * 100`,
таблицы дают среднее и диапазон.

Отклонённый кэш, xml_parse:

| Инструкции, % | Такты, % | Внутреннее время, % |
|---:|---:|---:|
| −0,151 (−0,155…−0,148) | +2,15 (+0,20…+3,89) | +2,37 (+0,68…+4,21) |

Причина замедления не установлена; влияние размещения кода не исключено.
Уменьшение аллокаций само по себе не было основанием оставить этот вариант.

Итог без кэша:

| Сценарий | Инструкции, % | Такты, % | Внутреннее время, % |
|---|---:|---:|---:|
| json_write | +0,003 (−0,001…+0,007) | −1,54 (−4,14…−0,74) | −2,15 (−4,20…−0,77) |
| xml_parse | −0,092 (−0,093…−0,087) | +0,70 (−1,37…+2,36) | +0,68 (−1,65…+2,36) |
| xml_write | +0,006 (−0,002…+0,018) | +1,52 (−1,18…+5,01) | +1,58 (−1,68…+4,83) |

Ускорение по времени не доказано. Итоговая правка оставлена как удаление
лишней копии с измеренным уменьшением аллокаций и числа инструкций, без
роста удерживаемой памяти. Writers не исполняют изменённый код; их время
не приписывается этой правке. Выигрыш для длинных или преимущественно
одноразовых ключей отдельно не измерялся.
