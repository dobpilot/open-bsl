# onec_llvm

Интерпретатор BSL (встроенный язык 1С:Предприятие) на Rust: регистровая
байт-код VM в стиле Lua, без LLVM (имя репозитория осталось от исходного
замысла).

Крейты по слоям: `bsl-number` (десятичное число), `bsl-syntax` (лексер и
парсер), `bsl-sema` (резолвинг), `bsl-bytecode` (кодоген), `bsl-rt`
(значения и коллекции), `bsl-format` (`Строка`/`Формат`/`Число`), `bsl-vm`
(цикл диспетчеризации), `bsl-cli` (запуск скрипта и REPL).

```bash
cargo test --workspace
```

## Замеры для человека

Целевая семантика снимается с РЕАЛЬНОЙ 1С, а не выводится логически: числа
в `bsl-number` (27 знаков у деления, half-up на ничьей, точное умножение)
подтверждены измерениями, и заменить их нечем. Ниже — то, что пока НЕ
измерено. Пока замеров нет, соответствующие места в коде помечены
`// НЕ ИЗМЕРЕНО` и НЕ должны подгоняться под догадку.

Три открытых вопроса:

1. **`Sqrt`.** Модель «15 значащих с округлением» воспроизводит `Sqrt(2)`,
   но не `Sqrt(0.02)`, и ни одно простое правило не описывает обе точки.
   Тест `sqrt_small_argument_unresolved` в
   `crates/bsl-number/tests/oracle.rs` остаётся под `#[ignore]`, пока это
   не разрешено.
2. **Режим округления `Округл`.** Не измерено ни умолчание, ни то, какими
   числами платформа кодирует режимы, ни даже что вторая схема — именно
   half-even (у 1С режимы называются `Окр15как10`/`Окр15как20`, и «как10»
   может быть округлением половины ВНИЗ, а не к чётному). См.
   `bsl_number::RoundMode` и `DEFAULT_ROUND_MODE`.
3. **`n-body-precision`.** У `tests/conformance/fixtures/n-body-precision.bsl`
   нет `.expected`, и раннер такие фикстуры честно пропускает. Выдумывать
   `.expected` из вывода собственной реализации нельзя: тест, сравнивающий
   систему саму с собой, хуже отсутствующего.
4. **`ЗначениеЗаполнено` на спорных значениях.** Измерено (и зашито) только
   `Ложь` для `Неопределено`, `Null`, пустой строки, нуля и пустой даты.
   Строка из одних пробелов, `Ложь`, пустые `Массив`/`Структура`/
   `Соответствие` — догадка, помеченная `// НЕ ИЗМЕРЕНО` в
   `BslValue::is_filled`.
5. **`КодСимвола` на суррогатной паре.** Возвращает платформа код-юнит
   (`55357`) или полную кодовую точку (`128512`)? Здесь взята кодовая
   точка — ради того, чтобы `КодСимвола(Символ(к)) = к`; см.
   `BslString::char_code_at`.
6. **Даты: представление по умолчанию.** Печатает ли `Строка(Дата)` время
   всегда или опускает его при нулевом времени суток, и как выглядит пустая
   дата. Взято `дд.ММ.гггг ЧЧ:мм:сс` без исключений, см.
   `bsl_rt::date::DEFAULT_PATTERN`.
7. **Даты: `ДобавитьМесяц` и первый день недели.** `31 января + 1 месяц` —
   зажатие в последний день месяца (взято) или ошибка? `ДеньНедели`/
   `НачалоНедели` считают неделю с понедельника (взято) или с воскресенья?
   См. `BslDate::add_months` и `BslDate::weekday`.
8. **Даты: `ДЛФ`.** Набор кодов длинных локальных форматов и вид каждого в
   русской локали — целиком догадка, см. `bsl_rt::date::format_long`.
9. **Коллация `ТаблицаЗначений.Сортировать`.** Главный неизмеренный вопрос
   волны 2. 1С сортирует строки ПО ЛОКАЛИ, а не по кодовым точкам: `ё`
   стоит после `е`, регистр обычно вторичен, кириллица и латиница
   упорядочены не по номерам символов. Сейчас в `bsl_rt::table::collate`
   стоит приближение «сначала `ВРег`, потом исходный вид», и оно заведомо
   неверно на `ё` и на взаимном порядке алфавитов. После замера станет
   ясно, хватает ли его или нужна полная UCA (`feruca`, `icu_collator`) —
   заменяется ровно эта одна функция.
10. **`Итог` по нечисловой колонке.** Сейчас нечисловые значения молча
    ИГНОРИРУЮТСЯ (колонка из одного текста даёт `0`). Возможные варианты
    платформы: то же, ошибка, или счёт нечисловых нулём.
11. **Порядок разнотипных значений при сортировке.** Колонка со смешанным
    содержимым упорядочивается по рангу типа (`bsl_rt::table::type_rank`),
    порядок рангов выбран произвольно.
12. **Мелочи строковых функций.** Пустая подстрока в `СтрНайти`,
   перекрывающиеся вхождения в `СтрЗаменить`, число строк у пустого текста,
   `СтрПолучитьСтроку` за границей, пустой разделитель в `СтрРазделить` —
   всё это выбрано по здравому смыслу и перечислено в фикстуре
   `tests/conformance/fixtures/strings-and-types.bsl`, у которой намеренно
   нет `.expected`.

Фикстуры без `.expected` — это и есть очередь на замер: раннер их
пропускает, а прогон на платформе даёт готовый эталон построчно.

Скрипт для прогона на платформе:

```bsl
// Sqrt: разрешить противоречие
Сообщить(Формат(Sqrt(2),      "ЧГ=0; ЧРД=."));
Сообщить(Формат(Sqrt(0.02),   "ЧГ=0; ЧРД=."));
Сообщить(Формат(Sqrt(200),    "ЧГ=0; ЧРД=."));
Сообщить(Формат(Sqrt(0.0002), "ЧГ=0; ЧРД=."));
Сообщить(СтрДлина(Строка(Sqrt(2))));
Сообщить(Формат(Log(2), "ЧГ=0; ЧРД=."));
Сообщить(Формат(Exp(1), "ЧГ=0; ЧРД=."));

// Округл: режим по умолчанию и явные режимы
Сообщить(Формат(Округл(2.5),       "ЧГ=0; ЧРД=."));
Сообщить(Формат(Округл(-2.5),      "ЧГ=0; ЧРД=."));
Сообщить(Формат(Округл(3.5),       "ЧГ=0; ЧРД=."));   // 4 везде, или 3 при half-even
Сообщить(Формат(Округл(2.675, 2),  "ЧГ=0; ЧРД=."));   // 2,68 = decimal, 2,67 = f64
Сообщить(Формат(Округл(2.5, 0, 0), "ЧГ=0; ЧРД=."));
Сообщить(Формат(Округл(2.5, 0, 1), "ЧГ=0; ЧРД=."));

// ЗначениеЗаполнено: спорные случаи
Сообщить(ЗначениеЗаполнено("   "));            // пробелы — пусто или нет
Сообщить(ЗначениеЗаполнено(Ложь));
Сообщить(ЗначениеЗаполнено(Новый Массив));
Сообщить(ЗначениеЗаполнено(Новый Структура));

// ТипЗнч: имена типов на выходе
Сообщить(Строка(ТипЗнч(1)));
Сообщить(Строка(ТипЗнч("а")));
Сообщить(Строка(ТипЗнч(Неопределено)));
Сообщить(Строка(ТипЗнч(ТипЗнч(1))));

// СтрНайти: индексация
Сообщить(СтрНайти("абвгд", "вг"));             // 3 при индексации с единицы
Сообщить(КодСимвола(Символ(128512)));          // кодовая точка или суррогат

// Даты: формат по умолчанию и арифметика
Сообщить(Строка(Дата(2024,1,15,10,30,0)));
Сообщить(Строка(Дата(2024,1,15)));             // время нулевое: печатается?
Сообщить(Строка('00010101'));
Сообщить(Формат(Дата(2024,1,15), "ДФ='дд.ММ.гггг'"));
Сообщить(Дата(2024,1,15) - Дата(2024,1,14));   // 86400?
Сообщить(Строка(ДобавитьМесяц(Дата(2024,1,31), 1)));  // 29.02 или ошибка
Сообщить(ДеньНедели(Дата(2024,1,15)));         // пн = 1 или 0
Сообщить(Строка(НачалоНедели(Дата(2024,1,17))));

// Коллация: как 1С реально сортирует
ТЗ = Новый ТаблицаЗначений;
ТЗ.Колонки.Добавить("С");
Для Каждого з Из СтрРазделить("яблоко,Яблоко,ёлка,Ель,zebra,Апельсин,10,2", ",") Цикл
    ТЗ.Добавить().С = з;
КонецЦикла;
ТЗ.Сортировать("С");
Для Каждого с Из ТЗ Цикл Сообщить(с.С); КонецЦикла;

// Итог по нечисловой колонке
ТЗ2 = Новый ТаблицаЗначений;
ТЗ2.Колонки.Добавить("К");
ТЗ2.Добавить().К = "текст";
Сообщить(ТЗ2.Итог("К"));                        // 0, ошибка или пропуск

// Фикстуры целиком, вывод построчно положить в соседний .expected:
//   n-body-precision.bsl
//   strings-and-types.bsl
//   dates.bsl
//   table-wave2.bsl
```

## Уже измеренные эталоны

Менять эти значения нельзя — они сняты с платформы.

```
1/3                     -> 0,333333333333333333333333333    (27 знаков)
2/3                     -> 0,666666666666666666666666667    (округление вверх)
10/3                    -> 3,333333333333333333333333333    (27 после точки, 28 значащих)
1/268435456             -> 0,000000003725290298461914063    (half-up на ничьей)
Sqrt(2)                 -> 1,4142135623731
Sqrt(0.02)              -> 0,141421356237309                (ОТКРЫТО, см. выше)
1.10 * 1.00             -> 1,1
Pow(10, 30)             -> 1 000 000 000 000 000 000 000 000 000 000  (точно)
СтрДлина(Строка(1/3))   -> 29
Строка(1000.5)          -> 1 000,5
КодСимвола(разделитель) -> 160                              (NBSP)
Число(Строка(1000000))  -> 1 000 000                        (round-trip живой)
Строка(Истина)          -> Да
Строка(Новый Массив)    -> Массив
```

Почему это именно так, чтобы не «исправить» как баг:

* Лимит деления — на МАСШТАБЕ, а не на значащих: `1/3` даёт 27 значащих,
  `10/3` — 27 знаков после точки при 28 значащих.
* Half-up подтверждён точной ничьей: 1/2²⁸ = 0,0000000037252902984619140625
  ровно; платформа дала `...063`, half-even и truncate дали бы `...062`.
* Умножение без границы масштаба — это семантика, а не недосмотр: `x = x * x`
  в цикле подвешивает саму платформу. `MAX_SCALE` в коде — защита от OOM.
* `Pow(10,30)` точный: через f64 вышло бы `1 000 000 000 000 000 019 884 624 838 656`.
* n-body с `Для i = 1 По 50000000` неисполним нигде, включая 1С: масштаб
  растёт примерно на 50 знаков за итерацию. Фикстуры намеренно урезаны до
  100/3/200 итераций — увеличивать их обратно не нужно.

Целимся в 1С, не в OneScript. OneScript, судя по всему, на C# `decimal` с
кэпом 28–29 разрядов, и округлит там, где 1С не будет: расхождения с ним
ожидаемы и документируются, а не чинятся.
