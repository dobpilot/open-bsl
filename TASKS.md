# Backlog

Line format (order top-to-bottom by priority):

    - [ ] (slug) [hard] short description

- `(slug)` is a stable id with no spaces. The arbiter ticks the box by matching
  it, so it must be unique. Reuse OpenQuestion IDs where one exists.
- `[hard]` is optional. Tag a task hard to trigger the two-reviewer panel (two
  independent reviewers, both must PASS) and max effort on review. Use it for
  subtle platform semantics, decimal edge cases, and VM/bytecode correctness.
- The reviewer flips `- [ ]` to `- [x]` — never do it by hand mid-run.

## Notes for the loop

- Платформа 1С на машине ЕСТЬ — измеряй, а не предполагай. Полный цикл:
  проба в measure-скрипт -> `./tests/conformance/measure/1c/run-on-1c.sh
  <скрипт>` (~6 секунд; окружение и ручки — в шапке самого скрипта) ->
  построчный дифф платформенного вывода с выводом этого интерпретатора ->
  закрытие вопроса переносом из `OPEN_QUESTIONS` в `MEASURED_ANCHORS`.
  `.expected` для фикстур снимается ТОЛЬКО прогоном фикстуры на платформе
  (`run-on-1c.sh путь/фикстура.bsl` кладёт `<фикстура>.platform.txt` рядом)
  и НИКОГДА — выводом этого интерпретатора. Решение, которое замером
  закрыть не удалось, — тройка `НЕ ИЗМЕРЕНО(ID)` + запись в
  `crates/bsl-rt/src/open_questions.rs` + одна строка в measure-скрипте
  (реестровый тест `open_questions_registry_matches_source_markers`
  проверяет все три стороны).
- Грабли платформы, уже стоившие таймаутов: встроенную ФУНКЦИЮ (например,
  `Вычислить`) нельзя вызвать как процедуру-оператор — ошибка компиляции
  всего модуля, симптом «пустой вывод, exit 0»; необработанное исключение
  и модальное окно из прогона выглядят одинаково — таймаут 180 с, поэтому
  каждую пробу — в `Попытка`. `--ingest-measurements` пишет `platform.tsv`
  РЯДОМ с поданным файлом: ингест `measure-*.platform.txt` из каталога
  measure затирает оракул `measure-all`.
- Каждый новый тип проходит все таблицы-единственные-источники:
  `BUILTIN_FN_NAMES`/`BUILTIN_METHOD_NAMES` + `arity_range` +
  `call_builtin_fn` в builtin.rs, `NEW_TYPES` в resolver.rs, `enums.rs`;
  новые опкоды — ещё и `text.rs` (`write_instr`/`parse_instr`/`OPCODES`) с
  классификацией эффектов в `bundle.rs`.
- Перед сдачей задачи: `cargo fmt --all -- --check`, `cargo clippy
  --workspace --all-targets -- -D warnings`, `cargo test --workspace` —
  все зелёные. Комментарии и rustdoc — русской технической прозой.
- Prefer empirical fixtures captured from the real platform over doc claims.
- Numeric/format tasks assert exact strings (NBSP separator, stripped trailing
  zeros), not approximate equality.
- Фикстура `json-dates.expected` снята с платформы в зоне Europe/Moscow и
  зависит от часового пояса машины (см. её шапку): если конформанс-тест
  падает ТОЛЬКО на ней на машине с другой зоной — это смена исходных данных
  пробы, а не регрессия; не «чинить» код под неё.
